## Goal

Wire recalculation into the one edit seam: `AppCtx::push_edit` runs the
pass over the step's dirty cells (and again after `revert`), wraps the
step and a `RecalcEdit` value snapshot into one undo entry, and the
editing commands report their dirty cells. Resize stops calling
`scale_geometry`; `GUARD` protects its cell from indirect writes.

## Interfaces

- `AppCtx::push_edit`'s recalc extension (in `app.rs`)

## Acceptance criteria

- [ ] One user action is one undo step including every recalculated cell;
      undo restores the previous values **by snapshot** (test that a
      recomputed cell's pre-edit value, including an unknown function's
      cached value, comes back unchanged).
- [ ] The ADR 0040 undo property holds for a resize with formulas (run,
      undo, compare documents; run, undo, redo, compare).
- [ ] Resize of a master instance recomputes geometry through `recalc`
      and never calls `scale_geometry` (assert in a test; the model
      function is untouched).
- [ ] A `GUARD`-ed cell survives an indirect write (move/resize) with one
      `Guarded` warning and its formula unchanged; a direct cell edit
      replaces it.
- [ ] A failing edit changes nothing and recalculates nothing (ADR 0039).
- [ ] `dirty_cells` covers every edit type that writes cells (a test per
      type).
- [ ] Connector re-routing skips a connector whose geometry rows carry
      formulas (ADR 0056's rule, one test).
- [ ] Hand-off gate green in the worktree (AGENTS.md section 7: `--quick`

### What changed

**`crates/commands/src/recalc.rs`** (was the stub; now the whole seam):

- `recalc_after_edit(ctx, session, dirty)` runs the pass over the step's
  dirty cells and their dependents with `materialise_inherited`
  (ADR 0056's edit pass), using `recalc_with` and the session's
  `DepGraph` (ADR 0055). Warnings land on `AppCtx::warnings`; the
  signature is the committed one.
- `fill_missing` / `fill_missing_with` are the fill-in entry point of
  ADR 0057 that task P6-08 calls after a read (no undo entry).
- `RecalcEdit` is the undo entry: the step plus the snapshot of
  everything the pass changed. `apply` re-runs the step and the pass
  (the pass again after a revert: every redo recomputes from the step's
  own writes); `revert` restores the snapshot and then reverses the
  step, so the document comes back exactly as it was — the recalculated
  cells by snapshot, never by recomputation.
- `SnapshotEngine` wraps `DocumentEngine`: it records every sheet before
  the first write to it, which covers the side-effect writes
  `RecalcOutcome::updates` does not list (`Document::write_cell`'s
  derived-cell refreshes, P6-06 open issue 3, and `SETF` targets).
- The ADR 0056 writer classification: `formula_computes` (does the
  formula read a cell or call a function?), `formula_is_guarded`,
  `geometry_is_formula_driven` (the connector rule), `literal_number`
  (the constant a resize scales), and the dirty-address builders
  (`subtree_addresses`, `document_addresses`, per-sheet push).

**`crates/commands/src/app.rs`**: `DocumentSession::graph:
Option<DepGraph>` (built on the first pass, kept beside the undo stack);
`push_edit` checks the session first (a failed edit changes nothing,
ADR 0039), runs the pass over `Edit::dirty_cells`, and pushes one entry
holding the step and the pass's snapshot.

**`crates/commands/src/builtins/edit.rs`**:

- `CellEdit` reports its touched cells (the target plus the derived
  cells of ADR 0038 rule 2), and splits **indirect** writes (a move, a
  resize: skipped for a `GUARD`-ed cell with one `Guarded` warning, the
  formula unchanged) from a **direct** user edit (`CellEdit::direct`,
  which replaces the formula `GUARD` and all).
- `StructuralEdit` reports every cell of the subtree it adds or removes.
- `GeometryEdit` is now the **constant-geometry** rescaler (ADR 0056's

### Deviations

1. **`RecalcEdit` is a wrapper with entry snapshots, not P6-01 open
   issue 2's `(label, Vec<CellUpdate>)`.** A value snapshot cannot undo
   a materialised formula (or restore an entry's absence), and criterion
   2 compares whole documents; the snapshot keeps the exact entries.
2. **The pass runs after `apply` and on every re-apply (redo);
   `revert` restores by snapshot and does not re-run the pass.** Read
   "the pass again after `revert`" as the pass on the re-apply that
   follows a revert: a pass after `revert` itself would recompute the
   very cached values criterion 1 requires back unchanged (an unknown
   function's cached value, a cycle's kept values) and re-materialise
   the `Inh` rows criterion 2's comparison needs restored.
3. **The snapshot is per sheet, one clone per sheet the pass touches**
   (captured before its first write). It is the only way to cover the
   unlisted side-effect writes without a write hook inside the model;
   `RecalcEdit` restores whole sheets to the post-step, pre-pass state
   and the step's own inverse then runs.
4. **A bare literal is not "a formula" for the writer split.**
   `formula_computes` is true only for a formula that reads a cell or
   calls a function (`Inh` counts); `-2`, `2+3` and `2 in` are constant.
   The Phase 5 router writes literal formulas on the paths it owns
   (ADR 0045), so the strict reading would have made the router skip
   its own paths after the first route. The connector rule and the
   resize split share this one classification.
5. **Constant geometry still scales on a resize** (through `GeometryEdit`,
   over the section write; `Document::scale_geometry` is not called).
   Without it a resize of a shape with constant geometry rows (our
   catalog masters, the drawing tools) would stop scaling its outline:
   a gap the ADR accepts only for rows whose formulas the evaluator
   cannot cover (`NurbsTo` E, `PolylineTo` A). The two writers never
   touch the same cell.
6. **Out-of-lane edits**, each small: `crates/commands/src/edit.rs`
   (`CompositeEdit` must aggregate its steps' dirty cells or a
   multi-cell command recalculates nothing) and
   `crates/commands/src/builtins/connector.rs` (the one `continue` of
   the ADR 0056 skip rule in `reroute_document`, and
   `PathEdit::dirty_cells`).
7. `CellEdit::direct` is `#[allow(dead_code)]` until task P6-09's panel
   edits call it (the P5-04 `StructuralEdit::insertion` precedent); its
   unit test pins the "a direct cell edit replaces `GUARD`" half of
   criterion 4, and the `insert.shape` glue-failure integration test
   compares reachable state (the P5-09 arena rule) where the strict
   `Document` equality is reserved for the failing-`CellEdit` unit test.

### Open issues

1. **Our catalog masters carry constant geometry**
   (`crates/model/src/stencils`, not this task's lane): a resized
   Ferrogram catalog instance scales its rows literally instead of
   recomputing them, because the masters author no geometry formulas.
   Formula geometry for the masters (X = `Width*0.5` and friends) is a
   model change for the master; until then the catalog and drawing-tool
   shapes keep the Phase 5 resize behaviour.
2. **A row-union instance with no own geometry rows** cannot be
   materialised by the pass: `Document::write_row_cell` needs the row on
   the shape's own sheet. Corpus instances carry their own `Inh` rows,
   so the exit criterion is unaffected; a future case would need a
   row-insertion mutation in the model.
3. **Page-level edits** (`builtins/page.rs`, not this task's) keep the
   default empty dirty set: a page add or delete recalculates nothing.
4. The dependency graph is re-linked per pass; a removed shape leaves
   stale nodes (harmless, its addresses resolve to nothing). A full
   rebuild on structural edits can wait.
5. The master rung (graph edge 2 and `geometry_source`) is the master's
   shape that carries rows — the P6-06 open issue 2 approximation: the
   model's `master_shape` position rule is not public.
6. Defensive arms left uncovered (P5-15's note): `run_pass`'s "no
   dependency graph" arm, `warning_line`'s `#[non_exhaustive]` wildcard,
   `document_addresses`' `u32::try_from` guard and `reads_or_calls`'
   unknown-node arm. None is reachable through the public API.
7. **`Document::scale_geometry` now has no caller in `crates/commands`**
   and stays untouched in the model (criterion 3); a later cleanup task
   may delete it or re-home the constant-geometry scaling.
8. Black-box check: does Visio scale the geometry rows of
   a shape whose rows are literal constants when the shape is resized?
   The rule here keeps the Phase 5 answer (it scales).
9. For P6-08/P6-09/P6-10: the fill-in entry point is
   `commands::recalc::{fill_missing, fill_missing_with}`; the panel
   edits should write through `CellEdit::direct`; the recalc report of a
   step is `RecalcReport` (unchanged) and the pass's undo entry is
   internal to `crates/commands/src/recalc.rs`.
