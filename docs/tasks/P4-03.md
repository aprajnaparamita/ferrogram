## Goal

A running desktop window and a wasm build: menus for the Phase 4
commands, the shell that hosts the stub widgets, settings persistence,
native file dialogs on desktop, upload/download on wasm, and the
`--ui-layout` flag.

## Interfaces

Implemented over the fixed stubs (bodies only):

```rust
shell::Shell::show(&mut self, &egui::Context) -> Result<Vec<Intent>, UiError>
shell::Shell::dispatch(&mut self, &[Intent]) -> Result<Vec<Result<Outcome, CommandError>>, UiError>
shell::dispatch_one(&Registry, &mut AppCtx, &CommandId, Invocation) -> Result<Outcome, UiError>
settings::load_settings/save_settings/show_options
dialogs::NativeFilePicker as FilePicker   // rfd, sync API
```

Shell frame layout (top to bottom): title strip with the quick access
toolbar (`ribbon::Ribbon::show_quick_access`), menu bar (File, View,
Help dispatching registry ids), ribbon (`Ribbon::show`), the canvas area
(`canvas::show` between the shapes window (`shapes_window::ShapesWindow::show`)
on the left and the panels (`panels::show_shape_data`,
`panels::show_size_position`) on the right), page tabs
(`canvas::show_page_tabs`), status bar (`canvas::show_status_bar`).
Widget stubs return `UiError::NotImplemented` in this task's absence:
render the frame anyway and show the error text in the status bar; do
not crash (AGENTS.md section 6).

The `NeedsInput` flow (ADR 0036/0028): `Shell::dispatch` sees
`CommandError::NeedsInput(NeededInput::Path { purpose, suggested })`
from an interactive `Source`, asks the `FilePicker`, and re-dispatches
the same id with `path` (desktop) or `name` + `data: Bytes` (wasm
upload) filled in. Programmatic sources get the error back untouched.

`apps/ferrogram/src/main.rs`: parse `--ui-layout 2016|365` (and
`--help`) before the eframe loop; build `builtins::registry()`, load
both layouts with `ui_spec::Loader` (embedded loader is P4-04's; use the
disk `Loader` here and switch when it lands), load settings through the
eframe-backed `SettingsStore`, run `Shell`. The web app main is the same
with `eframe::WebRunner` and the wasm `FilePicker`.

**Deviations** (closest correct version, per the implementer role):

1. `Shell::show_in(&mut egui::Ui)` added; `Shell::show(&Context)` is
   kept as the fixed P4-01 entry point and delegates through
   `Context::root_ui`. egui 0.37 hands the root `Ui` to
   `eframe::App::ui` and panics on `root_ui` while it is borrowed, so
   the two apps call `show_in` with the ui they were given; `show`
   serves callers outside a frame pass (the tests).
2. `Shell` carries widget-local state (ribbon, shapes window, canvas
   cache, picker, pending pick, modal flags, status line, quit flag;
   ADR 0029 keeps widget state in `crates/ui`) with additive methods
   `set_picker`, `status`, `quit_requested`, `note_error`.
   `Shell::new`'s signature is unchanged.
3. `FilePicker` gained a defaulted `poll() -> PickState` for the wasm
   asynchronous pick; `save(request, data)` with empty `data` means
   "ask for the target only" (the `NeedsInput` re-dispatch writes the
   file), with non-empty `data` it writes/downloads the bytes.
4. `app.quit` and `app.office.center.options` are window-level
   commands the shell runs itself (quit the viewport; open the
   ADR 0032 dialog): their `commands.yaml` rows are stubs and
   `crates/commands` is not ours — the P4-02 note sanctions this for
   `app.quit`. They render enabled in the menus; `Shell::dispatch`
   intercepts them, while `dispatch_one` still reports `Unsupported`
   to programmatic callers. Every other menu entry is a plain registry
   id (labels and enabled state from the registry).
5. `eframe::Storage` is not `Send` but `SettingsStore: Send`, so no
   store can hold `&mut dyn Storage`. `settings::TextStore` is the
   store over the slot *text*: the app reads the slot, loads/saves
   through the seam and writes `TextStore::take_written()` back. The
   corrupt-store warning reaches `AppCtx::warnings` through
   `TextStore::take_warning` (exactly one).
6. Cancelled dialog: one result entry per intent
   (`Outcome::message("Cancelled")`, nothing dispatched); a
   `NeedsInput` no dialog can answer (text, number, folder) goes back
   untouched even for interactive sources.
7. Outcome messages show in the title strip (`Shell::status`); the
   status bar shows the last warning (P4-05's `show_status_bar`
   contract). `canvas::show` and `canvas::show_rulers` draw in the
   same rect, the rulers painting over the canvas bands.
8. The zoom clamp stays where the master note put it: the shell never
   clamps zoom itself (the canvas and `builtins` share
   `ZOOM_MIN`/`ZOOM_MAX`).

**Open issues**:

- `file.open` still does not update `Settings::recent_files` (P4-02
  open issue; the shell shows the opened file in the title strip).
- Right-click context menus are not wired: the shell never calls
  `Ribbon::set_context_menu` (P4-09 wiring; the committed menus carry
  no controls yet).
- Keyboard shortcuts (P4-08 `shortcuts::dispatch`) are not hosted by
  the shell yet; when they land, the shell adds the pass over egui
  input before the widgets (ADR 0036).
- `file.exit` exists in `commands.yaml` next to `app.quit` and is
  unused; Phase 5/8 should pick one id for quitting (the shell
  intercepts `app.quit`).
- A real options command returning `UiRequest::ShowOptions` (e.g. a
  `view.options` builtin) would remove the
  `app.office.center.options` shell intercept; it belongs in
  `crates/commands` (P4-02's file).
- On wasm only one asynchronous pick runs at a time (thread-local
  slot) and `save` with empty data reports a cancel (the web has no
  target chooser; `file.save` produces an `Outcome::payload` there).
- The desktop `NativeFilePicker` bodies open real dialogs and are not
  unit-tested; the picker flows are tested through an injected fake.
- The Options dialog edits `Settings` in place (ADR 0032) and the app
  persists on the settings-snapshot change, at `App::save`, and on
  shutdown; a crash in the same second as a change can lose that
  change (acceptable for the alpha).
