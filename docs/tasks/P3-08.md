## Goal

## Interfaces

Implements (signatures fixed by P3-01):

```rust
impl VisualStyles {
    pub fn load() -> Result<VisualStyles, Error>;
    pub fn line_pattern(&self, index: u32) -> Option<LinePatternTemplate>;
    pub fn line_end(&self, index: u32) -> Option<LineEndTemplate>;
    pub fn fill_pattern(&self, index: u32) -> Option<PatternTemplate>;
    pub fn shadow(&self, index: u32) -> Option<ShadowTemplate>;
}
```

`load` parses `include_str!("../data/visual-styles.yaml")` with
`serde-saphyr` (already a dependency of `crates/render`); unknown indices
return `None` and the caller substitutes the no-op style with a warning
(ADR 0021). The data file format is the one in ADR 0023; extend it with
extra optional fields only if a template needs them, and note the change
in the Result.

Consumers: `ferrogram-render`'s scene builder (P3-05) scales templates by
the shape's cells (dash by `LinePattern` and line width, arrowheads by
`BeginArrowSize`/`EndArrowSize`, tiles by spacing, shadows by the shadow
cells).

## Result

Filled in 2026-10-14. Branch `agent/P3-08`.

### What was built

- `crates/render/data/visual-styles.yaml` (new, our own work): visual
  style definitions with a provenance header (what is ours, which index
  comes from which source, date, conventions). Entries:
  - `line_patterns` 0..23 (every index the reference documents),
    dash rhythms as multiples of the line width;
  - `line_ends` 0..24 (`BeginArrow`/`EndArrow` share the index space),
    our own arrowhead paths in a unit box (x = 0 tip at the vertex,
    x = 1 tail along the line, y = 0.5 line centre; `width` scales y and
    `length` scales x, both multiples of the arrow size class);
  - `fill_patterns` 0..24: `none`, `solid` and 23 tile patterns; the
    fill/shadow pattern names (`visNoFill` .. `visThinDiagonalCross`)
    come from the `VisCellVals` enumeration (derived facts) and appear in
    each entry's `note`;
  - `shadows` 0..1 (hidden / simple drop shadow).
- Every corpus index has an entry (corpus census in the header):
  `LinePattern` 0/1/23, `BeginArrow`/`EndArrow` 0, `FillPattern` 0/1/24,
  `ShdwPattern` 0. Each entry has a `note` describing intent.
- `crates/render/src/styles.rs`: `VisualStyles::load` parses the file
  with `serde-saphyr` (`include_str!`, no runtime file access) and the
  four lookups resolve an index to a template; unknown indices return
  `None`. A small absolute path dialect of our own (`M`, `L`, `Q`, `C`,
  `Z`, case-insensitive) parses the shapes and tiles with bounded
  segments; all malformed input returns `Error::InvalidStyleData`, never
  a panic. 35 unit tests cover the committed data, every lookup, the
  corpus indices and the malformed-input paths (99.1% line coverage for
  `ferrogram-render`, threshold 75%).

### Deviations from the P3-01 interfaces

- `crates/render/src/error.rs` (outside the task's file list) gained
  `Error::InvalidStyleData`: the fixed `load` signature needs a way to
  report broken committed data, and neither existing variant fitted.
- `PatternTemplate` gained `kind: PatternKind` (`None`, `Solid`, `Tile`),
  `spacing: f64` (tile pitch as a multiple of the line width) and
  `invert: bool` (tile draws the background colour; the `visBackDots`
  family). Without `kind` the builder cannot tell "no fill" from "solid
  fill"; `spacing` and `invert` are the ADR 0023 `spacing` field plus one
  optional field the back-dots tiles need. All other signatures are
  unchanged.
- `VisualStyles` no longer derives `Eq` (the templates hold `f64`).
- The data format carries `note` on every entry (ADR 0023) and optional
  `filled`, `invert`, `width`, `length`, `spacing`; unknown fields are
  ignored, so the format stays extensible.

### Open issues

- `error.rs` was edited although the task owns only `styles.rs` and the
  data file (see deviations); the master may rename or move the variant.
- ADR 0023 scales dashes with the line width. Visio likely uses absolute
  dash lengths for thick lines; revisit in the screenshot pass if the
  output diverges.
- Line end indices 25..45 (extra bars and combined heads), fill pattern
  indices 25..40 (gradients; they map to `Paint::LinearGradient` /
  `RadialGradient`, ADR 0020) and patterned shadow bodies (`ShdwPattern`
  2..40 in the ShapeSheet reference) have no entries yet; they return
  `None` and the caller warns (ADR 0021).
- The arrow size classes 0..6 are recorded as names and indices
  (`visArrowSizeVerySmall` .. `visArrowSizeColossal`, [MS-VSDX] spells
  class 4 "Extra Large"); the scale factor per class is left to the
  scene builder (P3-05).
- The `.vsd` corpus was not scanned for style indices (no binary parser
  yet). `Themed` cell values are not indices; they resolve elsewhere
  (see the P3-02 master note).
- The scene builder (P3-05) must follow the unit-box and tile-box
  conventions documented in `styles.rs` and the data file header.
