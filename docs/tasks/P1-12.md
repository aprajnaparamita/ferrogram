## Goal

Read ADR 0005 and `corpus/manifest.toml`. Implement:

```
cargo xtask corpus [--verify-only] [--offline <dir>]
```

- For each `[[file]]`: if `corpus/<name>` exists with the right sha256, skip. Otherwise download from the source's `mirror_raw` URL template (`{commit}`, `{path}` substituted), verify size and sha256, and write atomically (temp file + rename). A sha256 mismatch is an error naming the file; never keep a mismatched file.
- `--verify-only`: download nothing; report missing or mismatched files and fail if any.
- `--offline <dir>`: copy from a local directory (e.g. `reference/corpus-candidates/libvisio/test-data/`) instead of the network; same verification.
- `name` must be a relative path inside `corpus/` with no `..` or absolute components; reject otherwise (hostile-manifest test).
- Print a summary: fetched / already present / failed.
- HTTP: use a small blocking client with a permissive license (e.g. `ureq` with rustls). sha256: `sha2`. Check `cargo deny check` passes with the new dependencies.
- Never panics (workspace lints apply).

CI: add a step `cargo xtask corpus` before the gate in `.github/workflows/ci.yml`, and set `LARRYGRAM_REQUIRE_CORPUS=1` for the gate step.

## Result

### What changed

- `xtask/src/corpus.rs` (new): `cargo xtask corpus [--verify-only] [--offline <dir>]`.
  Parses `corpus/manifest.toml`, validates `name` (rejects empty, absolute,
  `..`, or any non-normal component), then for each `[[file]]` skips it when
  `corpus/<name>` already matches its size + sha256, otherwise fetches it from
  the source's `mirror_raw` template (`{commit}`/`{path}` substituted) or from
  `--offline`'s directory (looked up by the file's basename, matching the
  `reference/corpus-candidates/libvisio/test-data/` layout). Downloads are
  verified for size + sha256 and written atomically (temp file + rename); a
  mismatch removes the file and errors, naming the file. `--verify-only`
  downloads nothing and fails on any missing/mismatched file. Summary prints
  `fetched / already present / failed`.
- `xtask/src/main.rs`: `mod corpus;`, a `corpus` arm, and usage text.
- `xtask/Cargo.toml`: added `sha2`, `ureq`, `rustls-native-certs`.
- `.github/workflows/ci.yml`: added a `cargo xtask corpus` step before the gate
  and `LARRYGRAM_REQUIRE_CORPUS=1` on both gate steps.

### Deviations / decisions

- **HTTP client + rustls**: `ureq` 3's `rustls` and `platform-verifier` features
  both transitively pull in `webpki-roots` / `webpki-root-certs`, now licensed
  `CDLA-Permissive-2.0`, which is not in `deny.toml`'s allow list. To keep
  `cargo deny check` green **without** editing `deny.toml` (outside this task's
  lane), I wired rustls with the ring provider only
  (`rustls-no-provider` + `_ring`) and load the OS trust store myself via
  `rustls-native-certs` (Apache-2.0/ISC/MIT), building `RootCerts::Specific`.
  No CDLA-licensed crate remains in `Cargo.lock`.

### New dependencies

(Apache-2.0/ISC/MIT) and their transitive rustls/ring/security-framework/
schannel/openssl-probe crates. All licenses already in `deny.toml`.
