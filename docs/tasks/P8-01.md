## Goal

Plan Phase 8 so that as many workers as possible run at once, beside the
Phase 7 workers, on disjoint files.

1. **Plan (`docs/plans/phase-8.md`).** Scope, the versions supported
   (decide which file versions are in scope for the alpha; libvisio
   reads versions 1 to 11), what maps to the model and what is dropped
   with a warning, the exit criteria, and the order of work as a
   dependency graph in the style of `docs/plans/phase-7.md` section 4.
2. **ADRs.** At least: the container and stream layer (the OLE compound
   file reader: a permissive crate such as `cfb`, checked with
   `cargo deny`, or our own; the decompression), the chunk and pointer
   model per version, the mapping into `model` (shapes, geometry, text,
   styles, masters, pages, the unit rule), error handling and limits
   (never crash, capped allocations, bounded recursion), and the oracle
   comparison (what is compared against `vsd2raw`/`vsd2xhtml` output,
   and how a mismatch is reported).
3. **Module skeleton in `crates/vsd-binary`.** One module per parallel
   task, with the types and function signatures the others call, as
   stubs. Every file carries the MPL-2.0 header. The public entry point
   is one function that takes bytes and returns a `model::Document` (or
   an error) plus import warnings.
4. **Task files.** Split the implementation so tasks own disjoint files.
   A starting point to refine:
   - container and streams;
   - chunks and pointers (per version);
   - shapes, transforms and geometry into the model;
   - text, characters and paragraphs (code pages, as in the two
     `fdo86729` files);
   - styles, colours, fills and lines;
   - pages, masters and stencils (`.vss`), templates (`.vst`);
   - the oracle harness and a corpus census (more openly licensed
     `.vsd` files: list candidates with licence and source for the
     master; never commit them);
   - the open-path integration: the file-open command, the file dialog
     filter and the CLI accepting `.vsd`/`.vss`/`.vst`. This one touches
     `crates/commands/src/builtins/file.rs`, `crates/ui` and `apps/*`;
     Phase 7 tasks are told not to touch `builtins/file.rs`, but the
     dialog filter and the CLI may collide with P7-09, so say when it
     can run;
   - then tests and golden images, the three audits (review, coverage,
     clean-room) and a fix task, as in earlier phases.
   Each task file follows the format of `docs/tasks/P7-02.md`: role,
   depends on, parallel-safe with, model tier, Launch, Owns, Inputs,
   Goal, Acceptance criteria and an empty Result.
5. **Machine load.** The plan says how many Phase 8 workers can run at
   once beside Phase 7 (the phase-7 plan caps the total at twelve,
   and wave 1 of Phase 7 takes eight).

## Acceptance criteria

## Result

Filled by the architect (P8-01), 2026-10-23.

### What changed

- **`docs/plans/phase-8.md`.** Scope and the alpha version decision
  (file versions 6 and 11 in; 1–5 get `Error::UnsupportedVersion`),
  the mapping and drop-with-warning tables, the layering inside
  `crates/vsd-binary`, the work order as a dependency graph and the
  machine load (at most four Phase 8 workers beside the full Phase 7
  wave 1, of the twelve-worker cap).
- **ADRs 0068–0072.** 0068 the compound container and streams (an own
  MS-CFB reader, clean-room from the Microsoft Open Specifications;
  the `cfb` crate was rejected over the never-crash rule), 0069 the
  chunk and pointer model and the version scope, 0070 the mapping into
  the model and the unit rule (cached values only, no formulas), 0071
  errors, warnings and limits, 0072 the oracle comparison
  (`vsd2raw`/`vsd2xhtml`, normalisation and mismatch reporting).
- **The skeleton in `crates/vsd-binary`.** One module per parallel
  task: `container.rs`, `chunks.rs`, `shape.rs`, `text.rs`,
  `style.rs`, `pages.rs`, `pipeline.rs`, plus `error.rs`, `warning.rs`
  and `limits.rs` (final types). The one entry point is
  `import(bytes, limits) -> Result<Import, Error>`; `Import` carries
  the `larrygram_model::Document` and the `ImportWarning` values.
  Every entry point is an interface stub returning
  `Error::NotImplemented`, with a test of that contract (22 unit
  tests). Every file carries the MPL-2.0 header. `Cargo.toml` gained
  `larrygram-model` (path dependency, layer L1); no third-party
  dependency and no `deny.toml` change.
- **Task files P8-02 to P8-14** in the P7-02 format. Wave A (P8-02
  container, P8-03 chunks, P8-04 shapes, P8-05 text, P8-06 styles) is
  pairwise parallel-safe on disjoint files; P8-07 (pages and the
  pipeline) is the integration point and depends on wave A; P8-08
  (oracle harness and census) and P8-09 (open path, after P7-09) are
  parallel-safe with each other; P8-10 (tests, fuzz, golden images)
  then the three audits (P8-11 to P8-13) and the fix task P8-14.

### Deviations from the task brief

- The brief's starting split is kept, refined in two places: P8-07
  depends on wave A (it is the task that wires `pipeline::import`, so
  it cannot verify end to end before them), and P8-10 runs parallel to
  P8-09 (disjoint files) instead of waiting for it, so the Phase 8
  tests are not tied to the Phase 7 shell timeline.
- The seam stubs carry `#[allow(dead_code)]` with a comment: nothing
  calls them until P8-07 wires the pipeline. The alternative (wiring
  the pipeline for real) would add unreachable code and drop coverage.
- No libvisio code was copied. The plan and ADRs are written from the
  reference sources' structure; the record id tables and payload
  layouts are left to the implementing tasks (P8-03 onwards), which
  work inside the MPL-2.0 crate under ADR 0003.
