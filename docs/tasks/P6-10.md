the agreement rate with cached values (ADR 0059), and pin the exit
criterion in a test — resizing a master-based corpus shape recomputes its
geometry correctly for supported functions.

### Engine fixes the harness found (surgical, in `resolve.rs`)

Every one is pinned by the corpus' own cached values, and every one is
listed here as the task requires (the engine modules belong to
P6-02..P6-06).

1. **A read prefers the resolved cached value** (`eval_reference`): it
   re-ran the referenced cell's formula first, so a referenced unknown
   function leaked its `#N/A!` placeholder into every dependent instead
   of keeping that cell's cached value (ADR 0053), and a nested
   evaluation that failed (`Sheet.5!Width` on an instance) overwrote a
   perfectly good cached value with `#REF!`. Reading a cell now answers
   its cached value (ADR 0054's value side, the `Inh` snapshot rule) and
   evaluates the formula only when nothing is cached (the fill-in case,
   ADR 0057). This was 2 889 of the first run's 3 183 disagreements.
   Two unit tests added (`a_read_prefers_the_cached_value_over_the_stored_formula`,
   `a_read_evaluates_the_formula_when_nothing_is_cached`).
2. **`Geometry1` names the *first* `Geometry` section.** The instance
   number was used 0-based (`Geometry1` picked the second section).
   `graph.rs`'s own `split_section_number` already says "the first"
   (the dependency edges linked the right cells while the values read
   the wrong ones). Fixed in `match_section` and `section_slot`.
3. **A row index is the row's `IX`** (`Geometry1.X1` is the row with
   `IX` 1); it matched the row at that *position*. Corpus proof:
   `shape2!Geometry1.X4` caches 0 (`Geometry1.X1` = the `IX` 1 row) where
   the position reading gave 5.9 in. Now matches `IX` first and falls
   back to the position, like `graph.rs`'s `find_row_with_position`.
4. **An `Inh` snapshot on a style sheet resolves as `Local`** (it was
   labelled `HardDefault`, the "no cell defines it" rung), so a real
   cell can be told from a table default.

`crates/shapesheet/tests/resolve.rs`'s `a_numbered_section_names_the_section_instance`
and `a_masters_named_sub_shape_resolves` pinned the pre-fix semantics
(`Geometry1` = the second section, rows by position); they now build
`IX`-bearing rows and pin the corpus rules.

### Harness rules beyond the ADR's letter (for the master to write down)

1. **Boolean spelling bridge** (comparison table): a `BOOL` cell caches
   in the file as `V='0'`/`V='1'` without `U="BOOL"`, so an evaluated
   `Bool` agrees with a cached `Number(0.0)`/`Number(1.0)` exactly (and
   the other way round). Without it the run reports 290 kind mismatches
   that are one spelling rule. ADR 0059's "Bool | exact" reads as exact
   *value*; the table row could say so.
2. **Rule 3's hard-default reading**: a reference must resolve to *a
   cell* that has a value. A name only the ShapeSheet table knows
   (`DropOnPageScale`, `LockTextEdit`) resolves to the hard default —
   no cell of the document holds it — and is skipped as
   `missing-reference`. 29 cells, all of them cases where the model
   cannot know the file's value (see Open issues 1).
3. **The scan set** (rule 1's implementation): a formula that is the
   `Inh` marker is not scanned (nothing to evaluate; 10 608 corpus
   cells); a `No Formula` marker is scanned and skipped as `no-formula`
   (2 589 cells). Hence `formulas` = 9 242 and `formulas = counted +
   skipped` holds per file and in total.

ADR 0059's example `total` line (11 903 / 5 312 / 6 591) is inconsistent
with its own per-file row (blue-box's 876 counts the `Inh` markers its
total excludes). The measured numbers above follow the row-sum rule over
the model's sheets; the counted difference against the estimate (5 184
vs 5 312) is rule 2's 29 hard-default cells plus the cells their
references pull in.

### The 32 documented exclusions (six causes)

| Cause | Cells | Why we accept it |
|---|---|---|
| `SETF("User.X", v)` string-literal target | 5 | ADR 0053's basic `SETF` takes `GetRef(...)`; an action cell caches 0 whatever it evaluates to |
| `User.LCID` on a `LangID` cell | 9 | Visio maps an LCID number to a locale tag; ADR 0052 has no such coercion |
| `NA()` on an event cell | 5 | `NA()` is `#N/A!` by definition; Visio caches 0 on event cells |
| `Themed` marker in a theme-driven cell | 8 | the model keeps the `Themed` marker (ADR 0021 resolves theme values in the renderer) |
| `GUARD(0)` on `Character.Size` | 4 | Visio clamps a character size to 1 pt where the formula computes 0 |
| `RGB(...)+1` | 1 | colour arithmetic: Visio caches the RGB unchanged, we coerce the colour to a number (ADR 0052) |

### Deviations

1. **`exit_resize.rs` also reads `testfile5.vsdx`** (the task names only
   `blue-box.vsdx` and `qs-box.vsdx`). Neither named file holds a master
   instance: their one master ("Dynamic connector") is unused and both
   page shapes carry no `Master` attribute (verified in the packages and
   in the model). The named files' resize case runs as written (formula
   cells recomputed at hand-computed values, `Rel*` geometry rows kept,
   ADR 0056), and the master-based case — `Inh` geometry rows
   materialising to the master's `Width*1`/`Height*1` at the new size —
   runs on `testfile5.vsdx`, whose instance is exactly the exit
   criterion's shape. Expectations are literal constants in the test
   (4 x 2 in gives X = 4, Y = 2); no cached value from the file is read.
2. The evaluation count is measured by replaying the resize's exact
   dirty set (`Outcome::edit::dirty_cells`, taken through
   `Registry::execute` because the `dispatch` seam consumes the edit)
   with a counting `FormulaEngine` wrapper; the number is the pass's
   cell evaluations, not the changed cells.
3. The comparison bridge and the two rule readings above are harness
   rules the ADR does not spell out (listed for the master to amend
   ADR 0059's table).

### Open issues

1. **The document sheet is not modelled.** `visio/document.xml`'s cells
   (2 542 non-`Inh` formulas, and values like `DropOnPageScale` = 1)
   are kept as `Preserved` (ADR 0012) and `masters.xml`'s MasterSheet
   (119) is not a sheet either. A future task could give the model a
   document/master sheet rung (ADR 0013) so those formulas enter the
   cross-check and names like `DropOnPageScale` resolve to the file's
   value instead of the hard default. Until then they are
   `missing-reference` skips (781 in total, including other
   table-only names).
2. **ADR 0059's comparison table** needs the boolean spelling bridge
   and rule 3's hard-default reading (Deviation 3), and its example
   `total` line could be re-derived from the numbers above.
3. **The six exclusion causes** are candidates for black-box
   checks (event cells caching 0, the 1 pt character-size
   clamp, `SETF`'s string target, the LCID-to-locale-tag mapping) and
   for the theme model (ADR 0021) and ADR 0052 (colour arithmetic);
   each cause retired removes its exclusion lines.
4. The harness scans the model's sheets only (ADR 0055's `sheet_refs`
   set): stylesheet rows are not addressable by `SheetRef`, so style
   formulas are outside the cross-check. A `SheetRef::Style` variant
   would widen the net.
5. `RecalcOptions::DEFAULT_MAX_EVALUATIONS` (100 000) is ~4 500× the
   measured resize case (22); see the numbers above for a suggested
   tightening.
