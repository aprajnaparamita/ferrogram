## Background

issues". The master decided them as follows:

  the doc comment.

## Goal

1. Change the `fluent_id` cross-reference so it checks against the
   union of the Fluent ids in **both** layouts.
   - `Loader::load(kind)` keeps its signature and return type. It
     reads and schema-validates both layout files, but returns only
     the requested `LayoutSet`. The `control_command` and
     `command_id` checks are unchanged.
   - Add `Loader::load_all(&self) -> Result<LayoutSets, LoadError>`,
     where `LayoutSets { visio_2016: LayoutSet, visio_365: LayoutSet }`
     reads every file once. Add `LayoutSets::get(kind) -> &LayoutSet`.
     Keep `LayoutSet::select` as it is.
   - `CrossReference { kind: "fluent_id", referenced_by, .. }`: make
     the message say "not in any layout".
2. Regression tests:
   - A command whose Fluent id exists only in the 365 layout loads
     without error for both `LayoutKind`s (extend the `good/` fixture,
     e.g. a 365-only control mapped in `commands.yaml`).
   - A Fluent id in neither layout still fails with `kind: "fluent_id"`.
     The `xref-fluent/` fixture needs a `visio-365.yaml` now; add one.
   - A control with `command: null` loads, and appears in
     `CommandLookup::labels` but not in `commands`.
   - An empty `shortcuts.yaml` (`[]`) loads. An empty
     `commands.yaml` loads when no control has a non-null command.
   - Unit tests for `load_all` and `LayoutSets::get`.
3. Fix the `ContextMenu.label` doc comment in `lib.rs` to match the
   schema (1 to 80 characters, never empty).
