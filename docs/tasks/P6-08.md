## Goal

Close the value pipeline end to end: the fill-in pass after a read (so
the five blank corpus files render), and the writer's typed `V`/`U`
spelling (so a value we write reads back the same, P2-14). The writer
still never recalculates and `read(write(read(write(d))))` still equals
`read(write(d))` (ADR 0048).

### Deviations

1. **The five blank corpus files do not render (acceptance bullet 2
   unmet; `SKIP_RASTER`/`KNOWN_BLANK` stay).** The ADR 0057 premise is
   factually wrong: **no corpus `Cell` has a formula without a cached
   value** (scanned all 15 files, all parts: 0 such cells), so the
   fill-in pass has nothing to fill in any of them and cannot change a
   raster. The measured causes (a scratch scene dump of every corpus
   file, deleted again):
   - `dwg`, `fdo86664`, `testfile5`: the page shapes are master
     instances with no `FillStyle`/`LineStyle`/`TextStyle` of their own,
     and `model::Document::resolve` never consults the **master's**
     style chain (`via=[Local, Master, SectionDefault, HardDefault]`),
     so `FillPattern`/`LinePattern` fall through to the hard default 0
     and the shapes draw nothing. Proof of the fix: copying the master's
     style links onto the instances makes all three rasterize
     non-blank (844/534/640 non-background pixels at 10 px/in). That is
     a `crates/model` change (P6-05's crate, not this task's files):
     Open issue 1.
   - `tab-short-prefix`: the shape has no size, geometry or text cells
     and no formula anywhere (only a `Tabs` section), so nothing draws
     and nothing is evaluable; even Visio cannot render it non-blank.
   - `recursion-cycle`: the package has no page contents (`<Rel>` points
     at `pages.xml` itself), so there is no raster at all.
2. **The `Value::to_cached` round-trip test is in
   `crates/commands/tests/`, not `crates/vsdx/tests/`.** `Value` lives
   in `ferrogram-shapesheet` (L2) and `ferrogram-vsdx` (L2) may not
   depend on it (ADR 0002; the gate's `layers` step went red on the
   dev-dependency and there is no exception mechanism). The named
   `crates/vsdx/tests/value_roundtrip.rs` pins the same file-level
   contract with the cached forms `Value::to_cached` produces; the
   `to_cached`-driven test sits in the first crate above both layers.
3. **`commands::recalc::fill_missing` (P6-07) has not landed**, so the
   fill-in pass calls `ferrogram_shapesheet::recalc` with
   `fill_missing_only` directly, as the task allows. When P6-07 lands,
   `builtins::file.rs` should call its helper instead (one call site).
4. **`materialise_inherited` is not set** (the master note offers it):
   ADR 0057's fill-in contract is "fill only what is missing", and a
   materialised formula would rewrite untouched files on save. It would
   not have helped the corpus anyway (the missing cells have no formula
   any rung can reach, see deviation 1).
5. **The two P5-10 preservation artefacts stay.** Removal is optional
   ("with a round-trip test" if done). It cannot be done in the owned
   files: the `U` preservation decision is `read/sheet.rs`'s
   (`value::unit(..).is_none()`), and dropping it would let the writer
   strip `U="COLOR"`/`U="STR"` from cells whose value reads back the
   same either way (`<Cell V='Themed' U='COLOR'/>`), breaking the corpus
   round-trip `diff`. The writer now re-derives every kind code
   (`BOOL`/`STR`/`COLOR`/`LIST`), so removal becomes safe only with a
   reader rule that keeps codes it does not re-derive: Open issue 5.
6. **`U="LIST"` is our own spelling.** [MS-VSDX]'s `U attribute value`
   table (2.2.5.3.3.1) has no list code (`LayerMember` is a `PtgString`,
   2.2.3.x) and the corpus spells list strings (`LayerMember V='1;0'`,
   a `Format` choice list) without a code, so a list and a string
   cannot be told apart on read back. The alternative (classify a
   code-less `;`-separated `V` as a list) misreads real corpus strings
   (`Prompt V='0=Normal;  1=Summary'`), so it was rejected. `U` is
   `xsd:string` in the schema (no validation impact); what Visio does
   with `U='LIST'` is a black-box question.
7. **Section-level cells are not filled.** `recalc` resolves a cell
   with a section and no row as a direct cell (`graph::effective`'s
   dispatch), finds no formula and skips it; the test pins the current
   behaviour and the formula survives the file round trip: Open issue 3.

### Open issues

1. **`model::Document::resolve` does not consult the master's style
   chain for an instance** (deviation 1). Rule 3 of ADR 0013 selects
   "the shape's `LineStyle`/`FillStyle`/`TextStyle`-selected style", and
   an instance that omits the attributes inherits the master's links
   ([MS-VSDX] 2.2.5.4.1: "Any sections, rows, cells, or subshapes not
   specified in the instance are inherited from the master"). With the
   master's links in place, `dwg`, `fdo86664` and `testfile5` rasterize
   non-blank and the three `KNOWN_BLANK` rows can go. Suggested home:
   `crates/model/src/lookup.rs` (P6-05 follow-up), with the P6-05 note
   about the two `Inh` lookup tests kept in step.
2. **Two corpus files cannot render non-blank by construction**
   (`tab-short-prefix`: no size/geometry/text cells and no formulas;
   `recursion-cycle`: no page contents). The acceptance bullet assumed
   all 15 could; the harness needs a rule for files with nothing to
   draw (today: the `KNOWN_BLANK`/`SKIP_RASTER` markers) before the
   markers can be deleted.
3. **`graph::effective`'s dispatch resolves a section-level cell (a
   section, no row) as a direct cell** (`crates/shapesheet/src/graph.rs`),
   so `recalc` never evaluates such cells (the fill-in test pins it).
   A section-aware resolve (`resolve_section_cell`) would close it.
4. **`crates/vsdx/tests/properties.rs` `arb_cell_value` still excludes
   `CellValue::List`** ("no `U` code maps back to a list"). The new
   `LIST` spelling makes the generator's exclusion unnecessary; a later
   vsdx test task can drop the comment and generate lists.
5. **The P5-10 preservation artefacts** (deviation 5): remove them with
   a reader rule that preserves only the codes the writer does not
   re-derive (`DATE`, `GUID`, `PNT`, `DT`, `DL`, ...), then add the
   round-trip tests ADR 0057 asks for. `read/sheet.rs` and
   `read/mod.rs` are outside this task's files.
6. **ADR 0057's consequences paragraph** says the five blank corpus
   files render after the fill-in pass and that an untouched file saves
   byte-identical; the first claim needs the Open issue 1 fix (the
   fill-in alone changes nothing in the corpus), and the ADR may want a
   correcting amendment.
7. The fill-in pass **drops `RecalcOutcome` warnings** (unknown
   functions, cycles) at load; if `AppCtx` ever wants load warnings,
   the pass can report them (ADR 0055 already returns them).
