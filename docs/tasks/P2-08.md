## Goal

Build the fixture set every later test uses: a minimal drawing, a minimal
stencil, a minimal template, and one malformed file per failure mode. The
builder generates packages byte by byte so variants (deep nesting, huge
declared sizes, ...) are one function call, not one blob.

## Interfaces

Provides (in `crates/vsdx/tests/common/mod.rs`, `#[cfg(test)]`-style helper
module used by integration tests):

```rust
/// What the builder produces.
pub enum Fixture { Drawing, Stencil, Template, Malformed(Malformed) }
pub enum Malformed {
    TruncatedZip, BadCentralDirectory, NoContentTypes, DanglingRelationship,
    MissingMainPart, HugeDeclaredSize, DeepNesting, BadContentTypes,
    ZipBomb, ManyEntries,
}

/// Builds the raw bytes of a fixture package. Hand-authored XML, our own
/// work (recorded in corpus/PROVENANCE.md).
pub fn build(fixture: Fixture) -> Vec<u8>;

/// Path of a committed fixture under corpus/fixtures/, if it is committed
/// rather than generated.
pub fn path(name: &str) -> Option<std::path::PathBuf>;
```

The builder writes plain zip archives with a minimal Visio part set
(`[Content_Types].xml`, `/_rels/.rels`, `/visio/document.xml`,
`/visio/pages/pages.xml`, `/visio/pages/page1.xml`, masters for the stencil
and template kinds). No third-party bytes anywhere.

## Result

_Filled in by the worker at hand-off._

**Built** (branch `agent/P2-08`, gate green):

- `crates/vsdx/tests/common/mod.rs`: the fixture builder. `Fixture`
  (Drawing, Stencil, Template), `Malformed` (all 10 variants),
  `build(Fixture) -> Vec<u8>`, `path(name) -> Option<PathBuf>`, plus three
  helpers later test crates need: `file_name(&Fixture)`,
  `COMMITTED_FIXTURES`, `fixtures_dir()`. Packages are plain zip archives
  with a minimal Visio part set (`[Content_Types].xml`, `/_rels/.rels`,
  `/visio/document.xml` + rels, `pages/pages.xml`, `page1.xml`, masters for
  stencil and template). The XML is hand-written and our own; element
  names, content types and relationship type URIs are structural facts from
  [MS-VSDX] and `docs/vsdx-inventory.md`. Output is deterministic (stored
  entries, fixed clock-free timestamp), so committed files can be compared
  to builder output byte for byte.
- Malformed coverage per ADR 0017 section 3: truncated zip, bad central
  directory (byte surgery on the EOCD-recorded offset), no
  `[Content_Types].xml`, dangling relationship, missing main part, huge
  declared size (local + central header patched to 100 MiB on `page1.xml`),
  deep nesting (200 nested elements in `document.xml`, cap 128), bad
  content types (not well-formed), zip bomb (8 MiB zeros deflated, ratio
  ~1000:1, cap 200), many entries (8193, cap 8192).
- `crates/vsdx/tests/fixtures.rs`: smoke test per variant (13), builder
  determinism for every variant, distinct file names, `path` behaviour,
  provenance-row check, and `committed_fixtures_match_the_builder_output`
  (the acceptance test). Regeneration: `cargo test --test fixtures
  regenerate_committed_fixtures -- --ignored`.
- 11 committed files in `corpus/fixtures/` (3 minimal + 8 malformed), each
  with a `corpus/PROVENANCE.md` row in the same commit (AGENTS.md section
  4). No third-party bytes anywhere; no Microsoft content.

**Deviations** (interface is as specified otherwise):

- Extra helpers `file_name`, `COMMITTED_FIXTURES`, `fixtures_dir` (needed
  by the tests and by P2-09).
- Stencil part set: `pages.xml` present but empty, `page1.xml` absent. The
  task prose lists `page1.xml` in the base set; ADR 0016 says a stencil has
  "an empty or absent pages.xml", and a stencil fixture with a page would
  round-trip lossily against the writer's stencil layout. Drawing and
  template use the full base set.
- `malformed-zip-bomb.vsdx` and `malformed-many-entries.vsdx` are generated
  at test time, not committed: the bomb's deflate stream is not stable
  across `flate2` versions (it would break the byte-equality test on a
  dependency bump), and the many-entries archive is ~700 KiB of boring
  headers. `path()` returns `None` for them; the smoke tests build them.
- `build` ignores zip-writer errors instead of unwrapping (never-crash
  rule); the smoke tests assert entry lists, so a silent skip would fail a
  test.

**Dependencies:** `zip` added as a dev-dependency of `ferrogram-vsdx`,
same version and features as the runtime dependency (ADR 0014). No new
crate in the tree; `cargo deny` unchanged. Shared file touched:
`crates/vsdx/Cargo.toml` (new `[dev-dependencies]` section) — P2-05/06/07
may conflict there; the master resolves.

**Oracle smoke path:** not applicable — the Phase 1 libvisio oracle reads
the binary `.vsd` format only. As the minimum, a test asserts the minimal
drawing is a valid zip with the full Visio part set and the drawing main
content type.

**Gate:** `cargo xtask gate` green (fmt, clippy, test, doc, coverage, deny,
layers, wasm, fuzz all pass).

**Open issues:**

- AGENTS.md section 4 says every committed asset file needs an
  `ATTRIBUTION.md` row. These fixtures are our own work with
  `corpus/PROVENANCE.md` rows, and the task does not own `ATTRIBUTION.md`;
  the master decides whether test fixtures count as "assets" there.
- `common::tests` (5 unit tests of the zip byte surgery) run once per
  integration-test binary that does `mod common;`. Harmless, but P2-09
  adding test files duplicates that output; move them into one test file if
  it annoys.
- The deep-nesting fixture nests custom `<Deep>` elements inside
  `VisioDocument`, so it is not schema-valid content. The schema-validation
  test (P2-09, ADR 0017 section 6) must validate written files from the
  corpus round-trip, not the malformed fixtures.
- Byte-equality of committed fixtures pins `zip` crate header output. A
  `zip` upgrade that changes header bytes fails
  `committed_fixtures_match_the_builder_output`; fix by re-running the
  regenerate test and committing the new bytes.
- Malformed fixtures are all `.vsdx` (drawing kind). If P2-09 wants a
  malformed `.vssx`/`.vstx`, that is one more `Malformed` variant here.
