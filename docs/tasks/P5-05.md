## Goal

The pointer tool works end to end: select and marquee, move, resize and
rotate with handles, snapping on, overlays drawn over the cached raster,
fast enough to drag a 1000-shape page.

## Interfaces

Implement the stubs exactly as signed (`ToolMachine::handle`,
`pointer::handle`, `handles::{handle_at, handles_for, selection_bounds}`,
`snap::{Snapper::snap_move, snap_point}`). Dispatch rules (ADR 0042):
`ToolMachine::handle` is read-only over `&AppCtx` and returns
`ToolEffect { intents, overlay }`; the shell executes the intents. The
canvas cache key becomes `(SessionId, changes, page, raster scale)` and
drops the per-frame document comparison (ADR 0040 rule 3).

Your `ToolMachine::handle` routes `ToolEvent`s to the other tool modules
(`draw`, `stencil`, `text`, `connector`) by `ToolMachine::tool`; those
modules are owned by P5-06..P5-08 and stay `Err(UiError::NotImplemented)`
until they land — dispatch to them and propagate their errors unchanged.

Consumers: P5-06..P5-08 add tool modules and may add at most these lines
of yours: `canvas.rs` — the tool-picker wiring lines they name in their
Results; `shell.rs` — none.

## Note from the master

- P5-04 open issue: `shell::dispatch_one` must push an `Outcome::edit` through `AppCtx::push_edit(session, edit)`, not `session.undo.push(edit)`. ADR 0040 rule 2 makes `push_edit` the only push path, and it carries the drop-with-warning rule for nested edits.
- P5-04 semantics to build on: `shape.move` and `shape.rotate` take deltas (`rotate` in radians); `shape.resize`, `shape.set.width` and `shape.set.height` set absolute sizes; `shape.set.*` act on the anchor shape. A handle drag is one command, so one undo step. `Selection` has an `entered` group (enter/exit group) and `refresh_page`/`clear`.
- Edits bump the session `changes` counter in `apply`/`revert`; selection-only commands do not. The canvas cache key relies on that.

## Result

Filled by the P5-05 worker, 2026-10-18, branch `agent/P5-05`.

### What changed

- **Pointer tool** (`tools/pointer.rs`, `tools/mod.rs`): click select,
  Shift toggle, Ctrl add, marquee (intersection, replace on empty space,
  add with Shift/Ctrl), page-level group mapping, double-click
  `shape.enter_group`, and one move/resize/rotate drag per gesture. A
  drag previews with overlay marks and emits exactly one
  `shape.move`/`shape.resize`/`shape.rotate` intent on release, so it is
  one undo step (ADR 0040). Alt is read at every event and disables
  snapping. The pointer keeps a scene cache keyed by
  `(SessionId, changes, page)`; events in any order are no-ops, never
  errors.
- **Handles** (`handles.rs`): `handle_at`, `handles_for`,
  `selection_bounds` and the shared scene helpers (`scene_for`,
  `node_entries`, `paths_for_shapes`, `subtree_ids`, rotated bounds).
  The handle tolerance is 6 screen pixels converted with the zoom; the
  rotate handle sits 0.25 in above the top edge. One selected shape uses
  its rotated bounds; several use the axis-aligned union (the
  `build_selection_overlay` rule).
- **Snapping** (`snap.rs`): grid, alignment (edges/centres) and
  connection-point candidates, one axis at a time, with ADR 0043's
  priority (connection point, alignment, grid). Move snaps the delta so
  a multi-shape drag keeps its relative layout; `snap_point` serves the
  drawing tools and drops. Alt and the per-target settings disable it;
  the drag overlay draws `SnapGuide` marks when a snap won.
- **Canvas** (`canvas.rs`): `show_with_overlay` emits `ToolEvent`s in
  page inches (page y up, the raster's y-down flip accounted for) and
  draws the overlay as egui vector art over the cached texture. The
  cache key is now `(SessionId, changes, page, raster scale)`; the
  per-frame `Document` snapshot comparison is gone (P4-05 closed).
  `show` remains as the no-overlay wrapper for existing callers.
- **Shell** (`shell.rs`): owns the `ToolMachine` and the last overlay,
  applies selection updates, dispatches the tool intents, clears the
  selection when the document or page changes, reads keyboard focus from
  egui's focused widget id (P4-14 closed: Tab on the canvas activates the
  `Page` scope), and routes `Outcome::edit` through `AppCtx::push_edit`
  (the P5-04 open issue closed).
- **Panels** (`panels.rs`): with a selection the Shape Data panel shows
  the anchor's name and Visio id and Size & Position shows editable
  Width, Height, Pin X, Pin Y and Angle fields that dispatch
  `shape.set.*`; with no selection the Phase 4 page/document rows stay.
  Missing values record directly on `AppCtx::warnings` (the P4-07
  warning-sink fix; no warning pseudo-rows).
- **Tests**: new `crates/ui/tests/phase5/` (`main.rs`, `pointer.rs`,
  `snap.rs`) drives the real canvas, `ToolMachine` and registry through
  `egui_kittest`: click-select, Shift toggle, marquee, one move/resize/
  rotate drag, Alt-disabled snapping, snap guides, drag frames never
  re-rasterizing, Tab focus dispatching a page-scoped shortcut, and the
  panel subject. Unit tests cover the handle math, snap priority and
  malformed input, the pointer state machine's event orders, panel
  warning/argument paths and the cache key.

### Deviations (closest correct version, per the implementer role)

1. **Selection is a tool effect field, not a command.** P5-04's command
   set has no "select this shape" command, so `ToolEffect` gained
   `selection: Option<SelectionUpdate>`; the shell applies it after the
   read-only `ToolMachine::handle` call. This keeps the tool read-only
   over `AppCtx` (ADR 0042) without inventing a registry command in
   another crate's lane. A future `edit.select` command would let the
   control channel and MCP select shapes too (open issue 1).
2. **Rotate handle offset is 0.25 page inches, not a fixed screen
   offset.** `handles_for` has no zoom parameter in the signed interface,
   so `handle_at` and the overlay agree on one page offset. At the
   default zoom that is about 24 px; at extreme zooms it is not constant.
3. **Editable panel fields are in inches/degrees.** The row value text
   still formats in `Settings::units`, but the `DragValue` edits the
   internal inches (degrees for Angle) so no conversion loss enters the
   command arguments. The unit-aware editor is open issue 4.
4. **Page-switch clearing lives in the shell.** `page.next`/`page.previous`
   and the page tabs do not clear the selection themselves; the shell
   compares the previous `(SessionId, PageId)` each frame and clears it
   on a change (the P5-04 page-command open issue stays for P5-08/P5-09).
5. **`ToolMachine::state` is a `PointerState`, not an `Option`.** The
   P5-01 stub carried `Option<PointerState>`; every pointer operation
   needs the state, and the other tool modules do not read it.
6. **Master connection points are not collected yet.** Snapping reads a
   shape's own `Connection` rows; stencil masters' `MasterDef::connection_points`
   are not merged into the shape sheet here (P5-06's stencil/drop work
   can request it).

### Open issues

1. Add an `edit.select` (or `shape.select`) command to `crates/commands`
   so selection can also be driven by the JSON control channel and MCP;
   the shell would then dispatch it instead of applying
   `SelectionUpdate` directly. This is the one place P5-05 steps outside
   the registry-only intent flow (deviation 1).
2. Expose the page-size rule from `ferrogram_commands` (its
   `builtins::view::page_size` is private). The canvas uses the renderer's
   scene size and the panels keep the existing cell reader, so the
   renderer's per-axis fallback is still the single visual rule, but the
   helper request in the task remains open.
3. Make the rotate handle offset zoom-dependent (`handles_for` would need
   a zoom parameter or a separate screen-space handle layout).
4. Unit-aware editable panel fields (deviation 3): convert the
   `DragValue` value from `Settings::units` before dispatching.
5. Master connection points for snapping and glue (deviation 6): merge
   `MasterDef::connection_points` into the shape's connection candidates,
   with the master transform applied.
6. Timing: the P5-11 8 ms drag budget can reuse the `CanvasRig` in
   `crates/ui/tests/phase5/main.rs` (real canvas + tool + registry) as
   the harness hook; no timing assertion is included here because P5-11
   owns the reference-machine measurement.
7. Black-box checks stay on the screenshot-pass list: the rotate handle
   offset, the marquee intersection rule, Alt as Visio's snap modifier,
   and the panel field units.
8. The page commands (`page.next`/`page.previous`, P5-04 open issue)
   should call `Selection::refresh_page` or clear the selection at the
   command layer; the shell's frame comparison currently masks the stale
   `Selection::page` for one frame.
