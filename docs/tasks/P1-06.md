## Goal

Implement a loader for `ui-spec/visio-2016.yaml`,
`ui-spec/visio-365.yaml`, `ui-spec/commands.yaml` and
`ui-spec/shortcuts.yaml`. The loader:

1. Reads a YAML or JSON file from disk.
2. Validates the file against `ui-spec/schema.json` (the same schema
   the xtask extractor uses). The schema lives in the repository at
   `ui-spec/schema.json`; the loader resolves it relative to the
   workspace root via `CARGO_MANIFEST_DIR`.
3. Deserialises the validated data into the public types in
   `lib.rs` (the P1-02 stubs, updated to use `FluentId` for layout
   ids and `Option<CommandId>` on each `Control`).
4. Cross-checks references: every Fluent id in `commands.yaml` must
   appear in at least one layout; every control's `command` value
   must appear in `commands.yaml`; every shortcut's `command` value
   must appear in `commands.yaml`.
5. Builds a `CommandLookup` from the layout + commands.
6. Supports both layouts (2016 and 365) and a runtime switch via a
   `LayoutSwitch` API.

## Public API

```rust
use ferrogram_ui_spec::{
    CommandId, FluentId, LayoutKind, LayoutSet, Loader,
    CommandLookup, LoadError,
};

let loader = Loader::new(&workspace_root)?;  // loads the schema once
let set_2016 = loader.load(LayoutKind::Visio2016)?;
let set_365  = loader.load(LayoutKind::Visio365)?;

// The CommandLookup is built on demand from a LayoutSet.
// `labels` is keyed by FluentId; `commands` maps each FluentId to
// the CommandId it dispatches; `fluent_by_command` is the reverse
// index.
let lookup = set_2016.command_lookup();
assert!(lookup.labels.contains_key(&FluentId::new("FileSave")));
assert_eq!(
    lookup.commands.get(&FluentId::new("FileSave")),
    Some(&CommandId::new("file.save")),
);

// Layout switching: pick at runtime.
let active = LayoutSet::select(LayoutKind::Visio365, &set_2016, &set_365);
```

## Implementation notes

- **Validation first, then deserialize.** Use `jsonschema` to
  validate the raw YAML/JSON before turning it into our types. A
  validation failure returns `LoadError::Schema { path, message }`
  with the validator's error list joined by `; `. The schema is
  loaded once in `Loader::new`; the `Validator` is `Send + Sync`
  and cheap to clone (it holds an `Arc`).
- **YAML deserialization.** Use **`serde-saphyr`** (MIT, pure
  Rust) — not `serde_yaml` (archived) or `serde_yml` (RUSTSEC).
  The P1-02 review explicitly rejected those; see ADR 0007. P1-06
  adds `serde-saphyr` to `crates/ui-spec/Cargo.toml` and uses
  `serde_saphyr::from_str` into the typed structs after validation.
- **Cross-references.** Build two sets at load time:
  - `fluent_ids`: the union of every control id in the layout's
    QAT, tabs, groups, backstage tabs, and context menus.
  - `command_ids`: the set of every `commands.yaml` entry's `id`.
  Then:
  - For each entry in `commands.yaml`, every name in its
    `fluent_ids` must be in `fluent_ids` (collected above). A
    mismatch is `LoadError::CrossReference { kind: "fluent_id",
    id, referenced_by }`.
  - For every control in the layout, the optional `command` value
    (a `CommandId`) must be in `command_ids`. A mismatch is
    `LoadError::CrossReference { kind: "control_command", id,
    referenced_by }`.
  - For each entry in `shortcuts.yaml`, the `command` must be in
    `command_ids`. A mismatch is `LoadError::CrossReference { kind:
    "command_id", id, referenced_by }`.
- **`CommandLookup` builder.** Walks the layout once, recording
  for each `Control.id` (a `FluentId`):
  - its `label`,
  - its `command` link (an `Option<CommandId>`),
  - and reverse-indexing each `CommandId` to the `FluentId`s that
    surface it.
  Returns a `CommandLookup`. The lookup is `BTreeMap`-backed so
  iteration is sorted.
- **Layering.** `crates/ui-spec` is L0 (ADR 0002). It depends on
  `serde`, `serde-saphyr`, `jsonschema`, `thiserror` (all from
  crates.io; no workspace deps). Confirm `cargo xtask layers` is
  green.
- **No panics.** Workspace lints apply. The loader must not
  `unwrap`, `expect`, `panic!`, or `unreachable!`. Tests may use
  them via `clippy.toml`.
- **Schema is committed.** `ui-spec/schema.json` is the
  source of truth. The loader reads it at runtime via
  `include_str!` to avoid a runtime path lookup; the workspace
  root is passed in for the data files.

## Acceptance criteria

- [ ] `Loader::new` loads `ui-spec/schema.json` once and is
      reusable across `load` calls.
- [ ] `Loader::load(LayoutKind::Visio2016)` reads
      `ui-spec/visio-2016.yaml`, `ui-spec/commands.yaml`, and
      `ui-spec/shortcuts.yaml` from the workspace root, validates
      each, deserialises, and returns a `LayoutSet`.
- [ ] A `LayoutSet` has `layout`, `commands`, and `shortcuts`
      fields all populated. `layout.tabs[0].id` is a `FluentId`
      (e.g. `TabHome`), not a `CommandId`.
- [ ] `LayoutSet::command_lookup()` returns a `CommandLookup`
      with `labels` keyed by `FluentId`, `commands` mapping each
      `FluentId` to its dispatched `CommandId`, and
      `fluent_by_command` mapping each `CommandId` to the
      `FluentId`s that surface it.
- [ ] `LayoutSet::select(LayoutKind::Visio365, &set_2016, &set_365)`
      returns `&set_365`; the same with `Visio2016` returns
      `&set_2016`.
- [ ] A hand-written bad fixture
      (`crates/ui-spec/tests/fixtures/bad.yaml`) is rejected with
      `LoadError::Schema { .. }` and a non-empty message.
- [ ] A hand-written cross-reference violation (a command with a
      `fluent_id` that is not in any layout) is rejected with
      `LoadError::CrossReference { kind: "fluent_id", .. }`.
- [ ] A second cross-reference violation (a layout control whose
      `command` is not in `commands.yaml`) is rejected with
      `LoadError::CrossReference { kind: "control_command", .. }`.
- [ ] `crates/ui-spec/Cargo.toml` adds `serde-saphyr` (not
      `serde_yaml` or `serde_yml`) and a current `jsonschema`
      version. `cargo deny check advisories` is green; in
      particular, RUSTSEC-2025-0068 and RUSTSEC-2026-0333 are
      not raised.
- [ ] `cargo xtask gate` green (full gate, not `--quick`).
- [ ] Coverage of `ferrogram-ui-spec` ≥ 85% (the threshold in
      `coverage.toml`). Add unit tests for the loader, the
      cross-reference checker, the `CommandLookup` builder, and the
      `LayoutSet::select` helper.
- [ ] Result section lists the file paths the loader reads, the
      number of controls per layout, and any deviations from the
      P1-02 public types.
