   insert a shape onto a read page, write a cell the read shape does not

### Deviations

1. **`sync_uint`'s overwrite and set-new arms (`write/patch.rs:138-140`)
   are unreachable through the public API.** `sync_uint` has one caller
   (`patch_style`, the stylesheet `ID`) and that attribute is also the
   `sync_children` claim key, parsed with the very `u32` parse the arm
   compares against: a claimed element always lands on "already equal"
   (`137`), and an element without `ID` can never be claimed at all. The
   tests cover `sync_uint`'s reachable arm and `bool_matches` fully (see
   Goal 1); closing the last three lines needs an inline unit test in
   `write/patch.rs`'s own test module (Open issue 1). The unparseable
   spelling also cannot come from `to_model` — the reader rejects an
   unparseable mapped attribute with `Error::InvalidPackage` — so the
   model of that case reads from a well-spelled twin package and only
   the source *tree* carries the foreign spelling (the patcher's real
   input: whatever a foreign writer left behind).
2. **The `hit.rs` catch-alls (`432-439`, `569`) cannot be reached from a
   test.** They are `_` arms for *future* `ferrogram_geom::Segment`
   variants (the enum is `#[non_exhaustive]`); no test outside
   `ferrogram-geom` can construct one, and geometry row kinds map to
   segments in `build.rs`, so a fixture with an unmapped row kind does
   not come near them. The test pins the fallback the review meant
   instead (Goal 4).
3. **The connector tool's "Connector master missing" arm
   (`tools/connector.rs:168-170`) is unreachable from a test.**
   `connector_master()` reads `ferrogram_model::stencils::catalog()`, a
   fixed table that always ships the "Connector" master (the P5-08 open
   issue). The test replaces `connector.draw` in a private registry with
   a command that fails with the tool's exact message and pins the
   contract at that seam: the one-line message reaches the status bar
   and nothing is inserted (shape count and undo stack unchanged).
