**Deviations** (the role file's "closest correct version" clause):

1. **The ADR 0048 model equality is `Document ==` after three extra
   ignorable rules.** `model::Document`'s `PartialEq` includes arena
   addressing (`Shape::id`, `Page::shapes`, `Master::shapes`), and the
   writer/reader renumber the arena (the reader fills masters' shapes
   first; a model built in memory interleaves them with instances), so
   a built document can never compare equal to its read-back as raw
   `Document` values. The test's comparison therefore (a) canonicalises
   every `ShapeId` into document order, (b) drops preserved `Rel`
   children (a read `Master`/`Page` keeps the relationship reference; a
   built model has none — plumbing, not content), and (c) drops
   preserved cell `U` attributes (the writer's `U="BOOL"`/`U="STR"`
   kind spelling, which the reader parks in `Cell::preserved`; see open
   issue 1). Everything else compares exactly: with these rules the
   saved and reopened flowcharts are equal, and the ADR's own
   read-write identity is asserted literally in the exact ADR form.
   All rules are documented in the test's module docs and pinned by
   `the_model_comparison_ignores_addressing_and_plumbing`.
2. `file.new` produces a document with **no pages**, so the harness
   runs `page.add` before the first `insert.shape` (the interface list
   mentions `page.add` only for page two).
3. The ten `insert.shape` dispatches are the ten flowchart shapes; the
   two form-2 connectors each add one more `insert.shape` of the
   "Connector" master (12 `insert.shape` dispatches in total), so both
   connector forms run end to end as the master's note requires.
4. **Command-row `out-of-scope` matching is case-insensitive** against
   `ui-spec/out-of-scope.txt` (the list holds CamelCase Fluent ids
   while command ids are lowercase: `tools.macro.dlg` vs `*Macro*`),
   and a command whose *every* Fluent id is listed is out of scope too
   (e.g. `tools.macro.play`). `out-of-scope` beats `implemented`, as in
   the control table; control-table matching is unchanged
   (case-sensitive). Without this rule `tools.macro.dlg` and
   `file.save.as.macro.drawing` would sit in `stub`, contradicting the
   alpha's product decision.
5. The interface list has no text step, so the harness sets no shape
   text (text round trip is covered by P5-02's `roundtrip_edit`).
6. `Shell::canvas_raster` was **not** added (`crates/ui` untouched):
   the harness asserts at the model level, so `shell.rs` needed no
   accessor. `xtask/src/gate.rs` untouched (see above).

**Open issues:**

1. `crates/vsdx` (for a fix task): the reader parks the writer's
   `U="BOOL"`/`U="STR"` kind spelling in `Cell::preserved` instead of
   consuming it (unit codes like `IN` do map to `Cell::unit`). A
   read-write-read round trip is stable (P5-02's `roundtrip_edit`), but
   a built model and its read-back differ in this plumbing; the reader
   could treat a kind-code `U` as mapped. This is why the harness's
   comparison drops preserved cell `U` attributes.
2. `crates/vsdx` (same class): read `Master`/`Page` values keep their
   `<Rel>` child in `Preserved` while a model built in memory has none;
   `to_model` already reads the relationship id and could consume the
   child it resolves.
3. If the master prefers the commands table's `out-of-scope` matching
   to be case-sensitive (deviation 4), `command_status` changes in one
   place; the 13 rows become 11 (`tools.macro.dlg`,
   `file.save.as.macro.drawing` fall to `stub`).
4. `commands.yaml` labels show as generated: some are extractor
   artefacts (`tools.macro.dlg` label "Dlg",
   `file.save.as.macro.drawing` label "Drawing").
5. The harness keeps its own `TempDir` helper (std only) instead of the
   `tempfile` crate; if a later test wants one, promote it to a shared
   test helper then.
