## Goal

Both layouts render as egui ribbons from the committed YAML, every
placement accounted for, controls without implemented commands disabled
with "Not yet implemented", and the layouts load from embedded YAML so
the wasm build works without a filesystem.

## Interfaces

```rust
pub const SHORTCUTS_YAML: &str = include_str!("../../../ui-spec/shortcuts.yaml");

// crates/ui-spec/src/loader.rs (one addition)
impl Loader {
    /// Loads both layout sets from the embedded YAML (ADR 0031).
    /// Same validation path as `load_all`, minus the schema file read.
    pub fn from_embedded() -> Result<LayoutSets, LoadError>;
}
```

Ribbon behaviour (ADR 0031): walk the layout tree by placement path;
`Ribbon::show` renders the tab strip and the active tab's groups;
galleries/dropdowns/menus are one-button dropdowns; `splitButton` is a
button plus an arrow button; `labelControl`/`control`/`none` are labels.
Every actionable widget produces `Intent { command, invocation:
Invocation::empty(Source::Ribbon) }` when its command is
`CommandStatus::Implemented` and `Enabled::yes`; otherwise it renders
disabled with the tooltip "Not yet implemented" (or the `Enabled`
reason). Repeats inside one container with identical id, label and order
render once (first wins, ADR 0031). The quick access toolbar uses the
same rules from `Layout::quick_access_toolbar`.

Icons: `icons::placeholder` draws our own simple marks (letter or
geometric glyph) sized `SizeVariant`-independent for now; no icon set is
committed (ADR 0030).

**Deviations from the task text** (closest correct version; all
documented in the code):

1. `Loader::from_embedded` runs the full staged validation *including*
   the schema check; "minus the schema file read" is satisfied in the
   sense that nothing is read from disk (the schema is `include_str!`'d
   in the loader already).
2. The test seam for "an enabled implemented control produces its
   Intent": `Registry::register`/`from_mappings` are still P4-01 stubs
   (P4-02 fills them), so no test can put an implemented command in a
   real registry. The rules live in the pure `action_for_command`, and
   `show_with`/`show_*_with` take an injected resolver that the tests
   drive; `Ribbon::show` with the real registry path is tested with an
   empty registry (stub tooltip end to end). Once P4-02 lands
   `register`, an end-to-end click-through-registry test belongs with
   P4-09's UI tests.
3. A dropdown control *with* nested controls is the dropdown affordance
   (always enabled, opens the list; the items carry the commands); its
   own `command` link is not dispatched by the button. Without children
   it is a plain button under the command rules. `splitButton`'s
   primary button always dispatches its own command, the arrow opens
   the items.
4. `toggleButton`/`checkBox` carry display-only toggle state inside
   `Ribbon` (nothing owns real toggle state before Phase 5).
5. `show_context_menu` needed a menu selector the stub did not have:
   additive `Ribbon::set_context_menu`/`context_menu`; `None` draws
   nothing. New additive accessors: `set_active_tab`,
   `set_active_backstage_tab`, `set_backstage_open`,
   `active_backstage_tab`.
6. The split arrow is a painted triangle named by our "More items"
   tooltip (egui's bundled fonts have no triangle glyph, and an
   unnamed icon-only button fails the egui_kittest accessibility
   check). `ComboBox` gets its accessible name from `on_hover_text` of
   its label (egui's documented fix); the tooltip is that label.
7. `embedded` gained `OUT_OF_SCOPE_TXT`/`is_out_of_scope` beyond the
   four constants (ADR 0031 rule 3 needs the list at render time).

**Open issues**:

- The ADR 0031 dedup key is (id, label, order). The 365 backstage entry
  `TabSave` repeats `TabSave` nine times with *different* orders and
  parents, so the rule does not collapse them and nine widgets render.
  Same for `LineStylesDialog` twice in one group (orders 1 and 2). This
  is exactly the case ADR 0031 cites as motivation; the rule as written
  does not cover it. For the ADR 0007 amendment review (P4-11/P4-13):
  either drop `order` from the key, or accept the repeats as placements.
- `type: control` with a `command` link (e.g. `FormatPainter`) renders
  as a non-actionable label per the ADR 0031 mapping table, so the
  command never dispatches from the ribbon. Same review.
- A gallery/dropDown/menu whose own `command` link matters (e.g. a
  gallery with a default action) has no dispatch path yet (deviation
  3); revisit when a command needs it.
- The committed `context_menus` carry no controls (43 menus, 0
  controls), so `show_context_menu` renders nothing today; it shows
  whatever the extractor fills in.
- The ribbon test harness uses a 12000x4000 window: clicks outside the
  egui screen rect never reach a widget, and the committed ribbons are
  about 5000 points wide.
- `text::Layout`-style placement of chrome fonts (Selawik) stays an
  open item (ADR 0030); the chrome uses egui's bundled font.
