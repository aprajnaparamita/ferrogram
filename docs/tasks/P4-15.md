   `file.open` seed the new session's `ViewState::show_grid` /
   `show_rulers` from `Settings`. `view.toggle_grid` and `view.rulers`
   flip the active `ViewState` and write the new value to
   `Settings::show_grid` / `show_rulers` (the default for new
   sessions). With no document open they still flip the `Settings`
   default, and say so in the outcome message.
2. **Commands the Options dialog needs (review major 4, ADR 0032
   amendment).**
   - `app.office.center.options`: implemented, always enabled, returns
     `UiRequest::ShowOptions`.
   - `view.units` (new Larrygram-only id, add it to `OUR_COMMANDS` with
     label "Units"): takes a `units` string argument (the
     `DisplayUnits` names you find in `Settings`), sets
     `Settings::units`; a missing or unknown value is
     `CommandError::InvalidArgs` (or the existing equivalent) naming
     the accepted values.
   - `app.quit`: implemented, returns a new `UiRequest::Quit`. Bind
     `file.exit` to the same handler so both ids quit.
3. **Review minors.**
   - 1: `Registry` stores commands in a `BTreeMap<CommandId, …>` (ADR
     0028).
   - 2: `UndoStack::default()` uses `DEFAULT_CAPACITY`. If
     `with_undo`'s `mem::take` placeholder needs a zero-capacity stack,
     construct that one explicitly.
   - 3: `with_undo` puts the stack back on the same session even if
     the edit opens or closes documents (track the session by identity,
     not by index; add the smallest id you need and document it).
   - 4: `UndoStack::push` is infallible.
   - 5: `AppCtx::close_document` keeps the active document when a
     different one closes (shift `active` down only when
     `active > index`).
   - 6: `page: 0` is an argument error; the error carries the caller's
     number, not a saturated one.
   - 7: the wasm no-path save reports a write failure with the ADR
     0026 `cannot write output:` prefix.
   - 8: one parse path for `commands.yaml`. Build the registry's stub
     rows from `larrygram_ui_spec::Loader::from_embedded()` (or the
     embedded `commands` data it exposes) instead of a second

     makes that wrong, say why in the Result and leave it.
   - 12: `CommandId::intern` validates the id before checking the pool

### What changed

**Goal 1 — settings and view state (review major 1).**
`ViewState::from_settings(&Settings)` builds a new session's view and
`file.new` / `file.open` seed their sessions with it
(`crates/commands/src/app.rs`, `builtins/file.rs`). `view.toggle_grid`
and `view.rulers` are always enabled now: they flip the active
`ViewState` and copy the new value into `Settings::show_grid` /
`show_rulers` (the default for new sessions). With no document open
they flip the settings default alone and say so in the outcome
("Grid off (default for new drawings)").

**Goal 2 — the Options dialog commands (review major 4, ADR 0032
amendment).**

- `app.office.center.options`: implemented, always enabled, returns
  `UiRequest::ShowOptions` (`view::run_options`).
- `view.units` (new Larrygram-only id in `OUR_COMMANDS`, label
  "Units"): takes `units`, a `DisplayUnits` name (ASCII
  case-insensitive; `DisplayUnits::NAMES` / `name` / `parse` added).
  A missing, non-text or unknown value is `CommandError::InvalidArgs`
  naming the accepted values; success sets `Settings::units`.
- `app.quit` and `file.exit` bind the same handler
  (`file::run_quit`), returning the new `UiRequest::Quit` with the
  message "Quit" (the line the shell intercept shows today, so P4-16
  can drop the intercept without changing output).

**Goal 3 — review minors** (all in `crates/commands` unless noted):

1. `Registry` is `BTreeMap<CommandId, Box<dyn Command>>`-backed (ADR
   0028); `ids()` iterates in id order.
2. `UndoStack::default()` builds a `DEFAULT_CAPACITY` stack; the
   `with_undo` placeholder is an explicit `UndoStack::new(0)`.
3. `with_undo` returns the stack to the session it came from, found by
   the new `DocumentSession::id`. The smallest id that works: a
   `SessionId(u64)` from a process-local `AtomicU64` counter, assigned
   in `DocumentSession::new`, compared but never ordered (documented
   on the type). An edit whose `revert` closes another document no
   longer loses the stack.
4. `UndoStack::push` is infallible; the dead `map_err` at the one
   `crates/ui/src/shell.rs` call site is gone.
5. `AppCtx::close_document` keeps the active document when a different
   one closes: `active` shifts down only when `active > index`, and
   moves only when the active document itself closes.
6. `page: 0` is `CommandError::InvalidArgs` ("page must be counted
   from 1, got 0") and every page error carries the caller's own
   number (`u32::try_from` replaced the silent saturate to `u32::MAX`).
7. The wasm no-target save reports a write failure with the ADR 0026
   `cannot write output:` prefix (it used `render failed:`). The body
   is now `payload_save`, kept compiled on every target under
   `cfg(any(test, target_arch = "wasm32"))` so the host tests cover it.
8. One parse path for `commands.yaml`: `builtins::registry()` builds
   its stub rows from `larrygram_ui_spec::Loader::from_embedded()` —
   the same staged load (parse, schema validation, decode) the command bar
   and the loader tests use — cached once per process, instead of a
   private `include_str!` + YAML-to-JSON round trip. The dependency
   direction already existed (`commands` depends on `ui-spec` at
   L4 → L0) and the loader exposes the parsed `Commands` document, so
   nothing was wrong with the format. `serde-saphyr` is now unused in
   the crate and is dropped (the only dependency change; none added).
   `RegistryError::BadMapping` now wraps a loader failure; there is no
   testable way to make the embedded load fail, so that one mapping
   line is untested.
12. `CommandId::intern` validates an id before consulting the pool
    cap; the pool half is `intern_into`, so the cap branch is tested
    without filling the process-global pool (P4-10 finding 5).

**P4-12 commands minors 1–5 (reachable arms).** Regression tests for
every `validate_id` reject arm (the two dead arms — "empty id" and the
unreachable duplicate "empty part" — are removed, so every arm fires),
the intern pool-full branch, `meta_for`'s `RegistryError::BadId`
mapping, `no_document` and `with_undo`'s no-document branches (direct
calls; the enabled-state predicates block these paths in
`Registry::execute`), `move_page`'s no-pages error,
`positive_cell`'s page-size fallback and the `UndoStack` `Debug` impl.
Not reachable: the poisoned intern-pool lock (nothing can panic while
the lock is held) and `UndoStack::undo`'s missing-entry guard (the
cursor invariant protects it).

### Open issues

1. **Parity rows for command-only ids (the acceptance criterion this
   task cannot meet in-lane).** `docs/parity/controls.md` is generated
   with one row per Fluent control id in `ui-spec/panel-2016.yaml` /
   `panel-365.yaml` (`xtask/src/extract/parity.rs::generate`), so
   `app.office.center.options`, `app.quit`, `file.exit` and
   `view.units` cannot show there today: the `FileExit` family is
   dropped as "Not in the Ribbon" by `xtask/src/extract/fluent.rs`
   (see its `FLUENT_COMMANDS` note), `app.office.center.options` has
   no control either, and `view.units` is a Larrygram-only dialog
   control. To make the four ids "show as implemented", the generator
   needs a second table — suggested: a `| command | label | status |`
   table after the control table, built from `commands.yaml` (id,
   label) and `StatusRules::implemented`. `xtask/src/extract/parity.rs`
   is P4-17's file (parallel task), so this change is left to P4-17 or
   the master; `docs/parity/controls.md` then regenerates through
   `cargo xtask parity`.
2. **Transient `cargo deny` red (heads-up for the master).** For a few
   hours on 2026-10-18 the `deny` step failed on three brand-new
   RustSec "unmaintained" advisories — RUSTSEC-2026-0370
   (`zvariant`), RUSTSEC-2026-0371 (`zbus_names`) and RUSTSEC-2026-0372
   (`zvariant_derive`, the code moved into `zbus` 6) — reaching us
   only through eframe → egui-winit → accesskit_winit →
   accesskit_unix → atspi, with no version that fixes them
   (`cargo update -p zbus_names -p zvariant` to 4.3.5/5.15.1 did not
   clear them; the bump was reverted). `deny.toml` and ADR 0014 are
   master territory (AGENTS.md section 6), so nothing was changed here;
   the advisories then disappeared from the upstream database and
   `cargo deny check` is green again. If they return, the fix is the
   master's 2026-10-17 zip precedent: three `deny.toml` ignores with
   the "unmaintained, transitive via eframe/accesskit_unix, no fix
   available" reason plus an ADR 0014 note.
3. `with_undo`'s placeholder stack is zero-capacity and visible to an
   `Edit`'s `apply`/`revert` while its step runs (an edit that reads
   `session.undo` sees an empty stack). No Phase 4 edit does this;
   revisit with the first Phase 5 edits.
4. `Shell::dispatch_one` pushes an `Outcome::edit` onto the *active*
   document's stack after the run — a different session when the
   command opened a document. The identity seam now exists
   (`DocumentSession::id`, see Goal 3 item 3); P4-16 can use it the
   same way `with_undo` does.
5. The P4-10 interner test hazard (the process-global 4096-id pool)
   remains; `intern_into` gives tests a private pool for the cap
   branch, but a test that interns arbitrary ids can still exhaust the
   global one.
