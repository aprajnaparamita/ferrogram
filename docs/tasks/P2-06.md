## Goal

Implement `to_model` and `read_document`: known parts become model entities,
everything unmapped lands in `Preserved` (ADR 0012), unknown parts stay in
the package. Inheritance is never flattened (ADR 0013).

## Interfaces

Implements:

```rust
pub fn read_document(bytes: &[u8], limits: &Limits) -> Result<Document, Error>;
pub fn to_model(package: &Package) -> Result<Document, Error>;
```

Consumes (from P2-05, merged): `read_package` already parses every XML part
into `PartData::Xml(XmlNode)`, enforcing `max_xml_depth` and
`max_attributes_per_element`. The helpers are `pub(crate)` in
`crates/vsdx/src/package/xml.rs`:

```rust
pub(crate) fn parse_xml(text: &str, limits: &Limits) -> Result<XmlNode, Error>;
pub(crate) fn write_xml(node: &XmlNode) -> String;
```

Notes from P2-05 (see its Result):

- Two corpus files (`recursion-cycle.vsdx`, `tab-short-prefix.vsdx`) have no
  `[Content_Types].xml`. The package reader then infers `application/xml`
  for every `.xml` part. Find the main document part through the package
  root relationship (`/_rels/.rels`), not only by content type, and default
  `DocumentKind` to `Drawing` when the content type is the inferred
  `application/xml`.
- The XML declaration is not kept in `XmlNode`. The package writer emits
  `<?xml version="1.0" encoding="UTF-8" standalone="yes"?>` on every XML part.

Mapping rules (documented in the module docs):

- `pages.xml` + `page{N}.xml` -> `Document::pages` and the shape arena;
  `masters.xml` + `master{N}.xml` -> `Document::masters` and master shapes;
  `document.xml` -> stylesheet, document properties, root `Preserved`.
- Shape `Cell`/`Section`/`Row`/`Cell` elements map to `Sheet`; cell `U` is
  the `Unit`, `V` the cached value (canonical units, ADR 0011), `F` the
  formula string.
- Every unmapped attribute goes to the entity's `Preserved::attributes`;
  every unmapped child to `Preserved::children`, in order.
- Malformed-but-recoverable input degrades, never panics: a missing master
  part gives `Master::shape: None`. `CellValue::Error(raw)` is only for
  cached error values (`#VALUE!`). A numeric value that fails to parse for
  its declared unit is `Err(Error::InvalidPackage)` naming the part and the
  cell.
- `Document::kind` from the main part's content type (ADR 0016).

## Note from the master (after P2-04 merged)

**Cell and section names.** `.vsdx` spells some cells and sections
differently from `ui-spec/shapesheet.toml` (for example `ColorTrans` /
`Transparency`, `BulletStr` / `BulletString`, `HorzAlign` / `HAlign`,
section `Connection` / `Connection Points`, `Property` / `Shape Data`; see
the P2-04 Result). Decision:

- The model stores names **as spelled in the file** (`N` / `T` / `IX`
  attributes), because MS-VSDX is the source of truth for `.vsdx` and the
  writer must emit them unchanged. Do not rename to table spellings.
- Add `crates/model/src/aliases.rs`: a hand-maintained table that maps a
  file spelling to its ShapeSheet-table spelling, with
  `pub fn table_name(file_name: &str) -> &str` (identity when there is no
  alias). Use it only where `lookup.rs` looks a name up in the generated
  table (the section-default rung and the section-to-style selection), so
  those rungs work for file spellings. Local, master and style cells keep
  matching by file spelling.
- Build the alias list from the corpus: add a test that reads every corpus
  file and lists the cell and section names with no table entry, after
  aliasing. Record that list in your Result. Every entry must be either
  aliased or explained (for example, a cell the table does not cover).

**`Error::NotImplemented`.** Leave the variant in `ferrogram_model::Error`.
It is removed together with the `vsdx` one after P2-07.
