## Result

Filled in by the worker at hand-off (2026-10-18).

### What changed

- **`AppCtx::push_edit(session, edit)`** (ADR 0040 rule 2, the only push
  path) with the undo-suspension flag on `AppCtx`: while an `Edit`'s
  `apply`/`revert` runs it drops the edit and records exactly one
  warning ("an edit tried to record during undo; step dropped"). The
  session is found by `SessionId`; an unknown `SessionId` is
  `Err(CommandError::Failed)`. `AppCtx::touch_session` bumps one
  session's `DocumentSession::changes`; `touch()` now routes through it.
- **The recording gate** (`undo.rs::run_suspended`): `UndoStack::undo`/
  `redo` and `CompositeEdit::apply`/`revert` run every step with the
  gate closed, so the runner's zero-capacity placeholder stack is inert
  (the P4-10/P4-15 items close). No `undo.rs` API change.
- **`CompositeEdit::apply`/`revert`** forward and backward over the
  steps, plus `push`/`len`/`is_empty` helpers. A failing step stops the
  run and its error propagates (the earlier steps stay applied; the
  stack keeps its cursor).
- **Undo steps** in `builtins/edit.rs`: `CellEdit` (one sheet-cell
  write), `StructuralEdit` (one shape subtree: `removal` and
  `insertion` polarities), `GeometryEdit` (one `scale_geometry`
  rescale). All restore the **exact** prior model state: `revert(apply(x)) == x`
  and `apply(revert(x)) == x` under `Document` equality (ADR 0040 rule
  4). `StructuralEdit` re-resolves its page by Visio `ID` (then `NameU`)
  before every replay, and `Selection::refresh_page` re-derives
  `Selection::page` from the shapes, per the master's note.
- **Commands** (all `CommandStatus::Implemented` with real handlers):
  `edit.delete`, `edit.select_all`, `edit.deselect` (`builtins/edit.rs`)
  and `shape.move`, `shape.resize`, `shape.rotate`, `shape.set.width`,
  `shape.set.height`, `shape.set.pin`, `shape.set.angle`,
  `shape.enter_group`, `shape.exit_group` (`builtins/shape.rs`), with
  the argument names of the Interfaces contract. One command returns one
  `Outcome::edit` (`CompositeEdit`, one undo step per drag); selection
  commands return no edit and do not bump `changes`.
- **Extractor** (`xtask/src/extract/commands.rs`): all 31 Phase 5 ids
  the derivation does not produce (the whole Interfaces list at once)
  joined `OUR_COMMANDS` (`fluent_ids: []`, `mapping_confidence: unknown`);
  ids `commands.yaml` already had keep their rows. `ui-spec/commands.yaml`
  (944 to 975 rows) and `docs/parity/controls.md` regenerated with
  `cargo xtask extract`; a new `our_commands_are_well_formed` test pins
  the table's grammar, order and uniqueness.
- **Tests**: `crates/commands/tests/editing.rs` (18 tests: every handler
  through `Registry::execute` with `Source::Test` — happy paths,
  `NotEnabled` reasons, `NeedsInput`/`InvalidArgs` cases, apply/revert
  pairs per command, one drag = one undo step, the change counter,
  stale-selection and unreachable-cell behaviour, no-dialog rule) and
  `crates/commands/tests/undo.rs` (4 tests: the recording gate during
  undo/redo and during direct composite runs, one composite = one undo
  step, `push_edit` session routing), plus unit tests alongside every
  edit type and handler (90 lib tests in `commands`).

### Deviations (closest correct version, per the implementer role)

- `CellEdit::revert` restores the captured `Cell` entries directly in
  `Sheet::cells` (`restore_cells`): `Document::write_cell` cannot
  express "no entry", a formula-less literal or the file's own `unit`,
  and the undo property needs the exact entry. All forward writes go
  through `Document::write_cell` (ADR 0039); only undo restoration
  touches the cell list. **Request:** a model task could add
  `Document::restore_cell(sheet, name, Option<Cell>)` and this moves
  into `mutate.rs`.
- A third undo step type, `GeometryEdit`: the interface named only
  `CellEdit`/`StructuralEdit`, but a resize rewrites whole geometry
  sections (`scale_geometry` materialises inherited rows), whose
  inverse is the section list.
- `Selection` gained `entered: Option<ShapeId>` (the
  `shape.enter_group`/`shape.exit_group` state of ADR 0041) plus
  `refresh_page` and `clear`; ADR 0041's field list predates the
  enter-group state.
- Semantics chosen (our own rules, black-box checks for the screenshot
  pass): `shape.rotate`'s `angle` is a **delta** in radians
  (`shape.set.angle` is absolute); `shape.move` is a delta,
  `shape.resize`/`set.width`/`set.height` set the absolute size.
  `shape.move`/`resize`/`rotate` act on every selected shape
  independently (resize gives each the target size, rotate turns each in
  place); `shape.set.*` edit the anchor (the panes' subject).
  `shape.enter_group` selects the group's members and remembers the
  group; `shape.exit_group` selects the group again and enters its
  parent group. `edit.select_all` selects the entered group's members
  while inside one.
- My ids' rows live in the per-module `TABLE`s (`builtins/edit.rs`,
  `builtins/shape.rs`) rather than `BUILTINS` in `builtins/mod.rs` (the
  ADR 0040 seam chains the tables onto it); `mod.rs` gained the shared
  predicates and helpers (`has_selection`, `edit_outcome`, `model_error`,
  `need_finite`, `need_size`).
- `StructuralEdit::insertion` (the insert polarity P5-06..P5-08 need)
  carries `#[allow(dead_code)]` until their commands use it; its unit
  tests cover both directions.
- Out-of-lane forced companion: `crates/ui-spec/tests/committed.rs`
  count pin 944 to 975 (the data pin follows the regenerated
  `commands.yaml`; nothing else in that file changed).

No new dependencies. `Cargo.lock` untouched.

### Open issues

- **P5-05** (consumer): `ui::shell::dispatch_one` should push the
  `Outcome::edit` through `AppCtx::push_edit(session, edit)` instead of
  `session.undo.push(edit)` (ADR 0040 rule 2 makes `push_edit` the only
  push path; the drop-with-warning behaviour comes with it).
- **P5-08/P5-09** (page commands): a page delete/move must call
  `Selection::refresh_page` (or clear the selection); the same goes for
  `page.next`/`page.previous` in `builtins/view.rs`, which today leave a
  stale `Selection::page` behind when the active page switches (ADR 0041
  says the switching commands clear the selection). `edit.delete` does
  its own tidy-up.
- The change-counter rule for later tasks: an `Edit`'s `apply`/`revert`
  bumps its session's `changes` through `AppCtx::touch_session` after a
  successful mutation (that covers commands, undo and redo uniformly);
  selection- and view-only commands never bump it. New edit types should
  keep that rule.
- `touched_cells` in `builtins/edit.rs` mirrors the model's
  derived-cell rule (`DERIVED_CELLS` in `mutate.rs`); the
  `a_width_write_refreshes_the_derived_cells` unit test pins the mirror
  and fails loudly if the model's rule changes.
- The black-box checks (Visio comparison) stay open: the rotate delta
  semantics, the multi-shape resize rule (each shape gets the target
  size), the enter-group state and the marquee-independent selection
  tidy-up are ours until the screenshot pass.
- `need_finite` accepts `ArgValue::Integer` and converts it (`dx: 2` is
  a move by 2.0), for the Phase 8 JSON channel's integer literals.
