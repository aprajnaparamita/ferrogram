### What was built

  first, which agrees with our reader.

### Deviations

1. `tests/roundtrip.rs` is P2-07's (master's note after P2-06); its bullet and
   the first acceptance criterion are not done here.
2. The schema harness cannot validate with the XSD as published. Two facts,
   both recorded in the test file's docs and both worked around only in a
   temp copy (`adjust_for_xmllint`):
   - The embedded XSD is **XSD 1.1** — 460 `xsd:assert` elements,
     `xsd:alternative`, and `maxOccurs` above 1 inside `xsd:all` — and
     `xmllint` is an XSD 1.0 tool. It refuses the schema outright ("Schemas
     parser error" at the first `xsd:assert`), so with the schema as
     extracted zero parts can be validated. The test runs and records that
     outcome too, then derives a temp-only copy with those three constructs
     stripped.
   - The schema's target namespace is
     `http://schemas.microsoft.com/office/visio/2011/1/core`, while every
     `.vsdx` instance and MS-VSDX write
     `http://schemas.microsoft.com/office/visio/2012/main`. The derived copy
     retargets the two namespace strings; without that, nothing matches a
     global declaration. The derived copy never leaves the temp directory and
     is a diagnostic aid, not a corrected schema.
   The harness has teeth where teeth make sense: the test fails if the
   derived schema does not load in `xmllint` (a verdict means nothing
   otherwise) and asserts every regenerated part gets a verdict. Per-part
   pass/fail is recorded data, per the master's note.

### Schema findings on the source parts (upstream data, not task failures)

With the derived schema: **106 regenerated corpus parts, 3 valid, 103
invalid**. Valid: `recursion-cycle.vsdx` `visio/document.xml`,
`tab-short-prefix.vsdx` `visio/document.xml` and `visio/pages/page1.xml`. The
failures are three recurring schema-versus-reality gaps in the 2014 docs
schema (the messages above are `xmllint`'s first error per part, so later
errors are hidden):

- `xml:space` is not allowed on `Pages` / `Masters` / `MasterContents` /
  `PageContents`, but Visio writes `xml:space="preserve"` there (most parts);
- `FaceName@NameU` is not allowed (every `document.xml`);
- `Rel@r:id` is not allowed (surfaced on the `pages.xml` of the two files
  whose root has no `xml:space`, where it is the first error).

Consequence for P2-10: "every written part validates" cannot be the rule with
this XSD — the source parts do not validate either. The workable rule is
probably "a written part validates exactly as far as its source part does",
or an XSD 1.1 validator with the instance namespace. That is the master's
call.
