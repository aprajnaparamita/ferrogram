## Goal

Show typed values in the Shape Data and Size & Position panes and accept
typed input with unit suffixes, converting through the engine's unit
table and `Settings::units`. Formula cells are read-only and say so.

## Interfaces

No new public interfaces: the panes read through `CellReader`
(`larrygram-model`) and the engine's `Value` (`larrygram-shapesheet`),
and write through registry commands only (`larrygram-commands`). Any
helper you need lives as a private function in `panes.rs`.

## Result

_Filled in by the worker at hand-off: what changed, deviations, new dependencies, gate summary, open issues._

### What changed

- `crates/ui/src/panes.rs` (rewritten, ~1000 lines with tests) and
  `crates/ui/tests/panes_typed.rs` (new, 14 tests).
- **Shape Data is typed** (ADR 0058): with a selection the pane shows
  the anchor's name and id, then one row per `Prop` row — the `Label`
  text (falling back to the row name, which stays as the row's hover
  note), and the `Value` cell typed through the engine's
  `Value::from_cached`: a number with its unit in `Settings::units`
  (lengths and typographic lengths via `canvas::format_length`, angles
  in degrees, ratios in percent), a boolean as a disabled check box
  (`TRUE`/`FALSE`), a colour as its `#RRGGBB` RGB value, a string as
  written, an error as its `#...` text, a list as its cached entries
  and a duration as its cached number (the model drops the spelling,
  ADR 0052). One `egui_kittest` test per kind.
- **Size & Position shows the evaluated cells**: `PinX`, `PinY`,
  `Width`, `Height`, `Angle` (the editable fields) plus the ADR's
  `LocPinX`, `LocPinY`, `FlipX`, `FlipY` (read-only rows), read
  through `CellReader` (the recalc result, ADR 0055) and marked
  `(formula)` (data-level `PanelRow::edit == None` and a visible
  marker with a hover hint) when the cell carries a formula that
  computes.
- **Typed input** on the five editable fields: a `TextEdit` field whose
  entry parses with `shapesheet::parse` (so the pane and the grammar
  never disagree) and converts through the engine's unit table
  (`Unit::to_canonical`/`from_canonical`) into the field's own unit
  (inches for width/height/pin, degrees for angle — P5-05) before the
  `shape.set.*` argument is built. `2.5 cm` stores 0.984 in,
  `5 1/2` stores 5.5, `37%` stores 0.37, `45 deg` stores 45° (0.785
  rad in `shape.set.angle`). The field text is itself a literal the
  grammar accepts (`50.8 mm`, `30°`).
- **Refusals** each record one status line and change nothing: a bad
  entry (`abc`, `Width`, `2 in +`, `"text"`, `1/0`, `1e999`, and any
  non-literal such as `ABS(-2)`) and an edit of a formula cell
  ("is a formula cell; formulas are read-only in this release").
  The document is deep-equal before and after in both tests.
- Every accepted edit is one `Intent` that the shell (or the test)
  dispatches through `larrygram_commands::dispatch`, which is one undo
  step (`push_edit` runs the recalc pass); the pane itself never
  touches the model — asserted in the tests.

### Deviations

1. **`crates/ui/Cargo.toml` gained a runtime dependency on
   `larrygram-shapesheet`** (shared file; the task's shared-file rule
   anticipated at most a dev-dependency). The panes need
   `Value::from_cached`, `shapesheet::parse`/`eval` and the engine's
   unit table in their own code — the Interfaces section names both
   crates — so requesting the line instead would have left `panes.rs`
   uncompilable. L6 → L2 is within the layering (the `layers` step is
   green) and the dependency is already in the tree through
   `larrygram-commands`. `Cargo.lock` and `crates/ui/fuzz/Cargo.lock`
   follow.
2. **Shape Data `Prop` values are display-only.** No registry command
   writes a `Prop.Value` cell: ADR 0035's `data.set.property` is a
   reserved id and the P5-10 parity table has none (the Inputs say the
   table "names what exists"), and the pane may not touch the model
   directly. ADR 0058's "a text field writes a string; a boolean field
   writes `TRUE`/`FALSE`" therefore waits for that command; an
   always-editable field that refused on commit would violate ADR
   0035's "no control that looks editable and does nothing".
3. **`CellEdit::direct` (P6-07 note 7) has no call site from L6.** It
   is `pub(crate)` in `crates/commands`; the pane's edits dispatch the
   `shape.set.*` commands, which stage `CellEdit::new` (indirect). The
   observable behaviour matches ADR 0058 anyway: the pane refuses
   every formula cell before dispatch (so the `GUARD` skip can never
   fire on a pane edit) and a direct user edit of a `GUARD`-ed cell is
   refused this phase. Closing the note needs a command that builds
   `CellEdit::direct` (see open issue 1).
4. **"Carries a formula" is P6-07's classification** (`formula_computes`:
   a formula that reads a cell or calls a function; `Inh` counts). A
   constant literal formula — exactly what `shape.set.*` writes after
   the first edit (`F="5"`) — stays editable, matching P6-07 deviation
   4 and keeping a field editable after its first edit. An unparseable
   formula is treated as computing (read-only, conservative).
5. **The `Prop` row's `Type` cell is not consulted.** ADR 0058 makes
   the cached kind win whenever the two disagree, so no display outcome
   can depend on `Type`; the disagreement case is pinned by
   `the_cached_kind_wins_over_the_type_cell`.
6. **A typed entry must be a *literal*** ("the same literals the
   grammar does", ADR 0058): a literal under any chain of unary `+`,
   `-`, `%`. `2+3` and `ABS(-2)` parse but are refused — the formula
   editor is a later phase. A literal of another family converts over
   the canonical units (`45 deg` into a width field is 0.785 in); a
   literal without a unit is a number of the field's unit and a ratio
   is its fraction of it (`37%` is 0.37).
7. ADR 0058 names `Value::to_cached` as "the typed mapping"; the
   display direction is its inverse, `Value::from_cached` (ADR 0052's
   P2-14 bridge).
8. `shape_data_rows`/`size_position_rows` keep their signatures and
   `PanelRow` its four fields (`crates/ui/tests/phase5/pointer.rs` uses
   them); the row model grew only private helpers (`Entry`, `Field`,
   `EntryUnit`).

### Open issues

1. **`data.set.property` (ADR 0035's reserved id) has no registry
   command.** Shape Data values stay display-only until a task in
   `crates/commands` adds it — ideally writing through
   `CellEdit::direct`, which closes P6-07 note 7 and deviation 3 at the
   same time. That command also needs the row-target argument contract
   (`shape`, `row`, `value`).
2. **`Prop` rows do not include the master chain's rows.** The pane
   shows the shape's own `Property` section rows (Visio shows the union
   of instance and master rows); `Document::master_chain_shapes`
   exists, but the union needs the row-matching rules (IX vs position)
   and is a `crates/ui` change for a follow-up.
3. **Mid-edit selection changes can carry typed text** between the same
   row of two shapes: the field buffer is keyed on the pane title and
   the row label and resyncs when no edit is open (a rare UI edge, not
   a data risk — the commit still parses before anything dispatches).
4. **Two defensive fallbacks are unreachable from outside
   `larrygram-shapesheet`** (the `#[non_exhaustive]` arms of `Value`
   and `ExprKind` in `typed_value` and `formula_computes`). They are
   the never-crash fallbacks (a value kind with no display shows "—",
   an unknown expression kind keeps the cell read-only).
5. **A `Prop` value of an unknown error spelling** (`#NAME?`) has no
   typed mapping (`ErrorCode::from_text` refuses it) and shows "—"
   with one warning; the pane could show the raw text instead if the
   master prefers it.
6. Black-box check: does Visio's Size & Position show
   `LocPinX`/`LocPinY`/`FlipX`/`FlipY`, and is a formula field editable
   there (it is, with a formula bar)? The read-only rule of ADR 0058 is
   a this-phase decision, not an observation.
