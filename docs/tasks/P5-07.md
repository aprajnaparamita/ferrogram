## Goal

Edit shape text in place: open an editor over the shape's text block,
commit as one run, undoable, with the `Text` shortcut scope active while
editing.

## Interfaces

Implement `TextEditor::{begin, finish, original_text}` and `tools/text::handle`
(signatures fixed by P5-01), and `builtins/text.rs` `TABLE` with:

- `text.begin` — open the editor on the selection's anchor shape;
- `text.commit` / `text.cancel` — end the edit (commit writes, cancel
  discards);
- `shape.set.text` — arg `text` (`ArgValue::Text`); writes one run
  (ADR 0044 rule) through `Document::set_shape_text`; one undoable edit
  whose revert restores the old `TextContent` verbatim.

The editor renders in `crates/ui` (egui `TextEdit` in a floating area at
the shape's text-block rect from the scene); the `Text` shortcut scope is
active while `TextEditor::is_active()` (coordinate with P5-05's
`ActiveScopes` wiring; the scope hook reads your editor state).

### What changed

- **Commands** (`crates/commands/src/builtins/text.rs`): `text.begin`,
  `text.commit`, `text.cancel` and `shape.set.text` in the module `TABLE`.
  `shape.set.text` reads the `text` argument (missing = `NeedsInput::Text`,
  wrong type = `InvalidArgs`), writes one run through
  `Document::set_shape_text`, and returns one `TextEdit` undo step. The
  edit captures the old `TextContent` and the shape's exact `Preserved`
  block, so undo restores a multi-run text verbatim and restores a shape
  that had no text back to `None` (no leftover `Text` element). The run
  keeps `Character`/`Paragraph`/`Tabs` markers at `IX` 0 when the shape
  has undeleted rows of that kind; an empty buffer writes empty text.
- **Editor state** (`crates/ui/src/text_edit.rs`): `TextEditor::{begin,
  finish, original_text, is_active, cancel}` plus `show`. `begin` keeps
  the plain buffer and the original marker kinds. `finish` returns the
  one-run text or `None` when unchanged and always returns to idle.
  `show` draws a floating multiline `TextEdit` over the supplied text-block
  rectangle, requests focus on the first frame, and commits on Escape or
  a click outside. `original_text` rejects a stale shape or a missing
  document. `editor_rect` maps a scene's text block (or node bounds for a
  fresh empty text box) through the ancestor transforms and the canvas
  pan/zoom into screen points.
- **Text tool** (`crates/ui/src/tools/text.rs`): a pointer release emits
  `insert.drawing.text_box` (x, y, default 2 x 0.5 in box) followed by
  `text.begin`; a double click emits `text.begin`. The tool never mutates
  the selection or the model; P5-06's insert command selects the new box.
- **Tests**: `crates/commands/tests/text.rs` runs all four ids through
  the registry with `Source::Test`, checks one-run markers, missing and
  mistyped arguments, disabled/stale targets, one undo step, exact
  undo/redo and a shape that had no text. `crates/ui/tests/phase5/text.rs`
  drives the real `TextEditor` in `egui_kittest` (typing reaches the
  buffer, the `Text` shortcut scope resolves `Ctrl+B`, Escape commits),
  and drives the text tool plus a fake `insert.drawing.text_box` (P5-06
  is parallel work) through the real `ToolMachine` and registry.
- **Test seam updates**: `crates/ui/src/tools/mod.rs`'s stub test no longer
  expects `text::handle` to return `NotImplemented`; `phase5/main.rs`
  declares the new `text` module. Both are test-only edits outside the
  task's Owns list and are noted here.

### Deviations

1. **The command layer cannot own the editor.** `crates/commands` is L4
   and must not depend on egui (ADR 0002), while `TextEditor` is L6.
   `text.begin` therefore validates the anchor and announces the edit
   request, and `text.commit` without a `text` argument announces the end;
   the UI owns the buffer and commits through `shape.set.text`. With a
   `text` argument, `text.commit` performs the same write as
   `shape.set.text`. This is the closest correct layering.
2. **`TextEditor::begin` cannot reject a stale id.** Its fixed signature
   receives only `(ShapeId, &TextContent)`, not `AppCtx`. The UI reads the
   shape before calling `begin`, `original_text(ctx)` rejects a stale id,
   and every command target is validated; `begin` itself accepts any id.
3. **The editor's text-block rectangle is axis-aligned.** egui text edits
   cannot rotate; `editor_rect` uses the axis-aligned bounds of the
   rotated block. The field still sits over the block's centre.
4. **Default text-box size is ours.** ADR 0044 does not fix one; the tool
   uses 2 x 0.5 in so a new label has usable room. Check against Visio in
   the screenshot pass.
5. **Field text becomes literal on commit.** ADR 0044 writes literal text
   plus first-row markers only; a field's cached display text is included
   as text, not re-emitted as an `fld` marker. This is the documented
   single-run limit.
6. **Observed multi-run behaviour.** With the test corpus fixture, all
   `cp`/`pp`/`tp` markers in a multi-run text collapse to `IX` 0 (the
   first run) and the literal parts concatenate in order. The model keeps
   `TextContent` unchanged, so the loss is only in the editor's write, not
   at the API level.

### Open issues

1. **Shell/canvas/pointer wiring is still needed** (files owned by P5-05,
   outside this task). The shell should own a `TextEditor`; each frame it
   should call `editor_rect(&scene, shape, viewport, pan, zoom)` and
   `TextEditor::show`, dispatch `shape.set.text` with the committed text,
   and dispatch `text.cancel` on the explicit cancel path. The pointer
   tool's `DoubleClick` branch should emit `text.begin` (or the shell
   should call `begin` directly on the hit shape) when a shape is clicked.
   Until that lands the editor and tool logic are complete and tested, but
   the running app does not yet display the overlay.
2. The text tool creates a fixed-size box on release; a Visio-style
   click-drag size gesture needs a per-tool drag anchor on `ToolMachine`
   (P5-05's file).
3. The new text box has no text block yet, so `editor_rect` falls back to
   the shape bounds. After P5-06 lands, check that its `Txt*` cells make a
   sensible editor rectangle.
4. `TextEditor::begin` cannot report a stale id (deviation 2); a future
   signature could take `ctx` and read the shape itself.
5. Black-box checks for the screenshot pass: Escape/outside-click commit,
   the text-box default size, and whether Visio sets an initial caret at
   the click point rather than at the start of the buffer.
