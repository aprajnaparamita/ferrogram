## Goal

Implement the model types and the two pieces of logic Phase 2 needs from
them: the semantic XML `diff` (ADR 0012) and the inheritance lookup
(ADR 0013). Construction/mutation helpers the mapper needs are allowed
(they are trivial); editing commands are not (Phase 4).

## Interfaces

Implements the stubs in `crates/model` (`Cell::set_*`, `Document::*`
accessors, `Resolved::empty`, ...) and these two, whose `Err` stubs become
real:

```rust
// raw.rs — semantic XML equivalence, ADR 0012 rule table
pub fn diff(a: &XmlNode, b: &XmlNode) -> Result<Vec<XmlDifference>, Error>;

// lookup.rs — ADR 0013 resolution order and cycle handling
impl CellLookup for Document {
    fn resolve(&self, shape: ShapeId, cell: &CellName) -> Result<Resolved<'_>, Error>;
}
```

Adds (trivial construction helpers, all documented):

```rust
impl Document {
    /// Appends a shape to the arena and returns its id.
    pub fn add_shape(&mut self, shape: Shape) -> ShapeId;
    /// Finds a shape by Visio `ID` within a page, or `None`.
    pub fn shape_by_visio_id(&self, page: PageId, visio_id: i32) -> Option<ShapeId>;
    /// Finds a master by `NameU`, or `None`.
    pub fn master_by_name_u(&self, name_u: &str) -> Option<MasterId>;
    /// Finds a style by `Name`, or `None`.
    pub fn style_by_name(&self, name: &str) -> Option<StyleId>;
}
```

`resolve` uses the generated table's `default_value`/`default_unit` for the
`SectionDefault` rung (ADR 0013) and parses `default_value` strings with
`larrygram_geom::Unit` conversions. The cycle rule: visited set per chain,
stop at the first repeat, record it in `via`, never loop, never error.

### Deviations and decisions

- **`resolve_with_table` (crate-private) takes the cell catalogue as a
  parameter.** The generated table records no `default_value` strings
  yet (`grep default_value ui-spec/shapesheet.toml` finds none), so the
  section-default rung could not be tested through the real table. The
  `CellLookup::resolve` signature is unchanged; it passes
  `generated::CELLS`.
- **Interned section defaults.** `Resolved::value` is `Option<&CellValue>`
  and the parsed default outlives the lookup, so parsed defaults are
  interned in a small bounded cache (`Box::leak` per distinct
  `(default_value, default_unit, kind)` triple from the static table) and
  hard defaults are `OnceLock` statics. No allocation per call.
- **`via` lists every consulted rung**, misses included, so a complete
  miss reads `[Local, Master(..), Style(..), SectionDefault,
  HardDefault]` with `source` the last entry. On a cycle the repeated
  source is pushed once more before the defaults, which keeps "the last
  entry is `source`" true (the ADR's "once more at the end of via" is
  then followed by the default rungs it resolves down to).
- **A source defines a cell** when the cell carries a formula or a cached
  value; an empty cell entry does not stop the chain.
- **Whitespace rule.** Whitespace-only text is ignorable only in
  element-like content (the parent has an element, comment or PI child
  and no non-whitespace text child), including leading/trailing
  pretty-print whitespace around the children. Whitespace that is the
  whole content of a text-bearing element stays significant ("any other
  text is significant", the `docProps` note).
- **Numeric attribute comparison is suffix-aware**: number-with-suffix
  values compare numerically only when their suffixes match after
  trimming (`0.5 in` = `.50 in`, `1 in` ≠ `1 mm`, no unit conversion).
- **Comment and PI data differences report `DifferenceKind::Text`** (the
  enum is the fixed stub interface and has no comment/PI variant);
  structural differences are `DifferenceKind::Child`.
- **`Error::NotImplemented` is kept** as a variant because
  `crates/vsdx/src/error.rs` (P2-05's lane) constructs it in its tests;
  no operation of `crates/model` returns it any more. See open issues.
- **Style names** come from `Shape::line_style/fill_style/text_style`
  (ADR 0011 holds the cells' values there); the style chain follows
  `Style::base_style` only, as the ADR specifies.

### Open issues

- **Cell-name spelling mismatch (affects P2-06/P2-07).** `.vsdx` spells
  some cells and sections differently from the ShapeSheet table (e.g.
  `ColorTrans` vs `Transparency`, `BulletStr` vs `BulletString`,
  `HorzAlign` vs `HAlign`, section `Connection` vs `Connection Points`,
  `Property` vs `Shape Data`). `resolve` matches table names exactly, so
  the mapper must store table names in `CellName`/`SectionName` for known
  cells (or we add an alias map in `model` later); otherwise those cells
  resolve to hard defaults and no style.
- **`Error::NotImplemented`.** Remove the variant together with its uses
  in `crates/vsdx/src/error.rs` tests in a follow-up (both files change
  at once; the lane rule kept me out of `crates/vsdx`).
- **`default_value` strings** are absent from `ui-spec/shapesheet.toml`;
  when the extractor starts recording them the section-default rung
  lights up with no code change (parsing supports `String`, `Bool`
  (`TRUE`/`FALSE`), `Color` (`#RRGGBB`, `#RGB`), `List` and `Number`
  literals with unit suffixes, converted with `larrygram_geom::Unit`
  and kind-checked with `UnitKind`).
- **ADR 0013's master cycles** mention `BaseID`; the model stores no base
  master, so only nested instances can chain today. If `BaseID` lands on
  `Master`, the visited-set loop in `resolve` already handles it.
- If P2-09 finds the suffix-aware numeric attribute rule too lenient,
  tightening it to pure number literals is a one-line change in
  `raw.rs`.
