## Goal

1. **Bindings per scope.** Today a trie leaf holds one `Entry` and a
   repeated sequence is dropped first-wins, so `Ctrl+C`, `Ctrl+V`,
   `Delete`, `Ctrl+A`, the arrow keys and others work in one scope
   only, and `tools.format_painter` (`Ctrl+Shift+C`/`Ctrl+Shift+V`,
   `global`) is lost behind the `text` alignment bindings. A leaf must
   hold one entry per scope. `dispatch` picks the binding of the most
   specific active scope (order in ADR 0036). A completed sequence with
   no active binding is still consumed (unchanged rule).
2. **Conflicts.** Only (sequence, scope) pairs naming different
   commands are conflicts. Exact repeats are dropped without a
   warning. With the committed table, `conflicts()` must be empty
   unless the file really has such a pair; say in the Result which
   ones exist, if any.
3. **Shell pass** (ADR 0036 "Precedence over egui"). The shell owns a
   `ShortcutMap` built from the loader's `shortcuts.yaml` (the same
   embedded source the ribbon uses). In `Shell::show_in`, before the
   widgets draw, call `shortcuts::dispatch` with the focused scope
   (`Page` when the canvas has focus, `Ribbon` when the ribbon has
   focus, else `Global`; add the smallest focus tracking that gives
   this, and say how in the Result). Return the intent with the
   frame's other intents so it runs through `Shell::dispatch`
   (`Source::Shortcut`). A disabled command shows its reason in the
   status bar, as for any intent. At load, copy `conflicts()` into
   `AppCtx::warnings`. While `pending()` is true, the status line shows
   the chords typed so far.

`Shell::new`'s signature stays. If the map needs input the shell does
not have yet, add an additive setter like `set_picker`, and note it.
