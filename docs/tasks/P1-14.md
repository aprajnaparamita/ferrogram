## Goals

1. **Duplicate ids (R8).** The loader rejects:
   - a Fluent id used twice as the primary `id` within one layout (across tabs, groups, controls, backstage and context menus);
   - a command `id` that appears twice in `commands.yaml`.

   Add `LoadError::Duplicate { path, kind, id }`. Test each case with a fixture.

   **Before you enforce this, check the real data.** Load the committed `ui-spec/*.yaml` and count duplicates. P1-03 reported `TabSave` repeated in the 365 backstage. If the real data has duplicates, do not enforce for that surface. Report what you found under "Open issues" with the exact ids, and the master decides. The committed-data test (`tests/committed.rs`) must stay green.
2. **JSON fallback (R8).** Add an end-to-end test where a workspace has only `.json` data files and loads.
3. **Serialize (R9).** Derive `serde::Serialize` on every public model type. The output must round-trip: deserialize, serialize, deserialize gives an equal value. Add a proptest or a test over the committed data.
4. **Validated ids (R9).**
   - Add `CommandId::parse(&str) -> Result<CommandId, IdError>` implementing the ADR 0006 grammar, the same as the schema `commandId` pattern.
   - Add `FluentId::parse` with the pattern `^[A-Za-z_][A-Za-z0-9_]*$`.
   - Hand-roll both; do not add a regex dependency.
   - Keep `new` for trusted and test use, and document that it does not validate.
   - Add a proptest that `parse` agrees with the schema pattern (the `jsonschema` validator compiled with a tiny schema is fine as the reference).
5. **One layout switch (R9).** Remove `LayoutSet::select` and keep `LayoutSets::get`. Update the tests and doc examples. Nothing outside the crate uses `select` (check with grep).
6. **Docs and errors (R9).**
   - Fix the stale P1-06 future-tense docs on `CommandLookup`.
   - Give `LoadError::Unknown` a `path` field like the other variants.
7. **Coverage gaps (C9).**
   - Test the plain-miss fallthrough in `data_file`: a non-`.yaml` primary path that is missing.
   - Test the `layout` and `shortcuts` arms of `DocKind::noun`.

### What changed

1. **Duplicate ids (R8).** New `LoadError::Duplicate { path, kind, id }`
   (`src/error.rs`). The loader rejects a command `id` used twice in `commands.yaml`
   (`check_duplicate_command_ids`, run right after the table decodes,
   `kind: "command_id"`). Unit tests plus fixture `tests/fixtures/duplicate-command/`
   (integration test `duplicate_command_id_is_rejected`, through both `load` and
   `load_all`). The committed `ui-spec/commands.yaml` has 935 entries and **no**
   duplicate ids, so this surface is enforced. The layout-side rule is **not**
   enforced: the committed layouts reuse primary Fluent ids heavily (Open issues 1).
   Fixture `tests/fixtures/duplicate-fluent/` pins today's accepting behaviour with a
   comment pointing at the open issue. `tests/committed.rs` stays green.
2. **JSON fallback (R8).** The end-to-end test `json_data_files_load_too` already
   covered a workspace of only `.json` files (the reviewer's report predates it);
   extended it to assert that no `.yaml` data file exists and to exercise `load_all`
   as well. New unit test `data_file_prefers_yaml_and_falls_back_to_json` pins the
   resolution order: missing both, `.json` fallback, `.yaml` primary.
3. **Serialize (R9).** `serde::Serialize` on every public model type: `CommandId`,
   `FluentId`, `ControlType`, `SizeVariant`, `MappingConfidence`, `ShortcutScope`
   (string forms mirroring their `Deserialize`), `Bounds`, `Control`, `Group`, `Tab`,
   `Backstage`, `BackstageTab`, `ContextMenu`, `QuickAccessToolbar`, `Layout`,
   `CommandMapping`, `Shortcut`, `Commands`, `Shortcuts`, `LayoutSet`, `LayoutSets`,
   `CommandLookup`, `LayoutKind`. `Commands` and `Shortcuts` serialize (and
   deserialize) as the bare entry list of their data files, so the on-disk shape
   round-trips. Round-trip (deserialize, serialize, deserialize, equal) is tested
   over the whole committed data set (`tests/committed.rs`) and over hand-built
   values of every type (src unit tests).
4. **Validated ids (R9).** `CommandId::parse` implements the ADR 0006 grammar, same
   language as the schema `commandId` pattern; `FluentId::parse` implements
   `^[A-Za-z_][A-Za-z0-9_]*$`. Both hand-rolled; no regex dependency. New public
   `IdError` (with `value()` and `reason()`). `CommandId::new` and `FluentId::new`
   stay for trusted and test use and now say explicitly that they do not validate.
   `tests/ids.rs` has proptests where both parsers must agree with the schema
   patterns, using a `jsonschema` validator over a tiny schema as the reference, plus
   a deterministic both-directions example table.
5. **One layout switch (R9).** `LayoutSet::select` removed; `LayoutSets::get` is the
   only switch. Grep confirmed nothing outside the crate used `select`. Tests and
   doc examples now use `get`.
6. **Docs and errors (R9).** The stale P1-06 future-tense text on `CommandLookup`
   (struct doc, `commands` field doc, `empty` doc) is rewritten in the present tense.
   `LoadError::Unknown` now carries a `path` field like the other variants; its
   `message` no longer embeds the path and `Display` output is unchanged.
7. **Coverage gaps (C9).** Unit tests for the plain-miss fallthrough of `data_file`
   (a non-`.yaml` primary path that is missing) and for the `layout` and `shortcuts`
   arms of `DocKind::noun`.
