## Goal

1. **Units.** Since P6-08, the writer spells a `U` code for every value
   kind (`BOOL`, `STR`, `COLOR`, `LIST`). The reader keeps in
   `Preserved` only the codes the writer does not re-derive (for example
   `DATE`, `GUID`, `PNT`, `DT`, `DL`). Check the list against
   `write/value.rs` and say how you checked it.
2. **`Rel` children.** A read `Page` or `Master` does not keep the
   `<Rel>` child that names its contents part, because the writer
   writes it again. Keep any other unmapped child as today.
3. **Drop the comparison rules.** Remove the two rules from
   `flowchart.rs` (`normalised` then compares more), and keep the test
   green.
4. **Generate lists.** `properties.rs` `arb_cell_value` can now generate
   `CellValue::List` (P6-08 Open issue 4).

### Goal 1: the code list and how it was checked

The kept/dropped split is **per cell**: a code is consumed exactly when
the writer writes the same code back for that value and unit
(`UnitSpelling::Keep`, or `Code` with the same code). Checked against
`write/value.rs` two ways:

1. **Read the two tables against each other.** `write/value.rs`
   `unit_code` re-derives 14 codes (its `spelled` list: `IN`, `FT`,
   `YD`, `MI`, `MM`, `CM`, `M`, `KM`, `PT`, `P`, `C`, `DEG`, `RAD`,
   `PER`) and `kind_code` re-derives 4 (`BOOL` always for a `Bool`,
   `LIST` always for a `List`, `STR` for a string whose shape would
   misread or that carries a unit, `COLOR` for a colour that carries a
   unit). Everything else in `read/value.rs`'s tables is never produced
   by the writer: `DATE`, `GUID`, `PNT` (string codes), the 20 numeric
   codes with no `Unit` variant (`AC`, `AD`, `C_D`, `CY`, `DA`, `DE`,
   `DP`, `DT`, `ED`, `EH`, `EM`, `ES`, `EW`, `F_I`, `HA`, `IN_F`,
   `MI_F`, `NM`, `P_PT`, `DL`), and any unknown code. Those are kept for
   every value.
2. **Scanned the corpus.** All 15 files, every part: 5266 cells carry a
   `U`, 14 distinct codes (`MM` 3587, `PT` 752, `STR` 255, `BOOL` 242,
   `IN` 192, `DL` 153, `DA` 24, `DEG` 23, `DATE` 20, `IN_F` 9,
   `COLOR` 4, `DT` 2, `PER` 2, `GUID` 1). Under the rule, 4556 are
   consumed and 710 are kept (the corpus identity test, green and
   unchanged, proves every one writes back unchanged).

### Deviations

1. **The writer changed too (`write/mod.rs`, outside this task's
   files).** Goal 2 says the writer "writes the `Rel` again"; it writes
   the *element* again but `ensure_list` recovered the contents
   relationship id from the preserved `Rel`. Dropping the `Rel` without
   touching the writer made every patched file grow a second
   relationship and a second `Rel` (the corpus identity test failed).
   `ensure_list` now recovers the id from the source list element the
   reader read it from (`source_rel_id`, matched by the entity's `ID`),
   before allocating a fresh id; every other behaviour is unchanged
   (the wrong-`Rel`-id case of `write_edge_cases.rs` still works
   because that `Rel` is still preserved). ~35 lines plus the
   `ListEntity::visio_id` accessor. The implementer role's "closest
   correct version" clause applies; see Open issue 1.
2. **The kept/dropped split is per cell, not per code (Goal 1 wording).**
   A static list cannot work: `STR` and `COLOR` are re-derived only for
   some values (`U='STR' V='Bottom'` and `U='COLOR' V='#ffffff'` — 233
   and 4 corpus cells — would be stripped by the writer and the corpus
   round trip would fail). So "a cell read with each re-derived code has
   an empty `Preserved`" holds for every code *the writer re-derives for
   that cell*: `BOOL`, `STR` (number-like strings), `LIST` and the 14
   unit codes. A read `COLOR` cell is the documented exception: `COLOR`
   is re-derived only for a colour that carries a unit and
   `read::value::unit` maps no `COLOR` code, so no read cell ever
   re-derives it and its code is kept (tests pin both cases).
3. **`U='MM' V='Themed'`-style mismatches keep the code** although the
   writer overwrites it with `STR` on the next write (P2-14's unit drop
   on a non-numeric kind). The code is then the only record of the
   file's spelling. No corpus cell has this shape; the churn predates
   this task (the writer has overwritten such spellings since P6-08).

### Open issues

1. **`write/mod.rs::source_rel_id` should move or be reviewed** with the
   rest of the writer (Deviation 1). Its `ID`-matching duplicates the
   reader's association in a second place; a contents relationship id
   on the model (`Page`/`Master` field) would remove both the source
   scan and the preserved-`Rel` channel entirely.
2. **`read/value.rs` and `write/value.rs` docs are stale** (P6-08's
   files, not owned here): `read/value.rs` says every code with no
   `Unit` spelling "is left in `Cell::preserved`" and `write/value.rs`
   says "the reader keeps every other code in `Preserved`"; both should
   point at the per-cell rule of `read/sheet.rs::writer_spells_code`.
3. **A `Keep`-first tweak in `write/value.rs` `unit_spelling`** (check
   `declares_kind(current, value)` before `kind_code`) would let the
   writer keep any spelling that already declares the value's kind
   (`U='STR' V='Bottom'`, `U='COLOR' V='#ffffff'`) instead of relying on
   the reader to preserve it; then the reader rule could be a static
   code list. P2-14's unit-drop churn (Deviation 3) would shrink too.
4. **`U='LIST'` remains our own spelling** (P6-08 deviation 6, not
   changed here): what Visio does with `U='LIST'` is a black-box
   question for a black-box check.
5. The flowchart comparison still canonicalises arena ids (`canonical`,
   the documented P5-10 deviation); that one is real model behaviour,
   not a reader artefact.
