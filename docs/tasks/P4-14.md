## Goal

1. **Bindings per scope.** Today a trie leaf holds one `Entry` and a
   repeated sequence is dropped first-wins, so `Ctrl+C`, `Ctrl+V`,
   `Delete`, `Ctrl+A`, the arrow keys and others work in one scope
   only, and `tools.format_painter` (`Ctrl+Shift+C`/`Ctrl+Shift+V`,
   `global`) is lost behind the `text` alignment bindings. A leaf must
   hold one entry per scope. `dispatch` picks the binding of the most
   specific active scope (order in ADR 0036). A completed sequence with
   no active binding is still consumed (unchanged rule).
2. **Conflicts.** Only (sequence, scope) pairs naming different
   commands are conflicts. Exact repeats are dropped without a
   warning. With the committed table, `conflicts()` must be empty
   unless the file really has such a pair; say in the Result which
   ones exist, if any.
3. **Shell pass** (ADR 0036 "Precedence over egui"). The shell owns a
   `ShortcutMap` built from the loader's `shortcuts.yaml` (the same
   embedded source the ribbon uses). In `Shell::show_in`, before the
   widgets draw, call `shortcuts::dispatch` with the focused scope
   (`Page` when the canvas has focus, `Ribbon` when the ribbon has
   focus, else `Global`; add the smallest focus tracking that gives
   this, and say how in the Result). Return the intent with the
   frame's other intents so it runs through `Shell::dispatch`
   (`Source::Shortcut`). A disabled command shows its reason in the
   status bar, as for any intent. At load, copy `conflicts()` into
   `AppCtx::warnings`. While `pending()` is true, the status line shows
   the chords typed so far.

`Shell::new`'s signature stays. If the map needs input the shell does
not have yet, add an additive setter like `set_picker`, and note it.

**What changed** (branch `agent/P4-14`, worktree
`/Volumes/Dara/ferrogram/worktrees/P4-14`):

- `crates/ui/src/shortcuts.rs`: scope-aware bindings (P4-14 goal 1
  and 2).
  - A trie leaf holds one `Entry` per scope: a repeated sequence is
    kept per scope instead of dropped first-wins. `dispatch` picks the
    binding of the most specific active scope (`ActiveScopes`, ADR
    0036 order: `Text`, `Selection`, `Page`, `Ribbon`, `Window`,
    `Global`); a completed sequence with no active binding is still
    consumed. The new `ActiveScopes` struct carries the four scope
    flags and is built in `dispatch` from the focus argument,
    `Context::text_edit_focused()` and `AppCtx::selection`.
  - Conflicts key on (sequence, scope): only a pair naming two
    different commands is a conflict (first in file order wins, one
    `conflicts()` line); an exact repeat (same command) is dropped
    silently. `len()` now counts **bindings** (documented): one per
    kept (sequence, scope) pair.
  - The deferred completion (a sequence that is a prefix of longer
    ones) holds all bindings of its leaf and fires the most specific
    active one on mismatch or timeout.
  - New accessors `pending_chords()` and `pending_display()` for the
    shell's status line.
- `crates/ui/src/shell.rs`: the shell shortcut pass (goal 3, ADR 0036
  "Precedence over egui").
  - `Shell::show_in` calls `shortcuts::dispatch` with the focused
    scope **before the widgets draw** and returns the intent with the
    frame's other intents, so it runs through `Shell::dispatch` as
    `Source::Shortcut`. A dispatch failure goes to the status bar.
  - Focus tracking (the smallest that gives the three scopes): the
    shell remembers the canvas area and the ribbon strip rects of the
    previous frame and maps the frame's primary-button press to
    `Page` / `Ribbon` / else `Global`. Clicks take effect in their own
    frame (the pass runs before the widgets). `Text` is egui's own
    text-edit focus; `Selection` stays empty in Phase 4.
  - The `ShortcutMap` is built in `Shell::new` from the loader's
    `shortcuts.yaml` (`layouts.get(kind).shortcuts`, the same embedded
    source the ribbon uses) — `Shell::new`'s signature is unchanged;
    the additive setter is `Shell::set_shortcuts(&Shortcuts)` (like
    `set_picker`) and `Shell::status_line()` is new. A table that
    fails to load falls back to an empty map with one warning.
  - At load, `conflicts()` is copied into `AppCtx::warnings`. While
    `pending()` the status line (the title strip label) shows the
    chords typed so far (`Alt+H`). A command the registry reports
    `NotEnabled` for shows its reason in the status bar for every
    intent source (`note_disabled`); the error still goes back to the
    caller untouched.
- `crates/ui/tests/shortcuts_dispatch.rs`: the P4-14 acceptance
  tests — `Ctrl+C` resolves to `edit.copy` both with the canvas
  focused and inside a text edit, `Ctrl+Shift+C` fires
  `tools.format_painter` outside text and `format.text.align_center`
  inside, one real (sequence, scope) conflict warns exactly once while
  an exact repeat is silent, `len()` is pinned at 74 for the committed
  table, and the most specific active scope wins. The P4-08 tests were
  updated to the amended conflict rule and the narrowed deferral (see
  deviations).
- `crates/ui/src/shell.rs` tests: `Alt+F6` in a real frame dispatches

  key event consumed before the widgets; a half-typed `Alt+H, F`
  shows `Alt+H` in the status line; the focus tracking, the load
  warnings and the disabled-command reason are covered.

**Conflicts in the committed table** (goal 2): **none**. The 90
entries are 74 distinct (sequence, scope) bindings, 16 exact repeats
dropped silently (e.g. `arrange.bring_to_front` `Ctrl+Shift+F`
selection appears twice), and 61 distinct sequences (no multi-chord
sequences). The only sequence bound to different commands in different
scopes is `Ctrl+Shift+C` / `Ctrl+Shift+V` (`format.text.align_center` /
`align_bottom` in `text` vs `tools.format_painter` in `global`), which
is legal under the amended rule and no longer dropped.

**Deviations:**

1. `ShortcutMap::resolve` takes the active scopes
   (`resolve(&mut self, &[KeyChord], &ActiveScopes)`): the ADR's
   signature has no scope input and cannot choose between the
   bindings of one leaf. `dispatch`'s signature is unchanged.
2. The never-steal rule is narrowed (P4-08 behavior change): inside a
   text edit only chords **without** `Ctrl` or `Alt` (typing,
   shift-typing, the caret keys) pass to egui. A bound `Ctrl`/`Alt`
   chord dispatches there, which acceptance criteria 1 and 2 require
   (`Ctrl+C` resolves in a text edit; `Ctrl+Shift+C` picks the `text`
   binding). Consequences: `Ctrl+Z`/`Ctrl+Y` run `edit.undo`/
   `edit.redo` in a text edit (egui's text undo is shadowed),
   `Ctrl+Backspace` now fires `edit.delete_back_word` (closes P4-08's
   open issue), and `Ctrl+A` picks the `text`-scoped
   `edit.select_all`.
3. Focus tracking is pointer-press based (rects of the previous
   frame), not egui widget `Id`s: the canvas and ribbon widgets do not
   expose focusable ids, and the shell's own two rects are the
   smallest thing that answers `Page` / `Ribbon` / `Global`. A
   keyboard-only focus move (Tab) does not change the scope.
4. The status line is the title strip label (`Shell::status_line`);
   `canvas::show_status_bar` (P4-05's file, untouched) keeps showing
   the last warning.
5. Only `CommandError::NotEnabled` is copied to the status bar by
   `Shell::dispatch` ("a disabled command shows its reason"): other
   errors still return to the caller so a programmatic call sees them
   untouched.

**New dependencies:** none.

**Open issues:**

- The committed table has no multi-chord sequence, so the shell
  pending-chord test synthesizes one (`Alt+H, F`); the keytip
  sequences land with the ribbon keytips (P4-09).
- egui multipass: `Context::run_ui` may run several passes per frame
  and only the first pass sees the frame's key events (egui takes the
  input on the first `begin_pass`). Each pass dispatches its own
  intents, so the shell is correct; tests must collect across passes.
- `Window` is always active in Phase 4 (ADR 0036), so `Delete`,
  `Ctrl+C`, `Ctrl+V` fire the `window` bindings wherever focus is
  (outside text edits; inside they defer or the `text` binding wins).
  The single-window rule should be revisited when the stencil window
  can really hold focus.
- `Ctrl+V` in a text edit runs `edit.paste` (the document paste), not
  a text paste — the same class of behaviour acceptance criterion 1
  mandates for `Ctrl+C`; revisit in the parity pass with a black-box
  check against Visio.
- The 2 second sequence timeout and prefix-wait rules are still not
  black-box checked (P4-08 note, no Visio here).
- `Shell::set_shortcuts` is only used by tests so far; a layout switch
  does not rebuild the map (both layout sets embed the same
  `shortcuts.yaml`). If a future layout ships its own table, call it
  from `set_layout_kind`.
