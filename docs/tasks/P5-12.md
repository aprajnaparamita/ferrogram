## Goal

Read-only review of correctness, error handling, API design, idiomatic
Rust, dead code and duplication, with severities (blocker / major /
minor) so the fix tasks are unambiguous.

Focus for Phase 5:

- Undo correctness: every editing path returns exactly one edit;
  `apply`/`revert` are true inverses; the suspension flag covers every
  nested-dispatch path.
- Invariants of ADR 0039 (id stability, no cycles, clamped indices)
  checked against the implementation, not just its tests.
- Never-crash: input-derived arithmetic, recursion caps, `get()` over
  indexing in parser crates, stale ids on every command path.
- Hit-test and snap policy vs the ADRs (z-order, tolerance, priority).
- The writer additions (ADR 0048): patching vs emitting, deleted parts,
  relationship hygiene.
- API design: anything public that should be private, duplicated logic
  between `commands` and `ui`, and the stub seams that outlived their
  task.
