## Goal

Read-only review of correctness, error handling, API design, idiomatic
Rust, dead code and duplication, with severities (blocker / major /
minor) so the fix tasks are unambiguous.

Focus for Phase 5:

- Undo correctness: every editing path returns exactly one edit;
  `apply`/`revert` are true inverses; the suspension flag covers every
  nested-dispatch path.
- Invariants of ADR 0039 (id stability, no cycles, clamped indices)
  checked against the implementation, not just its tests.
- Never-crash: input-derived arithmetic, recursion caps, `get()` over
  indexing in parser crates, stale ids on every command path.
- Hit-test and snap policy vs the ADRs (z-order, tolerance, priority).
- The writer additions (ADR 0048): patching vs emitting, deleted parts,
  relationship hygiene.
- API design: anything public that should be private, duplicated logic
  between `commands` and `ui`, and the stub seams that outlived their
  task.

**Majors** (each with a reproducing path in the report):

1. `edit.delete` of a selection holding a group and its own member
   detaches the group, then fails on the member with **no undo step**
   (`crates/commands/src/builtins/edit.rs:607-619`). `edit.select` can
   build that selection (it resolves sub-shapes). Fix: drop targets
   whose ancestor is also a target, or roll the applied steps back.
2. `Document::group_shapes` writes non-finite cells (the bounding-box
   check misses the derived `width`/`height`/`centre`) and leaves a
   half-built group when a later `write_cell` fails
   (`crates/model/src/mutate.rs:1410-1470`); `ungroup_shape` has the
   same non-atomic failure shape. Fix: validate before mutating.
3. The `Outcome::edit` dispatcher lives in `crates/ui::shell`
   (`dispatch_one`); ten `crates/commands` test files re-implement it
   and a Phase 8 programmatic caller would drop or misplace its edit.
   Fix: move the dispatcher into `ferrogram_commands`.
