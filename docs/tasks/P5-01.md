## Decisions to make (one ADR each where significant)

1. **Editing without a formula engine.** Phase 6 brings formulas. Decide
   what an edit writes now: cached values, literal formulas, or both. Say
   what happens to cells that depend on the changed cell (for example
   geometry written as `Width*0.5` in a master, or `LocPinX`), and how
   Phase 6 takes over without a data migration.
2. **Model mutation API** (`crates/model`). Creating, deleting and
   re-parenting shapes, writing cells, adding and reordering pages, new
   shape and page ids, master instances, and `Connects`. The invariants
   each operation keeps, and how errors come back (never a panic).
3. **Edits and undo** (`crates/commands`). How each editing command builds
   an `Edit` (ADR 0028), how edits group (one drag is one undo step),
   redo, and the property test that undo is the inverse of every command.
   Fix the open items: the `with_undo` placeholder stack has zero
   capacity, and `with_undo` puts the stack back by document index. Add a
   document change counter, so the canvas can stop comparing a document
   snapshot every frame (P4-05).
4. **Selection and hit-testing.** Where the selection lives (ADR 0029),
   hit-testing against the scene (filled and unfilled shapes, lines, text,
   groups, tolerance in screen pixels), the marquee, multi-select, and the
   focus scope (also fix "keyboard focus moves do not change the scope",
   P4-14).
5. **Interaction tools and handles** (`crates/ui`). The tool state machine
   (pointer, rectangle, ellipse, line, connector, text), the move, resize
   and rotate handles, the drag preview, and redraw speed. A full raster per
   frame while dragging may be too slow: decide whether there is an
   overlay or a partial redraw, and give a frame-time budget.
6. **Snapping.** Snapping to the grid and to connection points, the snap
   distance in screen pixels, and its priority over other targets.
7. **Text editing on shapes.** An in-place editor over the canvas, how text
   with runs is written back (ADR 0019 text content), and the shortcut scope
   while editing (ADR 0036 Text scope).
8. **Dynamic connector.** Glue to connection points and to the shape
   outline (the `Connects` part and the glue cells), straight and simple
   right-angle routing, re-routing when a glued shape moves, and the
   connector master. Our own routing, not copied from Visio.
9. **Stencil drag** (the P4-06 deferred item). Drop at the pointer
   (`PinX`/`PinY`), the instance size, and glue on drop.
10. **Clipboard, arrangement, pages.** The clipboard format: internal, and
    whether there is a text or image export to the system clipboard (and on
    wasm). Copy, cut, paste, duplicate and delete. Align, distribute,
    group and ungroup, bring forward and send backward. Add, rename,
    delete and reorder pages. Which of these are command bar controls with
    `commands.yaml` ids, so the parity matrix moves.
11. **Saving.** "Saved files re-open identically in our app": define
    "identically" (model equality, ignoring what?), the writer additions
    for new shapes, pages and connects, and a round-trip test.
12. **Test strategy for the exit criterion.**
    - Headless command-level tests through the registry for every editing
      command.
    - Undo property tests and connector glue tests.
    - `egui_kittest` interaction tests: drag, handles, marquee and text.
    - A scripted flowchart test for the exit criterion: 10 shapes, two
      pages, save, reopen, edit again.
    - Coverage targets per crate.
    - The parity matrix commands table (the P4-15 deferred item: command-only
      ids are not listed).

Propose the tasks with disjoint ownership. A starting point; change it as
the design requires:

- then the test-engineer, reviewer, coverage-auditor and cleanroom-auditor

For each task file, use `docs/tasks/TEMPLATE.md`. Give each its Owns list,
Inputs, Interfaces (the exact stub signatures it implements or consumes),
acceptance criteria, the hand-off gate steps it must run (AGENTS.md
section 7), and a suggested model tier. Mark which tasks can start at once
and which wait for others. Include the Launch prompt.

Lessons from Phases 3 and 4:

- Give every shared file (a crate's `lib.rs`, `Cargo.toml`, `error.rs`,
  `shell.rs`, the app's `main.rs`) to exactly one task. In each dependent
  task's file, say which lines it may add.
- `crates/ui` and `crates/commands` will be touched by most tasks: split
  them into modules up front (one per task) so the tasks do not collide.
  `Shell::dispatch` and the builtin registry list are the usual collision
  points.
- Write acceptance criteria against real user behavior. In Phase 4 two
  criteria were wrong: Ctrl chords inside text edits, and command ids in a
  matrix that lists only Fluent controls. Check each criterion against how
  the feature is used.
- Each new fuzz directory needs its own `.gitignore` with `!corpus/`, and
  seeds in per-target subdirectories (`corpus/<target>/`).

**Deviations.**

- The undo recording gate (ADR 0040 rule 2) lives on `AppCtx`
  (`push_edit` + a suspension flag), not on `UndoStack`: the stack is
  swapped out of the session during `apply`/`revert`, so a flag on the
  stack would guard the placeholder, not the real one. `push_edit` is
  P5-04's; `AppCtx::touch()` (a one-line `wrapping_add`) is written now.
- Glue primitives (`add_connect`, `remove_connects`, `connects_of`) are
  model methods (P5-02), not a `commands::glue` seam, so P5-06's drop glue
  and P5-08's connector glue share one data layer with no cross-task stub.
- `scene::Shape` gained a public field (public API of `render` changes, as
  the gate note expected); the literal updates in tests are mechanical.
- The only new `vsdx` public seam is `Package::remove_part` /
  `next_relationship_id`; writing new shapes and pages is internal writer
  work (ADR 0048). P5-02 may add another entry point and note it.

  transcription task, not decided here; the ADR says where they come from.

  measured number; P5-11 measures and reports it.

  empty leaves `STUB_TABLES` entries empty; harmless, but a later task
