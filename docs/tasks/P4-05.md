## Goal

Opening a corpus file shows the page on the canvas: the scene renders to
a raw RGBA texture, the view pans and zooms, rulers and grid draw around
it, page tabs switch pages, and the status bar reports the page, zoom and
warnings.

## Interfaces

```rust
// crates/render/src/raster.rs (stub filled in)
pub fn render_raster(scene: &Scene, opts: &RasterOptions) -> Result<RasterImage, Error>;
```

Implementation rule (ADR 0033): `render_raster` and `render_png` share
one rasterizer; `render_png` encodes the raster `render_raster` returns
(no pixel divergence; the PNG goldens cover the canvas pixels). The ADR
0025 caps and errors apply unchanged.

```rust
// crates/ui/src/canvas.rs (stubs filled in)
pub fn show(&mut Ui, &mut DocumentSession, &mut CanvasCache) -> Result<CanvasOutput, UiError>;
pub fn show_rulers(&mut Ui, &DocumentSession) -> Result<(), UiError>;
pub fn show_page_tabs(&mut Ui, &mut DocumentSession) -> Result<Vec<Intent>, UiError>;
pub fn show_status_bar(&mut Ui, &AppCtx) -> Result<(), UiError>;
```

Cache rules (ADR 0033): re-rasterize on document change or page switch;
on zoom change only when the settled zoom moved more than 10% from the
rasterized zoom; panning never re-rasterizes (texture transform). The
texture is uploaded to egui with `Context::load_texture` and dropped via
`TexturesDelta` handling (egui 0.37: apply or clear deltas; never leave
unapplied deltas — it panics on drop).

Interaction: middle-drag or space-drag pans; Ctrl + wheel zooms at the
pointer; the `view.zoom.in`/`view.zoom.out`/`view.zoom.fit` commands
(registered by P4-02) are produced as `Intent`s from the canvas keys and
menu items. Rulers draw ticks at 1/8 inch in `Settings::units`
(conversion at this edge only, AGENTS.md section 6). The grid draws
behind the texture when `ViewState::show_grid`. Page tabs produce
`page.next`/`page.previous` intents and direct `active_page` changes on
click. The status bar shows page name and size, zoom percent, and the
last `AppCtx::warnings` entry.

**What changed**

- `crates/render/src/png.rs`: the body of `render_png` is extracted
  into `pub(crate) fn rasterize(scene, scale, antialias) -> Result<Pixmap,

- `crates/render/src/raster.rs`: `render_raster` is filled in. It
  rasterizes through the shared path and returns

  writes, straight (non-premultiplied) RGBA. The ADR 0025 caps surface
  unchanged (`InvalidOptions`/`TooLarge`).
- `crates/render/tests/raster.rs` (new): byte parity between
  `render_raster` and the decoded `render_png` output (fixture with
  opaque, translucent and stroked content, at four scale/antialias
  combinations), determinism, and the ADR 0025 caps from both backends
  (bad scale, one side over `MAX_DEVICE_EXTENT`, raster over 256 MiB,
  degenerate page).
- `crates/ui/src/canvas.rs`: `CanvasCache`, `show`, `show_rulers`,
  `show_page_tabs`, `show_status_bar` implemented (ADR 0033). The scene
  of the active page renders at `zoom * 96` pixels per inch into one
  egui texture (`Context::load_texture`; the handle drops normally and
  its free joins the next `TexturesDelta`, which the frame applies).
  Cache rules: re-rasterize on document change or page switch, and on a
  settled zoom more than 10% from the rasterized zoom; panning never
  re-rasterizes. Interaction: middle-drag or space-drag pans, Ctrl +
  wheel (egui's zoom modifier) zooms at the pointer, the canvas keys
  Ctrl + `+`/`=`, Ctrl + `-`, Ctrl + `0` produce the
  `view.zoom.in`/`view.zoom.out`/`view.zoom.fit` intents. The grid draws
  behind the texture (1/8 inch, stronger every inch) when
  `ViewState::show_grid`; the rulers draw 1/8 inch ticks with labels in
  the display units; page tabs switch `active_page` on click and emit
  `page.previous`/`page.next` from their buttons; the status bar shows
  page name and size, zoom percent and the last `AppCtx::warnings`
  entry. New helpers `format_length`/`format_number` (inches converted
  only at this edge, AGENTS.md section 6).

**Deviations**

- `show_rulers` takes a third parameter `units: DisplayUnits` (the stub
  signature had none, and the ruler labels must honour
  `Settings::units`, which `&DocumentSession` cannot reach). Call sites
  (P4-03's shell) become `show_rulers(ui, session, app.settings.units)`.
- Document-change detection: `DocumentSession` has no generation
  counter, so `CanvasCache` stores a `Document` snapshot and compares it
  per frame (exact, O(document) per frame) plus `active_page`. A
  generation counter would make it O(1) (Open issues).
- `CanvasCache` also keeps the last `RasterImage` (`CanvasCache::raster`)
  for the P4-09 exit-criterion test; the memory cost is accepted in
  Phase 4.
- Render/build failures map to `UiError::Io` because `crates/ui` has no
  render variant and `lib.rs` belongs to P4-03 (Open issues). The scale
  is clamped to the ADR 0025 caps and the backend `max_texture_side`
  first, so the error path is defensive.
- `view.zoom.fit` is bound to Ctrl + `0` on the canvas (our own
  binding; `shortcuts.yaml` has no fit chord). The keys are consumed
  (`InputState::consume_key`), so the shortcut layer never
  double-dispatches them. Wheel zoom reads raw Ctrl + wheel and
  `Event::Zoom` events (pinch) instead of `InputState::zoom_delta`, so
  "Ctrl + wheel" works literally on every platform.

**New dependencies**

- `png = "0.18"` as a dev-dependency of `larrygram-render` (parity
  test decodes `render_png` output). The crate is already in the tree
  through tiny-skia's `png-format` feature; no new crate in the supply
  chain, `cargo deny` unchanged. `Cargo.lock` carries the dev edge.
