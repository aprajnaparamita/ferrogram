## Goal

Download every Phase 1 source into `reference/`, organised one directory per source, and record provenance. Report the shape of each dataset so the architect (P1-02) can design formats and extractors.

Layout:

```
reference/
  SOURCES.md
  fluent-ui-ids/        # git clone of OfficeDev/office-fluent-ui-command-identifiers
  office2016-ui-ids/    # only if the 2016 Visio data is missing from the repo above
  learn/visuicmds/      # saved HTML or Markdown of the VisUICmds page(s)
  learn/enums/          # other Visio enumerations (section, row, cell indices; units)
  ms-vsdx/              # [MS-VSDX] PDF/DOCX and its XML schemas (XSD)

  support/shortcuts/    # "Keyboard shortcuts for Visio" page
  libvisio/             # git clone; record commit hash
  corpus-candidates/    # downloaded test files before license triage
```

## Sources

1. **Office Fluent UI control identifiers**: https://github.com/OfficeDev/office-fluent-ui-command-identifiers — clone it. Find the Visio files for Office 2016 and for Microsoft 365. Record the repo commit and the license (check its LICENSE file).
   - If the 2016 Visio data is missing, the fallback is https://www.microsoft.com/en-us/download/details.aspx?id=50745. Download it only if it is a plain data/document archive (zip or xlsx). If it is an executable or installer (.exe/.msi), **do not run, unpack or inspect it**; record that in the Result and stop on this item.
2. **VisUICmds**: https://learn.microsoft.com/en-us/office/vba/api/visio.visuicmds. Also the enumerations the model needs: VisSectionIndices, VisRowIndices, VisCellIndices, VisUnitCodes, and others you find relevant (geometry row types, VisRowTags). Save each page. The Learn content is also on GitHub (MicrosoftDocs/VBA-Docs); a clone of the Visio subset is acceptable and easier to parse. Record its license.
3. **[MS-VSDX]**: from Microsoft Open Specifications on learn.microsoft.com. Get the latest PDF and/or DOCX and the XML schema files (XSD). Record version and date. Note the Open Specifications terms (Open Specifications Promise) in SOURCES.md.
4. **ShapeSheet reference** on Microsoft Learn: sections, rows, cells, functions (index pages plus the per-cell/per-function pages). The MicrosoftDocs GitHub repo is again acceptable.
5. **"Keyboard shortcuts for Visio"** on support.microsoft.com. Save the page.
6. **libvisio**: clone from https://git.libreoffice.org/libvisio (or its GitHub mirror). Record the commit hash. Read `COPYING`; confirm the license (expected MPL-2.0). Write the commit hash into `NOTICE` where it says "(recorded in Phase 1)". List which CLI tools exist in `src/conv/` (vsd2raw, vsd2xhtml, vss2raw, others) and the build dependencies (librevenge, etc.). Do not build it; that is P1-07.
7. **Openly licensed test files**: libvisio's test data (`src/test/data` or similar) and LibreOffice's Visio test files (in the LibreOffice core repo, e.g. `sd/qa/unit/data/vsd*`, `sd/qa/unit/import-tests` data). Download candidates into `reference/corpus-candidates/`. Triage:
   - Copy into `corpus/vsd/` or `corpus/vsdx/` only files whose license is clear (e.g. the repo's license covers test data). Record each in `corpus/PROVENANCE.md` with origin URL, commit, license, author if known.
   - Skip anything whose license is unclear; list skipped files in the Result.
   - Keep the committed corpus small: at most ~20 MB total, prefer small files. Do not commit files created by Microsoft as product samples.
   - Hand-authored minimal and malformed fixtures are for later tasks; do not author them here.
