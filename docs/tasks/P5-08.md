## Goal

Connectors glue to shapes, route straight or with one right-angle elbow,
and re-route when their shapes move — ours, not Visio's (ADR 0045).

## Interfaces

Implement `geom::routing::route` (signature fixed by P5-01),
`tools/connector::handle`, and `builtins/connector.rs` `TABLE` with:

- `connector.glue_begin` / `connector.glue_end` — args `connector`
  (Visio id), `target` (Visio id), optional `point` (the connection row
  `IX`; absent = outline glue); one undoable edit each.
- `connector.unglue` — args `connector`, `end` (`"begin"`/`"end"`).
- `connector.reroute_all` — no args; recomputes every glued connector's
  path on the active page (idempotent, not undoable).
- `connector.style` — arg `style` (`"straight"`/`"right_angle"`).

Also export from `builtins/connector.rs`:
`pub(crate) fn reroute_after_edit(ctx: &mut AppCtx, page: PageId)
-> Result<usize, CommandError>` — the hook the editing commands call
after a move/resize/rotate/delete/undo/redo (P5-04 wires the calls; if
its task already landed without them, add the two call lines to
`builtins/shape.rs` and `builtins/edit.rs` and note it in the Result).

The connector tool drags out a connector from a connection point or
shape to another, previewing the routed path on the overlay (ADR 0042)
and committing `insert.shape` (the connector master instance, P5-06's
command) plus the glue records.

## Result

### What changed

- **Routing** (`crates/geom/src/routing.rs`): `route` implements
  `Straight` (the two endpoints) and `RightAngle` (one deterministic
  elbow, horizontal first when `|dx| >= |dy|`). Degenerate and
  axis-aligned endpoints return exactly two points; a non-finite
  endpoint is `Error::InvalidArgument`. Unit tests plus the new
  `crates/geom/tests/routing.rs` (including a proptest) pin the rule.
- **Connector commands** (`crates/commands/src/builtins/connector.rs`):
  `connector.glue_begin`, `connector.glue_end`, `connector.unglue`,
  `connector.reroute_all` and `connector.style`, all in the registry.
  Glue records use the transcribed `VIS_BEGIN`/`VIS_END`,
  `VIS_CONNECTION_POINT + IX` and `VIS_WHOLE_SHAPE` constants; a new
  glue replaces the endpoint's old record; unglue removes only that end.
  `GlueEdit` restores the exact prior `Connect` records and the
  connector's prior geometry on undo. `connector.style` writes the
  ShapeSheet `ShapeRouteStyle` cell (1 = right angle, 2 = straight).
- **Re-route hook** (`reroute_after_edit`): drops records whose target
  is detached (one warning line), resolves connection-point and outline
  endpoints in page coordinates through the shape's parent chain, routes
  the connector's own `ShapeRouteStyle`, and writes the path through
  `Document::write_connector_path`. One pass covers every glued
  connector on the page; it is idempotent and not undoable. The hook is
  wired into `shape.move`/`resize`/`rotate`/`set.*`, `edit.delete`, and
  `edit.undo`/`edit.redo`. Deleting a target adds one warning line per
  glue the model detaches.
- **Connector tool** (`crates/ui/src/tools/connector.rs`): a drag
  previews the straight route on the overlay (`OverlayMark::
  ConnectorPreview`), prefers the nearest connection point within the
  8 px snap distance, falls back to alignment/grid snapping and outline
  glue, and commits `insert.shape` plus `connector.glue_begin` /
  `connector.glue_end` intents. Alt disables snapping/glue; a degenerate
  drag emits nothing.
- **Tests**: new `crates/commands/tests/connector.rs` builds a
  five-connector flow headlessly, moves a box and checks re-route plus
  undo/redo, verifies stale/detached record cleanup, cyclic/overflowing
  transforms, every geometry-row kind, unglue/style argument paths and
  the right-angle style. Unit tests cover the glue record shape and the
  edge cases of the handlers. Existing commands tests still pass.

### Deviations (closest correct version)

1. **`connector` is optional on glue/unglue.** The connector tool cannot
   know the Visio id of the shape `insert.shape` is about to create, so
   after an explicit id is absent the handlers use the selection anchor
   (P5-06 selects the new instance). Programmatic callers pass the id.
2. **`connector.style` applies to the selected shapes.** The interface
   names no connector argument; the selected shapes' `ShapeRouteStyle`
   is written, and the page re-routes after the edit.
3. **Unglue removes one endpoint record directly from `Page::connects`.**
   P5-02's `remove_connects` removes every record naming a shape, so it
   cannot unglue one end of a two-ended connector. The replacement keeps
   the record list positions for an exact undo.
4. **Hook calls were added to `builtins/view.rs` as well as `shape.rs`
   and `edit.rs`.** P5-04 had landed without the calls; undo/redo is in
   `view.rs`, so the acceptance criterion "including after undo and
   redo" required it.
5. **`ToolMachine` gained a `pub(crate) connector` state field** in
   `crates/ui/src/tools/mod.rs`. The P5-01 stub carried only the pointer
   state and every tool signature is fixed, so the connector drag state
   needed one field. The module's stub test now treats the connector
   tool as implemented.
6. **A re-route failure after a successful glue/unglue/style edit is
   ignored** (`let _ = reroute_after_edit`): the edit is already applied
   and must still return its undo step. The failure is not reachable
   with a well-formed model; the other editing commands record a warning
   line because their re-route runs in the same command.

### Open issues

1. The tool relies on P5-06's `insert.shape` selecting the new instance
   and on the "Basic Flowchart"/"Connector" master names (looked up in
   `stencils::catalog()`); if P5-06 changes either, the glue intents
   need an explicit connector id.
2. An unglued tool endpoint keeps the connector master's default
   diagonal geometry (there is no command to write an arbitrary path).
   Both-ends-glued is the documented Phase 5 flow.
3. `point` is treated as the zero-based `Connection` row `IX` and
   indexes the valid points returned by `Document::connection_points`.
   Sparse rows with skipped invalid points are not re-mapped.
4. Outline glue uses the nearest point on the target's page-aligned
   bounds, not its rotated outline (ADR 0045 says "bounds"). `PageId`
   renumbering during an open undo step is handled through `PageKey`.
5. A connector inside a group still writes its path through its own
   transform only (`write_connector_path`, P5-02), so a nested connector
   would need the parent transform; out of scope here.
6. `connector.reroute_all` bumps the change counter because it mutates
   the model, even when the written path is unchanged. It is idempotent
   in content, not in the counter.
