## Goal

1. **Errors reach the user (review major 2).** Every `Err` that
   `Shell::dispatch` gets back for an intent goes to `note_error` (one
   line, ADR 0021), not only `NotEnabled`. A cancelled dialog stays
   quiet. Both apps keep working as before.
2. **No dialog for programmatic sources (review major 3).**
   `apply_outcome` handles a payload (save dialog or download) only for
   `source.is_interactive()`; for other sources the outcome goes back
   to the caller untouched. Test both.
3. **Options through the registry (review major 4, ADR 0032
   amendment).** `show_options` no longer mutates `Settings`: it returns
   the `Intent`s for what the user changed (`view.ui_layout.*`,
   `view.toggle_grid`, `view.rulers`, `view.units` with its `units`
   argument), and the shell dispatches them. Remove the shell
   intercepts for `app.quit` and `app.office.center.options`: the shell
   handles `UiRequest::ShowOptions` and `UiRequest::Quit` from the
   registry instead.
4. **Review minors.**
   - 9: drop `UiError::NotImplemented` (no producer left). Leave the
     context menus parked; note it.
   - 10: remove `Shell::show(&Context)` (the panic footgun); tests and
     callers use `show_in`.
   - 11: a page whose raster fails is not retried every frame:
     remember the failed cache key and retry only when the key
     changes. Report the error once.
5. **Shortcut mismatch (P4-10).** When a chord mismatches a half-typed
   sequence and fires the held-back shorter completion, the
   mismatching chord is then tried as the start of a new sequence
   instead of being dropped. Update the test that pins the old
   behavior and the ADR 0036 wording is already compatible (say if
   not).
6. **Coverage gaps (P4-12 majors 1–4).**
   - the `NeedsInput` retry, pending and no-dialog arms in
     `shell.rs`;
   - every arm of the shortcut `key_token` table (a table-driven test
     that maps each egui key to its token and back);
   - the canvas raster failure path and its `UiError::Render` mapping;
   - the native picker bodies: if they cannot run headless, move the
     rfd calls behind the thinnest seam you can test, and say what is
     left untested.
7. Add `proptest` to `crates/ui` dev-dependencies and turn at least the
   settings-slot round trip (P4-10, `crates/ui/tests/settings_slot.rs`)
   into a `proptest` property.

### What changed

**Goal 1 — errors reach the user (review major 2).** Every
`CommandError` `Shell::dispatch` gets back for an intent goes through
`note_error` as one line (ADR 0021), whatever the kind — not only
`NotEnabled` (`crates/ui/src/shell.rs`, `dispatch_intent`; the
`note_disabled` helper is gone). The error still reaches the caller
untouched. A cancelled dialog stays quiet (its "Cancelled" outcome is
synthetic and records no warning). The apps are unchanged and work as
before: they already forwarded the outer `UiError`; the inner errors
are now recorded by the shell itself, so every caller benefits.
Tests: `a_failed_command_reaches_the_status_bar`,
`a_failed_retry_after_a_pick_reports_the_error` (the `Ask::Again`
error arm), the existing disabled-hint test.

**Goal 2 — no dialog for programmatic sources (review major 3).**
`apply_outcome` takes the `Source` and does its follow-up work
(`ui_request` windows, `Payload` save dialog/download) only for
`source.is_interactive()`; a programmatic outcome goes back to the
caller untouched — never a silent quit, never a dialog, never a
download (AGENTS.md section 6). The status line still shows the
outcome message (a shell label, not a dialog; the outcome itself is
returned in full). Tests: `a_payload_is_handed_to_the_picker`
(interactive) and `a_programmatic_payload_goes_back_untouched` /
`a_programmatic_quit_only_returns_the_request` (programmatic).

**Goal 3 — Options through the registry (review major 4, ADR 0032
amendment).** `settings::show_options` no longer mutates `Settings`:
it draws its rows over a draft copy and returns the `Intent`s for what
the user changed (`option_changes`): the layout radios dispatch
`view.ui_layout.panel_2016` / `view.ui_layout.panel_365`, the grid and
rulers checkboxes `view.toggle_grid` / `view.rulers`, the units combo
`view.units` with its `units` argument. The shell dispatches them like
any other control. The shell intercepts for `app.quit` and
`app.office.center.options` are gone (`SHELL_HANDLED`, `QUIT`,
`OPTIONS`, `menu_enabled` removed): both commands run through the
registry and the shell acts on `UiRequest::ShowOptions` /
`UiRequest::Quit` (interactive sources only). Tests: the
`option_changes` unit tests, `the_window_commands_run_through_the_registry`
(a stub row fails and the shell does not quit on its own), and the two
acceptance tests in `crates/ui/tests/phase4/interactions.rs`:
`switching_layouts_from_the_options_dialog_needs_no_restart` now also
pins that the radio's switch comes from the registry (the status line
shows the command's "Panel layout: Panel (365 data)", and the dialog writes
nothing itself) and the command bar switches on the next frame, and
`toggling_grid_in_options_changes_what_the_canvas_draws` counts the
grid lines one `canvas::show` frame paints before and after the
Options checkbox (N > 0, then 0, with `ViewState::show_grid` and the
settings default flipped by `view.toggle_grid`).

**Goal 4 — review minors.**
- 9: `UiError::NotImplemented` is dropped (no producer left). The
  context menus stay parked as instructed (`TabBar::show_context_menu`
  / `set_context_menu` are still never called by the shell).
- 10: `Shell::show(&Context)` is removed (the `Context::root_ui`
  panic footgun); the one test that used it now calls `show_in`
  through `root_ui` explicitly.
- 11: a page whose raster fails is not retried every frame: the cache
  remembers the failed key (document snapshot, page, zoom) and
  rasterizes again only when the key changes. The first failure is
  reported once (`UiError::Render`); later frames at the same key are
  quiet. Tests: `a_page_that_cannot_raster_reports_once_and_is_not_retried`
  (every key component retriggers), `a_successful_raster_clears_the_failed_key`.

**Goal 5 — shortcut mismatch (the P4-10 finding 2).** A chord that
mismatches a half-typed sequence fires the held-back shorter
completion and is then tried as the start of a new sequence instead of
being dropped. One chord can therefore complete two sequences:
`ShortcutMap::resolve` and `shortcuts::dispatch` return one intent per
completion, in order (`Vec<Intent>`). Two adjacent fixes in the same
trie: `reset` now drops a held-back completion that a longer completed
sequence superseded (it used to leak and fire on a later mismatch),
and `expire` takes the completion before the reset. Tests: the updated
`a_prefix_sequence_defers_and_fires_on_a_mismatch` (the mismatching
chord is bound now and both bindings fire; typing it again dispatches
it again), `a_mismatch_that_fires_a_held_back_completion_retries_the_chord`,
`a_mismatching_chord_can_start_a_new_sequence`,
`a_completed_longer_sequence_drops_the_held_back_completion`.
ADR 0036 check: the *wording* is compatible — "the map records the
chords typed so far and resets on any mismatch or after 2 seconds"
still holds (the buffer resets and the chord starts a new sequence;
the ADR never said the chord was dropped). The *sketched signature*
`resolve(…) -> Option<Intent>` is not: it now returns `Vec<Intent>`.
See Open issues 1.

**Goal 6 — coverage gaps (P4-12 majors 1–4).**
- The `NeedsInput` arms in `shell.rs`: retry (success and the
  re-dispatch error arm), `Pending` (an asynchronous pick in flight)
  and the no-dialog arm each have a test.
- The key-token table: `every_key_of_the_token_table_maps_to_its_token_and_back`
  is table-driven over every arm of `key_token` and `key_for_token`
  (84 forward rows including the shifted symbols, 83 backward rows),
  plus the uncovered-key arms.
- The canvas raster failure path: `render_errors_map_into_ui_errors`
  and the failing-raster tests above exercise
  `larrygram_render::Error` → `UiError::Render`.
- The native picker bodies: the rfd calls moved behind the thinnest
  testable seam (`picked_path`, `save_picked` in `crates/ui/src/dialogs.rs`),
  so the pick mapping, the ask-only rule, the write and its error all
  run headless (5 new tests). **Left untested:** the
  `rfd::FileDialog::pick_file` / `save_file` calls and `open_dialog`'s
  dialog configuration (title, filter, suggested path) — they need a
  real desktop session; `rfd::FileDialog` exposes no getters to
  assert on headless.

**Goal 7 — proptest.** `proptest = "1"` added to the `crates/ui`
dev-dependencies (the workspace convention) and the P4-10 settings
round-trip property in `crates/ui/tests/settings_slot.rs` is now a
proptest strategy over arbitrary `Settings` (hostile `recent_files`
included); the seeded LCG is gone.

**Master note — P4-15 open issue 4.** `Shell::dispatch_one` records
the active session's `DocumentSession::id` before the run and pushes
the `Outcome::edit` onto that session afterwards (the `with_undo`
way): a command that opens a document no longer leaves its edit on the
new document's stack. With no session before the run the edit lands on
the session the command opened (the `file.new`-will-be-undoable case);
a run whose session closed drops the edit with the existing warning.
Tests: `an_edit_lands_on_the_session_the_command_ran_against`,
`an_edit_lands_on_the_session_the_command_opened_first`.
