## Goal

Make the corpus render the way the files describe, not as open outlines in
default colours with dozens of warnings per page. Three fixes, each with
corpus tests.

### 1. Geometry row union

`Document::shape_geometry` returns the shape's own rows whenever it has
any. In the corpus, instances often carry only some rows of a `Geometry`
section (for example two `LineTo` rows at `IX` 2..3, every cell `F='Inh'`),
and the master holds the rest. Merge them: for each `Geometry` section
(matched by its `IX`), start from the master's rows, then apply the
instance's rows by row `IX` (an instance row overrides the cells it
defines; cells it does not define, or defines with `Inh`, come from the
master row). A row with `Del='1'` removes the inherited row. The same
applies to the section-level cells (`NoFill`, `NoLine`, `NoShow`,
`NoSnap`, `NoQuickDrag`). Apply it through every master rung the lookup
already walks. Record the rule as an ADR 0019 amendment.

### 2. Theme variant colours

Every `QuickStyle*Color` value in the corpus is 100 or above, or 200 or
above. Today these resolve to `UnresolvedTheme` and the hard default, so
pure `Themed` fills render as no fill. Find what the 100+ and 200+
encodings mean (the Quick Style cell pages on Microsoft Learn, [MS-VSDX]
on the theme part and its Visio extensions such as variation colour
schemes) and resolve them against the document theme. Read whatever the
theme part needs on the read side (`a:fmtScheme` fill, line and effect
lists if `QuickStyleFillMatrix` and friends are needed for the colour).
If a part of the encoding has no published meaning, say so and keep the
`UnresolvedTheme` warning for that part only. Record the rule as an ADR
0021 amendment and the sources in `docs/sources.md`.

### 3. Quiet documented defaults

The ShapeSheet table has no default values, so every cell a file omits
(`FlipX`, `Angle`, `LocPinX`, ...) records a `Missing` warning on each
read. Real pages produce dozens of warnings. A cell that is absent at
every rung and has a default documented on its ShapeSheet reference page
is not an error: resolve it to that default with no warning. Keep a
`Missing` warning only for a cell with no documented default, and keep
the error and kind-mismatch warnings as they are. Put the documented
defaults for the cells the renderer reads in one table in the model
(derived facts, with the source row in `docs/sources.md`). Do not change
`ui-spec/shapesheet.toml` or the extractor. Record the rule as an ADR 0021
amendment.

## Result

### What was built

**Fix 1 — the geometry row union** (`crates/model/src/geometry.rs`,
`lookup.rs`, `section.rs`; ADR 0019 amendment). `Document::shape_geometry`
returns the union of a shape's `Geometry` rows and its master chain's
rows, not "the shape's own rows whenever it has any". Per section
(matched by `IX`, else by position): the furthest rung's rows are the
base, each nearer rung applies its rows on top, a row overrides the
merged row it matches (by `IX` when both sides have one, else by
position; an `IX` mismatch never matches by position), a `Del` row
(`Row::is_deleted`, new) removes the merged row, an unmatched row inserts
in `IX` order, and `T` comes from the nearest rung that declares one.
Cells still resolve per cell through `resolve_row_cell`, so a row
overrides only the cells it defines; `Inh` and absent cells come from the
rung below. Section-level cells (`NoFill`, `NoLine`, `NoShow`, `NoSnap`,
`NoQuickDrag`) merge the same way through the lookup. Corpus evidence and
tests: `bgcolor.vsdx` shape 1 (the two `LineTo` rows at `IX` 2..3, all
`F='Inh'`, now draw the master's closed rectangle),
`testfile1.vsdx`/`testfile3`/`testfile4`/`testfile6` shapes 8, 11, 14.

**Fix 2 — theme variant colours and themed fill patterns**
(`crates/model/src/theme.rs`, `values.rs`, `crates/vsdx/src/read/theme.rs`;
ADR 0021 amendments). The theme part now maps `vt:variationClrSchemeLst`
(`Theme::variations`), the `bkgnd` extension (`Theme::background`) and
what a themed `FillPattern` needs from `a:fmtScheme` (`Theme::fill_kinds`,
`Theme::variation_styles`). `QuickStyle*Color` resolves per [MS-VSDX]'s
`QuickStyleFillColor` table: 0 `dk1`, 1 `lt1`, 2..7 `accent1..6`, 8 the
theme background, 100..106 `varColor1..7` of the variation colour scheme
the `VariationColorIndex` cell selects (65534 defers to the page sheet's
cell, [MS-VSDX]). The 200..206 family has **no published meaning**; the
corpus shows the same variation colours (`color-boxes.vsdx` shapes 68..74
cache those colours modulated by the line style matrix,
`tdf154379-QuickStyleFillMatrix.vsdx` shape 317 caches `varColor1`
unshaded), so 200+k resolves like 100+k and is flagged corpus-derived.
A themed `FillPattern` resolves through the fill style its
`QuickStyleFillMatrix` names ([MS-VSDX]): 1..6 the `a:fmtScheme`
`fillStyleLst` fills, 100..103 the `fillIdx` of the `vt:varStyle` of the
`VariationStyleIndex` scheme (1-based), mapped `noFill` 0, `solidFill` 1,
`gradFill` 25. Following the master note (added mid-task): `LinePattern`
resolves through `lnStyleLst` (`a:noFill` 0, solid 1), `LineWeight` from
the line's `a:ln/@w` width (EMU), and `FillForegndTrans`/`FillBkgndTrans`/
`LineColorTrans` from the style colour's `a:alpha` (transparency =
1 - alpha/100000). Where the theme cannot answer — including a dash
preset, which names no Visio `LinePattern` index — the fallback is the
**visible** value (`FillPattern` 1, `LinePattern` 1, `ShdwPattern` 0) and
for `LineWeight` the hairline default, each with `UnresolvedTheme`, never
0 for fill and line. The 7 `color-boxes.vsdx` fills and lines now render
in their theme variant colours.

**Fix 3 — quiet documented defaults** (`crates/model/src/defaults.rs`,
`values.rs`; ADR 0021 amendment). A cell absent at every rung with a
default documented on its ShapeSheet reference page resolves to that
default with no warning: `ferrogram_model::defaults` transcribes the
documented defaults of the cells the scene builder reads (`LocPinX`/Y and
the `Txt*` formulas flattened to one multiplication of `Width`/`Height`,
`TxtAngle` 0, the four text block margins 0.1 inch / `TopMargin` 4 point,
the five transparency cells 0%). A cell something defines but that caches
no value still warns; a cell with no documented default keeps its
`Missing` warning (the reference documents none for `FlipX`, `Angle`,
`ShapeShdwShow`, `FillPattern`, `Size`, ...).

Tests: 9 unit tests for the row union (override by `IX`, partial cell
override, `Del`, section-level cells, multi-rung chains), unit tests for
the theme slots, variation selection (own / 65534 / page / fallback),
fill-style matrices, documented defaults and the strict row matching;
corpus tests in `crates/vsdx/tests/read_mapping.rs` (the two acceptance
shapes, with the expected RGBs and the reasoning in comments) and
`crates/render/tests/build_scene.rs` (closed paths, themed fills in the
scene, the master-note acceptance (page 1 of `color-boxes.vsdx` has filled
and stroked shapes), and the quiet-defaults count across every corpus
page).

### Deviations

- `Document::shape_geometry` also changes two details the ADR 0019
  amendment records: a section's position now counts the same-named
  sections (it used to count all sections of the sheet), and row matching
  is strict (an `IX` mismatch never falls back to position). Both are
  what the union needs to agree with itself.
- New public items (additive; no signature changed, `crates/render`
  compiles unchanged): `ferrogram_model::defaults::{DocumentedDefault,
  documented_default}`, `Row::is_deleted`, `Document::page_of`,
  `ThemeVariation`, `ThemeVariationStyles`, `ThemeFillKind`, and four new
  public fields on `Theme` (`variations`, `background`, `fill_kinds`,
  `variation_styles`). `Theme::new` fills them; nothing constructs `Theme`
  as a literal outside the crate's tests.
- Formula defaults evaluate one multiplication from the named cell's
  cached value (0 when it has none), not a formula engine: Phase 6
  replaces it. The table flattens `TxtLocPinX = TxtWidth*0.5` chains.
- `Font`'s documented default is the font *number* 0 ("the default
  font"); it is not transcribed (the renderer would read the string "0"
  as a family name instead of falling back to the theme font).
- The master note asks for "a hairline default" for a `Themed`
  `LineWeight`; we substitute **0.7 point**, the value the `THEMEVAL`
  page documents for a theme-less document ("the function returns
  '0.7 pt.'"), instead of inventing a hairline measure. Say the word in
  review and we switch (0.5 point or 0.25 point are the usual hairline
  readings).

### Open issues

- **The style-matrix modulation of colours is not applied.** `CellReader`
  resolves the theme's own colour; Visio's cached snapshots show the
  colour after the `a:fmtScheme` `tint`/`shade` modulation (about 0.73
  per channel for `QuickStyleLineMatrix` 6; HSL luminance/saturation per
  [MS-VSDX] `ThemeCBV`). The exact transform goes to the screenshot pass.
- **Themed values that keep `UnresolvedTheme`**: `ShdwPattern` (the
  effect style list and its shadow tables are not mapped; the fallback 0
  draws no shadow), a dashed `LinePattern` (the `a:prstDash` presets name
  no Visio pattern index; the fallback 1 draws a solid line), themed
  gradient stop colours, the shadow and text transparencies, and
  `QuickStyle*Matrix` 0 (the root style sheet). A themed `gradFill`
  renders as the renderer's `FillForegnd` to `FillBkgnd` gradient: the
  `a:fmtScheme` gradient stops are not read.
- **`QuickStyleType` is ignored**: the effect scheme (`a:fmtScheme`) is
  always used, never the connector scheme (`fmtConnectorScheme`) that
  [MS-VSDX] documents for connector shapes.
- **Residual `Missing` warnings** for cells with no documented default
  (`ShapeShdwShow` is the loudest, 59 in the corpus sweep). Extending the
  table needs another source (a black-box observation pass) or the CLI
  filter of the P3-05 alternative. The quiet-defaults test counts them
  (currently about 300 across the corpus) and demands zero only for
  cells with a documented default.
- **Inherited row cells are the master's cached values** in the master's
  coordinate space: a resized instance whose own rows are all `Inh`
  (e.g. `bgcolor.vsdx`'s rectangles) draws the master's geometry at
  master coordinates. The instance's snapshots are not used (ADR 0013).
  Formula evaluation (Phase 6) fixes the scaling.
- **Row-union edges unobserved in the corpus**: a row re-added by a
  nearer rung after a `Del` may still take cells from a further rung's
  row of the same `IX`; an unmatched row inserts in `IX` order (our
  rule); a merged row without `IX` resolves by position per rung (every
  corpus `Geometry` row has an `IX`).
- **`GeometryPath` has no `NoSnap`/`NoQuickDrag` slots** (the union merges
  them and `Document::resolve` reads them); the scene builder does not
  need them yet. Add the slots when it does (a public struct change).
- **`ThemeIndex`/`ColorSchemeIndex`** (which theme part applies) still
  uses `themes[0]` (the P3-01 deferred item).
- Odd but harmless: the ShapeSheet table types `QuickStyle*Matrix`,
  `QuickStyle*Color` and `VariationColorIndex` as `Color`, so an absent
  one resolves to a colour hard default; the readers match on numbers and
  treat any other kind as absent.
