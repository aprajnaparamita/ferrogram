## Goal

Implement the three commands end to end through library calls, with our
own help text, stable JSON and the documented exit codes.

## Interfaces

Implements (signatures fixed by P3-01):

```rust
pub fn parse(args: impl Iterator<Item = OsString>) -> Result<Option<Command>, Usage>;
pub fn run(command: &Command) -> Result<i32, Error>;
pub fn main_from(args: impl Iterator<Item = OsString>) -> Result<i32, Error>;
```

`parse` uses `lexopt`; `Ok(None)` means `--help` was requested and usage
was written to stdout. `run` maps `Error` variants to the exit codes of
ADR 0026 (`exit::OK/USAGE/READ/RENDER/WARNINGS`). The `Command` enum is
the Phase 4 registry seam; do not change its shape. New public items need
doc comments.

## Acceptance criteria

- [ ] `inspect`, `render` and `export` implemented per ADR 0026: text and
      `--json` output for `inspect`, page selection (1-based), format from
      the extension or `--format`, `--scale`, `--background` for `render`,
      `--strict`.
- [ ] Our own `--help` and usage text (AGENTS.md section 4: our own
      descriptions); an unknown or missing argument prints usage to stderr
      and exits 1.
- [ ] Warnings print one line each to stderr and the run still exits 0;
      with `--strict` the run exits 4 (the output is still written unless
      rendering failed).
- [ ] Exit codes tested for: success, usage error, missing/unreadable

      without `--strict`.
- [ ] `inspect --json` output is tested with `insta` (stable keys); the
      warning count is included (ADR 0021).
- [ ] Programmatic entry points (`parse`, `run`, `main_from`) are unit
      tested; nothing writes to stdout except `inspect` and `--help`.
- [ ] `cargo xtask gate` green; `ferrogram-cli` coverage meets its 50%
      threshold and its 66.6 ratchet.

## Result

_Filled in by the worker at hand-off._

**Built** (2026-10-15, branch `agent/P3-09`):

- `apps/ferrogram-cli/src/cli.rs` keeps the P3-01 types and the three entry
  points; the implementation lives in `src/cli/parse.rs` (lexopt parsing,
  our own help text in `USAGE_TEXT`), `src/cli/exec.rs` (execution, warning
  and error reporting, exit codes) and `src/cli/inspect.rs` (the summary and
  its text/JSON forms).
- `inspect`, `render` and `export` per ADR 0026: text and `--json` output,
  `--page` selection (1-based), format from the extension or `--format`,
  `--scale` (pixels per inch, default 96), `--background #RRGGBB|none` for
  `render`, `--strict`. `export` writes `page-<N>.<ext>` in document order
  and creates the output directory.
- Exit codes via `Error::exit_code` (`exit::OK/USAGE/READ/RENDER/WARNINGS`).
  `run` maps a failure to its code and prints `error: <message>` to stderr;
  `Err` is returned only when that report itself cannot be written.
  Warnings print one line each to stderr (ADR 0021), e.g. `warning: shape 1
  PinX: wrong kind, using 0`; the run still exits 0, and 4 with `--strict`
  after the output is written.
- `inspect` builds each summarised page's scene (so the warning count is the
  real rendering count) and reports kind, per-page name/size/shapes/warnings
  and the master, style and theme counts. The JSON keys are the serde_json
  map order (sorted, stable), tested with `insta` inline snapshots.

**Deviations from the stubs** (closest correct version, per the implementer
role):

- `Render` gained `background: Option<Background>` and a public `Background`
  enum (`Transparent` | `Color(Rgba)`): the stubs predate the `--background`
  option of ADR 0026 and had nowhere to put it. The `Command` enum keeps its
  three-variant shape as the Phase 4 registry seam.
- `Error::NotImplemented` is gone (the stub marker). `Error::exit_code` is
  new (public, documented).
- `export` without `--format` defaults to PNG (the out path is a directory,
  so no extension names the format).
- `--page 0` is a usage error (exit 1); a page number the document does not
  have is an input error (exit 2). A render/export build failure is exit 3.
- `inspect --json` prints pretty JSON (2-space) with a trailing newline.
- `--strict` is accepted by `render` and `export` only (ADR 0026 lists it
  there); `inspect` warns and always exits 0.

**New dependencies**: `insta` (dev-dependency, MIT OR Apache-2.0) for the
`inspect` output snapshots. `lexopt` and `serde_json` were already declared
by P3-01. `Cargo.lock` grows insta and its tree; the master resolves lock
conflicts.

**Tests**: 53 unit tests (`cargo test -p ferrogram-cli`), covering the
programmatic entry points, every parser error path, the exit codes 0
(success), 1 (usage error), 2 (missing file, unparsable package, missing
page), 3 (unwritable output) and 4 (warnings with `--strict`, output still
written) and 0 without it, `insta` snapshots of the text and JSON summaries
(stable keys, warning count included), and that `render`/`export` write
nothing to stdout.

**Gate**: `cargo xtask gate` green (codegen, fmt, clippy, test, doc,
coverage, deny, layers, wasm, fuzz). `ferrogram-cli` line coverage is
92.6% (threshold 50, ratchet 66.6); `main.rs` (0%) is the untested binary
shell, everything else is 89–98%.

**Open issues**:

- Without `--background`, a render is transparent, because
  `Scene::background` is always `None` (the P3-05 note). Visio shows a white
  page; the builder (or a CLI default of white) should decide this, not the
  CLI invent one.
- `main.rs` keeps its `Err` branch as a safety net; handled failures already
  become exit codes inside `run`.
- `inspect` counts shapes as page shapes plus group sub-shapes (walked once,
  cycle-safe); a "shape count" that matches Visio's status bar may count
  differently.
- A stale page number for `render --page N` and an empty document for
  `export` share the input-error code with unreadable files; split them if a
  caller (Phase 4 registry) needs to tell them apart.
