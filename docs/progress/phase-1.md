Code and tools:

- **`crates/ui-spec`** (P1-06, P1-06b, P1-14): runtime loader. It validates against the embedded schema, decodes into typed models and cross-checks references:
  - every Fluent id in `commands.yaml` appears in at least one layout;
  - every control command and shortcut command is a known command id;
  - command ids are unique.

  Also: `CommandLookup`, `LayoutSets::get`, validated `CommandId::parse` / `FluentId::parse`, and `Serialize` on all model types. It has a fuzz target (`crates/ui-spec/fuzz`).
- **xtask:**
  - `extract [--check]` (P1-02 skeleton; extractors from P1-03 to P1-05);
  - `corpus`, which fetches the third-party test files listed in `corpus/manifest.toml` and checks their sha256 (P1-12, ADR 0005);
  - `oracle`, which builds the libvisio CLI tools outside the repo as a dev-only test oracle (P1-07, ADR 0010).
- **Sources and provenance** (P1-01): `docs/sources.md`, `corpus/PROVENANCE.md`, `corpus/manifest.toml` (20 libvisio test files, pinned commit).
- **`.gitattributes`:** generated outputs and fixtures always check out with LF line endings.

## Reviewer findings and resolution

Three audits ran in parallel after the test-engineer pass (P1-08). Full reports are in `docs/reviews/`.

| Report | Verdict | Blocker / major / minor | Resolution |
|---|---|---|---|
| [Code review](../reviews/phase-1-reviewer.md) (P1-09) | approve with fixes | 0 / 2 / 8 | P1-13 (xtask) and P1-14 (ui-spec) |

| [Clean-room](../reviews/phase-1-cleanroom.md) (P1-11) | pass with findings | 0 / 1 / 4 | history rewrite (master), P1-13 |

Majors, all resolved:
- **Wrong file in xtask schema errors; every read error reported as "missing":** fixed in P1-13, with regression tests.
- **Corpus fetcher network and checksum-failure paths untested:** P1-13 added tests against a local HTTP listener, plus the bad-download cleanup arms.
- **Verbatim support-page text in git history:** P1-04's Result quoted 151 action descriptions; I removed them at merge. With the user's approval, `git filter-repo` replaced that one blob in history. The final tree is unchanged.

Minors resolved in P1-13 and P1-14:
- placeholder error paths, and strict parsing of `Policy ID`;
- stale-output detection and CRLF handling in `--check`;
- unique temp dirs in tests;
- removal of duplicated extractor code;
- the ui-spec API gaps;
- hash keys instead of quoted phrases in the shortcut extractor;
- paraphrased test fixtures, and our own shortcut section names.

Decided by the master (recorded in `docs/STATUS.md`):
- **A Fluent id is not unique within a layout.** The same control appears in several places, so a placement is identified by its path. Command ids are unique and enforced.
- **Remaining items deferred to later phases:** listed below.

Fixes I made at merge during the phase:
- **Schema:** `command: null` and empty tables are now allowed.
- **Inventory:** OPC plumbing parts are marked `supported`, because the Phase 2 writer must rewrite them.
- **Align ids:** they use the ADR 0006 form (`arrange.align.left`).

  - When a remote exists, CI should also build the libvisio oracle on Linux and macOS.

- **Repeated controls:** some controls repeat inside one container (`TabSave` x9 in one backstage tab). Review this when Phase 4 builds the command bar.
