## Goal

Every shortcut in `shortcuts.yaml` dispatches its command through the
registry, multi-chord sequences work, scopes filter by focus, and egui's
own text-editing keys are never stolen.

## Interfaces

```rust
// crates/ui/src/shortcuts.rs (stubs filled in)
pub struct KeyChord { pub key: String, pub modifiers: Vec<String> }
pub struct ShortcutMap { /* chord-sequence trie -> CommandId */ }
impl ShortcutMap {
    pub fn from_shortcuts(&ui_spec::Shortcuts) -> Result<ShortcutMap, UiError>;
    pub fn resolve(&mut self, &[KeyChord]) -> Result<Option<Intent>, UiError>;
    pub fn pending(&self) -> bool;
    pub fn len(&self) -> usize;
    pub fn is_empty(&self) -> bool;
}
pub fn dispatch(&egui::Context, &mut ShortcutMap, &AppCtx, ShortcutScope)
    -> Result<Option<Intent>, UiError>;
```

Rules (ADR 0036): chords normalize from egui key events to the
`shortcuts.yaml` tokens (`Ctrl`, `Shift`, `Alt`, `A`, `F1`, ...); the
token table covers every token the file uses and an unknown token is a
load-time `UiError`. Multi-chord sequences are stateful (2 second
timeout, reset on mismatch). Scopes: `Global` always; `Page` when the
canvas has focus; `Text` defers to egui when a text edit has focus;
`Selection` is never true in Phase 4 (no selection); `Ribbon` when the
ribbon has focus; `Window` always in the single-window shell. Duplicate
sequences: first in file order wins, one warning recorded at load
(return the warnings in `UiError`? No: `from_shortcuts` returns the map;
record conflicts as `Vec<String>` reachable through
`ShortcutMap::conflicts()` — extend the struct with a public accessor).
A matched chord is consumed even when the command is disabled (the shell
shows the reason in the status bar).

## Acceptance criteria

- [ ] `ShortcutMap::from_shortcuts` loads every entry of the committed
      `shortcuts.yaml`; a token-coverage test asserts the egui mapping
      table covers every token in the file.
- [ ] Dispatch tests (plain `egui::Context`, synthesized key events):
      one single-chord shortcut per scope resolves to the right `Intent`;
      one multi-chord sequence resolves after its chords; a half-typed
      sequence sets `pending()` and times out.
- [ ] Scope filtering: a `Text` shortcut does not fire when no text edit
      has focus; `Selection` never fires in Phase 4.
- [ ] Conflict rule: a duplicated sequence resolves first-wins with one
      recorded conflict (test with a synthetic `Shortcuts`).
- [ ] `crates/ui` line coverage ≥ 50%.
- [ ] `cargo xtask gate` green in the worktree.
