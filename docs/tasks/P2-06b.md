## Decisions (from the master; record them in the ADR amendments)

1. **Section-level cells.** Add `Section::cells: Vec<Cell>` for `Cell`
   children of a `Section` that sit outside its rows (`Geometry`'s `NoFill`,
   `NoLine`, `NoShow`, `NoSnap`, `NoQuickDrag`). The reader maps them there
   instead of `Section::preserved`. `CellLookup` finds them: a cell name
   looked up in a section matches section-level cells before row cells.
2. **A master has several top-level shapes.** Replace `Master::shape:
   Option<ShapeId>` with `Master::shapes: Vec<ShapeId>`, in document order.
   The master rung of the lookup (the sub-shape position rule of ADR 0013)
   matches an instance against the master's first shape when the master has
   exactly one, and by position otherwise; document the rule in ADR 0013.
3. **Style references are Visio style IDs.** `.vsdx` writes `LineStyle="7"`,
   the style's `ID`.
   - `Shape::line_style`, `fill_style` and `text_style` become
     `Option<u32>` (the Visio style `ID`), parsed by the reader. A value
     that is not an unsigned integer is `Error::InvalidPackage`, the same
     rule P2-06 applies to other integers.
   - `Style` gets the same three fields (`line_style`, `fill_style`,
     `text_style`); they are a style's own inheritance chain in `.vsdx`.
     Remove `Style::base_style`.
   - Add `Document::style_by_visio_id(u32) -> Option<&Style>`. The style
     rung follows the chain for the cell's kind: a `Line Format` cell
     follows `line_style` links, `Fill Format` follows `fill_style`,
     `Character`/`Paragraph`/text cells follow `text_style`. The existing
     visited-set cycle cut applies. `style_by_name` stays for callers that
     have a name.
   - Add a test on a corpus file that a shape with `LineStyle` set and no
     local `LineWeight` resolves `LineWeight` from its style (`via` names
     the style).
4. **`Connect` keeps unmapped content.** Add `Connect::preserved:
   Preserved`; the reader stops falling back to the page's `Preserved`.
5. **Canonical angle unit is radians everywhere.** `ferrogram_geom::Angle`
   stores radians, `UnitKind::Angle` converts to radians, and every test and
   doc comment follows. This matches the file (P2-06 evidence) and ADR 0011.
   `lookup::parse_default_value` then produces radians with no change of its
   own; add a test that proves it.

Update every reader site and every existing test that the type changes
touch. Keep `crates/vsdx/tests/read_corpus.rs` green; its cell-count
identity must still hold, with section-level cells now counted as modeled.

### What was built

- **Decision 1, section-level cells.** `Section::cells: Vec<Cell>` holds the
  `Cell` children of a `Section` element that sit outside its rows
  (`Geometry`'s `NoFill`, `NoLine`, `NoShow`, `NoSnap`, `NoQuickDrag`).
  `read::sheet::map_section` maps them there instead of
  `Section::preserved`, and `lookup::sheet_cell` matches a section's own
  cells before its row cells (after the sheet's direct cells). The corpus
  cell-count identity still holds and now counts them as modeled.
- **Decision 2, several master shapes.** `Master::shapes: Vec<ShapeId>`
  replaces `Master::shape`; the reader keeps every top-level shape of a
  master part in document order (the corpus has masters with up to 33). The
  master rung matches an instance against the master's only shape when the
  list has exactly one, and by position otherwise: the instance root's
  position among its siblings (a parent group's children, or the page's
  top-level shapes), reused at every rung of a chained master reference. An
  out-of-range or unknown position degrades to the master's first shape.
  The rule is recorded in ADR 0013.
- **Decision 3, style references by Visio ID.** `Shape::line_style`,
  `fill_style` and `text_style` are `Option<u32>`, the `ID` of the
  stylesheet row the reference names; `Style` has the same three links (its
  own chain in `.vsdx`) plus its own `visio_id`, and `Style::base_style` is
  gone (`take_base_style` deleted; a `Style` cell is an ordinary cell). The
  reader parses the references as unsigned integers
  (`Error::InvalidPackage` otherwise, naming the part and the attribute,
  the same rule P2-06 applies to other integers). `Document::style_by_visio_id`
  finds a row by its ID; `style_by_name` stays. The style rung of the
  lookup follows the link of the cell's kind (`Line Format` -> `line_style`,
  `Fill Format` -> `fill_style`, `Character`/`Paragraph` -> `text_style`) at
  every chain step, with the existing visited-set cycle cut. The corpus test
  `corpus_lineweight_resolves_from_the_shape_style` proves it on
  `blue-box.vsdx`: the master's content shape carries `LineStyle` and no
  local `LineWeight`, and `LineWeight` resolves from the referenced style
  with `via == [Local, Style(..)]`.
- **Decision 4, `Connect` preservation.** `Connect::preserved: Preserved`
  holds the attributes and children of a `Connect` element the model does
  not hold; `map_connects` no longer falls back to the page's `Preserved`.
  A `Connect` with text, a comment or a PI is kept verbatim like a cell or
  a row; the `Connects` wrapper's own attributes follow the wrapper's owner
  (the page), matching the `Shapes` rule.
- **Decision 5, radians everywhere.** `ferrogram_geom::Angle` stores
  radians (`from_radians` stores as written), `UnitKind::Angle` converts to
  radians (`Unit::Radians` factor 1, `Unit::Degrees` factor `pi/180`), and
  every test and doc comment follows, including the one-line crate doc in
  `crates/geom/src/lib.rs`. `lookup::parse_default_value` is unchanged and
  `parse_default_angle_values_are_radians` proves an angle default now
  comes out in radians (a `Degrees` table default parses to `pi/2`).

### Deviations from the task text

- **`Style::visio_id: u32` is a new field.** `style_by_visio_id(u32)` needs

- **`Connect` drops its `Eq` derive**: `Preserved` compares with

  the canonical angle unit only.
- **`crates/vsdx/src/write/` is untouched** and still compiles (it only
  holds a stub importing `Document`).

### Open issues

1. **`F='Inh'` is not recognized as the inherit marker.** Real files write
   `F='Inh'` on cells that resolve through master, style or default
   inheritance (`blue-box.vsdx`'s `LineWeight` carries a cached value and
   `Inh`); `lookup::defines` still counts any formula as defining, so such
   a cell resolves `Local` and the style rung never runs for it. The
   decision-3 corpus test uses a shape without the cell at all. Treating
   `Inh` as "does not define" (and keeping its cached value in `Preserved`
   or as a hint) needs a master decision; do it before Phase 3 rendering,
   or inheritance on file-loaded shapes stays wrong for these cells.
2. **`style_by_visio_id` returns the first row with the ID.** Duplicate
   stylesheet `ID`s (invalid but readable) resolve to the first; the rest
   stay reachable only by list position. Same first-wins rule as
   `style_by_name` and `master_by_name_u`.
3. **A chained master rung reuses the instance's sibling position.** When a
   master's content shape at position *i* is itself an instance of a master
   with several shapes, the next rung matches position *i* again. No corpus
   file has such a chain (every chained content shape is the master's only
   shape); revisit if one appears.
4. The `Preserved` position question (P2-06 open issue 1) and
   `CellValue::List` (its issue 8) are untouched here; they belong to the
   writer and the formula engine.

   symlinks to `/Users/dara/ferrogram/corpus` (gitignored real directories
