### What changed

- `crates/geom/src/curve.rs`: `Curve::to_cubics` implemented for every
  curve kind of ADR 0022, plus `Cubic::eval`.
  - `Arc`: exact bow construction (radius `bow/2 + chord²/(8·bow)`,
    centre `apex - normal·radius_signed`), then arc splitting into at most
    90° pieces with the standard tangential cubic. Per-piece radial error
    bound `2e-5 · sweep⁶ · radius` (measured constant 1.82e-5, verified
    numerically against the exact circle); the piece count follows from
    the tolerance and is capped at 4096.
  - `EllipticalArc`: the three points and the major-axis angle fit an
    ellipse by solving for the centre in the major-axis frame (two linear
    equations from equal transformed radii); the arc flattens on the
    pre-image circle and the pieces map back affinely, so the error is
    bounded by the same formula with the larger semi-axis as the radius.
  - `Quad`, `Cubic`, `Polyline`: exact (quad to one cubic, cubic as is,
    polyline to straight segments).
  - `Nurbs`, `Spline`: de Boor evaluation on homogeneous control points,
    splitting at every distinct knot and bisecting each span until the
    chord deviation of 15 interior samples is within the tolerance
    (depth cap 10, output cap 4096 segments). Emits straight chords, per
    the ADR 0022 wording "until the chord deviation is below the
    tolerance".
  - Degenerate input (zero chord, `bow = 0`, `ratio <= 0`, wrong knot
    count, degree 0 or > 25, too few control points, unsorted knots, a
    knot run longer than `degree + 1`, non-positive or non-finite
    weights, overflowing products, non-finite values) degrades to the
    straight chord or to nothing; no panics, no errors.
- `crates/geom/src/path.rs`: `Path::bounds` (bounding box of the control
  points, `None` when the path holds no points).
- `crates/geom/src/error.rs`: `Error::NotImplemented` removed from the
  crate.
- `crates/geom/tests/curve_flattening_properties.rs`: proptest properties
  — arc flattening stays within the tolerance of its exact circle (random
  starts, bows, tolerances), and every curve kind converts on random
  bounded input without panicking and with finite output only.

Unit tests cover every curve kind (arc with positive, negative and zero
bow; elliptical arc with and without angle/ratio semantics and against
known ellipses; NURBS and spline with known control points: quadratic and
rational quadratic Bézier, degree-1 polyline) and every degrade path.

### Deviations and decisions

- **Knot vector semantics** (needs P3-05 confirmation): Visio stores one
  knot per control point plus a final knot (`n + 1` values; `SplineStart`'s
  `B`, `A`, each `SplineKnot`'s `A`, then `C`). The full knot vector is
  that list padded at the end with `degree` copies of the last knot, so
  the curve runs over `knots[d] ..= knot_last` and ends on its last
  control point. This matches libvisio's "fill in end knots" reading of
  the same data and makes a clamped degree-3 freeform a plain cubic
  Bézier; no corpus file contains `NURBSTo`/`SplineStart` rows, so a
  Visio black-box check is still open.
- A knot run longer than `degree + 1` degrades to the chord: the basis
  vanishes there and the de Boor denominators would be zero.
- `Nurbs::x_type`/`y_type` are informational: `to_cubics` has no size to
  scale fractions with, so the caller must resolve them first (documented
  on the struct).
- Weights must be positive and finite, or the curve degrades to the
  chord (the rational denominator can cross zero otherwise).
- `to_cubics` always returns `Ok` today; the `Result` is the interface
  fixed by P3-01 and is kept.
- A tolerance of `0`, negative or `NaN` is treated as `1e-9` inch; an
  infinite tolerance asks for one piece per 90 degrees.
- No new dependencies.
