## Goal

derived from the registry and gate-checked for freshness.

## Interfaces

Parity (ADR 0037):

```
cargo xtask parity            # regenerate docs/parity/controls.md
cargo xtask parity --check    # fail when the committed file differs
```

`xtask/src/extract/parity.rs` derives each control's status:
`implemented` when the control's `CommandId` (its `command` link, else
its `commands.yaml` entry) resolves in `larrygram_commands::builtins::registry()`
to `CommandStatus::Implemented`; `out-of-scope` when the Fluent id is in
`ui-spec/out-of-scope.txt`; else `stub`. `xtask/src/gate.rs` adds the
`parity` step after `codegen` (in `STEPS` and `run_step`).

Tests (`egui_kittest::Harness` plus plain `egui::Context` where enough):

1. `apps/larrygram/tests/open_corpus.rs` — the exit criterion. For each
   corpus `.vsdx`: `file.open` through `builtins::registry()` in a
   `Shell`, render one frame, assert `Ok`, assert the canvas raster is
   non-blank and matches `render::render_raster` of the same page within
   the ADR 0027 metric. `#[ignore = "needs corpus"]` unless
   `LARRYGRAM_REQUIRE_CORPUS=1`.
2. `crates/ui/tests/phase4/tab_bar.rs` — placement completeness for both
   layouts (extend P4-04's snapshots if they cover it; do not duplicate).
3. `crates/ui/tests/phase4/layout_switch.rs` — 2016 -> 365 without a
   restart (same `Context` and `AppCtx`), per ADR 0032.
4. `crates/ui/tests/phase4/enabled_state.rs` — stub vs implemented vs
   `Enabled::no(reason)` rendering and tooltips (ADR 0031).
5. `crates/ui/tests/phase4/file_flow.rs` — `NeedsInput` -> `FilePicker`
   test double -> re-dispatch with `path`/`data: Bytes` (ADR 0036).
6. `crates/commands/tests/headless.rs` — every registered command runs
   with `Source::Test` (extend P4-02's tests if present).

### Deviations

- **Status precedence:** `out-of-scope` wins over `implemented` (the
  task's clause order suggests the reverse). The extract fixture
  `check_seeds_the_out_of_scope_input` pins `FileSave` as
  `out-of-scope` while `file.save` is implemented, and the list's
  meaning is "the alpha does not implement that control". Unit-tested
  both ways (`out_of_scope_beats_an_implemented_command`,
  `flipping_one_handler_to_stub_flips_its_rows`).
- **`crates/ui/tests/phase4/*.rs` are modules of one test target**
  (`tests/phase4/main.rs`): cargo does not auto-discover
  `tests/phase4/tab_bar.rs` as its own target, and `crates/ui/Cargo.toml`
  is P4-03's file. Run with `cargo test -p larrygram-ui --test phase4`.
- **`open_corpus` self-skips without the corpus instead of
  `#[ignore = "needs corpus"]`:** with `#[ignore]`, the acceptance
  command `LARRYGRAM_REQUIRE_CORPUS=1 cargo test -p larrygram --test
  open_corpus` would run nothing. The Phase 3 convention
  (`crates/render/tests/common`) makes the run mandatory when the env
  var is set and skippable otherwise.
- **Per-file `skip_reason`s** (ADR 0037): `recursion-cycle.vsdx` has no
  page part; `dwg.vsdx`, `fdo86664.vsdx`, `tab-short-prefix.vsdx` and
  `testfile5.vsdx` rasterize blank (see open issue 2). The open, frame
  and raster-match assertions still run for those files; only the
  non-blank check skips.
- **The raster read:** `Shell` keeps its `CanvasCache` private, so the
  raster assertions run one `canvas::show` frame with the test's own
  cache over the same document (open issue 3).
