## Goal

One working registry that the CLI dispatches through. Register the
Phase 4 command set over its `commands.yaml` stubs, implement app state
mutation in the file and view commands, implement the undo stack, and
move `ferrogram-cli` onto the registry.

## Interfaces

You implement (bodies only; signatures are fixed by P4-01 stubs):

```rust
// crates/commands (already stubbed; fill in)
Registry::register(&mut self, Box<dyn Command>) -> Result<(), RegistryError>
Registry::from_mappings(&ui_spec::Commands) -> Result<Registry, RegistryError>
Registry::execute(&self, &CommandId, &mut AppCtx, Invocation) -> Result<Outcome, CommandError>
UndoStack::push/undo/redo                       // ADR 0028 semantics
builtins::registry() -> Result<Registry, RegistryError>
```

`builtins::registry` registers one real `Command` per id in this set
(argument names are the contract, ADR 0028):

| id | args | behaviour |
|---|---|---|
| `file.new` | — | empty `Document` session, becomes active |
| `file.open` | `path` (else `NeedsInput::Path{OpenFile}`; wasm: `name` + `data: Bytes`, see below) | `read_document`, new session, becomes active |
| `file.save` | — (uses `DocumentSession::path`; else `NeedsInput::Path{SaveFile}`) | `write_document`, clears `dirty` |
| `file.save_as` | `path` (else `NeedsInput::Path{SaveFile}`) | as `file.save`, then sets `path` |
| `file.close` | — | closes the active session; unsaved → `Outcome::ui_request = ConfirmClose` on interactive sources only |
| `file.inspect` | `page` optional | ADR 0026 `inspect` output as `Outcome::message` summary |
| `file.render` | `path`, `out`, `page`, `format`, `scale`, `background`, `strict` | ADR 0026 `render` |
| `file.export` | `path`, `out`, `format`, `scale`, `strict` | ADR 0026 `export` |
| `edit.undo`, `edit.redo` | — | `UndoStack::undo`/`redo`; disabled with reason when empty |
| `view.zoom.in`, `view.zoom.out` | — | `ViewState::zoom` clamped to [0.05, 40] |
| `view.zoom.fit` (ours) | — | zoom so the active page fits the canvas rect passed as `Args` `width`/`height` in points |
| `view.toggle_grid`, `view.rulers` | — | toggle `ViewState::show_grid` / `show_rulers` |
| `view.ui_layout.visio_2016`, `view.ui_layout.visio_365` (ours) | — | set `Settings::ui_layout` (ADR 0032) |
| `page.next`, `page.previous` (ours) | — | move `DocumentSession::active_page`, wrap |
| `help.about` (ours) | — | `Outcome::ui_request = ShowAbout` |

**Binary payloads (wasm upload/download, ADR 0036):** extend the
`ArgValue` enum with `Bytes(Vec<u8>)` and `Outcome` with
`payload: Option<Payload>` where

```rust
pub enum Payload { Bytes { name: String, data: Vec<u8> } }
```

(both enums/structs are yours to extend; keep them `#[non_exhaustive]`).
Then `file.open` accepts `path` **or** `name` + `data: Bytes` (the web
upload case, `DocumentSession::path` stays `None`), and `file.save` /
`file.save_as`, when the session has no `path`, return the serialized
package in `Outcome::payload` for the web app to download instead of
writing to disk. No base64, no stringly bytes.

Extractors: add a static "our own commands" list in
`xtask/src/extract/commands.rs` (ADR 0006 amendment) emitting
`file.inspect`, `file.render`, `file.export`, `app.quit`, `page.next`,
`page.previous`, `view.zoom.fit`, `view.ui_layout.visio_2016`,
`view.ui_layout.visio_365`, `help.about` with `fluent_ids: []` and
`mapping_confidence: unknown`, then re-run `cargo xtask extract` and
commit the regenerated YAML. Add Fluent→command mapping rules (in
`fluent.rs`) for the controls your commands cover, e.g.
`ShowRulerVisio` → `view.rulers`, `ShowGrid` → `view.toggle_grid`,
`ZoomFitToWindowVisio` → `view.zoom.fit`, `FileExit`-family →
`app.quit` (verify each id against the layout YAML first).

CLI move (ADR 0026): `run` builds `builtins::registry()` + `AppCtx`,
maps each `cli::Command` variant to its id and `Args` (`Source::Cli`),
and keeps the exact stdout/stderr and exit codes. `ferrogram-cli`
gains `ferrogram-commands` as a dependency.

### Deviations (interfaces)

- The task table lists only `page` for `file.inspect`; the ADR 0026
  flags need `path` and `json` too, so `file.inspect` takes `path`
  (falling back to the open document), `page` and `json`.
- `file.close` takes an optional `confirm` flag: unsaved work on an
  interactive source returns `Outcome::ui_request = ConfirmClose`
  without closing, and the caller answers by dispatching again with
  `confirm: true` (otherwise the confirm loop would never end).
- `Outcome` gains `payload: Option<Payload>` (as specified) and
  `warnings: Vec<String>` (the CLI must print every warning line
  exactly and `AppCtx::warnings` is a capped ring). `ArgValue` gains
  `Bytes(Vec<u8>)`; `Args::bytes` reads it. Both enums are
  `#[non_exhaustive]`.
- `DocumentSession` gains `preserve: Option<ferrogram_vsdx::Package>`
  (ADR 0029 extension) plus `with_preserve`: `write_document` patches
  the source package (ADR 0018), so a save needs what the document was
  read from. `UndoStack::undo`/`redo` take the stack out of the session
  for the call (the P4-01 signatures need `&mut AppCtx` while the stack
  lives inside it) and put it back.
- `RegistryError` loses the P4-01 `NotImplemented` variant and gains
  `BadMapping` (a broken embedded mapping table); `CommandError` loses
  `NotImplemented` (ADR 0028's variant list is the contract).
- `file.save` / `file.save_as` with no write target: per the table and
  ADR 0036 they return `NeedsInput::Path { SaveFile }` (desktop); per
  the payload paragraph the wasm build returns the serialized package
  in `Outcome::payload`. Reconciled with `cfg(target_arch = "wasm32")`;
  the wasm branch compiles in the gate but has no desktop test.
- Extractor bindings that the extracted data cannot express are skipped
  at extract time (the extractor tests run over a fixture tree without
  the real control names); the real data is pinned by the
  `real_fluent_command_bindings_apply` test (committed YAML only, no
  `reference/` needed).
- `mapping_confidence`: a binding onto a `visuicmd` row counts
  `inferred` (a hand pairing of the two names, not a name match); a row
  without a constant stays `unknown`, so `view.zoom.fit` (which gains
  `ZoomFitToWindowVisio`) stays `unknown`. The our-own rows carry
  `fluent_ids: []` except `view.zoom.fit`.
- Out of lane, for a green gate: `crates/ui-spec/tests/committed.rs`
  command-count pin 935 -> 943 (numbers only, with a comment).

### Open issues

- `Settings::recent_files` is not updated by `file.open` (no rule was
  given; needs a cap and ordering decision).
- On a failed `file.render`/`file.export`, warnings recorded before the
  failure print from `AppCtx::warnings` (the ring caps at 200); the
  success paths are exact via `Outcome::warnings`.
- `view.zoom.fit` reads the page's cached `PageWidth`/`PageHeight` with
  the renderer's per-axis fallback (8.5 x 11 in) instead of asking the
  renderer; the two rules must stay in step.
- A wasm `file.save` that receives a `path` argument would attempt
  `std::fs::write` and fail at runtime; the web app must call `save`
  without `path`.
- `app.quit` is in the data (and has no Fluent binding: there is no
  exit control in either layout) but is not in the Phase 4 table, so it
  stays a stub; the shell quits itself (P4-03).
- `file.render`/`file.export` carry `strict` for the ADR 0026 contract
  but the warnings exit code is decided by the CLI dispatcher.
- The `view.zoom.in`/`view.zoom.out` step factor (1.25) and the
  `view.zoom.fit` clamp (the same [0.05, 40]) are ours; adjust when the
  screenshot pass compares zoom behaviour with Visio.
