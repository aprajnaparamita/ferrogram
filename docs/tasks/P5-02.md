## Note from the master

- ADR 0038 rule 3: `scale_geometry` always materialises the row union into the instance's own `Geometry` section before scaling. A resized instance therefore draws at its new size even when the master's rows use formulas such as `Width*0.5`. The ADR's sentence about such masters "degrading to master coordinates" covers only instances that were never resized. Test it with one of our own P4-06 masters.

### Semantics the consumers (P5-04..P5-09) must know

- `write_cell` also refreshes the cells the documented-defaults table
  derives from the written cell by one multiplication (ADR 0038 rule 2:
  `Width` updates `LocPinX`, `TxtPinX`, `TxtLocPinX`, `TxtWidth`; `Height`
  the matching four) when the derived cell's formula is absent, `Inh` or
  the documented spelling (`Width*0.5`, `Width*1`, spaces and `=`
  ignored). A custom formula is left alone. `write_row_cell` writes only
  the named cell.
- `add_connect` keeps one record per connector endpoint
  (`FromSheet`, `FromCell`, `FromPart`): a repeat for the same endpoint
  replaces the old record (this is the de-duplication rule of ADR 0039
  invariant 5 and keeps `connects_of` well-defined).
- `scale_geometry` always materialises the row union into the shape's own
  `Geometry` sections before scaling: literal rows keyed by their merged
  position, plus `Del` rows that neutralise the master chain's rows the
  union did not keep. `Rel*` rows keep their fraction values; only the
  absolute coordinate cells (`X`, `Y` and the per-kind control points
  `A`/`B`/`C`/`D` of `EllipticalArcTo`, `Ellipse`, `InfiniteLine`) scale,
  per axis. The scalar cells (bow, knots, weights, angle, ratio) are not
  coordinates and stay. A zero-size `to` is legal (collapsed shape).
- `group_shapes` places the group at the members' bounding box (pin at
  the centre, `LocPinX = Width*0.5`, so the group's transform is the
  identity offset) and rewrites the members' `PinX`/`PinY` into the
  group's local box; `ungroup_shape` maps them back and absorbs the
  group's rotation/flips into the children. The drawing does not move on
  either operation. The group lands on top of the page z-order.
- `write_connector_path` takes the routed points **in page inches** and
  maps them into the connector's own local box (the inverse of its shape
  transform) before writing the literal rows.
- `set_shape_text` rebuilds the `Text` element in the shape's preserved
  content and sets `Shape::text`; the vsdx writer copies it into the
  source tree when it differs.
- `instantiate_master` writes exactly the six transform cells (literal
  `PinX`/`PinY`/`Width`/`Height`, documented `LocPinX = Width*0.5` /
  `LocPinY = Height*0.5`); `size: None` takes the master's first
  top-level shape `Width`/`Height`.
- Page ids are list positions: `delete_page` and `move_page` renumber
  `Page::id` and rewrite every `Page::background` reference to follow its
  page. An undo step holding a `PageId` across those operations must
  refresh it (the same holds for `DetachedShapes::page`).
- `delete_page` leaves the page's shapes in the arena (detached), as
  ADR 0039 requires for shape ids; `ungroup_shape` drops the `Connects`
  records naming the dissolved group itself (its signature returns only
  the children's ids).

### Open issues

1. **Empty new page, no contents part.** ADR 0048 says a new page gets
   "a new page part, its relationship, the content-type override and the
   `pages.xml` entry", but the P2-10 regression test (a file this task
   does not own) requires a content-less new page to get **no** `Rel` and
   no part. Today the part appears as soon as the page has shapes or
   connects. If Visio needs a contents part for every page, that rule and
   `tests/write_edge_cases.rs::a_new_entity_without_contents_gets_no_rel_marker`
   must change together (master decision).
2. **Materialised rows lose unmapped cells.** `scale_geometry` rebuilds
   rows from the typed `GeometryRow` values: cells the row kind does not
   model (the `NurbsTo` `E` data, the `PolylineTo` `A` point list,
   `Unknown`-row cells) are dropped in a materialisation. The encoded
   coordinate lists would need re-encoding to scale; the scalars are not
   coordinates. A Phase 6 recalc can replace the whole mechanism.
3. **Rows without `IX`.** The materialisation keys rows by merged
   position and neutralises the master chain's rows by `IX`; a master row
   without an `IX` can only be overridden positionally (the ADR 0019
   "every corpus `Geometry` row has an `IX`" limitation).
4. **Anisotropic arcs are approximate.** `ArcTo` bows,
   `EllipticalArcTo` ratios and spline knots are not scaled, so a
   non-uniform resize distorts arcs and splines slightly (uniform resizes
   are exact only for the coordinate cells; the bow stays).
5. **Group bounding boxes use the shape frame**, not the geometry rows:
   the box is the transform of the local `0..Width` x `0..Height` box, so
   geometry that sticks out of the frame is not counted.
6. **`Package::next_relationship_id` is implemented and tested but the
   writer still allocates ids with its own `fresh_rel_id` helper** (the
   shared page/master pipeline; rewiring it was not needed for ADR 0048).
7. **Adjacent text parts may coalesce.** Two consecutive
   `TextPart::Text` values serialise as adjacent text nodes and may read
   back as one part (XML text merging); P5-07 should keep runs split by
   markers or merge them itself.
8. **`Text` write-back compares nodes.** `patch_text` replaces the
   tree's `Text` element when the model's rebuilt one differs; a source
   element the reader normalised would be rewritten once (the `diff`
   comparison is attribute-order-insensitive, so the round-trip criteria
   still hold).
