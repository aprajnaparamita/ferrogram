## Goal

Implement a loader for `ui-spec/visio-2016.yaml`,
`ui-spec/visio-365.yaml`, `ui-spec/commands.yaml` and
`ui-spec/shortcuts.yaml`. The loader:

1. Reads a YAML or JSON file from disk.
2. Validates the file against `ui-spec/schema.json` (the same schema
   the xtask extractor uses). The schema lives in the repository at
   `ui-spec/schema.json`; the loader resolves it relative to the
   workspace root via `CARGO_MANIFEST_DIR`.
3. Deserialises the validated data into the public types in
   `lib.rs` (the P1-02 stubs).
4. Cross-checks references: every Fluent id in `commands.yaml` must
   appear in at least one layout; every command id in
   `shortcuts.yaml` must appear in `commands.yaml`.
5. Builds a `CommandLookup` from the layout + commands.
6. Supports both layouts (2016 and 365) and a runtime switch via a
   `LayoutSwitch` API.

## Public API

```rust
use ferrogram_ui_spec::{
    LayoutKind, LayoutSet, Loader, CommandLookup, LoadError,
};

let loader = Loader::new(&workspace_root)?;  // loads the schema once
let set_2016 = loader.load(LayoutKind::Visio2016)?;
let set_365  = loader.load(LayoutKind::Visio365)?;

// The CommandLookup is built on demand from a LayoutSet.
let lookup = set_2016.command_lookup();
assert!(lookup.labels.contains_key(&CommandId::new("file.save")));

// Layout switching: pick at runtime.
let active = LayoutSet::select(LayoutKind::Visio365, &set_2016, &set_365);
```

`LayoutSet::command_lookup()` returns a `CommandLookup` whose
`primary_path` is the ribbon path (`tab/group/control`) of the
control, picked by:

- prefer the QAT path if the control is in the QAT;
- else prefer the Home tab path;
- else prefer the first path in source order.

## Implementation notes

- **Validation first, then deserialize.** Use `jsonschema` to
  validate the raw YAML/JSON before turning it into our types. A
  validation failure returns `LoadError::Schema { path, message }`
  with the validator's error list joined by `; `. The schema is
  loaded once in `Loader::new`; the `Validator` is `Send + Sync`
  and cheap to clone (it holds an `Arc`).
- **YAML deserialization.** Use `serde_yaml::from_str` into
  intermediate `serde_yaml::Value`, then validate, then deserialize
  into the typed struct. Two passes (one for validation, one for
  typed deser) is fine: the files are small.
- **Cross-references.** Build two sets at load time:
  - `fluent_ids`: the union of every control id in the layout's
    QAT, tabs, groups, backstage tabs, and context menus.
  - `command_ids`: the set of every `commands.yaml` entry's `id`.
  Then:
  - For each entry in `commands.yaml`, every name in its
    `fluent_ids` must be in `fluent_ids` (collected above). A
    mismatch is `LoadError::CrossReference { kind: "fluent_id",
    id, referenced_by }`.
  - For each entry in `shortcuts.yaml`, the `command` must be in
    `command_ids`. A mismatch is `LoadError::CrossReference { kind:
    "command_id", id, referenced_by }`.
- **`CommandLookup` builder.** Walks the layout once, recording
  for each `Control.id`:
  - its `label`,
  - its primary path (the picking rule above).
  Returns a `CommandLookup`. The lookup is `BTreeMap`-backed so
  iteration is sorted.
- **Layering.** `crates/ui-spec` is L0 (ADR 0002). It depends on
  `serde`, `serde_yaml`, `jsonschema`, `thiserror` (all from
  crates.io; no workspace deps). Confirm `cargo xtask layers` is
  green.
- **No panics.** Workspace lints apply. The loader must not
  `unwrap`, `expect`, `panic!`, or `unreachable!`. Tests may use
  them via `clippy.toml`.
- **Schema is committed.** `ui-spec/schema.json` is the
  source of truth. The loader reads it at runtime via
  `include_str!` to avoid a runtime path lookup; the workspace
  root is passed in for the data files.
