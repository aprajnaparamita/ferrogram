## Goal

Every shortcut in `shortcuts.yaml` dispatches its command through the
registry, multi-chord sequences work, scopes filter by focus, and egui's
own text-editing keys are never stolen.

## Interfaces

```rust
// crates/ui/src/shortcuts.rs (stubs filled in)
pub struct KeyChord { pub key: String, pub modifiers: Vec<String> }
pub struct ShortcutMap { /* chord-sequence trie -> CommandId */ }
impl ShortcutMap {
    pub fn from_shortcuts(&ui_spec::Shortcuts) -> Result<ShortcutMap, UiError>;
    pub fn resolve(&mut self, &[KeyChord]) -> Result<Option<Intent>, UiError>;
    pub fn pending(&self) -> bool;
    pub fn len(&self) -> usize;
    pub fn is_empty(&self) -> bool;
}
pub fn dispatch(&egui::Context, &mut ShortcutMap, &AppCtx, ShortcutScope)
    -> Result<Option<Intent>, UiError>;
```

Rules (ADR 0036): chords normalize from egui key events to the
`shortcuts.yaml` tokens (`Ctrl`, `Shift`, `Alt`, `A`, `F1`, ...); the
token table covers every token the file uses and an unknown token is a
load-time `UiError`. Multi-chord sequences are stateful (2 second
timeout, reset on mismatch). Scopes: `Global` always; `Page` when the
canvas has focus; `Text` defers to egui when a text edit has focus;
`Selection` is never true in Phase 4 (no selection); `Ribbon` when the
ribbon has focus; `Window` always in the single-window shell. Duplicate
sequences: first in file order wins, one warning recorded at load
(return the warnings in `UiError`? No: `from_shortcuts` returns the map;
record conflicts as `Vec<String>` reachable through
`ShortcutMap::conflicts()` — extend the struct with a public accessor).
A matched chord is consumed even when the command is disabled (the shell
shows the reason in the status bar).

**What changed** (branch `agent/P4-08`, worktree

- `crates/ui/src/shortcuts.rs`: the P4-08 stubs are implemented.
  - `ShortcutMap::from_shortcuts` builds a chord-sequence trie from
    `ui_spec::Shortcuts`. Entry order is file order; a duplicate
    sequence is dropped first-wins and recorded in
    `ShortcutMap::conflicts()` (`&[String]`, one line each). The
    committed table has 90 entries and 61 unique sequences, so 29
    conflicts are recorded and `len() + conflicts().len() == 90`.
  - Chord normalization: modifiers deduplicated and sorted `Ctrl`,
    `Shift`, `Alt`; a shifted symbol key (`+`, `<`, `>`) absorbs
    `Shift` on both sides (the file writes `Ctrl+Shift+<` but `Ctrl++`).
    The egui token table covers every token of the committed file
    (`token_is_known`); `<` and `>` are the comma and period keys with
    Shift, `+` is `Key::Plus` and Shift+`Equals`, the pseudo-token
    `Arrow Keys` matches all four arrow keys (the source's held-key
    note, P1-04), and `Ctrl` also reads the macOS command key. An
    unknown token is a load-time error.
  - Multi-chord sequences are stateful in `pending`, reset on mismatch
    and after 2 seconds. `resolve` processes the chords it is given in
    order and returns the first completed intent. A sequence that is a
    prefix of a longer one waits; the shorter entry fires when the
    longer one mismatches or times out (the committed file has no such
    pair).
  - `dispatch(egui::Context, ...)` reads the `Event::Key` presses of
    the frame, resolves them and removes the matched ones from
    `input.events` before the widgets see them. A matched chord is
    consumed even when the command would not run (the scope does not
    match); an unmatched chord is left for the widgets.
  - Scopes: `Global` and `Window` always, `Page`/`Ribbon` when the
    `scope` argument (the surface the shell reports as focused) says
    so, `Text` only while `Context::text_edit_focused()`, `Selection`
    only with a non-empty `AppCtx::selection` (never in Phase 4).
  - Never steal: while a text edit has focus, plain typing and caret
    chords and the Ctrl editing chords egui owns (select, clipboard,
    undo/redo, delete word/line) are neither matched nor consumed.
- `crates/ui/tests/shortcuts_dispatch.rs` (new): 11 dispatch tests on
  a plain `egui::Context` with synthesized key events — the committed
  table loads, a token-coverage test over the committed file, one
  single-chord shortcut per scope, text and selection scope filtering,
  a multi-chord sequence and its timeout, the conflict rule with a
  synthetic table, and the egui text-key deferral. Unit tests (27)
  sit next to the code.

**Deviations:**

- `UiError` has no shortcut-specific variant and `crates/ui/src/lib.rs`
  is P4-03's file, so a load-time problem (unknown token, chord with
  no key or two keys, shortcut with no chord) is
  `UiError::Layout(LoadError::Parse { path: "shortcuts.yaml", .. })`.
- The interface has no clock, and `std::time::Instant` panics on wasm,
  so the 2 second timeout is applied by `dispatch` from the egui frame
  time; `resolve` alone is timeless and `pending()` reports the
  recorded buffer (a stale buffer is cleared on the next `dispatch`,
  which the shell runs every frame).
- `resolve` returns an `Intent` and knows nothing about focus; the
  scope filter lives in `dispatch` (the ADR's `resolve` signature has
  no `AppCtx`/scope).
- Conflict detection keys on the chord sequence alone (ADR 0036), so a
  scope-variant duplicate is dropped with its scope.

**Open issues:**

- P4-09 wiring (the shell hook this task cannot make): in
  `Shell::show_in`, before the widgets and per ADR 0036, call
  `shortcuts::dispatch(&ctx, &mut shortcut_map, &app, focus)` where
  `focus` is `Page` when the canvas has focus, `Ribbon` when the
  ribbon has focus, else `Global`; run the returned `Intent` through
  `Shell::dispatch` (`Source::Shortcut`); surface `map.pending()` in
  the status bar and copy `map.conflicts()` into `AppCtx::warnings`
  once at load (the map is built before the shell owns an `AppCtx`).
- The conflict key should probably include the scope (ADR 0007/0036
  review): the committed table loses 29 duplicates, and two of them
  bind different commands — `Ctrl+Shift+C` and `Ctrl+Shift+V` are
  `format.text.align_center`/`align_bottom` (text) in file order and
  drop `tools.format_painter` (global); `Ctrl+Shift+P` still runs the
  format painter.
- `edit.delete_back_word` (`Ctrl+Backspace`, scope `text`) never fires
  from the keyboard: egui's text edit owns that chord and ADR 0036
  defers to it. The same applies to the text-scoped undo/redo chords.
- Key handling on real keyboards: `+`, `<`, `>` depend on how the
  platform reports Shift with the comma/period/equals keys; the table
  assumes the US layout (`Equals` with Shift is `+`). Key repeats are
  treated as presses (needed for `Arrow Keys` nudge).
- `Selection` scope reads `!app.selection.is_empty()`, so it activates
  itself in Phase 5 with no change here.
- The timeout rules were not black-box checked against Visio (no
  Visio here): 2 s and "prefix waits" follow ADR 0036.
