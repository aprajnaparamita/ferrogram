## Goals

Each item needs a regression test unless it says otherwise. Use one commit per finding or per closely related group, and put the finding ids in the commit body.

**Error reporting**
1. **R1 (major).** Schema validation and parse errors in `xtask/src/extract/schema.rs` name the data file, not `ui-spec/schema.json`.
2. **R2 (major).** In `shortcuts.rs` and `visuicmds.rs`, only `NotFound` becomes `ExtractError::Missing`. Every other read error becomes `ExtractError::Io` and keeps the `io::Error` text. Test with a directory in place of the file and with a non-UTF-8 file.
3. **R3.** Replace the `<in-memory>` and `<layout>` placeholder paths with the real source paths.
4. **R4.** A non-empty `Policy ID` that does not parse is an `ExtractError::Parse` with the row number. Document what an empty cell means.

**`extract --check` and test hygiene**
5. **R5.** `--check` also flags committed generated files that no extractor produced. List the generated paths in one place. Exclude hand-maintained inputs (`ui-spec/schema.json`, `ui-spec/out-of-scope.txt`).
6. **R6.**
   - Add `.gitattributes` so every generated output and every fixture checks out with LF on all platforms.
   - Make `--check` treat CRLF and LF as equal when comparing.
   - Route every xtask test temp dir through one helper that names it with the pid and a counter. Fixed names such as `ferrogram-diff-test` must go.
7. **R7.** Remove the duplication:
   - one `emit_yaml` (holding the emitter options);
   - one write-and-validate helper;
   - one `write_atomic`, shared by `corpus.rs` and `extract/util.rs`, using unique temp names;
   - one HTML entity decoder;
   - `fluent_command_id` uses `fluent_words`.

   No test needed beyond the existing ones, but `cargo xtask extract --check` must still pass.

**Corpus fetcher coverage**
8. **C1 (major).** Test `download` against a local HTTP listener in the test (`std::net::TcpListener`, plain HTTP on 127.0.0.1). Cover a 200 response, a 404, and a body shorter than its `Content-Length`. If the URL scheme or agent setup gets in the way, make the agent injectable; the production path must not change behaviour.
9. **C2 (major).** Test the fetch loop's failure arms:
   - an unknown source name;
   - a fetch that produced no file;
   - size and sha256 mismatches, where the bad file is deleted and the error reported;
   - a stat error.
10. **C3.** Move the argument handling in `xtask/src/main.rs` into a testable function. Test the unknown subcommand, the help text and each subcommand's argument errors.

**Clean-room**
11. **F2.** Replace the phrase keys in `ACTION_TO_COMMAND` (`shortcuts.rs`) with the lowercase hex sha256 of the normalised phrase.
    - Pin the entry count in a test.
    - Explain in the module doc how a maintainer adds an entry: normalise the phrase from `reference/`, hash it, and add the hash.
    - Fix the module doc's claim that "no Microsoft prose is committed" so it states exactly what is kept.
    - `shortcuts.yaml` must be unchanged by this item.
12. **F3.** Paraphrase the sentence-length prose in the test fixtures of `shapesheet.rs`, `shortcuts.rs` and `fixtures.rs`. Keep the markup shape the parsers need. Do not copy any sentence from `reference/`.
13. **F4.** The `section` values in `shortcuts.yaml` become our own short group names: "Common", "Text", "Shapes", "Stencils", "Navigation", "Views", "Dialogs" and so on. Pick a small fixed set.
    - Map from the source heading by sha256 key, as in item 11.
    - An unmapped heading is an error, so a source change is noticed.
    - Regenerate `shortcuts.yaml`.

### What changed (one commit per finding or group)

- **R1** (`fix: extractor error reporting (R1-R4)`): `validate_str` /
  `validate_json` take the data path; only the two schema-file failures
  name `ui-spec/schema.json`. Test: `errors_name_the_data_file_not_the_schema_file`.
- **R2** (same commit): `extract::util::read_source` maps `NotFound` to
  `Missing` and every other read failure to `ExtractError::Io` keeping
  the io error text; used by `shortcuts.rs` and `visuicmds.rs`. Tests
  run with a directory in place of the file and with a non-UTF-8 file
  in both modules. `ExtractError::Io`'s display now reads "io error on
  <path>" (it covers reads too).
- **R3** (same commit): `<in-memory>` / `<layout>` are gone;
  `assemble_layout` gets the workbook path, `fill_layout_commands` the
  layout path, `build_entries` the `visuicmds.md` path (via
  `visuicmds::input_path`). Tests assert the paths in the messages.
- **R4** (same commit): a non-empty `Policy ID` that does not parse is
  `ExtractError::Parse` with the row number. An empty cell means the
  source does not order the control: it becomes `NO_POLICY_ID`
  (`i64::MAX`) and sorts after every numbered control (documented at
  the constant). Test `policy_id_parsing`.
- **R5** (`feat: extract --check flags stale generated files`):
  `GENERATED_OUTPUTS` is the one list of generated paths;
  `check` now returns a `CheckReport` that also lists committed
  generated files no extractor produced (fixed paths plus anything
  generated-looking under `ui-spec/`). Hand-maintained files are never
  flagged: `ui-spec/schema.json`, `ui-spec/out-of-scope.txt`, any
  `ui-spec/*.txt`, and `ui-spec/README.md` (see deviation 2). Three
  tests, including one pinning the list to what the extractors write.
- **R6** (`build: LF checkouts, CRLF-tolerant --check, one temp-dir
  helper`): new `.gitattributes` forces LF for every generated output
  and `crates/ui-spec/tests/fixtures/**`; `same_bytes` compares with
  carriage returns stripped (test `check_treats_crlf_and_lf_as_equal`);
  every xtask test temp dir goes through `util::test_support` (name =
  pid + counter). The fixed names (`ferrogram-diff-test`,
  `ferrogram-parity-oos`, `ferrogram-parity-test`, the `ferrogram-util-*`
  and pid-only names, plus the local `TempDir` structs in `corpus.rs`
  and `oracle.rs`) are gone; `fixtures.rs` and `vsdx_schema.rs` build
  their trees on the same naming helper.
- **R7** (`refactor: one emitter, writer, decoder and word-splitter`):
  `extract::util::emit_yaml` (holds the emitter options),
  `extract::util::write_and_validate`, `crate::util::write_atomic_bytes`
  (shared by `corpus.rs` and `extract/util.rs`, unique temp names),
  `extract::util::unescape_entities` / `collapse` (shared by shortcuts,
  shapesheet, markdown), and `fluent_command_id` derives its words from
  `fluent_words` (one stripping loop). `cargo xtask extract --check`
  passes with byte-identical outputs.
- **C1** (`test: cover the corpus fetcher and the fetch loop`):
  `download` is tested against a local `std::net::TcpListener` (plain
  HTTP on 127.0.0.1): 200 body, 404, and a body shorter than its
  `Content-Length`. `download_with` takes the agent so the explicit
  HTTP status check is reachable (ureq's default turns non-2xx into a
  transport error); `download` still passes `http_agent()`, so the
  production path is unchanged.
- **C2** (same commit): `run_with_fetch` injects the fetch step (the
  production wiring in `run_with_root` is unchanged). Tests cover: an
  unknown source name (fetch never called), a fetch that produced no
  file, size and sha256 mismatches (bad file deleted and the error
  reported), and a stat error before and after fetching.
- **C3** (`refactor: testable command-line dispatch`): `main.rs`
  argument handling moved into `parse_task` + `run_task`; every
  subcommand's arguments are validated by that subcommand's parser
  before anything runs. Tests cover the unknown subcommand, the help
  text (`usage()` lists every task) and each subcommand's argument
  errors. `coverage` now rejects unknown arguments instead of ignoring
  them (behaviour change, deliberate).
- **F2** (`refactor: hash the shortcut action keys`): `ACTION_TO_COMMAND`
  keys are the lowercase hex sha256 of the normalised phrase
  (`action_key`); `shortcuts.yaml` unchanged by that commit. Tests pin
  the 81 entries and the key shape; the module doc states exactly what
  is kept and how a maintainer adds an entry (normalise the phrase from
  `reference/`, hash it with `sha256_hex`, add the hash).
- **F3** (`test: paraphrase the extractor test fixtures`, plus a
  follow-up commit): all sentence-length prose in the fixtures of
  `shapesheet.rs`, `shortcuts.rs` and `fixtures.rs` is our own wording;
  the markup shape is unchanged. The shortcuts unit tests map their
  fixture rows through their own hashed tables (`run_with_tables`), and
  the dispatcher fixture keeps two short command labels ("Copy",
  "Paste") so the real table is exercised end to end. The last
  source-page titles in a fixture and one comment were renamed the same
  way.
- **F4** (`feat: shortcut section values are our own group names`):
  `SECTION_GROUPS` maps the normalised heading by sha256 to our group
  name and the scope; the groups are Common, Text, Shapes, Stencils,
  Navigation, Views, Dialogs. An unmapped heading is a hard error
  naming the heading and its hash (test
  `unmapped_section_heading_is_an_error`), so a source change is
  noticed. `shortcuts.yaml` regenerated.

### Deviations

   tag-stripping behaviour and shares only `collapse`.
3. Commit `fix: extractor error reporting (R1-R4)` also carries the
   first half of the R7 helper consolidation (`extract/util.rs`
   gaining `emit_yaml`, `write_and_validate`, `read_source`,
   `unescape_entities`, `collapse`); the consumers follow in the R7
   commit. Splitting them apart would have meant rewriting history.
