## Decisions to make (one ADR each where significant)

1. **Model additions for rendering.** What the reader must now map instead
   of preserving, and how, without breaking the Phase 2 round-trip (the
   patch writer must still reproduce the source):
   - typed geometry rows for every row type, from the `T` attribute and
     the row's cells, including the relative variants and
     `PolylineTo`/`NURBSTo` formula-encoded data (cached values only);
   - shape text: the `Text` element with its `cp`/`pp`/`tp` run markers and
     fields, linked to the `Character`, `Paragraph` and `Tabs` rows;
   - the theme part (colours, fonts, effects as far as rendering needs) and
     the document colour table;
   - layers and layer membership, background pages, page size and scale.
   Decide whether the ShapeSheet table gets row-type families (a Phase 1
   extractor change) or the row types are a hand-written enum backed by
   [MS-VSDX].
2. **Scene graph** (`crates/render`, L3). The intermediate representation
   between the model and the PNG and SVG backends: paths, paints
   (solid, gradient, pattern), strokes (weight, dash pattern, caps, joins,
   rounding), line ends, shadows, text runs and clipping. Transforms from
   the shape hierarchy (pin, local pin, angle, flips) into page coordinates.
   How rendering reads cells: always through the inheritance lookup, so
   master and style values apply, never by flattening.
3. **Cached values only.** No formula evaluation in Phase 3. Define what the
   renderer does when a cached value is missing or an error (`#VALUE!`):
   the default, a warning, and how warnings reach the caller and the CLI.
4. **Geometry semantics.** For each row type, its exact geometric meaning
   (arcs by bow, elliptical arcs by control point and eccentricity, NURBS,
   splines, ellipses, infinite lines), and the conversion to the scene
   graph's path primitives. Sources: [MS-VSDX] and the ShapeSheet
   reference only. Specify the tolerance for curve flattening if any.
5. **Visual styles we define ourselves.** Visio's line patterns, line-end
   (arrowhead) shapes, fill patterns and shadow styles are not specified in
   [MS-VSDX]. Decide how we produce our own versions from black-box
   observation, where those definitions live (a committed data file, our
   own work, with provenance) and what "close enough" means for the alpha.
6. **Text** (`crates/text`, L1, cannot see `model`). The layout API given
   plain runs, formatting and a box: wrapping, alignment, line spacing,
   bullets, tabs, vertical alignment, text block margins and rotation.
   Choose the shaping and font crates (for example `rustybuzz`,
   `ttf-parser`, `swash`, `cosmic-text` or `parley`); they must be pure
   Rust, permissively licensed, and build for `wasm32-unknown-unknown`.
   Fonts: bundle Carlito and Selawik with their OFL licences (AGENTS.md
   section 4); define the font fallback and how a missing font is
   reported. Fonts are assets: each needs an `ATTRIBUTION.md` row and a
   source in `docs/sources.md`.
7. **Backends and dependencies.** PNG through `tiny-skia`; SVG written by
   our own code or a crate (justify). DPI and scale options, background,
   anti-aliasing, and determinism (same input, same bytes) for golden
   tests. Check every new crate with `cargo deny check` and the wasm
   build.
8. **CLI** (`apps/ferrogram-cli`, L7). Commands `inspect`, `render` and
   `export`: their arguments, output formats (`inspect` as JSON and text),
   page selection, exit codes and error messages. The argument parser crate
   (for example `clap` or `lexopt`). The CLI dispatches through library
   calls now; the command registry (`crates/commands`, AGENTS.md section
   6) arrives in Phase 4, so say how the CLI moves onto it then.
9. **Test strategy for the exit criterion.**
   - Unit tests for every geometry row type (absolute and relative).
   - Golden image snapshots with a tolerance: the comparison metric, where
     the goldens live, how they are regenerated and reviewed, and that they
     are our own output (provenance rows).
   - Hand-authored fixtures that exercise each feature in KICKOFF's list,
     built by the P2-08 fixture builder or an extension of it.
   - A structural comparison against libvisio's SVG output where it is
     meaningful (`vsd2xhtml`, behind `FERROGRAM_LIBVISIO_ORACLE`): what is
     compared (shape count, bounding boxes, path counts) and the tolerance.
   - Every corpus file renders without panics (a corpus test and a fuzz
     target or property test over the scene builder).

## Task split

Propose the tasks with disjoint ownership. A starting point; change it as
the design requires:

  background pages (and keep the round-trip green)

  tasks, as in Phase 2
