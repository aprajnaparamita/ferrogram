## Decisions to make (one ADR each where significant)

1. **Command registry** (`crates/commands`, L4). The `Command` trait or
   table: id (the `commands.yaml` ids), label, enabled-state predicate over
   an app/document context, execution with arguments, and undo/redo (an
   undo stack design Phase 5 can fill in; Phase 4 commands are mostly file
   and view commands). How results and errors come back, how a command that
   needs input (a file path) gets it without opening a dialog when called
   programmatically. How the CLI moves onto the registry (ADR 0026 named
   `file.inspect`, `file.render`, `file.export`).
2. **Application state.** Where open documents, the active page, the
   selection (empty in Phase 4), view state (pan, zoom) and settings live,
   and which layer owns each: what is in `commands` (so headless callers
   and Phase 8 can use it) and what stays in `ui`.
3. **GUI stack.** `egui`/`eframe` versions, renderer backend (`wgpu` or
   `glow`) for desktop and wasm, `egui_kittest` for tests, `rfd` for native
   dialogs. Check licences (`cargo deny check`), the wasm build and the
   macOS build. UI fonts (Selawik is already bundled in `crates/text`).
4. **Command bar from ui-spec.** Load at runtime from the committed YAML or
   generate code at build time; how tabs, groups, controls, galleries
   (basic dropdowns), split buttons and the backstage map to egui widgets;
   how a control finds its command (through `commands.yaml`); controls with
   no implemented command render disabled with a "not yet implemented"
   tooltip; icons (placeholders or an open-licensed set, AGENTS.md
   section 4). The quick access toolbar.
5. **Layout switching.** 2016 and 365 layouts both bound to the same
   registry; switching at runtime from View/Options with no restart; the
   `--ui-layout` flag; the persisted setting (where it is stored on
   desktop and on wasm).
6. **Canvas.** How a page is drawn in egui: a third backend from the scene
   graph to egui shapes/meshes, or a `tiny-skia` raster uploaded as a
   texture, or both (justify by speed, fidelity and the Phase 5 need to
   hit-test and redraw while dragging). Pan, zoom, rulers, grid, page tabs
   and the status bar. Units stay inches until the screen edge.
7. **Shapes window and stencils.** Original "Basic Shapes" and "Basic
   Flowchart" stencils (our own masters, AGENTS.md section 4): their source
   format (hand-authored data turned into `.vssx` by our writer, or built
   in code), where they live, provenance rows, and how the Shapes window
   lists them. Dragging onto the page is Phase 5; say what Phase 4 shows.
8. **Panes.** Basic Shape Data and Size & Position panes: read-only in
   Phase 4 or editable through commands; what they show with no selection.
9. **Shortcuts and file I/O.** Dispatch from `shortcuts.yaml` through the
   registry (scopes, chords, conflicts with egui's own keys); open and save
   with native dialogs on desktop; upload and download on wasm.
10. **Test strategy for the exit criterion.** `egui_kittest` tests for
    command bar generation (every tab/group/control in both layouts), layout
    switching without restart, enabled/disabled state and shortcut
    dispatch; command-level headless tests; a test that opens corpus files
    and checks the canvas draws them; how the `ui` and app crates reach
    their 50% coverage thresholds; the `docs/parity/controls.md` generator
    (an `xtask` step and whether the gate checks it is fresh).

## Task split

Propose the tasks with disjoint ownership. A starting point; change it as
the design requires:

- P4-02 command registry and app state (`crates/commands`), including the
  CLI move onto it
- P4-03 GUI shell: eframe app, window layout, menus, settings persistence,
  file open/save (desktop and wasm)
- P4-04 command bar and quick access toolbar from ui-spec, layout switching
- P4-05 canvas: drawing the scene, pan, zoom, rulers, grid, page tabs,
  status bar
- P4-06 stencils: original Basic Shapes and Basic Flowchart, and the
  Shapes window
- P4-07 Shape Data and Size & Position panes
- P4-08 shortcuts dispatch
- P4-09 parity matrix generator and the Phase 4 test harness
- then the test-engineer, reviewer, coverage-auditor and cleanroom-auditor
  tasks, as in Phase 3

For each task file, use `docs/tasks/TEMPLATE.md`. Give each its Owns list,
Inputs, Interfaces (the exact stub signatures it implements or consumes),
acceptance criteria and a suggested model tier. Mark which tasks can start
at once and which wait for others. Include the Launch prompt.

Lessons from Phases 2 and 3:

- Give every shared file (a crate's `lib.rs`, `Cargo.toml`, `error.rs`,
  the app's `main.rs`) to exactly one task. In each dependent task's file,
  say which lines it may add.
- `crates/ui` will be touched by most tasks: split it into modules up front
  (one per task) so the tasks do not collide.
- Each new fuzz directory needs its own `.gitignore` with `!corpus/`,
  because the root rule `**/fuzz/corpus/` ignores seed corpora.

### Open issues

- **Chrome font**: egui's dependency-supplied default fonts (UFL-1.0)
  are the Phase 4 chrome font (ADR 0030). Switching chrome to Selawik
  needs a public font-bytes accessor in `crates/text` (not owned here);
  screenshot-pass item. `ATTRIBUTION.md` row lands with P4-03.
- **Units formatter** is specified for both the canvas rulers (P4-05)
  and the panes (P4-07). If P4-05's helper is not public, P4-07
  duplicates it and the master may lift it into `crates/ui/src/lib.rs`
  (P4-03's file) after both merge.
- **Double ruler id**: `view.rulers` (`visCmdViewRulers`) and
  `view.show.ruler.visio` (Fluent `ShowRulerVisio`) both exist in
  `commands.yaml`. ADR 0032's table wires the toggle to `view.rulers`;
  P4-02 maps the Fluent control to it in `fluent.rs`. If the extractor
  data disagrees, the fallback is registering the same behaviour under
  both ids.
- **Extractor artefact duplicates** (P1-14: `TabSave` x9,
  `LineStylesDialog` twice) are handled at render time (ADR 0031
  dedup). Fixing them in `xtask/src/extract/fluent.rs` is P4-02 work;
  if P4-04 finds more, raise it in its Result instead of editing the
  extractor.
- **`--ui-layout` parsing** lives in `apps/larrygram/src/main.rs`
  (P4-03). `larrygram-cli` does not take the flag (its commands are
  headless); say so in the Phase 4 report if KICKOFF expected both.
- **wasm performance** of the raster canvas is unmeasured (the gate only
  proves the build). If it is too slow, the Phase 5 vector backend
  (ADR 0033 upgrade path) is the lever.
- **`ArgValue::Bytes` and `Outcome::payload`** (binary payloads for
  wasm open/save) are specified as P4-02 extensions to the stubbed
  enums; P4-02 documents the final shape in its Result.
- **`Registry::from_mappings` id cap**: the interner caps at 4096 ids
  (ADR 0028). `commands.yaml` has ~1100 entries today; if the cap ever
  binds, raise it in `crates/commands/src/lib.rs` with a test.
