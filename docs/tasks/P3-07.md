## Goal

Write a standalone, deterministic SVG document for any scene.

## Interfaces

Implements (signatures fixed by P3-01):

```rust
pub fn render_svg(scene: &Scene, options: &SvgOptions) -> Result<String, Error>;
```

May add private helpers in `svg.rs` (element writing, number formatting,
XML escaping). The subset of SVG is fixed by ADR 0025: `svg`, `g`,
`path`, `defs`, `linearGradient`, `radialGradient`, `pattern`,
`clipPath`. Text is glyph outlines from `text::Font::outline`, never
`<text>`. Numbers use fixed 6-decimal formatting; attributes are written
in a fixed order; the `viewBox` is in scaled pixels.

Shared file: `crates/render/Cargo.toml` is owned by P3-05. If a test needs
`quick-xml` or `insta` as a dev-dependency, add exactly that line, and say
so in the Result so the master can merge.

## Result

**Done (2026-10-14, branch `agent/P3-07`).**

### What landed

- **`crates/render/src/svg.rs`** rewritten from the stub into the full
  writer (the file is the task's; no other source file touched):
  - `render_svg` writes one standalone document: XML declaration,
    `<svg>` (`xmlns`, `version`, `width`, `height`, `viewBox` in scaled
    pixels), an optional `<defs>` block, and a root `<g>` that flips y
    (page y up, SVG y down). Every number is fixed 6-decimal, every
    attribute list has a fixed order, ids are `g0`/`p0`/`c0` in
    discovery order: same scene, same bytes (ADR 0025).
  - Element subset exactly as ADR 0025 fixes it: `svg`, `g`, `path`,
    `defs`, `linearGradient`, `radialGradient`, `pattern`, `clipPath`
    (plus `stop`, which gradients cannot exist without). Rectangles are
    paths.
  - Paints: solids (`#rrggbb` + `fill-opacity`), linear/radial
    gradients (`gradientUnits="userSpaceOnUse"`, stops clamped to
    0..1), patterns (background box + tile in one `tile_size` tile).
    Coordinates are the scene's inches scaled by `scale`; a node's `d`
    is in its local space and its `transform` maps to the parent's, so
    gradients, tiles and clips resolve in the same space as the path.
  - Strokes: width, dasharray, cap, join, miter limit (cap/join/miter
    written only when they differ from the SVG defaults).
  - Line ends: the `render::styles` unit box (`x = 0` tip at the path
    vertex, `x = 1` tail along the line, `y = 0.5` centre; `length`
    scales x, `width` scales y, inches) placed on the path's end/start
    tangent. Filled ends paint with `color` or the stroke paint;
    unfilled ones stroke with the stroke's paint and width. An end on a
    path with no direction at that end is not drawn.
  - Shadows: offset copy of the shape in the shadow colour, drawn
    first. Blur is not drawn (the subset has no `filter`).
  - Text: one filled `path` per glyph from `Font::outline` (em units),
    never `<text>`. Bad font indexes, failed or empty outlines are
    skipped.
  - Safety and caps: every attribute value goes through one XML
    escaper; non-finite numbers and negative dashes write as
    `0.000000`; group nesting is capped at 128 and the document at
    64 MiB, both `Error::TooLarge`; the writer counts bytes as it
    writes, so a bad scene never allocates unboundedly.
- **Tests** (24 in `svg.rs`, synthetic scenes only, no golden
  harness): two hand-written pinned output strings (empty scene;
  background + one filled/stroked shape), byte-identical determinism,
  XML well-formedness parsed with `quick-xml`, one test per element
  kind (gradient defs, radial, closed and open pattern tiles, stroke
  attributes, filled and unfilled line ends with hand-computed unit-box
  geometry, directionless line ends, shadow order, clips, group
  transforms, depth cap), text placement with a hand-computed glyph
  matrix, text skips, non-finite sanitizing, invalid options and
  dimensions, the byte cap, attribute escaping, endpoint and unit
  vector edge cases, curves in line-end geometry.
- **`crates/render/Cargo.toml`** (shared file, owned by P3-05): one
  line added, as the task allows —
  `[dev-dependencies] quick-xml = "0.41"` (same version `larrygram-vsdx`
  uses). For the master to merge.

### Deviations from the P3-01 interfaces

1. **Glyph size and block rotation are missing from the fixed types
   (open issue 1 below).** `text::GlyphPos` carries no size and
   `text::Layout` no rotation, so `TextNode` cannot supply either and
   the master's note ("rotate each glyph outline by the block
   rotation") cannot be followed yet. The backend draws every glyph at
   12 pt and unrotated (exact for a 12 pt unrotated block; 12 pt is the
   size `text::layout` itself defaults to). The whole policy sits in
   one private helper (`Writer::glyph_transform`), so the fix is one
   function once the types carry the values.
2. **Invalid options return `Error::TooLarge`.** `error.rs` has no
   `InvalidOptions` variant (and is not this task's file), so a
   non-finite or non-positive `scale`, and a non-finite or negative
   page size, return `Error::TooLarge`. Semantically stretched;
   documented on `render_svg`.
3. **Pattern tiles fill or stroke by a heuristic.** `PatternPaint`
   carries no fill-or-stroke flag (the `PatternTemplate::filled` of
   P3-08 is lost before the scene), so a tile path with a `Close`
   segment fills with `foreground` and an open one strokes with a 1 px
   hairline. Every fill-pattern template in `visual-styles.yaml` is
   filled with closed paths, so real data renders correctly.

### Open issues

1. **(needs a type change; blocks correct text)** The scene/text types
   cannot express per-glyph size or text block rotation, and they also
   drop `Format::underline`/`strikethrough` ("the renderer draws it"),
   which nothing downstream can see. Suggested fix (owner decides):
   add `size: f64` (points) to `text::GlyphPos`, `rotation:
   larrygram_geom::Angle` to `text::Layout`, and underline/strike
   flags (or the run formats) where `TextNode` can read them. Then
   update `Writer::glyph_transform` in `svg.rs` and the equivalent in
   `png.rs` (P3-06 hits the same gap; the master should reconcile the
   two backends' text policies at merge). Until then SVG text is
   correct only for 12 pt unrotated blocks.
2. **`PatternPaint` loses `PatternTemplate::filled` and the tile stroke
   width.** Either add `filled: bool` (and a width) to `PatternPaint`,
   or let the builder pass closed silhouettes for filled tiles; the
   open-tile hairline and the close-segment heuristic then go away.
3. **Shadow blur is not representable in SVG** with the ADR 0025
   subset (no `filter` element). The shadow is an offset copy. If blur
   must match Visio, ADR 0025's subset needs `filter`/`feGaussianBlur`
   (and the PNG backend's blur policy must match).
4. **Line ends on dashed strokes stroke solid** (no dash), and a line
   end whose path end carries no direction is silently skipped. Fine
   for the alpha; revisit if a corpus file shows a real case.
5. **`error.rs` has no `InvalidOptions` variant** (see deviation 2);
   adding one would let `render_svg` (and `render_png`) report bad
   options accurately. `error.rs` is unowned by this task.
6. **For P3-10's goldens**, the fixed output shape to diff against:
   root y-flip group `matrix(1.000000 0.000000 0.000000 -1.000000
   0.000000 H)`, uniform 6-decimal numbers everywhere (including
   matrix components), defs omitted when unused, one element per line
   with 2-space indentation.
