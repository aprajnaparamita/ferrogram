## Decisions to make (one ADR each where significant)

1. **Grammar and AST.** The formula grammar: literals with units,
   strings, operators and precedence, function calls, and every reference
   form (local cell, `Sheet.N!Cell`, `ThePage!`, section and row
   references such as `Geometry1.X2`, `Char.Size`, `Prop.Name`,
   `User.Name`, `Scratch.X1`, local and universal names). Error
   reporting with spans. Limits on input length, nesting depth and token
   count (never a panic, bounded recursion). The AST is what `Expr`
   becomes; say what a printer produces, so a parse–print–parse property
   test is possible.
2. **Values and units.** The value type: number with unit, string,
   boolean, colour, error values. Unit families (length, angle,
   duration, typographic) and the conversions, built on ADR 0011
   (radians). Coercions between types, and non-finite handling (P3-11,
   P3-16). How a value maps to and from the model's cached `V` and `U`
   (P2-14).
3. **Function table.** The core set from KICKOFF (arithmetic and
   comparison, unit conversion, IF, AND, OR, NOT, MIN, MAX, ABS, INT,
   ROUND, GUARD, basic SETF, trig) plus the helpers the corpus masters
   need. Measure that need: list the functions used in the corpus
   formulas with counts. Decide whether the table is hand-written or
   generated from committed derived data. An unknown function keeps the
   cell's cached value and records a structured warning; it never fails
   the document.
4. **Reference resolution and inheritance.** How a reference finds its
   cell: shape, master, style and table default (ADR 0013); `Inh`;
   names spelled as in the file versus the alias table (P2-04, P2-06);
   references to missing cells, rows or sheets.
5. **Dependency graph and recalc.** Where the graph lives (respect the
   layering: `shapesheet` is L2 and may use `model`), how it is built
   (on open, incrementally), cycle detection and what a cycle evaluates
   to, evaluation order, and a time budget (for example a resize on a
   1000-shape page). What triggers recalc: an edit, a page change, an
   open.
6. **Edits with formulas (replaces ADR 0038).** What a move, resize,
   rotate or cell edit writes now: a value into a cell that has a
   formula, GUARD-ed cells, SETF. How dependent cells update, how undo
   restores them (store recalculated cells in the `Edit`, or recompute
   on revert), and what happens to `scale_geometry` (P5-02) and the
   connection-point scaling (P5-16). Connector re-routing (ADR 0045)
   versus formula-driven geometry.
7. **Values on open and in rendering.** Trust cached values or
   re-evaluate on open; how cells without cached values get them (the 5
   blank corpus files, P4-09); how the scene builder reads evaluated
   values (P3-15 inherited geometry).
8. **Saving.** What the writer emits for recalculated cells: `F` kept,
   `V` updated, units spelled how. The ADR 0048 identity with evaluated
   values, and the P5-10 reader artefacts (`U="BOOL"`/`U="STR"`, the
   `Rel` child).
9. **Typed Shape Data and panels** (P4-06). What the Shape Data and
   Size & Position panels show and accept once values are typed.
10. **The cached-value cross-check.** The corpus harness: which cells
    count (every function in the formula supported, no unsupported
    reference), the comparison tolerance per unit family, how the
    agreement rate is reported, and what disagreements are logged for.
11. **Test strategy and exit criterion.** Parser property tests and the
    fuzz target, function table tests, recalc order tests, the
    cross-check, and a scripted test for the exit criterion: resize a
    master-based shape from the corpus and check its geometry. Coverage
    targets per crate (`shapesheet` joins the 85% group with real code).

Lessons from Phases 4 and 5:

- Give every shared file (a crate's `lib.rs`, `Cargo.toml`, `error.rs`,
  `shell.rs`, the app's `main.rs`) to exactly one task. In each dependent
  task's file, say which lines it may add.
- `crates/shapesheet` will be touched by most tasks: split it into
  modules up front (one per task), so the tasks do not collide.
- Every edit goes through `ferrogram_commands::dispatch` and
  `AppCtx::push_edit` (ADR 0040). Recalc hooks into that seam; do not add
  a second undo path.
- A failed mutation changes nothing (ADR 0039 amendment). A failed or
  partial recalc must keep that rule.
- Write acceptance criteria against real behaviour. Check each criterion
  can be reached through the public API: in Phase 5 three coverage
  targets were unreachable arms.
- Give every interface stub a test of its "not implemented" contract, so
  coverage holds while the stubs wait.
- Each new fuzz directory needs its own `.gitignore` with `!corpus/` and
  seeds in per-target subdirectories (`corpus/<target>/`).
- A hand-added `commands.yaml` row must sit where the extractor puts it;
  run `cargo xtask extract --check` if a task adds command ids.
