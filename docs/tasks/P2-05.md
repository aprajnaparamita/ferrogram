## Goal

Implement the pure OPC layer: read a zip container into a `Package`
(enforcing every `Limits` cap before the allocation it guards), and write a
`Package` back to bytes. No Visio XML mapping here (that is P2-06/P2-07).

## Interfaces

Implements the stubs:

```rust
pub fn read_package(bytes: &[u8], limits: &Limits) -> Result<Package, Error>;
pub fn write_package(package: &Package) -> Result<Vec<u8>, Error>;
```

Consumes the `Package`/`Part`/`Relationship`/`Limits` types already defined
in `crates/vsdx/src/package/mod.rs`. Rules:

- `[Content_Types].xml` and every `*.rels` part are parsed into
  `content_types` and `relationships` (not kept as parts) and regenerated on
  write from those lists; every other part is `Part` data (XML parts parsed
  to `XmlNode` with prefix, attribute order and whitespace preserved).
- A missing content-type declaration for a part is `Error::InvalidPackage`;
  a relationship to a missing part is recorded, not an error (internal
  targets may legitimately dangle in the wild) — a relationship the
  *mapper* needs and cannot find is `Error::BadRelationship` there.
- Caps (ADR 0017) are enforced while reading, with checked arithmetic:
  `max_entries`, `max_part_uncompressed`, `max_total_uncompressed`,
  `max_compression_ratio` (bomb guard: compare declared sizes before
  inflating, and cap the inflate loop), `max_xml_depth`,
  `max_attributes_per_element`.
- The error enum (`crates/vsdx/src/error.rs`) is complete for all Phase 2
  tasks: P2-06 and P2-07 only add usages, never variants. If a variant is
  genuinely missing, note it under Open issues.
