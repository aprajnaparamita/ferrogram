## Goal

Draw rectangles, ellipses and lines on the canvas, and drop stencil
masters on the page at the pointer with the right size and glue.

## Interfaces

Implement `draw::handle` and `stencil::handle` (signatures fixed by
P5-01), and `builtins/insert.rs` `TABLE` with:

- `insert.shape` — args `stencil`, `master`, `x`, `y`, optional
  `width`, `height`, optional `glue_to` (`ArgValue::Integer`, the target
  Visio id) and `glue_point` (`ArgValue::Integer`, the connection row
  `IX`); one undoable edit (ADR 0040).
- `insert.drawing.rectangle`, `insert.drawing.ellipse`,
  `insert.drawing.line`, `insert.drawing.text_box` — args `x`, `y`,
  `width`, `height` (inches; `line` uses `x`, `y` as the start and
  `width`, `height` as the delta), one undoable edit each.

The drawing tools preview on the overlay (ADR 0042) and dispatch the
matching `insert.drawing.*` intent on release with snapped values (ADR
0043). Stencil drag previews the ghost, snaps the drop point and
dispatches `insert.shape` per ADR 0046 (master size; `Shift`-drag draws
the size rectangle; connection-point glue when in range).

## Result

_Filled in by the worker at hand-off: what changed, deviations, new dependencies, gate summary, open issues._

### What changed

- **`insert.shape`** (`crates/commands/src/builtins/insert.rs`):
  resolves a catalog master by stencil display name and master `NameU`
  (or display name), materialises it into the document on first use,
  and calls `Document::instantiate_master` with the dropped
  `PinX`/`PinY` and either the master size or the optional
  `width`/`height`. A non-master size rescales the instance geometry
  through `Document::scale_geometry`. Optional `glue_to`/`glue_point`
  add exactly one `Connect` record from the new shape's nearest
  connection point to the target's connection point; without
  `glue_point` the nearest target point is chosen. A glue failure rolls
  the just-inserted shape back out of the page. The new shape becomes
  the selection and the insertion is one `StructuralEdit::insertion`
  undo step.
- **Drawing commands** (`insert.drawing.rectangle`, `.ellipse`, `.line`,
  `.text_box`): one shape each with literal transform/style/geometry
  cells, one `StructuralEdit::insertion` undo step, and the new shape as
  the selection. Rectangle, ellipse and text box use `x`/`y` as the
  lower-left corner; the line uses them as its start and `width`/`height`
  as the signed delta.
- **Drawing tools** (`crates/ui/src/tools/draw.rs`): rectangle, ellipse
  and line drags snap their start and current points (`Snapper`), preview
  with `RubberBand`/`ConnectorPreview` overlay marks, and emit exactly
  one `insert.drawing.*` intent on release. Alt disables snapping;
  Cancel and out-of-order events are safe no-ops.
- **Stencil tool** (`crates/ui/src/tools/stencil.rs`): `begin_drag`
  starts a master drag, plain drops preview the master-size ghost and
  dispatch `insert.shape` at the snapped pointer, `Shift`-drags preview
  and send the drawn size, and a release within snap distance of an
  existing connection point adds `glue_to`/`glue_point`. Cancel and
  stale picks are safe; a stale pick still dispatches so the command
  reports the error.
- **Tests**: `crates/commands/tests/insert.rs` (17 headless tests:
  registration/coverage table, master drop, sized drop with scaled
  geometry, explicit and nearest glue, glue rollback errors, drawing
  commands and undo, malformed arguments) and
  `crates/ui/tests/phase5/draw.rs` (rectangle drag and stencil drop
  through the real canvas, `ToolMachine` and registry via
  `egui_kittest`).

### Deviations (closest correct version)

1. **Thread-local tool state.** `ToolMachine` owns only
   `pointer::PointerState` and this task may not edit `tools/mod.rs`, so
   `draw::handle`/`stencil::handle` keep their drag state in a
   thread-local slot keyed by the `ToolMachine` address. A UI process
   has one machine and one pointer; tests on separate threads stay
   isolated. This is the smallest change that implements the fixed
   `handle(state: &mut ToolMachine, ...)` signatures without editing
   another owner's struct.
2. **Minimal shared-file edits.** `tools/mod.rs`'s stub test still
   asserted that every non-pointer tool returns `NotImplemented`; it now
   checks the drawing/stencil modules handle events and only
   connector/text remain stubs. `crates/ui/tests/phase5/main.rs` gained
   the one `mod draw;` line so the new test file is compiled. Both are
   test-wiring-only edits; the tool-picker wiring itself is still open
   (issue 1).
3. **Catalog materialisation is not undone.** The first drop copies the
   catalog master (cells, geometry, Shape Data, connection rows) into
   the document, then inserts the instance. Undo detaches the instance
   and its glue, but leaves the now-unreferenced master. Materialising
   it is catalog infrastructure reused by later drops; removing it safely
   would need a master-removal mutation that keeps `MasterId` stability.
4. **`Connections.X<n>` cell spelling.** Glue records use the
   `Connections.X<n>`/`Connections.Y<n>` spelling observed in the
   corpus, with `FromPart`/`ToPart` = `VIS_CONNECTION_POINT + n`.
5. **Drawing selection is set by the command.** The tool cannot know the
   new shape's arena id when it emits the intent, so `insert.*` sets
   `AppCtx::selection` after insertion (the task's note allows the
   command handler to own it). No direct `edit.select` intent is emitted
   by these tools.

### Open issues

1. **Tool-picker and Shapes-window drag wiring.** The shell has no
   control that sets `Tool::Rectangle`/`Ellipse`/`Line`, and
   `ShapesWindow` still only selects a master. A later change should
   call `stencil::begin_drag(&mut tools, pick.stencil, pick.master)`
   when a row drag starts and feed canvas events to `stencil::handle`
   while `stencil::is_dragging` is true. The command handlers and tools
   are ready; only `shell.rs`/`shapes_window.rs` (other owners) need the
   lines.
2. **Master removal for exact undo.** The first drop leaves the
   materialised master behind after undo (deviation 3). A model-side
   master-removal operation that renumbers safely would close it.
3. **Connection-row index vs. candidate order.** `Document::connection_points`
   skips non-finite rows and returns a flat point list; the stencil's
   nearest-target scan enumerates that list, so a file with a skipped
   row could name a different row `IX` than the model's row index. The
   built-in stencils never skip rows; a model helper returning `(IX,
   point)` pairs would remove the ambiguity.
4. **Text-tool hand-off.** `insert.drawing.text_box` creates and selects
   a text box; opening the editor is P5-07's `text.begin` (it can read
   the selection).
5. **Glue cells for 2D drops.** The record uses connection-point parts;
   the screenshot pass can compare Visio's exact `FromCell`/`ToCell`
   spelling for a 2D shape glued to a point.
