## Goal

Both panels render honest read-only data in Phase 4: document and page
data with no selection, formatted in the user's display units, with the
`Row` seam ready for Phase 5 editing.

## Interfaces

```rust
// crates/ui/src/panels.rs (stubs filled in)
pub struct PanelRow { pub label: String, pub value: String, pub edit: Option<(CommandId, Args)> }
pub fn PanelRow::read_only(label, value) -> PanelRow;
pub fn shape_data_rows(&AppCtx) -> Result<Vec<PanelRow>, UiError>;
pub fn size_position_rows(&AppCtx) -> Result<Vec<PanelRow>, UiError>;
pub fn show_shape_data(&mut Ui, &AppCtx) -> Result<(), UiError>;
pub fn show_size_position(&mut Ui, &AppCtx) -> Result<(), UiError>;
```

Content (ADR 0035): with no selection, `shape_data_rows` lists the
document's `Property` rows (name, value) and the active page's name;
`size_position_rows` lists the active page's width and height in
`Settings::units` and its name. `edit` stays `None` (Phase 5 fills it).
Missing or non-finite values render "—" and record one warning on the
`AppCtx` the caller passes (take `&AppCtx`; if recording a warning needs
`&mut`, return the warning text in `UiError::Io`? No: return
`Result<Vec<PanelRow>, UiError>` and put the warning string in a
`PanelRow` value; document your choice). Both `show_*` functions render
the rows as a two-column `egui::Grid`.

### What changed

  selection, `shape_data_rows` lists the document's `Property` rows
  (name, value as written) and the active page's name;

  "No document" (the status bar wording). `edit` is `None` on every row
  (Phase 5 fills it).
- Missing, non-finite and empty values render "—" plus one warning row
  (`PanelRow::read_only("Warning", "<label>: no value")`, or
  "not a number" for a non-finite cached value). Rule documented in the
  module docs.
- 10 unit tests next to the code: the documented rows for a one-page
  document, the 8.5 x 11 in page reading "8.5 in"/"11 in" and
  "215.9 mm"/"279.4 mm" (also 21.59 cm), missing/empty/non-finite values,
  a stale page id, no document, and both panels in an `egui::Context`
  frame with `edit` `None` on every row.

### Deviations

- **Warnings do not reach `AppCtx::warnings`.** Both row builders and
  both `show_*` functions take `&AppCtx`, so they cannot call
  `record_warning`. Per the task note the warning string rides in the
  `value` of an extra `PanelRow` (`"Warning"` label) after the row it
  belongs to. See Open issues for the seam.
- **`shell.rs` test touched (P4-03's file).**
  `a_real_frame_renders_with_the_stub_widgets` asserted that a stub
  widget's "not implemented" error reaches `app.warnings`; the panels
  were the last stub in the frame path. The test is now
  `a_real_frame_renders_and_warnings_reach_the_status_bar`: it records a
  warning to stand in for a widget error and asserts it reaches the
  status-bar source, and still runs two real frames. One test body, no
  production code outside `panels.rs`. Master: please review.
- **Shape Data shows the page name only**, as the task's Content says;
  ADR 0035 also mentions the page size there, which would duplicate
  Size & Position. The name is `Page::name` (the `Name` attribute);
  empty renders "—", no `NameU`/`Page N` fallback (the status bar's
  `page_label` is private to `canvas.rs` and shows all three).
- Each panel draws its own strong title ("Shape Data", "Size &
  Position"); the shell has no headings for the right-hand area. Our UI
  choice (Open issues for the parity pass).

### Open issues

- Warning seam: give `shape_data_rows`/`size_position_rows` `&mut
  AppCtx` (or a warning sink) so warnings land on `AppCtx::warnings` and
  the status bar shows them; then the `"Warning"` rows can go.
- The panels show a non-positive `PageWidth`/`PageHeight` as "0 in" /
  "-1 in" while the canvas and the status bar fall back to 8.5 x 11 in
  (`FALLBACK_PAGE_SIZE`, P4-05). One rule for both in the parity pass.
- Property labels are the element names as written (e.g. "title"); the
  parity pass may want capitalized labels ("Title").
- A document property named "Warning" collides with the warning-row
  label (rare; harmless today, the rows are positionally after).
- `egui::Grid` id source is the panel title, so two instances of one
  panel would share an id (fine while the shell hosts one of each).
