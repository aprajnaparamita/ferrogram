## Result

Filled in by P3-12 (reviewer) on 2026-10-15, branch `agent/P3-12`.

**Verdict: approve with fixes — 0 blocker, 4 major, 8 minor.** Full
report: [`docs/reviews/phase-3-review.md`](../reviews/phase-3-review.md).

What was reviewed: `git diff phase-2..HEAD` for `larrygram-geom`,
`larrygram-model`, `larrygram-text`, `larrygram-render`,
`larrygram-vsdx` (the Phase 3 readers) and `apps/larrygram-cli`, against
AGENTS.md section 6, ADR 0002 and ADRs 0019–0027. No code was changed
(the reviewer role is read-only); this task owns only the report and this
section.

Findings (details and fixes in the report):

- **Major 1** `crates/render/src/build.rs:237`: `Ctx::finite` substitutes
  `0.0` for a non-finite cell number with no warning, the one silent
  substitution of the phase (ADR 0021 violation; the module docs promise
  `KindMismatch`). Non-finite cached numbers are reachable
  (`vsdx/src/read/value.rs:133` parses `inf`/`nan`/`1e999`).
- **Major 2** `crates/render/src/build.rs:1761` (`row_position`) with
  `crates/model/src/values.rs:150–245`: text row cells resolve by row
  position and never by `IX` when the shape lacks the row locally (the
  `ix as usize` fallback conflates the two namespaces), unlike the
  geometry rows, which pass `row_ix` per the ADR 0019 amendment.
- **Major 3** (the P3-07 decision): `PatternPaint`
  (`crates/render/src/scene.rs:99`) has no `filled` flag or tile stroke
  width, so PNG fills the tile path and SVG strokes open tiles as a
  hairline (`png.rs:533`, `svg.rs:580`). Latent with the shipped closed
  tiles. Fix decided: add `filled: bool` and `tile_stroke_width: f64` to
  `PatternPaint`, set from the template in `build_fill`, honor in both
  backends before the Phase 4 backend lands.
- **Major 4** (the P3-06 decision): `TextNode::rotation` and
  `TextRun::size` duplicate `text::Layout::rotation` and `GlyphPos::size`;
  the backends consume the layout fields, the scene fields are read only
  by docs and tests. Fix decided: keep the layout's two, remove the
  scene's two (`TextRun` keeps color/underline/strikethrough).
- **Minor 5** (the P3-11 decision): one shared cap for both backends —
  bound the device extent at 16384 px in PNG and SVG alike and add
  `Error::InvalidOptions` for a bad `scale` (also the P3-07 open item);
  the P3-11 test pinning the asymmetry changes.
- **Minor 6** (the P3-05 decision): a group's own geometry as the first
  child of its `Group` matches the ADR 0020 types and is drawn behind
  its sub-shapes; record the rule in an ADR 0020 amendment and check
  Visio's group z-order in the screenshot pass.
- **Minor 7** (the `e3d616f` check): builder and backends are correct on
  parent-relative transforms; one stale sentence in `scene.rs:27`
  ("maps it to the page").
- **Minor 8** ADR 0022 says degenerate curves degrade "and warn"; the
  degradation is silent (`geom` has no warning channel).
- **Minor 9** `exec.rs:233` prints builder `ErrorValue` prose as
  `cached error {:?}` (misattributed to the file's cached value).
- **Minor 10** `build.rs:1328` (`section_rows`) counts gradient rows via
  `master.shapes.first()` with a bound of 8, a different chain than the
  cell lookup.
- **Minor 11** backends skip un-drawable glyphs silently
  (`svg.rs:409–421`).
- **Minor 12** `BuildOptions::new` (background on) and `Default`
  (background off) disagree (`build.rs:141–156`).

Checks that passed: never-crash lints (clippy clean), parser
