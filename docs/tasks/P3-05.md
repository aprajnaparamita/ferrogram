## Goal

Build the scene graph of a page: every shape as a filled/stroked path with
the right transform, paint, stroke, shadow and text, warnings for bad
values, no panics.

## Interfaces

Implements (signatures fixed by P3-01):

```rust
pub fn build_scene(doc: &Document, page: PageId,
                   options: &BuildOptions) -> Result<Scene, Error>;
```

Consumes: `Document::shape_geometry`, `CellReader`, `Document::page_layers`
and `Document::shape_layers` (P3-02); `Curve::to_cubics` and `Path`
(P3-03); `text::layout` (P3-04); `VisualStyles` templates (P3-08). May add
private helpers in `build.rs` (row-to-path mapping, transform composition,
paint resolution) and documented public items only if the backends need
them (they should not: the scene is the contract).

## Acceptance criteria

- [ ] Every geometry row type maps to the right path — one test per

- [ ] Page size comes from the page sheet (`PageWidth`/`PageHeight`);

## Note from the master

P3-02 resolves `Themed` cached values and palette indices 0..23 inside
`CellReader::color` (see the master note in `docs/tasks/P3-02.md` and its
ADR 0021 amendment). Read colours only through `CellReader`; do not parse
`Themed` or indices in the scene builder. Add one test with a themed corpus
shape (for example from `blue-box.vsdx` or `tdf154379-QuickStyleFillMatrix.vsdx`)
whose fill is not the hard default.

P3-03 (merged) defines the knot convention in `crates/geom/src/curve.rs`
(module docs, "Knot vectors"): `Nurbs` takes the `n + 1` stored knots
(each point's knot plus `knot_last`), and `Spline::knots` is one knot per
control point plus a final knot. Assemble the lists from the `NURBSTo`
formula and the `SplineStart`/`SplineKnot` rows in that form. ADR 0022
does not say what happens when the `NURBSTo` formula does not parse: draw a
straight segment to the row's `X`/`Y` and record a warning, and add that
rule to ADR 0022 as an amendment. `Nurbs::x_type`/`y_type` are not applied
by `geom`: scale fractional coordinates by the shape's width and height
before calling `to_cubics`.


## Result

Filled in 2026-10-14. Branch `agent/P3-05`.

### What was built

- `crates/render/src/build.rs`: `build_scene` walks a page top-level
  shapes in file order, recurses into groups (depth cap 128, visited set)
  and builds the scene of ADR 0020. Implemented, with the policy the
  module docs list in full:
  - transforms exactly per ADR 0020 (`translate(Pin) · rotate(Angle) ·
    scale(FlipX, FlipY) · translate(-LocPin)`), children composed through
    the parent chain, tested against hand-computed matrices;
  - every `GeometryRow` variant mapped to a path through
    `Curve::to_cubics` at `0.25 / scale` inches (96 ppi default):
    `Rel*` rows scale by `Width`/`Height`, `NurbsTo` assembles its knots
    and weights from the formula plus the row's `A`..`D` (first and last
    control point), `SplineStart`+`SplineKnot` assemble one `Spline`,
    `Ellipse` flattens its conjugate-diameter parameterization,
    `InfiniteLine` clips to the page rectangle in shape-local space;
  - fills: solid, the `render::styles` tiles (unit-box convention, tile
    scaled to `spacing × line width`), and linear/radial gradients from
    the `FillGradient` stop rows (`FillGradientDir`/`FillGradientAngle`);
  - strokes: width, dash rhythms scaled by the width, caps, joins
    (`Rounding`), miter limit, and line ends from `BeginArrow`/`EndArrow`
    scaled by the `*ArrowSize` class;
  - shadows from the shadow cells and the `ShdwPattern` template;
  - text blocks: runs from `TextContent` and the
    `Character`/`Paragraph`/`Tabs` rows (font, size, `Style` bits,
    strike-through, colour with transparency, alignment, indents,
    spacing, bullets, tabs) laid out with `text::layout`;
  - layer visibility (a shape drops when every layer it names is
    invisible), background pages as a leading `Group` (cycle-safe), page
    size from `PageWidth`/`PageHeight`.
- `crates/render/src/scene.rs`: `TextNode` gained `runs: Vec<TextRun>`
  (per-run size in points, underline, strike-through, colour) and
  `rotation: Angle`, and the module docs now give the exact glyph
  placement recipe for the backends. `PatternPaint::tile` is documented
  as inches (the builder scales the unit-box tile).
- `crates/render/tests/build_scene.rs` (new): one test per
  `GeometryRow` variant (absolute and relative), transform composition,
  master inheritance (`dwg.vsdx`: instances with no local `Geometry`
  render the master's rows), a themed fill (`bgcolor.vsdx`), fills,
  strokes, line ends, shadows, text runs, layers, background pages, page
  size, bad-value warnings, and a run over every corpus page (no panics).
- `crates/render/src/build.rs` unit tests: 74 tests next to the code
  (row mapping, transforms, paints, text, layers, groups, cycles,
  clipping, ellipse flattening).
- `docs/adr/0022-geometry-semantics-and-curve-flattening.md`: amendment
  (the master note's rule) — an unparsable `NURBS(...)` formula draws a
  straight segment to the row's `X`/`Y` with one `ErrorValue` warning
  (replacing the "degree-3 B-spline from `A`..`D`" fallback), plus the
  knot-list assembly forms.

### Deviations from the P3-01 interfaces

- **`crates/model/src/values.rs` (outside the task's file list)**:
  `CellReader` gained `row_text`, `row_boolean` and `row_color`
  (`row_number` existed), with `text_from`/`color_from`/`list_from`
  factored out of `text`/`color`/`list` so every value policy (Themed,
  palette indices, defaults, warnings) stays inside the facade. Needed
  because text runs read `Character`/`Paragraph` row cells and gradient
  stops read `FillGradient` row colours; the master note ("read colours
  only through `CellReader`") rules out re-implementing the policy in
  `render`. Additive only; no signature changed. Flagged here and under
  open issues for review.
- **`crates/render/src/error.rs`**: added `Error::Model(ferrogram_model::Error)`
  for a stale page/shape id (the fixed `build_scene` signature returns
  `Result<Scene, Error>`; the existing variants did not fit). Same
  precedent as P3-08's `InvalidStyleData`.
- **`TextNode`**: the stub's fields cannot render text — a backend needs
  each run's size (points) and the block rotation the layout applied
  (ADR 0024 amendment says the backend rotates each glyph outline).
  Added `runs: Vec<TextRun>` and `rotation: Angle`; `glyph.run` indices
  (per paragraph in `text::Layout`) are remapped to index `TextNode::runs`
  globally, bullets included. The exact placement formula is in the
  `scene.rs` module docs.
- **`BuildOptions`** gained `scale: f64` (device pixels per inch,
  default 96) because the ADR 0022 tolerance `0.25 / scale` needs the
  target scale. `BuildOptions::default()` keeps `background: false`.
- ADR 0020 says scene paths are "in page coordinates", while the struct
  docs say `Shape::path` is shape-local with `Shape::transform` mapping
  to the page. Implemented per the struct docs (the ADR itself rejects
  baking transforms into paths); the ADR sentence needs a wording fix.

### Open issues

- **Model (review the deviation above)**: the `CellReader` row readers
  (`row_text`/`row_boolean`/`row_color`) were added to
  `crates/model/src/values.rs`, outside this task's file list. If the
  master prefers, they move to a follow-up task; `render` needs them for
  text runs and gradient stops.
- **Sparse geometry row sets** (corpus evidence): instances often carry
  only *some* `Geometry` rows (`bgcolor.vsdx`, `testfile1.vsdx` and
  others: two `LineTo` rows with `IX` 2..3 and every cell `F='Inh'`,
  while the master holds `MoveTo` + the closing rows). `shape_geometry`
  returns the shape's own rows whenever it has any, so the master's
  remaining rows do not appear and those shapes render as open
  polylines. A row-union (own rows override the master's rows matched by
  `IX`) in `Document::shape_geometry` would fix it; it is model code.
- **Themed colours in the corpus are variant encodings**: every
  `QuickStyle*Color` in the corpus is 100+ or 200+ (checked on all 15
  files), which the theme model answers with `UnresolvedTheme` + hard
  default (ADR 0021 amendment). A pure `Themed` fill therefore renders
  as no fill today (`FillPattern V='Themed'` too), so the themed-fill
  test uses `bgcolor.vsdx`, whose shapes cache their theme-derived fill
  (`THEMEGUARD(MSOTINT(THEMEVAL("AccentColor6"), 80))` → `#fff2cc`).
  Resolving the variant encodings needs the `a:fmtScheme` matrices
  (already an ADR 0021 open issue).
- **Warnings are chatty**: the ShapeSheet table has no `default_value`
  entries, so every cell a file omits (`FlipX`, `Angle`, ...) records one
  `Missing` warning per read. Real files therefore produce dozens of
  warnings per page. Either the table gains defaults (the P3-02 deferred
  item) or the CLI filters `Missing` on the transform cells.
- **Text block details**: `Txt*` placement cells are used only when the
  shape itself defines them (a master's `Txt*` values are ignored for
  resized instances; the shape box is used instead); `TextBkgnd` has no
  slot in `TextNode`; tab stops come from all `Tabs` rows' `Position`
  cells (a `tp` marker's row is not distinguished, and multi-stop rows
  are not read); a run's `BulletFont` is a FaceNames index (preserved
  only), so bullets use the run's family and our own symbols.
- **Approximations**: `Rounding > 0` becomes a round join (no geometry
  corner rounding); `LineCap` 0/1/2 maps to Round/Square/Butt (the
  reference's Rounded/Square/Extended); line gradients
  (`LineGradientEnabled`) are ignored (solid strokes); rectangular and
  path gradients (`FillGradientDir` 8..13) degrade to linear with a
  warning; the arrow size class scale (`ARROW_CLASS_IN`) and the tile
  pitch (`spacing × line width`, a zero line width falls back to 0.01 in)
  are ours and belong in the screenshot pass.
- `Scene::background` is always `None`: the model has no page colour
  cell, and Visio paints page backgrounds with background pages (which
  render as a leading `Group`). Revisit if a colour source appears.
- A group shape with its own geometry or text emits its shape node as
  the first child of its `Group` node.
