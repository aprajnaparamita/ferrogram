## Goal

Implement the geometry types the model and the `.vsdx` mapper need now: unit
conversions to and from canonical units, point/size/rect arithmetic, angles
and affine transforms. No path/arc/NURBS/spline types (Phase 3).

## Interfaces

Implements the stubs already in `crates/geom`:

```rust
impl Unit {
    pub fn to_canonical(self, value: f64) -> Result<f64, Error>; // lengths -> inches,
                                                                 // angles -> degrees,
                                                                 // percent -> fraction
    pub fn from_canonical(self, value: f64) -> Result<f64, Error>;
}
```

Adds the pure operations the stubs deliberately left out (signatures fixed
here):

```rust
impl Point {
    pub fn add(self, other: Point) -> Point;
    pub fn sub(self, other: Point) -> Point;
    pub fn scale(self, k: f64) -> Point;
}
impl Rect {
    pub fn width(self) -> f64;
    pub fn height(self) -> f64;
    pub fn union(self, other: Rect) -> Rect;
    pub fn contains(self, p: Point) -> bool;
}
impl Angle {
    pub fn from_radians(radians: f64) -> Angle;
    pub fn radians(self) -> f64;
}
impl Transform {
    pub fn translate(t: Point) -> Transform;
    pub fn rotate(a: Angle) -> Transform;
    pub fn scale(sx: f64, sy: f64) -> Transform;
    pub fn apply(self, p: Point) -> Point;
    pub fn then(self, next: Transform) -> Transform; // `next ∘ self`
    pub fn invert(self) -> Result<Transform, Error>; // singular -> Err, never panics
}
```

`Unit::to_canonical`/`from_canonical` return `Err(Error::NotImplemented)` no
longer: a unit outside a category (e.g. degrees for a length cell) is
`Err(Error::WrongUnit)` — add that variant in `crates/geom/src/error.rs`.
Every conversion is exact where the factor is exact (points: 1/72 inch) and
documented otherwise (miles, ciceros).

## Result

Filled in by P2-03 (worktree `agent/P2-03`).

### Built

- `crates/geom/src/units.rs`: `Unit::to_canonical`/`from_canonical` for all 19
  `Unit` variants (lengths to inches, angles to degrees, percent to fraction,
  `Unitsless` identity). Factors are exact where the definition is exact
  (feet 12, yards 36, miles 63 360, points 1/72, picas 1/6, millipoints
  1/72000, metric via the exact 25.4 mm international inch) and documented as
  approximate where not (ciceros: 12 didot points of 0.376 mm = 4.512 mm;
  radians: `180 / pi`, same rounding as `f64::to_degrees`).
- `crates/geom/src/units.rs`: new `UnitKind` (`Length`, `Angle`, `Ratio`,
  `Dimensionless`) with `Unit::kind()` and kind-checked
  `UnitKind::{to,from}_canonical(unit, value)`, returning
  `Err(Error::WrongUnit)` for a unit outside the expected kind (degrees for a
  length cell).
- `crates/geom/src/point.rs`: `Point::{add, sub, scale}`.
- `crates/geom/src/rect.rs`: `Rect::{width, height, union, contains}`
  (`contains` is edge-inclusive; `union` also normalizes two arbitrary
  corners).
- `crates/geom/src/angle.rs`: `Angle::{from_radians, radians}`
  (`f64::to_degrees`/`to_radians`).
- `crates/geom/src/transform.rs`: `Transform::{translate, rotate, scale,
  apply, then, invert}`. `then(self, next)` is `next ∘ self` (applies `self`
  first). `invert` returns `Err(Error::Singular)` for a zero or non-finite
  determinant and never panics.
- Tests: 52 unit tests plus 3 proptests (invert-of-composition round-trip and
  `invert(b) ∘ invert(a)` equality, `then` vs sequential `apply`, invert is an
  involution). `larrygram-geom` line coverage 100%.

### Deviations

- The fixed `Unit::to_canonical`/`from_canonical` signatures carry no cell
  category, so they cannot express "degrees for a length cell": they convert
  within the unit's own kind and always succeed. The `WrongUnit` check lives
  in the added `UnitKind::to_canonical`/`from_canonical`, which is what the
  model should call (it knows the cell's kind from the generated table).
  P2-04/P2-06 should use those and treat a unit-kind mismatch as a file
  error.
- `Error` replaces the stub variant `NotImplemented` with `WrongUnit` and
  `Singular` (the task named `WrongUnit` only; `Singular` is the error
  `Transform::invert` needs).
- Miles are exact (63 360 in = 5 280 ft x 12), so the factor is documented as
  exact; only ciceros and radians are approximate (the task implied miles
  might not be).

### New dependencies

  `larrygram-ui-spec`). No runtime dependencies.
