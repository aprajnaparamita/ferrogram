## Goal

Prove the Phase 5 exit criterion with one scripted test, and make the
parity matrix honest about command-only ids.

## Interfaces

- `cargo xtask parity` gains a second section in `docs/parity/controls.md`:
  a `| command | label | status |` table listing **every** registry id
  (including ids with no Fluent control: `app.quit`, `file.exit`,
  `view.units`, the Phase 5 editing ids), status derived as in ADR 0037
  (`implemented` / `stub` / `out-of-scope`). The existing control table
  is unchanged. `cargo xtask parity --check` fails on any drift.
- `apps/ferrogram/tests/flowchart.rs`: through `Shell` + `Registry` with
  `Source::Test`: `file.new`, ten `insert.shape` dispatches (a mix of
  process/decision/terminator masters from the stencils), five glued
  connectors (`connector.*`), `page.add` + shapes on page two,
  `file.save` to a temp path, `file.open` the same path, assert the ADR
  0048 model equality of saved and reopened documents, then `shape.move`
  a shape and `file.save` again successfully ("keep editing").
