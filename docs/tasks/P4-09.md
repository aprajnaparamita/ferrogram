## Goal

The Phase 4 exit criterion is proven by tests, and the parity matrix is
derived from the registry and gate-checked for freshness.

## Interfaces

Parity (ADR 0037):

```
cargo xtask parity            # regenerate docs/parity/controls.md
cargo xtask parity --check    # fail when the committed file differs
```

`xtask/src/extract/parity.rs` derives each control's status:
`implemented` when the control's `CommandId` (its `command` link, else
its `commands.yaml` entry) resolves in `ferrogram_commands::builtins::registry()`
to `CommandStatus::Implemented`; `out-of-scope` when the Fluent id is in
`ui-spec/out-of-scope.txt`; else `stub`. `xtask/src/gate.rs` adds the
`parity` step after `codegen` (in `STEPS` and `run_step`).

Tests (`egui_kittest::Harness` plus plain `egui::Context` where enough):

1. `apps/ferrogram/tests/open_corpus.rs` — the exit criterion. For each
   corpus `.vsdx`: `file.open` through `builtins::registry()` in a
   `Shell`, render one frame, assert `Ok`, assert the canvas raster is
   non-blank and matches `render::render_raster` of the same page within
   the ADR 0027 metric. `#[ignore = "needs corpus"]` unless
   `FERROGRAM_REQUIRE_CORPUS=1`.
2. `crates/ui/tests/phase4/ribbon.rs` — placement completeness for both
   layouts (extend P4-04's snapshots if they cover it; do not duplicate).
3. `crates/ui/tests/phase4/layout_switch.rs` — 2016 -> 365 without a
   restart (same `Context` and `AppCtx`), per ADR 0032.
4. `crates/ui/tests/phase4/enabled_state.rs` — stub vs implemented vs
   `Enabled::no(reason)` rendering and tooltips (ADR 0031).
5. `crates/ui/tests/phase4/file_flow.rs` — `NeedsInput` -> `FilePicker`
   test double -> re-dispatch with `path`/`data: Bytes` (ADR 0036).
6. `crates/commands/tests/headless.rs` — every registered command runs
   with `Source::Test` (extend P4-02's tests if present).
