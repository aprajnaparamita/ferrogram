## Goals

1. **Committed outputs load and validate.** In `crates/ui-spec/tests/committed.rs`:
   - Load the real files in the repository's `ui-spec/` with `Loader::load_all` (the workspace root is two levels above `CARGO_MANIFEST_DIR`).
   - Pin the real numbers: control counts per layout, number of commands, and number of shortcuts.
   - Assert `CommandLookup` invariants on both layouts:
     - every `commands` value is a known command id;
     - `fluent_by_command` is the exact inverse of `commands`;
     - every `command` in `shortcuts.yaml` has an entry in `commands.yaml`.
   - This closes the deferred P1-06b item in STATUS.md.
2. **Schema validation tests.** One xtask test validates each committed `ui-spec/*.yaml` against `ui-spec/schema.json` with the xtask validator. Also check that `ui-spec/shapesheet.toml` parses and has no duplicate section or cell names.
3. **One-command regeneration check.** Add `cargo xtask extract --check`.
   - It runs every extractor into a temp dir and compares each output byte-for-byte with the committed file.
   - It exits non-zero and lists the differing paths on any mismatch.
   - Add a test with a small fixture reference tree.
   - Do not add it to the gate: CI has no `reference/`. Record in the Result that the master runs it at each phase end.
4. **Property tests** (`proptest`, as a dev-dependency):
   - `xtask/src/extract/markdown.rs`: never panics on arbitrary input. A table that is rendered and then parsed again keeps its cells.
   - `shortcuts.rs`: the key-sequence parser never panics. Every chord it emits passes the schema's `keyChord` rule. Quoted YAML 1.1 boolean tokens (`Y`, `N`, `On`, `Off`) survive a write-then-read round trip.
   - `commands.rs`: the id derivation for any `visCmd[A-Za-z0-9]+` constant yields either an id that matches the schema `commandId` pattern or an error. It never yields an invalid id.
   - The out-of-scope glob matcher in `parity.rs`: never panics; `*` matches any string.
   - `crates/ui-spec`: the loader never panics on arbitrary bytes in any of the four files. It returns `Err`, never panics.
5. **Malformed-input tests** for the loader: truncated YAML, wrong top-level type, deep nesting, a 10 MB string label, duplicate keys, non-UTF-8 bytes. Each must give a `LoadError`, not a panic, and run in under a few seconds.
   - If something is unbounded, report it, or fix it in a `fix(ui-spec)` commit. Examples: recursion depth, or file size (consider a size cap in the loader).
6. **Fuzz target.** Add `crates/ui-spec/fuzz/` in the cargo-fuzz layout, with one target that feeds bytes to the loader's parse and validate path.
   - It must build with `cargo +nightly fuzz build`; the gate's fuzz step then stops skipping.
   - Exclude the fuzz crate from the workspace the usual cargo-fuzz way.
   - Run it locally for at least 5 minutes and report the result.
7. **Coverage.** Raise `xtask` line coverage as far as is useful. Raise `ferrogram-ui-spec` too if any loader branch is uncovered. Report before and after numbers per crate from `cargo xtask coverage`.
