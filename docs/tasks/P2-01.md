## Decisions to make (one ADR each where significant)

1. **Model shape** (`crates/model`, L1).
   - Document, pages, masters, shapes (including groups and sub-shapes), stylesheets, ShapeSheet sections, rows and cells.
   - Each cell keeps its formula, its cached value and its unit separately (ADR 0008 units; inches internally).
   - Choose an arena or index scheme for shapes and an id scheme that keeps Visio's `ID` and `NameU` values.
   - Plan for Phase 4 editing and undo: make the shape of mutations possible, without implementing them.
2. **Lossless preservation.** How unknown parts, elements, attributes, namespaces and element order are kept so they can be written back.
   - "Semantic XML equivalence" must be defined precisely, because the round-trip test depends on it. Cover attribute order, namespace prefixes, whitespace, number formatting, and self-closing versus empty elements.
3. **Inheritance lookup API.** Master/instance and stylesheet inheritance are resolved through a lookup, never flattened on load (KICKOFF). Define:
   - the resolution order (local cell, master shape, style chain, defaults);
   - how a caller sees where a value came from;
   - cycle handling.
4. **Crate split and dependencies.**
   - What goes in `vsdx` (OPC package, XML parts to model and back), in `model`, and in `geom` (units, points, transforms, at least what the model needs now).
   - Whether `shapesheet` (formula parsing) has any Phase 2 work. Formulas are stored as strings in Phase 2 unless you argue otherwise.
   - Pick the XML crate (for example `quick-xml`) and the zip crate (for example `zip` with only `deflate` via `miniz_oxide`). Check licences against `deny.toml` and advisories with `cargo deny check`. Reuse versions already in `Cargo.lock` where possible.
5. **Codegen** (ADR 0008).
   - Specify `cargo xtask codegen`: committed `ui-spec/shapesheet.toml` in, committed `crates/model/src/generated/shapesheet.rs` out, with a "generated, do not edit" header.
   - Add a gate check that fails when the generated file is stale.
   - Define what the generated code contains (section, row and cell enums or tables, types, default units) and how the model uses it.
6. **Stencils and templates.** Plan how `.vssx` and `.vstx` are read and written, which content types differ, and how they are tested with **hand-authored** fixtures only.
7. **Test strategy for the exit criterion.**
   - Round-trip every corpus `.vsdx` with semantic XML equivalence.
   - Property tests and malformed-input tests: zip bombs, huge part sizes, deep XML nesting, bad relationships, missing parts. Set the allocation and size caps.
   - A fuzz target for the package reader.
   - An oracle comparison against libvisio's raw dump: shape, page and master counts, plus key cell values. The tests find the oracle through `LARRYGRAM_LIBVISIO_ORACLE` (ADR 0010) and contain no libvisio code.
   - Schema validation of written files. Rust has no mature XSD validator. Choose an approach, for example `xmllint --schema` in a dev-only test that reads the XSD from `reference/` and skips with a message when either is missing. The XSD itself must not be committed unless its licence allows it; check and record.
   - Hand-authored minimal and malformed fixtures: where they live, how they are built (for example generated by a test helper rather than committed as binaries), and their provenance rows.

### Open issues

- **Angle unit:** ADR 0011 fixes degrees as the canonical angle unit. P2-06
  must verify the cached angle unit against the corpus and [MS-VSDX] and
  amend ADR 0011 if it is radians.
- **XSD licence:** ADR 0017 defers the `office-developer-client-docs` licence
  check to P2-09, which records it in `docs/sources.md`. Until then the XSD
  is not committed (default: never commit it).
- **Oracle coverage of `.vsdx`:** libvisio's tools are `.vsd` centric;
  P2-09's oracle tests compare what the oracle covers and say so (ADR 0017).
  The Phase 7 `.vsd` task gets the full oracle comparison.
- **Coverage ratchet:** `coverage.toml` `[ratchet]` has no entries for the
  four stub crates yet; only the master updates the ratchet at a phase end
  (AGENTS.md section 7). Suggested new numbers: geom 85.0, model 85.0, vsdx
  85.0, shapesheet 85.0 (the thresholds), to be tightened after P2-10.
- **`Resolved::via` size:** the provenance chain is a `Vec` on every lookup;
  fine for Phase 2, but Phase 3 rendering should measure and maybe pool it.
- **`Expr` in `shapesheet` is opaque with a private field.** It exists so the
  `parse` signature compiles; the formula-engine task owns its shape and may
  change the type freely.
