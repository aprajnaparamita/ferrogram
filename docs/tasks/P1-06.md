## Goal

Implement a loader for `ui-spec/visio-2016.yaml`,
`ui-spec/visio-365.yaml`, `ui-spec/commands.yaml` and
`ui-spec/shortcuts.yaml`. The loader:

1. Reads a YAML or JSON file from disk.
2. Validates the file against `ui-spec/schema.json` (the same schema
   the xtask extractor uses). The schema lives in the repository at
   `ui-spec/schema.json`; the loader resolves it relative to the
   workspace root via `CARGO_MANIFEST_DIR`.
3. Deserialises the validated data into the public types in
   `lib.rs` (the P1-02 stubs, updated to use `FluentId` for layout
   ids and `Option<CommandId>` on each `Control`).
4. Cross-checks references: every Fluent id in `commands.yaml` must
   appear in at least one layout; every control's `command` value
   must appear in `commands.yaml`; every shortcut's `command` value
   must appear in `commands.yaml`.
5. Builds a `CommandLookup` from the layout + commands.
6. Supports both layouts (2016 and 365) and a runtime switch via a
   `LayoutSwitch` API.

## Public API

```rust
use ferrogram_ui_spec::{
    CommandId, FluentId, LayoutKind, LayoutSet, Loader,
    CommandLookup, LoadError,
};

let loader = Loader::new(&workspace_root)?;  // loads the schema once
let set_2016 = loader.load(LayoutKind::Visio2016)?;
let set_365  = loader.load(LayoutKind::Visio365)?;

// The CommandLookup is built on demand from a LayoutSet.
// `labels` is keyed by FluentId; `commands` maps each FluentId to
// the CommandId it dispatches; `fluent_by_command` is the reverse
// index.
let lookup = set_2016.command_lookup();
assert!(lookup.labels.contains_key(&FluentId::new("FileSave")));
assert_eq!(
    lookup.commands.get(&FluentId::new("FileSave")),
    Some(&CommandId::new("file.save")),
);

// Layout switching: pick at runtime.
let active = LayoutSet::select(LayoutKind::Visio365, &set_2016, &set_365);
```

## Implementation notes

- **Validation first, then deserialize.** Use `jsonschema` to
  validate the raw YAML/JSON before turning it into our types. A
  validation failure returns `LoadError::Schema { path, message }`
  with the validator's error list joined by `; `. The schema is
  loaded once in `Loader::new`; the `Validator` is `Send + Sync`
  and cheap to clone (it holds an `Arc`).
- **YAML deserialization.** Use **`serde-saphyr`** (MIT, pure
  Rust) — not `serde_yaml` (archived) or `serde_yml` (RUSTSEC).
  The P1-02 review explicitly rejected those; see ADR 0007. P1-06
  adds `serde-saphyr` to `crates/ui-spec/Cargo.toml` and uses
  `serde_saphyr::from_str` into the typed structs after validation.
- **Cross-references.** Build two sets at load time:
  - `fluent_ids`: the union of every control id in the layout's
    QAT, tabs, groups, backstage tabs, and context menus.
  - `command_ids`: the set of every `commands.yaml` entry's `id`.
  Then:
  - For each entry in `commands.yaml`, every name in its
    `fluent_ids` must be in `fluent_ids` (collected above). A
    mismatch is `LoadError::CrossReference { kind: "fluent_id",
    id, referenced_by }`.
  - For every control in the layout, the optional `command` value
    (a `CommandId`) must be in `command_ids`. A mismatch is
    `LoadError::CrossReference { kind: "control_command", id,
    referenced_by }`.
  - For each entry in `shortcuts.yaml`, the `command` must be in
    `command_ids`. A mismatch is `LoadError::CrossReference { kind:
    "command_id", id, referenced_by }`.
- **`CommandLookup` builder.** Walks the layout once, recording
  for each `Control.id` (a `FluentId`):
  - its `label`,
  - its `command` link (an `Option<CommandId>`),
  - and reverse-indexing each `CommandId` to the `FluentId`s that
    surface it.
  Returns a `CommandLookup`. The lookup is `BTreeMap`-backed so
  iteration is sorted.
- **Layering.** `crates/ui-spec` is L0 (ADR 0002). It depends on
  `serde`, `serde-saphyr`, `jsonschema`, `thiserror` (all from
  crates.io; no workspace deps). Confirm `cargo xtask layers` is
  green.
- **No panics.** Workspace lints apply. The loader must not
  `unwrap`, `expect`, `panic!`, or `unreachable!`. Tests may use
  them via `clippy.toml`.
- **Schema is committed.** `ui-spec/schema.json` is the
  source of truth. The loader reads it at runtime via
  `include_str!` to avoid a runtime path lookup; the workspace
  root is passed in for the data files.

## Result

### What changed

- `crates/ui-spec/src/lib.rs` — the P1-02 public types unchanged in
  shape, plus `serde::Deserialize` support: `CommandId`/`FluentId`
  decode from strings, the four enums decode through their existing
  `parse()` vocabulary (so YAML strings stay single-sourced), and
  `Control.r#type` maps to the YAML key `type`. Module wiring and
  re-exports: `pub use error::LoadError; pub use loader::Loader;`.
- `crates/ui-spec/src/error.rs` (new) — `LoadError` (`Io`, `Schema`,
  `Parse`, `CrossReference`, `Unknown`) with `thiserror` Display
  impls. `CrossReference.kind` is `&'static str` so tests can match
  `kind: "fluent_id"` literally.
- `crates/ui-spec/src/loader.rs` (new) — `Loader` and `Loader::load`.
  Staged pipeline per document: read (`Io`), parse YAML or JSON into
  a raw value (`Parse`), validate against `ui-spec/schema.json`
  (`Schema`, validator errors joined by `; `), check the document is
  the kind of document that file holds (`Unknown`), decode into the
  typed model (`Parse`), then the three ADR 0007 cross-references
  (`CrossReference`): `fluent_id` (commands → layout), `control_command`
  (layout controls → commands) and `command_id` (shortcuts →
  commands). The schema is embedded with `include_str!` and compiled
  once in `Loader::new`; the `jsonschema::Validator` is `Send + Sync`
  and `Loader` is `Clone`.
- `crates/ui-spec/src/lookup.rs` (new) — `CommandLookup::build`
  (single walk: `labels` for every tab/group/backstage tab/context
  menu/control incl. aliases, `commands` for each control's primary
  id, `fluent_by_command` as the sorted de-duplicated reverse index),
  `LayoutSet::command_lookup`, `LayoutSet::select` (the runtime
  layout switch), and the shared `all_controls` walker.
- `crates/ui-spec/tests/loader.rs` (new) + `crates/ui-spec/tests/fixtures/`
  (new): hand-written fixture workspaces. `good/` is a complete
  consistent data set (both layouts + commands + shortcuts),
  `bad.yaml` violates the schema, `xref-fluent/`, `xref-control/` and
  `xref-shortcut/` each break exactly one cross-reference. 11
  integration tests drive the public API.
- `crates/ui-spec/Cargo.toml`, `Cargo.lock` — new dependencies (below).
  `Cargo.lock` is shared with P1-03/P1-05 (xtask dependencies); the
  master resolves the conflicts.

### Files the loader reads

From `Loader::new(workspace_root)`:

- `<workspace_root>/ui-spec/visio-2016.yaml` (`LayoutKind::Visio2016`)
  or `<workspace_root>/ui-spec/visio-365.yaml` (`LayoutKind::Visio365`)
  — the layout.
- `<workspace_root>/ui-spec/commands.yaml` — command mappings.
- `<workspace_root>/ui-spec/shortcuts.yaml` — keyboard shortcuts.

Each falls back to `<stem>.json` when the `.yaml` name is absent (the
loader reads YAML or JSON; `.json` paths are parsed as strict JSON).
`ui-spec/schema.json` is **not** read at runtime: it is compiled into
the binary via `include_str!("../../../ui-spec/schema.json")`, so the
schema in the repository is the schema the loader validates with.

### Deviations from the P1-02 public types

None in shape. Additive only: serde derive attributes on the existing
types, and the methods the task's public API requires
(`CommandLookup::build`, `LayoutSet::command_lookup`,
`LayoutSet::select`). Interpretations where the task was ambiguous:

- Goal 6's "LayoutSwitch API" is `LayoutSet::select(kind, &set_2016,
  &set_365)` exactly as the Public API section specifies; no separate
  `LayoutSwitch` type was added.
- `LoadError::Unknown` is defined as "schema-valid and parseable, but
  not the kind of document this file must hold" (e.g. a shortcuts
  table in `commands.yaml`). The other four variants cover the cases
  the task names.
- `fluent_by_command` is the exact reverse of `commands`: it lists
  each control's primary id only ("the primary path when a control has
  aliases"); aliases resolve to labels in `labels` but are not
  dispatch keys.
- The `fluent_id` cross-reference runs against the layout being
  loaded (per the task's implementation notes); see open issue 4.

### Open issues

1. **`ui-spec/schema.json` rejects `command: null`** (needs a
   one-line fix in a file this task does not own). The property is
   `"type": ["string", "null"], "$ref": "#/definitions/commandId"`;
   under Draft-07 the `$ref` overrides its siblings, so only the
   pattern applies and `null` fails — although the schema's own
   description ("or null if none"), ADR 0007 and
   `Control.command: Option<CommandId>` all require null to be
   allowed. Suggested patch:
   `"command": { "type": ["string", "null"], "anyOf": [ { "$ref": "#/definitions/commandId" }, { "type": "null" } ] }`.
   Until then every control in a valid document must carry a concrete
   command id (the fixtures do). P1-03/P1-04 will hit this the first
   time an extractor emits a null command.
2. **`ui-spec/schema.json` root `oneOf` rejects empty tables.** An
   empty list `[]` validates as both a `commands` and a `shortcuts`
   document, so `oneOf` fails ("valid under more than one") and an
   empty `commands.yaml`/`shortcuts.yaml` cannot be expressed.
   Suggested fix: use `anyOf` at the root (the loader disambiguates
   by shape), or discriminate the two array definitions explicitly.
3. **YAML 1.1 booleans in shortcut key tokens.** Plain `Y`, `N`,
   `on`, `off` are parsed as booleans by serde-saphyr (the schema
   then rejects the chord: `keyChord` must be a string). The
   shortcuts extractor (P1-04) must quote such tokens in
   `shortcuts.yaml` (`[Ctrl, "Y"]`). Found while writing the good
   fixture; noted for P1-04.
4. **Cross-reference strictness vs ADR wording.** The `fluent_id`
   check runs against the layout being loaded (the task's
   implementation notes), so every Fluent id listed in `commands.yaml`
   must exist in *both* layouts. ADR 0007 says "must appear in at
   least one layout"; if that reading is intended, the check needs
   both layouts at once (e.g. a `Loader::load_all()` returning both
   sets). The acceptance case ("not in any layout") is rejected under
   both readings. Master decision needed before the real files land.
5. **Minor:** `ContextMenu.label`'s doc comment says it "can be empty
   for canvas context menus", but the schema requires labels of
   1..=80 characters. The loader follows the schema; the doc comment
   (or the schema) should be aligned at some point.
