## Goal

Build a dev-only harness for libvisio's CLI tools (`vsd2raw`,
`vss2raw`, `vsd2xhtml`, `vss2xhtml`, `vsd2text`, `vss2text`) and
a small `cargo xtask oracle` task that wraps the build. The
harness is **optional for the gate**: a missing build does not
fail the gate; a test that uses the oracle is gated behind
`FERROGRAM_REQUIRE_ORACLE=1` (set in CI on Linux and macOS, not
Windows). See ADR 0010.

## Build script: `tools/libvisio-oracle/build.sh`

- Args: `build`, `clean`, `status`. Default: `status`.
- Resolves the build directory as
  `/Volumes/Dara/ferrogram/build/libvisio-oracle/` by default.
  Override with `--build-dir <path>` or the
  `FERROGRAM_LIBVISIO_BUILD_DIR` env var. CI sets
  `FERROGRAM_LIBVISIO_BUILD_DIR` on Linux runners (e.g. to
  `$HOME/libvisio-oracle`).
- `status`: prints `built` and exits 0 if all six binaries exist
  under `<build-dir>/bin/`. Prints `not built` and exits 0 if
  anything is missing. Exits non-zero only on a hard error
  (cannot read the directory).
- `build`:
  - If `status` is `built`, exit 0.
  - `mkdir -p "$BUILD_DIR"`. If `<build-dir>/src/libvisio/` is
    empty, `git clone --depth 1` libvisio from
    `https://git.libreoffice.org/libvisio` into that directory and
    `git -C src/libvisio checkout c7c970775b750a4bf7fd1b4364d69bac9815bfcb`
    (the commit hash from `NOTICE` and `docs/sources.md` source 6).
    The `--depth 1` clone avoids pulling the full history; the
    checkout restores the exact commit we want.
  - `cd src/libvisio && ./autogen.sh && ./configure --prefix="$BUILD_DIR" --disable-werror`.
  - `make -j"$(nproc 2>/dev/null || sysctl -n hw.ncpu)"`
  - `make install` (which writes to `$BUILD_DIR/bin/`).
  - On any error, exit non-zero with the failing command's output.
- `clean`: `rm -rf "$BUILD_DIR/bin" "$BUILD_DIR/src"`. Exit 0.
- A `--jobs N` flag overrides the parallelism (CI uses `-j 2`).
- The script is POSIX sh; no bash-isms. It must work on macOS,
  Linux, and the build containers used by CI.

No `tools/libvisio-oracle/libvisio/` submodule is created. The
P1-02 review explicitly rejected submodules (M3): libvisio's
source tree would fill the main drive in every worktree, and the
build script already pins the commit at `c7c970775b750a4bf7fd1b4364d69bac9815bfcb`.
No `tools/libvisio-oracle/Cargo.toml` is created; there is no
wrapper crate. The 10-line `oracle_dir()` helper used by tests
lives in the consumer crate's own `tests/common/`.

## `xtask/src/oracle.rs`

A small module wrapping `build.sh`. The public API:

```rust
/// Outcome of `build.sh status`.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum OracleStatus { Built, NotBuilt }

/// The build dir resolved from `FERROGRAM_LIBVISIO_BUILD_DIR` or
/// the default path. Returns the status and the path so the
/// caller can echo them.
pub fn status() -> (OracleStatus, std::path::PathBuf);

/// Runs `build.sh build [--build-dir <path>]` and returns the
/// captured stdout. The script is in
/// `tools/libvisio-oracle/build.sh`; its path is resolved from
/// the workspace root.
pub fn build() -> Result<String, String>;

/// Runs `build.sh clean` and returns the captured stdout.
pub fn clean() -> Result<String, String>;
```

`xtask/src/main.rs` adds an `oracle` task:

```
cargo xtask oracle status
cargo xtask oracle build [--build-dir <path>]
cargo xtask oracle clean
```

`status` calls `OracleStatus` and prints `oracle: built` or
`oracle: not built` for the gate summary. `build` calls
`OracleStatus::build` and surfaces failures. `clean` calls
`OracleStatus::clean`. CI runs `cargo xtask oracle status` before
the gate on Linux and macOS; if `not built`, the oracle-using
tests are skipped (they are `#[ignore]`).

## How tests find the oracle

Tests in any crate's `tests/` directory (e.g.
`crates/vsd-binary/tests/oracle_smoke.rs`) call a small helper:

```rust
fn oracle_dir() -> Option<PathBuf> {
    let p = std::env::var_os("FERROGRAM_LIBVISIO_ORACLE")?;
    let p = PathBuf::from(p);
    if p.is_dir() { Some(p) } else { None }
}
```

The helper returns `Some(path)` when `FERROGRAM_LIBVISIO_ORACLE`
is set to a directory that exists, and `None` otherwise. Tests
that need the oracle are `#[ignore]` by default and are included
only when the helper returns `Some`. Setting
`FERROGRAM_REQUIRE_ORACLE=1` in addition to
`FERROGRAM_LIBVISIO_ORACLE` flips the gate so a missing oracle is
a failure (CI on Linux and macOS does this). The helper is
~10 lines plus a unit test; the P1-07 task copies it into
`crates/vsd-binary/tests/common/mod.rs` and into
`xtask/src/oracle.rs` (the same shape) so the two call sites
share the same logic.

      coverage does not drop below the ratchet.
