## Goal

Produce three Phase 1 outputs from their respective reference sources
and one codegen file for `crates/model`:

1. `ui-spec/commands.yaml` — the Ferrogram command registry's mapping
   table. Each entry maps a Ferrogram command id to its VisUICmds
   constant and to its Fluent control names. See ADR 0006 and ADR 0007.
2. `ui-spec/shapesheet.toml` — the canonical catalogue of every
   ShapeSheet section, row, and cell that Ferrogram knows about. See
   ADR 0008.
3. `ui-spec/shortcuts.yaml` — the keyboard shortcut table. See ADR 0007.
4. `crates/model/src/shapesheet_table.rs` — a generated Rust file
   that exposes the TOML as a `pub static SECTIONS: &[Section]` and
   `pub static CELLS: &[Cell]` slice. See ADR 0008.

The merge file `xtask/src/extract/commands.rs` is new (it doesn't
have a P1-02 stub because the merge is only useful once P1-03 has
written the layouts). It calls `visuicmds::run` and reads the
P1-03 layouts from `ui-spec/`, joins them on `fluent_ids`, and
writes the final `commands.yaml`. The dispatcher in
`xtask/src/extract/mod.rs` is updated to call `commands::run` after
`visuicmds` and to drop the `visuicmds` row from the per-extractor
output list (the dispatcher logs `commands` instead). Wire
`Schema::validate_file` for `commands.yaml` and `shortcuts.yaml`.

## Outputs

### `ui-spec/commands.yaml`

A YAML list of command mappings, in the order:

1. VisUICmds that have a Fluent control mapping (`mapping_confidence: exact`).
2. VisUICmds that have only an inferred Fluent mapping
   (`mapping_confidence: inferred`).
3. VisUICmds with no Fluent mapping yet (`mapping_confidence: unknown`).

Inside each group, sorted by command id. The merge algorithm:

- For every VisUICmds constant `visCmd*`, derive a Ferrogram command
  id by stripping `visCmd` and lowercasing the first letter:
  `visCmdFileSave` → `file.save`. Multi-word constants are split
  on CamelCase boundaries: `visCmdAlignObjectLeft` → `align.object.left`.
  Override these splits with a small hand-written table in
  `xtask/src/extract/commands.rs::OVERRIDES` for cases where the
  CamelCase split gives the wrong scope (e.g.
  `visCmdABarAutoHeight` → `a_bar.auto_height` rather than
  `a.bar.auto.height`).
- Cross-check every Fluent control name in `commands.yaml` against
  `ui-spec/panel-2016.yaml` and `ui-spec/panel-365.yaml`. A Fluent
  name that appears in neither is a hard error (the cross-check is
  part of `commands::run`).
- A `label` is taken from the Fluent `Control Name` if available,
  otherwise from a hand-written table in
  `xtask/src/extract/commands.rs::LABELS` for the top 100 VisUICmds.
  Anything without a label uses the command id's last segment
  capitalised (e.g. `file.save` → `Save`). All labels are short;
  clean-room rule 4 still holds.

### `ui-spec/shapesheet.toml`

The shape is in ADR 0008. The extractor walks
`reference/ms-vsdx/office-developer-client-docs/docs/visio/`:

- Files matching `<name>-section.md` (no `cell-` substring) are
  sections. The section name is the title text before
  `(ShapeSheet)` or `(Visio)`. The `section_index` is looked up from
  `visio.vissectionindices.md`.
- Files matching `<cell>-cell-<section>.md` are cells. The cell name
  is the file's first word. The `cell_index` is looked up from
  `visio.viscellindices.md`. The `type` and `default_unit` are
  inferred from the cell's remark text using a small
  pattern-matching table in `xtask/src/extract/shapesheet.rs`.
- The four enumeration files are loaded for the integer lookups.
- The file is sorted by section name, then by cell name, then by
  row name. Output is deterministic (see the unit test).

### `ui-spec/shortcuts.yaml`

A YAML list of shortcuts. The extractor parses the HTML, finds each
`<table>`, walks the rows, and produces a `Shortcut` for each. The
mapping from a Microsoft action description ("Save", "Undo") to a
Ferrogram command id is a hand-written table in
`xtask/src/extract/shortcuts.rs::ACTION_TO_COMMAND`. Anything not in
the table is dropped with a warning to `stderr` and recorded in the
Result section. The 365 layout's command ids are preferred; the
2016 layout's ids are used as a fallback when a 365 id does not exist.

A header comment in the file records the Wayback snapshot URL and the
extraction timestamp.

### `crates/model/src/shapesheet_table.rs` (generated)

```rust
//! GENERATED by xtask extract. Do not edit.

#![allow(clippy::all)]

/// One ShapeSheet section as known to the model.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Section {
    pub name: &'static str,
    pub section_index: u16,
    pub kind: SectionKind,
    pub default_unit: Option<&'static str>,
}

/// One ShapeSheet cell as known to the model.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Cell {
    pub section: &'static str,
    pub name: &'static str,
    pub cell_index: u16,
    pub type: CellType,
    pub default_unit: Option<&'static str>,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SectionKind { Object, Collection }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum CellType { Number, String, Bool, Color, List }

pub static SECTIONS: &[Section] = &[ ... ];
pub static CELLS: &[Cell] = &[ ... ];
```

The build script reads `ui-spec/shapesheet.toml` and emits this file.
If the TOML is missing, the build script emits an empty `SECTIONS` and
`CELLS` and prints a warning. `cargo check` always succeeds; the
table's emptiness is a `cargo xtask extract` failure, not a build
failure.

## Implementation notes

- **Markdown table parsing.** The VisUICmds and enumeration files use
  a stable `| Constant | Value |` table format. A small hand-written
  parser in `xtask/src/extract/markdown.rs` (new, lives in this task)
  is enough — `pulldown-cmark` is overkill.
- **TOML writing.** Use the `toml` crate (already in xtask). Build
  `toml::Value::Table` and `toml::to_string_pretty`.
- **Build script.** `crates/model/build.rs` reads the TOML, builds the
  `Section` / `Cell` literals, and writes
  `crates/model/src/shapesheet_table.rs`. The script uses
  `cargo:rerun-if-changed=../../ui-spec/shapesheet.toml` so the
  generated file is rebuilt on every `cargo xtask extract`.
- **Cross-check.** `commands::run` loads `ui-spec/panel-2016.yaml`
  and `ui-spec/panel-365.yaml` (which P1-03 already produced) and
  reads their Fluent control names. Any `commands.yaml` entry whose
  `fluent_ids` includes a name absent from both layouts is an
  `Err(ExtractError::Schema { .. })`.
- **License.** `calamine` is MIT, `serde_yaml` is MIT, `toml` is
  MIT/Apache-2.0 (already in xtask). `cargo deny check` must remain
  green.
