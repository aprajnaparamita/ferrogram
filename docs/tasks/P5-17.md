## Goal

1. **Tool commands.** Implement a handler for each tool id that selects
   a tool:
   - pointer, rectangle, ellipse, line, connector and text;
   - choose one id per tool from `commands.yaml`, and say in the Result
     which ids alias which tool.
   - The active tool lives on `AppCtx` as a commands-layer enum. `ui`
     maps it to its `Tool`, because `commands` cannot depend on `ui`.
   - Choosing a tool is not an edit: no undo step and no change bump. It
     cancels any drag in flight.
   - The enabled predicate is "a document is open". Each tool command
     reports itself as checked when it is the active tool, if the
     registry has a checked-state seam; otherwise list that under Open
     issues.
2. **Wire the UI.** The ribbon buttons and the shortcuts for these ids
   then work through the registry with no extra code: check this with a
   test. The shell reads the active tool from `AppCtx` each frame and
   sets `ToolMachine::tool`. Escape returns to the pointer tool if Visio
   does that; check `shortcuts.yaml`.
3. **Shapes-window drag.** When a drag starts on a Shapes-window master
   row, call `stencil::begin_drag`. While `stencil::is_dragging` is true,
   the shell sends canvas pointer events to `stencil::handle`, whatever
   the active tool. A release over the canvas drops the shape, through
   `insert.shape`. A release elsewhere, or Escape, cancels the drag.
4. **Indexed connection points.** Add `Document::connection_points_indexed`
   (or change the existing function), returning `(row index or IX,
   point)` pairs, so a glue record names the exact row even when
   `connection_points` skips a malformed row. Update the stencil drop's
   glue, and P5-08's connector glue if it uses the same scan.

5. **Show the text editor.** The shell owns one `TextEditor`.
   - It opens the editor when `text.begin` succeeds on a shape. That
     happens after the text tool creates a box, and after a double-click
     on a shape that is not a group. Today the pointer's double-click
     enters a group; on a non-group shape it emits `text.begin` instead.
     Typing on a selected shape may also open it, if `shortcuts.yaml`
     or ADR 0044 says so.
   - Each frame, while the editor is active, place it with
     `text_edit::editor_rect` and call `TextEditor::show`.
   - On commit, dispatch `shape.set.text` with the new text: one undo
     step, and no step when nothing changed. On cancel, dispatch
     `text.cancel`.
   - Keyboard focus in the editor activates the `Text` shortcut scope
     (ADR 0036).

6. **A connector's free end.** P5-08 open issue 2: when a connector drag
   ends over empty canvas, that end is unglued, and the connector keeps
   its master's default diagonal geometry instead of reaching the
   release point. Let the connector tool pass the free end points (for
   example optional `begin_x`/`begin_y`/`end_x`/`end_y` arguments, in
   page inches, on the glue commands or on a small
   `connector.set_ends` command). Route between a glued end and a free
   point the same way as between two glued ends. One drag stays one undo
   step.

## Result

### What changed

- **Tool commands** (`crates/commands/src/builtins/tools.rs`, new):
  `AppCtx::active_tool` (the new `ActiveTool` enum) is the per-application
  tool choice. Every handler only sets it: no undo step, no change-counter
  bump. Enabled predicate: `has_document`. The aliases are
  `tools.pointer`, `tools.rectangle` + `shape.rectangle` (rectangle),
  `tools.ellipse` + `shape.ellipse` (ellipse), `shape.line` (line; there
  is no `tools.line` row), `tools.connector`, and `tools.text`.
- **Shell wiring** (`crates/ui/src/shell.rs`): each frame
  `sync_active_tool` mirrors `AppCtx::active_tool` into
  `ToolMachine::tool`; a change replaces the machine, which cancels any
  drag in flight. The shortcut and ribbon paths therefore work with no
  tool-specific UI code (a kittest presses `Ctrl+8` and draws one
  rectangle).
- **Shapes-window drag** (`shapes_window.rs`, `shell.rs`): a master row
  has a click-and-drag sense; a drag start is taken by the shell and
  calls `stencil::begin_drag`. While `stencil::is_dragging` is true the
  shell routes canvas pointer events to `stencil::handle` whatever the
  active tool, synthesizing the first `PointerDown` because the gesture
  started outside the canvas. Release over the canvas drops through
  `insert.shape`; Escape or a release outside cancels. A drag that leaves
  and returns to the canvas stays alive.
- **Text editor** (`shell.rs`, `canvas.rs`): the shell owns one
  `TextEditor`. A successful `text.begin` (from the text tool or the
  pointer tool's non-group double click) opens it; each frame
  `canvas::show_text_editor` places it with `text_edit::editor_rect`.
  Commit dispatches `edit.select` for the edited shape and then
  `shape.set.text` (one undo step, nothing when unchanged); `text.cancel`
  closes it. The `Text` shortcut scope is active while it is open. The
  pointer tool's `DoubleClick` branch now emits `edit.select` +
  `text.begin` for a non-group shape and still emits
  `edit.select` + `shape.enter_group` for a group.
- **Indexed connection points** (`model/src/connection.rs`):
  `Document::connection_points_indexed` returns `(row IX, point)` pairs;
  `connection_points` delegates to it. A malformed middle row no longer
  renumbers the good rows. The stencil drop (`insert.rs`), the connector
  tool and the connector glue/re-route code use the indexed form, so a
  `Connect` record names the file's `Row/@IX`.
- **Connector free end** (`commands/.../connector.rs`,
  `ui/src/tools/connector.rs`): a new `connector.draw` command inserts
  the connector, applies its endpoint glues and writes the routed path
  in one `CompositeEdit`, so one drag is one undo step. Its arguments are
  `stencil`, `master`, `x`, `y`, optional `begin_target`/`begin_point`,
  `end_target`/`end_point` and optional `begin_x`/`begin_y`/`end_x`/`end_y`
  (page inches). A free end is routed exactly like a glued one; the
  connector tool now emits this one intent instead of `insert.shape` plus
  two glue intents.
- **Tests**: `crates/commands/tests/tools.rs` (13 headless tests: every
  tool id and alias, no edit/change bump, disabled without a document,
  one-step glued/free connector drags through the registry, free-begin,
  rollback on a bad target, malformed arguments, indexed connection
  points are covered in `crates/model/tests/connection.rs`, plus a
  reroute-failure warning path), `crates/ui/tests/phase5/tools.rs`
  (4 `egui_kittest` tests through the real `Shell`: shortcut tool choice
  plus rectangle drag, Shapes-window drop and Escape cancel, double-click
  text edit in one undo step, double-click group entry).

### Deviations (closest correct version)

1. **`connector.draw` is a new Ferrogram-only id.** The task allowed the
   free end on the glue commands or on a small `connector.set_ends`
   command; neither can also fold the insertion into the drag's one undo
   step. `connector.draw` is registered in `ui-spec/commands.yaml`,
   `xtask/src/extract/commands.rs` (`OUR_COMMANDS`) and the committed
   count pin (`976` to `977`). This is one data row outside the literal
   Owns list; it is required by Goal 6's "one drag stays one undo step".
2. **The command layer cannot cancel a drag.** Tool handlers only set
   `AppCtx::active_tool`; the shell detects the change and replaces the
   `ToolMachine`. A headless caller choosing a tool has no machine to
   cancel.
3. **No checked-state seam.** `CommandMeta`/`Registry` have no checked
   state, so a tool command cannot report itself checked; the shell reads
   `AppCtx::active_tool` for its own state. Listed as an open issue.
4. **Escape is consumed by the shell when the editor or a stencil drag
   owns it.** `shortcuts.yaml` binds `Esc` to `view.full_screen_mode`,
   and the shortcut pass runs before the canvas; without this the editor
   could never commit on Escape (ADR 0044) and the drag could never
   cancel. The full-screen binding still fires when neither owns Escape.
5. **`run_draw` calls the `insert.shape` handler directly** and folds its
   applied edit, the glue edits and the path edit into one
   `CompositeEdit`; on any later failure it reverts what it applied. The
   materialised catalog master still stays behind after undo, as in
   P5-06.
6. **`crates/commands/src/builtins/insert.rs` was touched** beyond the
   Owns list: Goal 4 explicitly requires the stencil drop's glue to use
   the indexed points. The change is limited to `connection_points_indexed`
   call sites and the nearest-point helpers' return values.
7. **Escape returning to the pointer tool is not implemented.**
   `shortcuts.yaml` has no binding for it and Visio's behaviour is
   not checked, so the "if Visio does that" branch was left out.
8. **A non-group double click selects before it edits** (`edit.select`
   then `text.begin`), because `text.begin` reads the selection.

### Open issues

1. **Checked-state seam.** The registry has no checked state for toggles;
   a later change should add one so tool commands report themselves
   checked (and ribbon toggles can use it).
2. **Typing on a selected shape does not open the editor.** ADR 0044
   leaves it optional and `shortcuts.yaml` has no binding; add it when
   a black-box check settles the exact gesture.
3. **Escape to the pointer tool** is not bound and not implemented (see
   deviation 7).
4. **Tool choice is application-wide, not per document.** A document
   switch keeps the current tool; Visio may reset it. Screenshot-pass
   item.
5. **The text editor still collapses multi-run text** to the first-row
   markers (P5-07/ADR 0044 limit), now also reachable through double
   click.
6. **A connector whose connector shape itself is moved** keeps the free
   endpoint in its local geometry, so the free point travels with the
   connector; Visio's exact free-end behaviour is not observed yet.
7. **Commands coverage is inherited-red after the rebase.** `main` is
   at 97.9% against the 98.1 ratchet because of the merged P5-09 code;
   P5-18 is the tests-only task that restores it. Until P5-18 lands, any
   rebased worker sees this ratchet failure. This branch does not lower
   the rebased tree further (98.1% before the rebase; 97.9% equal to
   `main` after it).
