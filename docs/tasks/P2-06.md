## Interfaces


Consumes (from P2-05, merged): `read_package` already parses every XML part
into `PartData::Xml(XmlNode)`, enforcing `max_xml_depth` and
`max_attributes_per_element`. The helpers are `pub(crate)` in
`crates/vsdx/src/package/xml.rs`:

```rust
pub(crate) fn parse_xml(text: &str, limits: &Limits) -> Result<XmlNode, Error>;
pub(crate) fn write_xml(node: &XmlNode) -> String;
```

Notes from P2-05 (see its Result):

- Two corpus files (`recursion-cycle.vsdx`, `tab-short-prefix.vsdx`) have no
  `[Content_Types].xml`. The package reader then infers `application/xml`
  for every `.xml` part. Find the main document part through the package
  root relationship (`/_rels/.rels`), not only by content type, and default
  `DocumentKind` to `Drawing` when the content type is the inferred
  `application/xml`.
- The XML declaration is not kept in `XmlNode`. The package writer emits
  `<?xml version="1.0" encoding="UTF-8" standalone="yes"?>` on every XML part.

Mapping rules (documented in the module docs):

- `pages.xml` + `page{N}.xml` -> `Document::pages` and the shape arena;
  `masters.xml` + `master{N}.xml` -> `Document::masters` and master shapes;
  `document.xml` -> stylesheet, document properties, root `Preserved`.
- Shape `Cell`/`Section`/`Row`/`Cell` elements map to `Sheet`; cell `U` is
  the `Unit`, `V` the cached value (canonical units, ADR 0011), `F` the
  formula string.
- Every unmapped attribute goes to the entity's `Preserved::attributes`;
  every unmapped child to `Preserved::children`, in order.
- Malformed-but-recoverable input degrades, never panics: a missing master
  part gives `Master::shape: None`. `CellValue::Error(raw)` is only for
  cached error values (`#VALUE!`). A numeric value that fails to parse for
  its declared unit is `Err(Error::InvalidPackage)` naming the part and the
  cell.
- `Document::kind` from the main part's content type (ADR 0016).

## Note from the master (after P2-04 merged)

**Cell and section names.** `.vsdx` spells some cells and sections
differently from `ui-spec/shapesheet.toml` (for example `ColorTrans` /
`Transparency`, `BulletStr` / `BulletString`, `HorzAlign` / `HAlign`,
section `Connection` / `Connection Points`, `Property` / `Shape Data`; see
the P2-04 Result). Decision:

- The model stores names **as spelled in the file** (`N` / `T` / `IX`
  attributes), because MS-VSDX is the source of truth for `.vsdx` and the
  writer must emit them unchanged. Do not rename to table spellings.
- Add `crates/model/src/aliases.rs`: a hand-maintained table that maps a
  file spelling to its ShapeSheet-table spelling, with
  `pub fn table_name(file_name: &str) -> &str` (identity when there is no
  alias). Use it only where `lookup.rs` looks a name up in the generated
  table (the section-default rung and the section-to-style selection), so
  those rungs work for file spellings. Local, master and style cells keep
  matching by file spelling.
- Build the alias list from the corpus: add a test that reads every corpus
  file and lists the cell and section names with no table entry, after
  aliasing. Record that list in your Result. Every entry must be either
  aliased or explained (for example, a cell the table does not cover).

**`Error::NotImplemented`.** Leave the variant in `ferrogram_model::Error`.
It is removed together with the `vsdx` one after P2-07.

### What was built

- **`crates/vsdx/src/read/`** (new files `node.rs`, `sheet.rs`, `value.rs`,
  and `mod.rs` with `read_document` / `to_model`). The part table of the task
  is implemented as specified: `pages.xml` + `page{N}.xml` -> `Document::pages`
  and the shape arena, `masters.xml` + `master{N}.xml` -> `Document::masters`
  and the master's content shape, `document.xml` -> the stylesheet and the
  root `Preserved`, `docProps/core.xml` + `docProps/app.xml` ->
  `Document::properties`. Every other part is left in the `Package` untouched
  (the reader never modifies the package). The main document part is found
  through the package root relationship (`/…/document`), with a content-type
  fallback, and `Document::kind` follows the main part's content type (ADR
  0016): `application/xml` (the inferred type of the two corpus files without
  `[Content_Types].xml`) is a `Drawing`.
- **Sheet mapping.** `Cell`/`Section`/`Row`/`Cell` map to `Sheet`, `Section`,
  `Row` and `Cell` with the file's spellings (`N`, `T`, `IX`). `Cell` keeps
  `N` (name), `F` (formula, as written: `Inh`, `No Formula`, a formula), `V`
  (cached value), `U` (declared unit) and `E` (cached error) separately
  (ADR 0011). Group sub-shapes map to arena shapes with parent/child links,
  walked with an explicit stack (bounded by the input, never recursive).
- **Cached values (`read/value.rs`).** The corpus and [MS-VSDX] 2.2.5.3.3.1
  agree that `V` is written **in canonical units whatever `U` declares**:
  `PageWidth V='11.69291338582677' U='MM'` is a 297 mm page in inches,
  `Angle V='1.5707963267949' U='DEG'` a right angle in radians,
  `Value V='0.8' U='PER'` 80% as a fraction. So no conversion happens on
  read (nor is one needed on write), and `U` only declares the *kind* of the
  value and the unit spelling kept in `Cell::unit`. The `U` codes are the
  [MS-VSDX] table (`MM`, `PT`, `IN_F`, `DA`, `DL`, …); codes that name a
  `Unit` variant map to it (`IN`/`FT`/`YD`/`MI`/`MM`/`CM`/`M`/`KM`/`PT`/`P`/
  `C`/`DEG`/`RAD`/`PER`), every other code (`BOOL`, `STR`, `COLOR`, `DATE`,
  `GUID`, `DT`, `IN_F`, `NM`, …) has no `Unit` spelling and the `U` attribute
  stays in `Cell::preserved` (`NM` is nautical miles, deliberately not
  `Unit::Nanometers`). Value kinds: `BOOL` -> `Bool`, `COLOR` -> `Color` for
  `#RGB`/`#RRGGBB` literals (else `Str`), `STR`/`DATE`/`GUID`/`PNT` -> `Str`,
  numeric codes -> `Number` (a value that does not parse is
  `Error::InvalidPackage` naming the part and the cell), and an unknown or
  absent code classifies by the value's own shape. `E` makes the value
  `CellValue::Error`; then `V` and `U` stay in `Preserved` (one value slot
  per cell, the written value must not be lost).
- **Preservation (ADR 0012).** Every attribute a model field does not take
  goes to the entity's `Preserved::attributes`, every child element no field
  takes to `Preserved::children`, in document order. Namespace declarations
  are neither mapped nor preserved (`diff` ignores them; a write synthesizes
  them, per the P2-07 rule). Where several source elements map to one entity
  (a page and its page sheet and page-contents root), their unmapped content
  merges into that one `Preserved` in depth-first document order.
- **`crates/model/src/aliases.rs`** (new) plus `mod aliases` in `lib.rs` and
  the two table-lookup call sites in `lookup.rs` (`find_def`, the
  section-default rung, and `style_kind_for`, the section-to-style
  selection): both translate the file spelling to the table spelling before
  comparing. Local, master and style cells still match by file spelling.
- **ADR 0011 amended**: the canonical angle unit is **radians** (the task's
  "check the cached unit" found radians, with the evidence above).
- **Tests.** 50 unit tests in `read/{mod,node,sheet,value}.rs` and 4 in
  `aliases.rs`; `tests/read_fixtures.rs` (the P2-08 fixtures: drawing,
  stencil, template kinds, missing main part, no content types, dangling
  relationship, malformed packages never panic) and `tests/read_corpus.rs`
  (below). One unit test proves the no-flattening criterion: a master's
  `Width` cell and a style's cell are absent from an instance shape after

### Open issues

1. **`Preserved` records no position (affects P2-07's exit criterion).**
   Unmapped children are kept in document order *among themselves*, but the
   model does not record where they sat relative to the mapped children, and
   several source elements merge into one `Preserved` (a page + its page
   sheet + its page-contents root). The corpus does interleave:
   `PageSheet` children are `Cell*8, Trigger, Cell*…, Section*` (9 corpus
   files),
   `VisioDocument` children are `DocumentSettings, Colors, FaceNames,
   StyleSheets, DocumentSheet` (the stylesheet sits in the middle of
   unmapped siblings), `Shape` children end `…Section*, Text, Shapes`, and
   `docProps/app.xml` has `HeadingPairs`/`TitlesOfParts` between simple
   properties. A writer that emits "cells, sections, preserved" cannot
   reproduce those orders, so `write -> read` will not be `diff`-empty. Two
   fixes: (a) the writer patches the preserved part trees (`write_document`
   has the source package and can walk it, replacing the mapped elements in
   place); or (b) the model grows a position anchor on `Preserved`. (a) is
   entirely in P2-07's lane and needs no model change; this reader's
   contract is written so both work.
2. **Section-level cells have no slot.** `Geometry` writes `NoFill`, `NoLine`,
   `NoShow`, `NoSnap`, `NoQuickDrag` as `Cell` children of the `Section`,
   outside its rows; `Section` has only `rows`. They are kept verbatim in
   `Section::preserved.children` (lossless), but the lookup cannot see them.
   A `Section::cells` field (or a convention of a synthetic row) would fix
   both.
3. **A master has one content shape.** `Master::shape` is singular; a master
   with several top-level shapes keeps the first and the rest stay in the
   arena unreachable (every corpus master has exactly one, so no corpus file
   is affected). MS-VSDX explicitly allows several.
4. **`Connect` has no preserved slot.** A `Connect` element with an attribute
   or child the model does not hold is kept verbatim in the page's
   `Preserved` instead of being modeled (no corpus file does this).
5. **Style references are IDs, the lookup wants names.** `.vsdx` writes
   `LineStyle="7"` (the style's `ID`), so `Shape::line_style` holds `"7"`
   verbatim and `Document::resolve`'s style rung (P2-04, `style_by_name`)
   never matches a file-loaded shape. Either the reader resolves the ID to
   the style's `Name` (and P2-07 resolves it back), or the lookup gains an
   id-based rung. Related: a style's chain in `.vsdx` is its own
   `LineStyle`/`FillStyle`/`TextStyle` attributes, not a `Style` cell, so
   `Style::base_style` is `None` for every corpus file. Both need a master
   decision; this reader keeps the values verbatim so neither choice loses
   data.
6. **Angle canonical vs `ferrogram-geom`.** ADR 0011 now says the model's
   canonical angle unit is radians (file evidence), while
   `UnitKind::Angle` in `ferrogram-geom` converts to degrees. Nothing in the
   model converts, but `lookup::parse_default_value` (P2-04) parses the
   ShapeSheet table's `default_value` through `ferrogram_geom` and would
   produce degrees once the table records defaults. Reconcile before that
   lands.
7. **Where preserved content lives is not always routable.** Unmapped root
   attributes of `pages.xml`, `masters.xml` and the `docProps` parts merge
   into `Document::preserved` (nearest modeled ancestor, ADR 0012 rule 3);
   in the corpus that bag can hold several `xml:space="preserve"` attributes
   from different parts, plus the `xsi:type` of `dcterms:created`/
   `dcterms:modified` (a property element maps to `Property`, which has no
   attribute slot). A patch-based writer (issue 1a) is unaffected; a
   regenerating writer needs to route them (by vocabulary) or the model needs
   a per-source bag. `docProps/app.xml`'s `HeadingPairs` and `TitlesOfParts`
   have element children and are kept verbatim for the same reason.
8. **`CellValue::List` is never produced.** List-format cached values (e.g.
   `Format` cells like `;Not Started;In Progress;…`) arrive as `Str`; the
   formula engine (Phase 3+) can reinterpret them.
9. **Duplicate attributes are dropped.** An element with the same attribute
   twice (invalid XML) keeps the first; a second `Master` on a `Shape` is
   ignored. No corpus file does this.
