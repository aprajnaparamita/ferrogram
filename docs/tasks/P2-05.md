## Goal

Implement the pure OPC layer: read a zip container into a `Package`
(enforcing every `Limits` cap before the allocation it guards), and write a
`Package` back to bytes. No Visio XML mapping here (that is P2-06/P2-07).

## Interfaces

Implements the stubs:

```rust
pub fn read_package(bytes: &[u8], limits: &Limits) -> Result<Package, Error>;
pub fn write_package(package: &Package) -> Result<Vec<u8>, Error>;
```

Consumes the `Package`/`Part`/`Relationship`/`Limits` types already defined
in `crates/vsdx/src/package/mod.rs`. Rules:

- `[Content_Types].xml` and every `*.rels` part are parsed into
  `content_types` and `relationships` (not kept as parts) and regenerated on
  write from those lists; every other part is `Part` data (XML parts parsed
  to `XmlNode` with prefix, attribute order and whitespace preserved).
- A missing content-type declaration for a part is `Error::InvalidPackage`;
  a relationship to a missing part is recorded, not an error (internal
  targets may legitimately dangle in the wild) — a relationship the
  *mapper* needs and cannot find is `Error::BadRelationship` there.
- Caps (ADR 0017) are enforced while reading, with checked arithmetic:
  `max_entries`, `max_part_uncompressed`, `max_total_uncompressed`,
  `max_compression_ratio` (bomb guard: compare declared sizes before
  inflating, and cap the inflate loop), `max_xml_depth`,
  `max_attributes_per_element`.
- The error enum (`crates/vsdx/src/error.rs`) is complete for all Phase 2
  tasks: P2-06 and P2-07 only add usages, never variants. If a variant is
  genuinely missing, note it under Open issues.

## Result

_Filled in by the worker at hand-off._

**Done (branch `agent/P2-05`):** the pure OPC layer of `crates/vsdx` is
implemented.

- `package/xml.rs` (new, private): XML text to `XmlNode` and back, with
  prefix spelling, attribute order, namespace-URI resolution and whitespace
  text nodes preserved. Entity and character references decode into the
  surrounding text node; `max_xml_depth` and `max_attributes_per_element` are
  enforced while parsing.
- `package/read.rs`: `read_package` reads the zip container under every
  `Limits` cap (entry count, per-part and total uncompressed size with checked
  accumulation, compression ratio compared on the declared sizes *before*
  inflating, and a capped inflate loop as a second guard). `[Content_Types].xml`
  and every relationships part are parsed into `content_types` /
  `relationships`; all other parts become `Part` data (XML trees or bytes).
  Unknown content types are refused; a relationship with a dangling internal
  target is recorded, not an error.
- `package/write.rs`: `write_package` writes deflate entries deterministically
  (parts in `Package::parts` order) and regenerates `[Content_Types].xml` and
  the relationships parts from the package lists, so `read -> write -> read`
  keeps everything and the writer is a pure function of the `Package`.
- Tests: unit tests in `package/{read,write,xml}.rs`, integration tests in
  `crates/vsdx/tests/package_read.rs` (malformed input and one test per cap,
  including a test-built zip bomb of 256 KiB of zeros) and
  `tests/package_roundtrip.rs` (all 15 corpus packages round-trip with equal
  parts/content types/relationships and a stable second write, plus a
  hand-built package). All malformed cases return `Err`, none panics.
- The error enum needed no new variants; P2-06/P2-07 add usages only.

**Deviations from the task text**

- *Dangling relationship*: the Acceptance list says the malformed tests "all
  return `Err`", but the Interfaces section says a relationship to a missing
  part is "recorded, not an error". Implemented per Interfaces; the test
  asserts `Ok` with the relationship recorded.
- *`diff`-empty XML check*: `larrygram_model::raw::diff` is a P2-04 stub (group
  B, lands after this task), so the round-trip test asserts exact `XmlNode`
  tree equality, which is strictly stronger than "empty `diff`" and implies it.
  P2-09's harness can call `diff` when P2-04 has landed.
- *Missing `[Content_Types].xml`*: two corpus packages
  (`recursion-cycle.vsdx`, `tab-short-prefix.vsdx`, libvisio test data) omit
  `[Content_Types].xml` entirely, and the Phase 2 exit criterion requires every
  corpus file to round-trip. When the part is absent the reader infers
  declarations from part names (`xml` -> `application/xml`, anything else ->
  `application/octet-stream`, an `Override` for a part with no usable
  extension) and records them in `Package::content_types`, so the written
  package declares exactly what was inferred and the re-read matches. The
  strict rule (missing declaration for a part = `Error::InvalidPackage`)
  applies whenever `[Content_Types].xml` exists.

**New dependencies:** none (`zip` 8.6 + `flate2` + `quick-xml` 0.41 were
already declared by P2-01).

**Gate:** `cargo xtask gate` green in the worktree (fmt, clippy, test, doc,
coverage, deny, layers, wasm, fuzz). Line coverage of `larrygram-vsdx`:
95.6% (threshold 85%).

**Open issues**

- P2-08 builds a `Malformed::NoContentTypes` fixture. With the deviation
  above, "no `[Content_Types].xml`" reads successfully with inferred
  declarations (it is tolerated in the wild); only a *present but incomplete*
  `[Content_Types].xml` is an error. P2-08/P2-10 must assert the same, or the
  master must decide to make the missing part an error and accept that two
  corpus files cannot round-trip.
- `XmlNode` (P2-04 owns `crates/model/src/raw.rs`) has no slot for the XML
  declaration, so the declaration of an XML part is dropped on write. Same for
  comments and whitespace outside the root element. Semantic equivalence
  (ADR 0012) does not compare them; if byte-faithful rewrites of part headers
  are wanted later, `XmlNode` needs a document-level slot.
- The XML text/`XmlNode` helpers live in `crates/vsdx/src/package/xml.rs`
  because `crates/vsdx/src/xml/` belongs to P2-06. P2-06 should absorb the
  helpers into that module rather than write a second parser.
- `[Content_Types].xml` and relationships parts keep only their structured
  lists: attributes on the root `Types`/`Relationships` elements and unknown
  child elements are dropped (no field for them; `Relationship::preserved`
  keeps extra attributes of `Relationship` elements as specified). No corpus
  file uses any.
- `write_package` groups relationships by source part in first-appearance
  order. Each relationships part of a real package is one file, so its entries
  are contiguous and the order is preserved; a hand-built `Package` with
  interleaved sources is written grouped (documented on `write_package`).
