## Goal

Implement `from_model` and `write_document`: regenerate supported parts from
the model, copy everything unmapped from the preserved package and the
`Preserved` fragments, and produce a package that is semantically equivalent
to the input (ADR 0012).

## Interfaces

Implements:

```rust
pub fn from_model(document: &Document) -> Result<Package, Error>;
pub fn write_document(document: &Document, preserve: &Package) -> Result<Vec<u8>, Error>;
```

Rules:

- Supported parts are regenerated deterministically (stable element and
  attribute order) so `write -> read -> write` is byte-identical.
- Unmapped attributes and children are re-emitted from `Preserved` in their
  recorded order; unknown parts are copied from `preserve` verbatim.
- `[Content_Types].xml` and relationships come from `Package::content_types`
  and `Package::relationships`, refreshed for the parts actually written.
- `Document::kind` selects the main part's content type and the part set
  (ADR 0016); a stencil writes no pages part.
- The writer never emits an XML declaration or namespace prefix that the
  source did not use for the same URI; new elements use the schema's default
  namespace.

## Note from the master (after P2-06 merged)

Read the P2-06 Result, "Open issues" 1 and 7, before you start.

**Decision: the writer patches the source trees.** The reader keeps unmapped
children in order among themselves, but not their position relative to the
mapped children, and the corpus interleaves them (`Trigger` between
`PageSheet` cells in 9 files, `StyleSheets` between unmapped children of
`VisioDocument`, `HeadingPairs` between simple properties in
`docProps/app.xml`). Several source elements also merge into one
`Preserved`. A writer that emits "mapped, then preserved" cannot reproduce
that. So:

- `write_document(document, preserve)` walks each supported part's source
  tree in `preserve`. It updates every element that maps to a model entity
  from the model, in place. It keeps every unmapped element and attribute
  where it is. It removes source elements whose entity is no longer in the
  model, and inserts new model entities at the canonical position (after
  the last sibling of the same kind, or where MS-VSDX's sequence puts
  them).
- Match source elements to entities by identity, not by position: shapes,
  pages, masters and styles by `ID`; sections by `N` (and `IX` when
  present); rows by `IX` or `N`; cells by `N`.
- `from_model(document)` (no source package) generates parts from the model
  and emits `Preserved` content after the mapped content. It is used for new
  documents and is not part of the round-trip criterion.
- Write ADR 0018 for this design: the matching keys, the insert positions,
  how it serves Phase 4 edits, and the alternatives (regenerate with
  position anchors on `Preserved`; regenerate and accept reordering).

**Round-trip test.** `tests/roundtrip.rs` moves from P2-09 to this task,
with the same specification as in `docs/tasks/P2-09.md`: for each corpus
`.vsdx` file, read, write, re-read and re-write. Assert that `diff` is empty
for every XML part, that the part lists, content types and relationships are
equal, and that the second write is byte-identical to the first. Print the
`XmlDifference` paths on failure. Skip when `corpus/vsdx/` is missing;
`LARRYGRAM_REQUIRE_CORPUS=1` makes that a failure. This test is the Phase 2
exit criterion.

**Rule change.** The last rule above ("never emits an XML declaration")
is out of date. The package writer (P2-05) emits the standard UTF-8
declaration on every XML part. Do not change that.

### What was built

- **`crates/vsdx/src/write/`** (`mod.rs`, `patch.rs`, `emit.rs`, `value.rs`).
  `write_document(document, preserve)` walks each supported part's source tree
  and patches it from the model (ADR 0018): mapped attributes are updated in
  place, unmapped elements and attributes stay exactly where the source put
  them, elements whose entity is gone are removed (unless an identical node is
  still in the entity's `Preserved`), and new entities are inserted after the
  last sibling of their kind or where the [MS-VSDX] sequence puts them
  (`Cell` before `Section` before `Text` before `Shapes`, `Cell` before `Row`,
  `Shapes` before `Connects`, the `VisioDocument_Type` sequence for the main
  wrappers). Elements match entities by identity: shapes, pages, masters and
  styles by `ID`, sections by `N` and `IX`, rows by `IX` or `N`, cells and
  properties by name, connects by their attribute tuple. An attribute is
  rewritten only when it no longer matches the model and a matching spelling
  is kept (`2.0` stays `2.0`, `true` stays `true`), which is what makes
  `write -> read -> write` byte-identical.
- **`from_model`** generates the parts from the model alone (mapped content,
  preserved content after it), with fresh content types and relationships and
  the part set of [`Document::kind`] (ADR 0016: a stencil writes no pages
  part). A generated package reads back to the same model (unit tests).
- **Part and relationship bookkeeping.** Unknown parts are copied verbatim;
  `[Content_Types].xml` and the relationships are refreshed for the parts
  actually written (every part keeps or gets a declaration). A page or master
  whose contents part is missing but whose preserved `Rel` names a
  relationship gets its part generated; one that gained content with no `Rel`
  at all gets a synthesized `Rel` element, relationship and part (tested).
- **`tests/roundtrip.rs`** (the Phase 2 exit criterion, per the P2-09 spec):
  for every corpus `.vsdx` — read, write, re-read, re-write; `diff` empty on
  every XML part, equal part lists, content types and relationships, byte-equal
  binary parts, byte-identical second write, `XmlDifference` paths printed on
  failure, skip when `corpus/vsdx/` is absent and `LARRYGRAM_REQUIRE_CORPUS=1`
  turns the skip into a failure. `tests/write_fixtures.rs` round-trips the
  drawing, stencil and template fixtures (P2-08) with the right content types
  and part sets (the stencil keeps its empty `pages.xml` and writes no page
  contents). `tests/write_edits.rs` covers the Phase 4 edit shapes: changed
  cell, deleted and added shape, renamed page, new cell and property,
  preserved content untouched, the `Rel` synthesis.
- **The `NotImplemented` variants are gone** from `crates/vsdx/src/error.rs`
  and `crates/model/src/error.rs` (with their tests; the two assertions that
  used the model variant now use `UnknownShape`).
- **ADR 0018** records the matching keys, the insert positions, the attribute
  rules, how the design serves Phase 4 edits and the alternatives (regenerate
  with position anchors on `Preserved`; regenerate and accept reordering).
- **Tests.** 22 new unit tests in `write/value.rs`, 18 in `write/emit.rs`, 16

### Deviations from the task text

- **"Unmapped attributes and children are re-emitted from `Preserved` in their
  recorded order"** is what `from_model` does. `write_document` follows the
  master's note instead: the patched source tree *is* the record of unmapped
  positions (several source elements merge into one `Preserved`, P2-06 open
  issues 1 and 7), so the fragments are consulted only to tell "unmapped" from
  "deleted" and to find a `Rel` id. Editing the fragments themselves is not
  written back (ADR 0018 records this).
- **"Document::kind selects the main part's content type"**: in patch mode the
  kind's content type replaces the declared one only when the source declared
  a main content type at all. Two corpus files have no `[Content_Types].xml`
  and the reader infers `application/xml`; the round-trip criterion compares
  content types, so upgrading those to `drawing.main` would fail it. Generated
  parts always use the kind's content type.
- **"A stencil writes no pages part"** is `from_model`'s rule. `write_document`
  keeps the source part set: the P2-08 stencil fixture carries an empty
  `pages.xml`, and the fixture round-trips compare part lists.
- The last rule of the Interfaces block (no XML declaration) is dropped per
  the master's note; the P2-05 declaration is untouched.

### Open issues

1. **Deleting an entity does not delete its parts.** A removed page or master
   leaves its contents part and relationship in the package (harmless
   unreferenced content). Prune them once Phase 4 can delete pages and
   masters; the exit criterion forbids pruning anything the source has.
2. **A `Property` records no source part.** A property the model adds is
   written into the main part's `DocumentProperties` (with the namespace
   spelling of a sibling property), not back into `docProps/core.xml` or
   `docProps/app.xml`. Fix with a source-part marker on `Property` if Phase 4
   needs it.
3. **Preserved fragments are not edited back** (the merge of P2-06 open issue
   7): a command that changes `Preserved` content sees no write effect. All
   mapped editing goes through the model fields and is covered.
4. **Multiple `Shapes` wrappers on one shape**: only the first is patched (every
   corpus shape has one; [MS-VSDX] allows at most one).
5. **Boolean spelling**: a `Hidden` (or similar) attribute the source spelled
   `true`/`false` is rewritten as `0`/`1` only when the value changes; the
   corpus spells them `0`/`1`.
6. **Deep nesting**: the generator writes at most 128 levels of sub-shapes
   (the read cap), so a hand-built deeper model is truncated at the bottom
   rather than overflowing the stack. No read file can reach it.
