## Goal

Build the dependency graph over a document's formulas and implement the
incremental recalculation pass: dirty cells plus their transitive
dependents, evaluated in a deterministic topological order, with cycle
cutting, a deterministic evaluation budget, `SETF`-induced extra dirt, and
the write rules of ADR 0056 (values for cells that have formulas,
materialised formula + value for inherited ones).

### What changed

- `crates/shapesheet/src/graph.rs`: `CellAddress` gains the deterministic
  `Ord` of ADR 0055 (page sheets before shape sheets, then section, row,
  cell name). `DepGraph` holds forward and reverse edges and implements
  `build`/`build_with` (one walk over every page and shape sheet, one
  parse per formula), `update` (re-link only the nodes an edit touched),
  `dependencies`, `dependents` and `evaluation_order`. A node's
  dependencies are the cells its formula references plus, for an `Inh`
  (or absent) formula, the master rung that defines it — with the
  reference edges computed from the *effective* formula, so dirtying an
  instance's `Width` dirties its inherited geometry rows (the resize
  story of ADR 0054/0056). `evaluation_order` returns the dirty cells
  and their transitive dependents, dependencies first, ties broken by
  address (Kahn over a sorted ready set), and excludes every cell on a
  dependency cycle; `order_and_cycles` reports the cut cycles (one per
  back edge, in walk order) so the pass can warn and keep cached values.
  The file also holds the address helpers the pass shares:
  `effective` (the formula that defines a cell, own or inherited, through
  `Document::resolve`/`resolve_page_cell`/`resolve_row_cell`),
  `local_cell`, `normalize_address` (fills a row target's position and
  `IX` both ways and takes the model's spellings), `resolve_ref_address`
  (the ADR 0054 reference forms mapped to addresses) and `rung_address`.
- `crates/shapesheet/src/recalc.rs`: the `FormulaEngine` seam
  (`references`, `evaluate`), `Evaluation`, `CellWriteOp`, the production
  `DocumentEngine` (`parse_formula` + an iterative `collect_refs` over
  the AST, `eval_formula` against a recording `EvalContext` over
  `DocumentResolver`, `Value::to_cached` for the write form) and
  `recalc`/`recalc_with`. The pass: normalises the dirty set, refreshes
  those nodes' edges, evaluates in `evaluation_order`, and writes per
  ADR 0056 — a cell with its own formula gets only its cached value
  updated (the formula text is untouched), an inherited cell gets the
  evaluated formula and value materialised when
  `RecalcOptions::materialise_inherited` is set (the value only, keeping
  `F='Inh'`, otherwise; an absent cell is not half-written).
  `SETF` writes land as ordinary writes through the model's mutation
  API, are recorded as updates and dirty the target and its dependents
  within the same budget; a write to a cell already done or queued is
  cut by the cycle rule. An `UnknownFunction` warning keeps the cell's
  cached value (ADR 0053). `max_evaluations` counts evaluations; at the
  limit the pass stops, sets `truncated`, records one `BudgetExceeded`
  warning and leaves the rest stale. `fill_missing_only` restricts the
  pass to cells with a formula and no cached value (ADR 0057). One
  `CellUpdate` per changed cell holds the value before the pass and
  after the last write; a second pass over the same dirty set records
  nothing (idempotence).
- Tests: unit tests in both files (the acceptance criteria: diamond
  evaluated once, incremental 20-cell chain recomputing exactly the 16
  dependents, hand-built mutual and self reference cycles with one
  `Cycle` warning naming the cells and cached values kept, budget of 3
  over a 10-cell chain truncating, `SETF` writing and dirtying its
  target in the same pass, own-formula versus materialised writes,
  idempotence, `UnknownFunction` keeps the cached value, `fill_missing_only`,
  missing and unwritable targets as warnings, row writes through
  `write_row_cell`, and the graph's order/cycle/update rules). These
  drive a small in-crate `TestEngine` (a documented little formula
  language) because `parse`, `eval` and `DocumentResolver` are stubs
  until P6-02 to P6-05 land. Integration tests in
  `crates/shapesheet/tests/{graph.rs,recalc.rs}` pin the exported
  contract and accept `Ok` or `Error::NotImplemented` from the real
  pipeline, so they stay green before and after those merges.

### Deviations

- **Engine seam (`FormulaEngine`, `recalc_with`, `DepGraph::build_with`
  and `DepGraph::update` are new).** The committed `recalc(document,
  dirty, options)` signature has no way to pass the session's graph or a
  test engine, and the parallel build leaves `parse`/`eval` stubbed in
  this worktree. `recalc` keeps its signature (it builds a throw-away
  graph and uses `DocumentEngine`); `recalc_with` is the incremental
  entry point P6-07 should use with the session's `DepGraph`. Export
  lines requested under Open issues.
- **Cycle semantics.** The ADR says the pass "cuts the edge that closes
  it" and "every cell in the cycle keeps its cached value"; the pass
  therefore excludes every cycle member from the evaluation order (one
  `Cycle` warning per cycle, cells in walk order) and evaluates only the
  rest. Cells downstream of a cycle are evaluated against the kept
  values.
- **`RecalcWarningKind` is unchanged** (4 kinds). A write or lookup the
  pass cannot perform (missing section/row, unresolvable address) is
  reported as `MissingReference` with the cell name rather than a new
  kind.
- **`SETF` writes are recorded and applied by the pass**, not by
  `DocumentResolver::set_cell`: one write path (the model's mutation
  API) owns the document, and the write carries the formula text the
  engine spells (`literal_text`, numbers via
  `larrygram_model::mutate::literal`). A `SETF` write replaces the
  target's formula with that literal, which is why re-queuing the target
  is stable.
- **Reference-form mapping is best effort.** `resolve_ref_address`
  resolves bare names (the model's name search order), section/column
  names with row suffixes (`X2`, `Font[3]`, default row 0), named rows
  (`Prop.Cost`), `ThePage`, `Sheet.N` and same-page shape names. The
  column-versus-row split matches a column first (ADR 0054); row digits
  match by `IX` first and by position second; `Geometry1` is the first
  `Geometry` section. Multi-part paths (`Masters[Gear]!Shaft!...`) map to
  no address and add no edge.

   the committed names are reachable from `crates/shapesheet/tests/`,
   which is why the acceptance tests live as unit tests next to the
   code.
2. **Edge 2 is approximate for masters and absent for styles.** A
   master rung is addressed as the master's *first* top-level shape
   (the model's public API does not expose the position rule of
   `master_shape`), and a style rung has no `CellAddress` at all
   (`SheetRef` names shapes and pages only), so editing a style does not
   dirty instances through the graph. Fine for Phase 6 edits (page
   shapes and instances); revisit if master or style editing lands.
3. **The model's derived-cell refresh runs alongside recalc.**
   `Document::write_cell` refreshes `LocPinX`/`TxtPinX`/... for a write
   to `Width`/`Height` (ADR 0038 rule 2), including for `Inh` cells
   (their formula "follows"). Those side-effect writes are not in
   `RecalcOutcome::updates`; P6-07's `RecalcEdit` should either snapshot
   those cells too or note the gap. The recalc tests avoid those names.
4. **`Value::to_cached` (P6-03) is the only value bridge the production
   engine uses.** A `SETF` write of a unit-bearing number stores the
   canonical magnitude with a unit-less literal formula (the model sets
   the cell's unit from the ShapeSheet table); a unit suffix in the
   spelled formula would need the printer (P6-02) and is left open.
5. **`fill_missing_only` was interpreted as** "evaluate only cells whose
   local cached value is missing (any formula present)". P6-08 owns the
   fill-in pass; if it wants the inherited cells materialised too, it
   sets `materialise_inherited` as well.
6. **P6-10**: measure the resize case's evaluation count against
   `DEFAULT_MAX_EVALUATIONS` (ADR 0055 leaves the constant open), and
