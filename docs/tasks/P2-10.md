### What was built

- **Schema validation of written parts** (`crates/vsdx/tests/schema.rs`, the
  master's note): `written_parts_add_no_new_schema_errors` runs the P2-07
  round-trip over every corpus file and feeds both the source and the written
  package to the P2-09 harness. The new `validate_package_errors` returns
  **every** validation error of each part (the P2-09 `validate_package` kept
  only the first), normalized by `normalize_error`: the file name and line
  number are stripped, so one error compares by element name and error kind.
  The test asserts that each error of a written part also occurs for its
  source part and names the part on failure. Evidence run: 106 written parts
  checked, 203 recorded validation errors, 0 new. Skips with a message when
  `reference/` or `xmllint` is missing; `FERROGRAM_REQUIRE_SCHEMA=1` and
  `FERROGRAM_REQUIRE_CORPUS=1` turn the skips into failures.
- **Property tests (ADR 0017 section 2)** — the three properties that had no
  implementing task:
  - `crates/vsdx/tests/properties.rs`: random `Package` trees round-trip
    through `write_package` -> `read_package` with semantic equivalence (XML
    parts under `diff`, byte-equal binary parts, equal content types and
    relationships) and byte-identical writer stability; random model
    `Document`s round-trip through `from_model` -> `to_model` and through the
    composed `write_package` -> `read_document`. The generator is bounded
    (small trees and documents, safe alphabets) and only references entities
    that exist (a dangling `Master`/`BackPage` is preserved verbatim by
    design, so it cannot round-trip as a reference).
  - `crates/vsdx/src/package/xml.rs` (new test module): random `XmlNode`
    trees survive parse -> serialize -> parse with `diff` empty, plus entity
    and character-reference decoding, malformed references, two root
    elements and the `xml` prefix. New dev-dependency: `proptest` on
    `ferrogram-vsdx` (already in `Cargo.lock` via `ferrogram-geom` and
    `ferrogram-model`).
- **`geom`** (`crates/geom/tests/unit_and_transform_properties.rs`):
  conversion round-trips and kind-checked conversions as properties, a table

### Bug found and fixed

**Stray `Rel` on a new list entity without contents** (fixed in
`crates/vsdx/src/write/patch.rs`, commit `fix(vsdx)`): a page or master
inserted into a source list with no contents part and no preserved `Rel` was
written with a generated `Rel` naming `rId1`, a relationship that does not
exist. The next read kept that element as preserved content and the next
write grew a contents part for it, so `write -> read -> write` was not
byte-identical (a documented writer property). The generated element now
carries a `Rel` only when the entity has a contents relationship.
Regression test:
`write_edge_cases::a_new_entity_without_contents_gets_no_rel_marker`; the
two failing cases before the fix are the writer-stability assertions of
`list_inserts_follow_the_ms_vsdx_sibling_order` and the round-trip helper.
No other non-test code was changed.

### Open issues

1. **Generated packages lose two value kinds on re-read.** A hand-built
   `CellValue::Bool` writes `V`="1" with no `U` and reads back as
   `Number(1.0)`; `CellValue::List` has no `U` code the reader maps back to
   a list; a `Str` whose text looks like a number or a `#RGB` literal reads
   back as `Number`/`Color` (the reader classifies an unknown `U` by the
   value's shape). A value read from a file round-trips (its `U` spelling is
   preserved and rewritten), so this affects only models built in memory.
   The `from_model` property generator excludes those kinds and says so. A
   fix is a writer change (emit `U="BOOL"`/`U="STR"` when the value kind
   needs it) or a model change (a kind slot per cell); the master's call.
2. **The arena order of nested sub-shapes is not document order.**
   `read::map_shapes` walks `Shapes` wrappers with a stack, so the arena
   holds all top-level shapes first and then group children in wrapper
   order; a model built in pre-order does not compare equal to its read-back.
   The generator builds flat shapes; corpus files round-trip unchanged. Worth
   a decision before Phase 4 moves shapes between groups.
3. `model/src/lookup.rs` line coverage stops at 99.7%: the remaining
   unexecuted lines are match-arm braces and the poisoned-mutex fallback of
   `interned_default`, which no test can reach without panicking under the
   lock.
4. The schema harness still needs `xmllint` and `reference/` at run time;
   without them the written-parts rule silently skips (same as P2-09). CI
   should install `libxml2` and set `FERROGRAM_REQUIRE_SCHEMA=1` when it
   exists.
