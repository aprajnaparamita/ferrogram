## Note from the master

Two corpus findings the ADRs do not cover yet. Handle both in this task and
record the rule as an amendment to ADR 0021 (you own the model side; add the
amendment section to the ADR in your branch).

1. **`Themed` cached values.** Many colour and transparency cells cache the
   literal string `Themed` (for example `<Cell N='FillForegnd' V='Themed'
   F='Inh'/>`, `GradientStopColor` with `F='THEMEVAL()'`). Under ADR 0021
   as written, these would count as kind mismatches, so themed shapes would
   render in the hard default colour. Instead, `CellReader::color` (and the
   number accessor for the `*Trans` cells) must treat `Themed` as "resolve
   from the theme": use the shape's `QuickStyle*` cells (`QuickStyleLineColor`,
   `QuickStyleFillColor`, `QuickStyleShadowColor`, `QuickStyleFontColor`,
   and the matrix cells where needed) against `Document::themes[0]`. Take
   the meaning of the `QuickStyle*` values from the ShapeSheet reference on
   Microsoft Learn (an allowed source) and record it in `docs/sources.md`.
   If a value cannot be resolved, fall back to the hard default with a new
   `WarningKind` (for example `UnresolvedTheme`), not a kind-mismatch warning.
   The theme's format scheme (`a:fmtScheme`) is in scope only as far as the
   colour lookup needs it; line-weight and effect matrices may wait, with an
   open issue.
2. **Colour indices.** Cached colour values are often palette indices, not
   RGB (`<Cell N='LineColor' V='0' F='GUARD(0)'/>`). Documents store
   `ColorEntry` rows only from `IX='24'` up (checked on all 15 corpus files),
   so indices 0..23 must come from `palette`. Look for a Microsoft Learn
   page that lists the default colour indices first (allowed source). If
   none exists, transcribe them from black-box observation and say so.

## Result

Filled in by P3-02 (implementer) on branch `agent/P3-02`, 2026-10-14.

### What was built

**`crates/model` (all stub bodies; no signature changed):**

- `CellReader` implements the ADR 0021 policy end to end: one warning per
  missing, error and kind-mismatched cached value, hard-default
  substitution, and the master-note amendments (below).
- `values::palette` transcribes the fixed Visio palette (indices 0..23).
- `Document::resolve_row_cell` resolves one row cell of a repeated section
  with the ADR 0019 rungs: the local row, the master chain's row at the
  same position in the same section (matched by `IX` when both sides have
  one, else by position), **no style rung**, the section default and the
  hard default. `Inh` does not define; chains are cut on cycles.
- `Document::resolve_page_cell` resolves page-sheet cells: the page's own
  cell, the style chain from the page sheet's `LineStyle`/`FillStyle`/
  `TextStyle` links, the section default, the hard default.
- `Document::shape_geometry` types every `Geometry` row kind (`GeometryRow`
  variants, absolute and `Rel*`), decodes `NurbsTo`'s E-cell
  `NURBS(knotLast, degree, xType, yType, ...)` formula and `PolylineTo`'s
  A-cell `POLYLINE(xType, yType, ...)` list, and degrades to the row's
  `X`/`Y`/`A`..`D` cells when the encoded data is missing or unparsable.
  Row-level inheritance works for instances without their own rows
  (including empty sections, chained masters and a per-section fallback).
- `page_layers` and `shape_layers` read the `Layer` section rows and the
  `LayerMember` list.
- `Error::NotImplemented` is gone from `larrygram-model`.

**`crates/vsdx` (read side only; `src/write/` untouched):**

- `read/text.rs` maps the `Text` element's mixed content into
  `Shape::text` (`cp`/`pp`/`tp` run markers, `fld` fields with their cached
  display text). The element stays in `Preserved` as before.
- `read/theme.rs` maps the theme parts' `a:clrScheme`/`a:fontScheme` into
  `Document::themes` and the document `Colors`/`ColorEntry` rows into
  `Document::color_table` (the elements stay preserved; `FaceNames` and
  `a:fmtScheme` stay preserved-only).
- `read/value.rs` keeps a `Themed` cached value as the marker string
  whatever `U` declares (a themed value in a numeric unit used to be a
  read error).
- `tests/read_mapping.rs` pins the corpus evidence (text parts, field
  display text, theme schemes, colour table from index 24, FaceNames
  preservation, layer rows and membership, `Themed` cells).

**Master note (both findings handled, rules recorded as an amendment to
ADR 0021 in this branch):**

1. `Themed` values: `CellReader::color` resolves them from the shape's
   `QuickStyleLineColor`/`FillColor`/`ShadowColor`/`FontColor` cell
   against `themes[0]`. Slot meanings from the ShapeSheet reference
   (`docs/sources.md` row 12): 0 = Dark theme colour (mapped to `dk1`), 1
   = Light (`lt1`), 2..7 = Accent 1..6. A slot the theme cannot answer
   (8 = background, the 100+/2xx variant encodings) substitutes the hard
   default with the new `WarningKind::UnresolvedTheme`, never a kind
   mismatch. Themed transparencies and other themed values substitute the
   hard default with `UnresolvedTheme` (the `a:fmtScheme` matrices are
   deferred, see open issues).
2. Colour indices: `CellReader::color` resolves a cached number as a
   palette index (0..23, `values::palette`) or a document colour table
   index (24 and up, `Document::color_table`); an index neither knows
   warns `Missing` and substitutes black.

Also in the amendment: booleans and lists are read the way the files write
them (`FlipX V='0'` caches a number, `LayerMember V='0'` a one-element
list), so `boolean` accepts numbers and `list` accepts one number without
a kind-mismatch warning.

### Deviations

- `PolylineData` keeps only `points` (ADR 0019's type is fixed and the
  parallel tasks code against it), so `POLYLINE`'s `xType`/`yType` flags
  (fraction of width/height vs local coordinates) are parsed and dropped.
  Recorded as an open issue.
- `resolve_row_cell(sheet, section, row, cell)` resolves in the **first**
  section with that name when a sheet has several same-named sections
  (`Geometry` writes one section per path with an `IX`). The row resolver
  itself is section-aware (name + `IX` + position) and `shape_geometry`
  uses it, so typed geometry is correct per section; only the public
  one-name API cannot address the second section. Open issue.
- The page sheet's style links have no model field; `resolve_page_cell`
  reads the `LineStyle`/`FillStyle`/`TextStyle` attributes from
  `Page::preserved` (read-side interpretation of preserved content, in
  the spirit of ADR 0019 decision 1).
- Rendering-default substitutions that are not the CellReader policy
  (documented at the methods): a `Layer` row without `Visible` is visible
  (a `false` there would hide every shape), a missing section flag
  (`NoFill`/`NoLine`/`NoShow`) is `false` without a warning, and
  `EllipticalArcTo`'s absent `C`/`D` cells default to `0`/`1` per ADR
  0022 without a warning.

### Palette provenance (acceptance note)

Indices 0..23 and the colour names come from the `VisDefaultColors`
enumeration on Microsoft Learn (`docs/sources.md` row 11). **No Microsoft
page lists the RGB values** and the corpus stores `ColorEntry` rows only
from `IX='24'` up (checked on all 15 files), so there is no file evidence
for the fixed palette's RGB values either. They are our own transcription
of the named colours (the standard primaries and their dark variants, and
a 10%..90% gray ramp) and are marked unverified in `docs/sources.md`; a
black-box look at Visio's Line dialog colour collection settles it. The
table is one constant in `values::palette`, so a correction is one edit.

### Open issues

- **Variant theme colours.** `QuickStyle*Color` values 100+ and 2xx (the
  corpus shows 101..106 and 200..206) name colours derived from the
  theme's `vt:variationClrSchemeLst` extension and the style matrices,
  not plain `a:clrScheme` slots. They currently resolve to `UnresolvedTheme`.
- **`a:fmtScheme` matrices** (fill/line styles, effects, gradient stops,
  themed transparency and line weight) are deferred, as the master note
  allows. `LineWeight V='Themed'` (2 corpus cells) and
  `FillGradientEnabled V='Themed'` (1) therefore warn `UnresolvedTheme`.
- **Dark/Light slot mapping** (`dk1`/`lt1` vs `dk2`/`lt2`) is not stated
  by the ShapeSheet reference. Corpus evidence is consistent with
  `dk1`/`lt1` (`THEMEVAL("TextColor")` caches `#feffff`, which is `lt1`);
  a black-box check against Visio would settle it.
- **Colour indices 24 and up that the table does not hold** (layer rows
  cache `Color V='255'`) may be packed RGB values ("custom colors have
  values of 24 and above" in numeric operations, ShapeSheet reference).
  They warn `Missing` today.
- **`PolylineTo` `xType`/`yType`** are dropped (deviation above); extend
  `PolylineData` when a corpus file shows fraction-encoded polylines.
- **Multi-section row addressing** in the public `resolve_row_cell`
  (deviation above).
- Per-shape `ThemeIndex` stays deferred (P3-01 note); the renderer uses
  `themes[0]`.
