## Goal

Copy, cut, paste, duplicate, delete; align, distribute, group/ungroup,
z-order; add, rename, delete and reorder pages — all registry commands,
all undoable.

## Interfaces

Implement the three `TABLE`s with the ids of ADR 0047:

- Clipboard: `edit.copy`, `edit.cut`, `edit.paste`, `edit.duplicate` —
  `edit.paste` takes optional `x`, `y` (paste at the pointer) else the
  ADR 0047 offset; the payload is `commands::clipboard::ClipboardContent`.
- Arrangement: `arrange.align.left|center_x|right|top|middle|bottom`
  (arg-less: aligns to the selection bounds),
  `arrange.distribute.horizontal|vertical`, `arrange.group`,
  `arrange.ungroup`, `arrange.bring_forward`, `arrange.send_backward`,
  `arrange.bring_to_front`, `arrange.send_to_back`.
- Pages: `page.add` (optional `name`), `page.delete`, `page.rename`
  (`name`), `page.reorder` (`from`, `to`), `page.move_left`,
  `page.move_right`.

Every command returns exactly one `Edit` (a `CompositeEdit` when it
touches several shapes) and bumps `AppCtx::touch()` (ADR 0040).

## Acceptance criteria

- [ ] Copy/paste round-trips a group subtree with its internal connects;
      paste allocates fresh ids and keeps the `Master` links (tested).
- [ ] Cut = copy + delete in one undo step; duplicate in one step.
- [ ] Align/distribute move every selected shape in one undo step (delta
      math tested: left/centre/right/top/middle/bottom, and distribution
      spacing for 2 and 3 shapes).
- [ ] Group/ungroup round-trips a 3-shape group without changing the

- [ ] Z-order commands reorder `Page::shapes` and are undoable.

## Result

### What changed

- **Clipboard** (`builtins/clipboard.rs`, `clipboard.rs`): `edit.copy`,
  `edit.cut`, `edit.paste` and `edit.duplicate` over
  `commands::clipboard::ClipboardContent`. Copy clones each selected
  subtree plus the `Connects` whose two ends are both copied; paste
  inserts fresh arena and Visio ids, rebuilds the child links, remaps the
  internal connects and keeps the `Master` links. Paste is one
  `CompositeEdit` of `StructuralEdit::insertion` steps. `Clipboard`
  gained a public `pastes: u32` counter: without `x`/`y`, paste N lands
  at the recorded position offset by `(0.1, -0.1) * N` inches; with
  `x`/`y` the first root's pin lands on the pointer and the counter does
  not advance. Cut is copy + delete wrapped in one undo step; duplicate
  pastes a fresh copy at `(0.1, -0.1)` without touching the clipboard.
- **Arrangement** (`builtins/arrange.rs`): the six align commands
  (selection-bounds edges/centres), horizontal/vertical distribution,
  group/ungroup and the four z-order commands. Frames are read from
  `PinX`/`PinY`, `LocPinX`/`LocPinY`, `Width`/`Height` through
  `CellReader`. Every command returns one `CompositeEdit`; group and
  ungroup are undoable wrappers over `Document::group_shapes` /
  `ungroup_shape` that find the re-created group by its member set.
- **Pages** (`builtins/page.rs`): `page.add`, `page.delete`,
  `page.rename`, `page.reorder` and the `page.move_left`/`page.move_right`
  wrappers. Each uses the model page primitive and returns one
  `PagesEdit` snapshot of the page list and active page, so undo restores
  the exact ids, names, order and background references. Delete
  activates the next/previous neighbour and clears the selection.
- **View** (`builtins/view.rs`): `page.next`/`page.previous` now clear the
  selection when the active page changes (ADR 0041), so headless callers
  never keep a stale `Selection::page`.
- **File** (`builtins/file.rs`): `file.open` records
  `Settings::recent_files` most-recent-first, de-duplicated and capped at
  10. A wasm `file.save`/`file.save_as` with a `path` argument now returns
  the download payload instead of reaching `std::fs::write`.
- **UI** (`crates/ui/src/canvas.rs`): the page-tab context menu dispatches
  `page.rename`, `page.delete`, `page.move_left` and `page.move_right`.
- **Tests**: new `crates/commands/tests/{clipboard,arrange,pages}.rs`
  plus unit tests for the private clipboard/arrange/page/view helpers.
- **Generated**: `docs/parity/controls.md` regenerated because the new
  implemented ids flip their parity rows (the gate's parity check needed
  it; the master should expect a conflict with parallel tasks).

### Deviations and decisions

- Alignment/distribution uses the unrotated frame cells (the acceptance
  tests are unrotated); Visio's rotated-shape alignment is on the
  black-box check list.
- `arrange.align.center` (the `commands.yaml` row) is not implemented;
  ADR 0047 and the task name `arrange.align.center_x`, which is.
- Group/ungroup undo replays the model primitive: a re-created group has
  a new arena id and the old group stays in the arena (ADR 0039
  invariant 1). The undo equality for these commands is therefore over
  reachable page state, not the arena length (same as P5-04's insertion
  edits).
- `page.reorder` takes zero-based `from`/`to` list indices; `to` clamps
  in the model. Page undo is a whole-list snapshot because the model has
  no insert-page-at-index primitive.
- Clipboard fragments use the active page; the recorded `source_page` is
  kept for later glue work. A copied fragment whose parent is not copied
  is treated as a root.

### Open issues

- **Undo equality for insert/group:** detached arena entries remain, so
  `Document` equality after undo differs in `shapes.len()`. The P5-11
  property must compare reachable model state (or the model needs an
  arena compaction ADR).
- **Rotation:** align/distribute ignore `Angle`; check Visio's rotated
  behaviour in a black-box check.
- **Cross-document paste:** the `Master` link is kept even when the target
  document has no such master (ADR 0047 says keep it); the writer/reader
  needs a dangling-master rule if that case ships.
- **Clipboard source page:** paste always targets the active page; a
  selection spanning pages is not a supported UI state and only its
  first page is used for the connect records.
- **Wasm save:** the `path` branch is compiled into the wasm build but
  cannot be exercised headlessly here (the payload path itself is already
  covered by the existing host test).
- `docs/parity/controls.md` is generated and will conflict with the
  parallel Group D branches; regenerate at merge.
