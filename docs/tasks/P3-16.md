## Goal

Fix the review findings. Each fix gets a regression test.

1. **Major 1, silent non-finite substitution.** Reject non-finite numbers
   in `CellReader::number_from` (and `number_from_or`) with one
   `KindMismatch` warning. Remove `Ctx::finite` in `build.rs` or make it a
   no-op that cannot substitute silently. Test: a shape whose `PinX`
   caches `V='inf'` renders at the default and records one warning.
2. **Major 2, text rows by `IX`.** Thread the marker `IX` through as
   `row_ix` for the `CellReader::row_*` family, and delete the
   `ix as usize` fallback in `row_position`. Test: an instance with no
   `Character` section and a master whose rows are `IX` 0 and 5; the run
   marked `IX` 5 reads the master's row 5.
3. **Major 3, pattern tiles.** Add `filled: bool` and
   `tile_stroke_width: f64` to `PatternPaint`, set them from the
   `PatternTemplate` in `build_fill`, and make PNG and SVG both honor them.
   Test: an open tile draws the same marks in both backends.
4. **Major 4, duplicated text fields.** Keep `text::Layout::rotation` and
   `GlyphPos::size`. Remove `TextNode::rotation` and `TextRun::size`, and
   update the placement recipe in `scene.rs`.
5. **Minor 5, one scale cap.** Bound the device extent (page size times
   scale, at most 16384 px per side) in both backends. Add
   `Error::InvalidOptions` for a non-finite, non-positive or over-cap
   scale. Update `a_huge_scale_caps_the_raster_not_the_svg_text` (P3-11)
   and the CLI exit-code tests if the code changes (keep exit 3 or record
   the change in ADR 0026's amendment via an Open issue).
6. **Minor 6.** Amend ADR 0020: a group's own shape is drawn first, as
   the first child of its `Group`, with an identity transform; sub-shapes
   follow in file order.
7. **Minor 7.** Fix the stale sentence at `crates/render/src/scene.rs:27`:
   a node transform maps into the parent group's space; the ancestor chain
   maps to the page.
8. **Minor 9.** Formula-parse degradations in the builder use
   `KindMismatch` (or a new kind if ADR 0021's amendment says so), not
   `ErrorValue`, so the CLI no longer prints them as a cached error.
9. **Minor 10.** `section_rows` counts gradient rows through the same
   master rung as the cell lookup and shares `MAX_DEPTH`; remove the magic
   bound of 8.
10. **Minor 11.** Record one `CellWarning` at build time when a glyph cannot
    be drawn (font index out of range or no outline), or document the skip
    in the placement recipe. Pick one and say which in the Result.
11. **Minor 12.** Make `BuildOptions::new()` and `Default` agree
    (`background: true` for both, unless you find a caller that needs
    otherwise).

Major 8 (silent curve degradation) is P3-18's ADR amendment; do not add
warnings for it here.

### The fixes

1. **Major 1, silent non-finite substitution.** `CellReader::number_from`
   and `number_from_or` reject a non-finite cached number (`V='inf'`,
   `nan`, `1e999`) with one `KindMismatch` warning and their usual
   substitute; `related_number` (the documented formula defaults) passes
   on only finite values. `Ctx::finite` is deleted: the model is the one
   policy point and its numbers are always finite. Tests:
   `a_non_finite_cached_number_is_one_kind_mismatch`,
   `a_non_finite_optional_row_cell_keeps_the_row_default`,
   `a_non_finite_related_value_does_not_leak_into_a_documented_default`
   (model), `a_non_finite_cell_renders_at_the_default_with_one_warning`
   (render: the requested case, `PinX` caching `V='inf'` renders at the
   default with one warning).
2. **Major 2, text rows by `IX`.** `CellReader::row_*` now takes a
   `RowTarget` (`at(position)`, `by_ix(ix)`); the identity reaches the
   lookup as `RepeatedCell::row`/`row_ix`, and a row named by `IX` alone
   matches that `IX` in the sheet and in the master chain (an extension
   of the ADR 0019 decision 5 rule, recorded in ADR 0021's amendment).
   `row_position` is gone entirely: its only remaining job was the
   `ix as usize` fallback the task removes, and a marker names its row by
   `IX` (MS-VSDX `cp`/`pp` semantics). Tests:
   `a_row_read_by_ix_matches_the_master_row_by_ix` (model),
   `a_row_named_by_ix_alone_matches_only_that_ix` (lookup),
   `a_run_marker_reads_the_master_row_with_that_ix` (render: the
   requested case, an instance with no `Character` section and a master
   whose rows are `IX` 0 and 5; the run marked `IX` 5 reads the master's
   row 5, observed through its colour).
3. **Major 3, pattern tiles.** `PatternPaint` gains `filled: bool` and
   `tile_stroke_width: f64` (inches), set from the `PatternTemplate` in
   `build_fill`; the template's `tile_stroke_width` is a fraction of the
   tile box side (unit-box convention, default 0.05, ADR 0023
   amendment); both backends honor both fields. Implementing this
   exposed a second divergence the review did not list: the PNG tile
   pixmap mapped the tile path at `tile_w` pixels per inch instead of
   the device scale, so every tile mark drew `pitch`-times too small
   (the `render-fills` golden showed tiny dots where `visual-styles.yaml`
   defines wide vertical bands). The PNG mapping now fills the tile box
   exactly as SVG does. Tests:
   `an_open_tile_draws_the_same_marks_in_both_backends`
   (boundaries.rs: the ADR 0023 example tile `M 0 0 L 1 1`, the same
   72x72-pixel tile with a corner-to-corner 7.2-pixel diagonal in both
   outputs), `an_open_pattern_tile_strokes_with_its_width` (SVG),
   `a_tile_stroke_width_defaults_and_sticks`,
   `parse_rejects_bad_fill_patterns` (styles).
4. **Major 4, duplicated text fields.** `TextNode::rotation` and
   `TextRun::size` are removed; `text::Layout::rotation` and
   `GlyphPos::size` are the only copies. The placement recipe in
   `scene.rs` references the layout fields (tests updated to read glyph
   sizes and the layout rotation).
5. **Minor 5, one scale cap.** Both backends share
   `render::MAX_DEVICE_EXTENT` (16 384 px per side) and one scale
   policy: `Error::InvalidOptions` (new) for a scale that is not
   finite, not positive, or over the cap in pixels per inch; `TooLarge`
   when `page size x scale` exceeds the cap per side (so a huge page is
   still "too big", not "a bad option"). `a_huge_page_is_capped_not_a_panic`
   now asserts `TooLarge` in both backends (SVG used to write the huge
   page); `a_huge_scale_caps_the_raster_not_the_svg_text` became
   `a_huge_scale_is_invalid_options_in_both_backends`. The CLI keeps
   exit 3 for both (ADR 0026 unchanged) and reports the difference in
   words ("the render options are not valid"); its test
   `a_huge_scale_is_exit_three_not_a_panic` follows.
6. **Minor 6.** ADR 0020 amended: a group's own shape is drawn first,
   as the first child of its `Group`, with an identity transform, the
   sub-shapes in file order on top. The Visio z-order check is noted for
   the screenshot pass.
7. **Minor 7.** The stale sentence is fixed: a node transform maps into
   the parent group's space, the ancestor chain to the page.
8. **Minor 9.** Formula-parse degradations warn `KindMismatch`, not
   `ErrorValue` (the file's cached value is not an error; the builder
   cannot use the formula). The CLI no longer prints them as "cached
   error" (`nurbs_to_without_a_parsable_formula_draws_a_line_and_warns`
   and the build_scene formula test pin the kind).
9. **Minor 10.** `section_rows` counts through the lookup's master
   rungs via the new `Document::master_chain_shapes` (the P2-06b
   position rule and the sub-shape walk) and shares the builder's
   `MAX_DEPTH`; the magic bound of 8 is gone. Test:
   `section_rows_counts_the_master_shape_the_cells_resolve_from` (a
   two-shape master: the count and the stop colours both come from the
   shape the instance resolves through), plus
   `master_chain_shapes_follow_the_master_rungs` (model).
10. **Minor 11.** **Picked documentation** (the recipe in `scene.rs`):
    a glyph whose font index is out of range or whose outline is empty
    (a space, or a glyph id the font does not have) draws nothing and
    the placement recipe says the skip is intentional. A warning per
    skipped glyph would fire on every space in every text and make
    `--strict` useless; the real failures are `text::Layout`'s own
    `MissingFont`/`MissingGlyph` warnings. The backend skips are
    documented in `svg.rs` and `png.rs` as before.
11. **Minor 12.** `BuildOptions::default()` is `BuildOptions::new()`
    (background included); no caller needed the old asymmetry.

Major 8 is P3-18's; untouched here.

### Open issues

- `text::Layout`'s `MissingFont`/`MissingGlyph` warnings stay on
  `Layout::warnings` and do not reach `Scene::warnings` or the CLI
  (pre-existing; surfacing them is a small follow-up, needs a decision
  on mapping `text::Warning` to `CellWarning`).
- The number policy rejects non-finite values; the boolean and list
  coercions still accept them (`FlipX` with `V='inf'` reads `true`, a
  parsed list may hold `inf`). Left to the Phase 6 formula-engine pass,
  which owns value semantics end to end.
- A `Character`/`Paragraph`/`Tabs` row without an `IX` no longer
  matches a run marker positionally (the `ix as usize` rule the task
  removed). All rows of those sections in the 15 corpus files carry an
  `IX` (checked 2026-10-15); if a file appears without them, the fix is
  a positional fallback in `matched_row_cell`, not in the builder.
- `BuildOptions::scale` keeps its documented fallback (non-finite or
  non-positive becomes `DEFAULT_SCALE`); the backends are the
  enforcement point (ADR 0025 amendment).
- New public model API: `Document::master_chain_shapes` (minor 10 needs
  the lookup's master rungs from L3; the rung helpers stay
  crate-private).
