## Goal

1. **`edit.select`.** Add a registry command that sets the selection.
   - Arguments, JSON-friendly: the shapes as an `ArgValue::List` of Visio
     ids (as strings, matching how other commands name shapes; check
     P5-04's handlers first and use the same form), and a mode:
     `replace` (the default), `add` or `toggle`. An empty list with
     `replace` clears the selection.
   - It selects on the active page. Unknown ids are an error, not a
     panic and not a partial change.
   - It is not an edit: no undo step, and it does not bump `changes`.
2. **The pointer selects through the command.** Remove
   `ToolEffect::selection` (`SelectionUpdate`). The pointer tool emits
   an `edit.select` intent instead, and the shell dispatches it like any
   other intent. Behavior stays as P5-05 built it: click, Shift toggle,
   Ctrl add, marquee, the group mapping and the entered group. If the
   entered group needs a field the command cannot express, say how you
   handled it in the Result.
3. **Connection points from masters.** Add
   `Document::connection_points(shape: ShapeId) -> Vec<Point>` in
   `crates/model/src/connection.rs`. It returns the points in the
   shape's local coordinates:
   - the shape's own `Connection` rows when it has any;
   - otherwise the rows inherited through its master chain
     (`master_chain_shapes`), each `X`/`Y` scaled by the instance's
     `Width`/`Height` over the master shape's `Width`/`Height`, so a
     resized instance keeps its points on its outline. A zero or missing
     master size means no scaling.
   - Skip rows with a non-finite value. Bound the walk as the lookup
     does. No panics.
   `ui::snap::connection_points` calls it and applies the shape's
   transform as it does today. P5-08's glue will call the same helper.

## Result

Filled by the P5-16 worker, 2026-10-18, branch `agent/P5-16`.

### What changed

- **`edit.select`** (`crates/commands/src/builtins/edit.rs`): a
  registry command with `shapes` (an `ArgValue::List` of Visio id
  strings) and `mode` (`replace` by default, `add`, `toggle`). It
  resolves every id on the active page, so an unknown or malformed id
  fails the whole command and leaves the selection unchanged. Replace
  with an empty list clears the selection (including the entered group,
  as P5-05 did); an empty selection has no page. It is not an edit: no
  undo step and no `changes` bump.
- **Extractor and data**: `edit.select` joined `OUR_COMMANDS`;
  `ui-spec/commands.yaml` gained its row (975 to 976 commands) and the
  count pin moved with it. `cargo xtask extract` also regenerated
  `docs/parity/controls.md`; it has no diff because command-only ids do
  not appear in the Fluent control matrix yet (P4-15 open issue).
- **Pointer through the command** (`crates/ui/src/tools/pointer.rs`,
  `crates/ui/src/tools/mod.rs`, `crates/ui/src/shell.rs`): removed
  `ToolEffect::selection` and `SelectionUpdate`; the pointer now emits
  `edit.select` intents for click (replace), Shift (toggle), Ctrl (add),
  marquee (replace/add), empty-space clear and the double-click group
  selection before `shape.enter_group`. The shell and the Phase 5 test
  rig dispatch the intents like any other command.
- **Inherited connection points** (`crates/model/src/connection.rs`,
  `crates/model/src/lib.rs`): `Document::connection_points(shape)`
  returns the shape's own `Connection` rows, or the nearest master rung
  that has rows, scaled by the instance's `Width`/`Height` over that
  master shape's size. Missing, zero or non-finite sizes leave that axis
  unscaled; non-finite or incomplete rows are skipped; the chain walk is
  capped and cycle-safe.
- **Snapping** (`crates/ui/src/snap.rs`): the connection-point candidates
  come from the model helper and are mapped through the node transform,
  so a resized master instance exposes its scaled points.
- **Tests**: five model integration tests (own rows and malformed rows,
  stale/masterless shapes, resized built-in rectangle, chained rung,
  zero/missing sizes); two headless command tests (replace/add/toggle/
  clear/defaults, bad id/mode/type with no partial change); a pointer
  test proving a click reaches the registry; a snap test for the resized
  rectangle instance; the existing pointer tests now assert the emitted
  `edit.select` intent.

### Deviations

- `edit.select` keeps the entered group for a non-empty selection but
  clears it when the resulting selection is empty, matching P5-05's
  shell behaviour. The command has no `entered` argument: the pointer
  maps a hit to the entered group's direct child before emitting the
  intent, and P5-08 can do the same.
- Inherited points come from the **nearest master rung with rows**, not
  from merging every rung: this is the lookup's first-definer rule. The
  scale uses the instance's and that master shape's direct `Width`/
  `Height` cells (no formula evaluation, Phase 6).
- `docs/parity/controls.md` was regenerated but is unchanged; see the
  P4-15 open issue about command-only ids.

### Open issues

1. `edit.select` does not accept an explicit entered-group id. If a
   later control-channel caller needs to set the entered group
   independently, add an argument or a separate command.
2. `Document::connection_points` reads direct size cells only. An
   instance whose size is inherited without a direct cached value stays
   unscaled; the formula engine (Phase 6) can revisit this.
3. The chained-rung rule is nearest-definer; if a file ever needs the
   union of several masters' Connection sections, that is a new decision.
