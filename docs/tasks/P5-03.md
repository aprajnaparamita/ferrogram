### What changed

- `crates/geom/src/hit.rs`: the four math functions are implemented.
  Distances are plain geometry in inches; quadratic and cubic segments
  flatten through `Curve::to_cubics` (ADR 0022) and then to chords within
  `FLATTEN_TOLERANCE` (0.001 in) with bounded recursion (depth cap 12).
  `path_contains` uses the non-zero winding rule with each subpath closed
  virtually; a point exactly on the outline counts as inside.
- `crates/geom/src/snap.rs`: `snap_point` (nearest within a kind, the
  higher `SnapKind` wins across kinds even when slightly farther, ties by
  candidate order), `snap_axis` (nearest, candidate order breaks ties)
  and `snap_grid` (round half away from zero, via `f64::round`).
- `crates/render/src/hit.rs`: `hit_test`, `hit_marquee`, `node_bounds` and
  `scene_bounds` over a depth-capped scene walk (128, the builder's cap).
  Geometry is mapped into page space through the node's ancestor
  transforms before measuring, so `distance` is in page inches under any
  scale, rotation or flip. One hit per shape node, strongest part first
  (`Fill`, then `Stroke`, then `Text`), results topmost first (draw order
  reversed).
- `crates/render/src/overlay.rs`: `build_selection_overlay` emits one
  `SelectionOutline` per node (the node's own bounds box at its
  transformed centre, scaled by the transform's axes, turned by the
  transform's rotation) and one `Handles` mark (the same for one node,
  the axis-aligned union of the page bounds for several).
- `crates/render/src/build.rs`: the shape construction site records
  `shape_id: Some(id)`. No synthesised shape node exists today (shadow
  bodies are drawn by the backends, not as scene nodes), so the `None`
  case is documented on `scene::Shape::shape_id` and covered by tests
  that build nodes without a model shape.
- `crates/render/src/scene.rs`: doc comment of `shape_id` extended (no
  type changes).
- Tests: inline unit tests in both `hit.rs`/`snap.rs` modules (the P5-01
  stub tests are replaced), `crates/geom/tests/hit_curve_flattening.rs`
  (one hit-within-tolerance test per ADR 0022 curve family) and
  `crates/render/tests/hit.rs` (the ADR 0041 rules against real scenes:
  fill/outline/text with tolerance, z-order, nested groups, marquee
  intersection, rotated bounds, empty scenes, degenerate and non-finite
  paths, the bounded walk, and the builder's `shape_id`).

### Deviations from the signed interfaces

1. **Invalid snap arguments are `Error::WrongUnit`.** The stub docs leave
   the variant to P5-03 and `geom::Error` has no `InvalidArgument`;
   `error.rs` is P5-01's file. `WrongUnit` ("the unit does not measure
   the expected kind of quantity") is the closest existing variant for a
   `max_distance` or `spacing` that is negative or not finite. See open
   issue 1.
2. **A stale `NodePath` is `render::Error::InvalidOptions`** in
   `node_bounds` and `build_selection_overlay` (the closest existing
   variant for a caller-side bad request, the same standing the
   `Error::Model` doc gives caller bugs). See open issue 3.
3. **`Hit` ordering is z-order, not distance.** ADR 0041 says
   topmost-first; the `Hit::distance` doc said "results sort by it". The
   ADR wins and the doc comment now says so. `distance` is what the
   caller's tolerance matched (0 inside a fill or a text block).
4. **`snap_axis` has no kind priority.** Its signed doc ("the candidate
   order breaks ties") is a different rule from `snap_point`'s ADR 0043
   kind priority, so `snap_axis` takes the nearest candidate and breaks
   ties by candidate order. Pinned by `snap_axis_has_no_kind_priority`.
   See open issue 4.
5. **The empty `NodePath` is the scene root** (`scene_bounds`), since the
   stub called `node_bounds` with it. Documented on `node_bounds`.
6. **Text block bounds are approximate.** They are the layout block box
   `(0, 0)`..`(width, height)` turned by `Layout::rotation` about the
   box centre and placed at `TextNode::origin`. The layout bakes its
   rotation about the *input* block box centre, which `Layout` does not
   expose, so a block whose content is smaller than its box can differ
   slightly; overflow content outside the box is not hit-testable. Fine
   for Phase 5 selection, revisit for text editing (ADR 0044).
7. **A group's bounds** are the union of its members' bounds computed in
   the group's own space and then transformed: exact for unrotated
   groups, a slight overestimate for a rotated group with spread
   members.
8. **Marquee hits carry `distance: 0.0`** and `HitKind::Bounds`; at most
   one hit per shape node (`Fill` beats `Stroke` beats `Text`).
9. Non-finite rules (documented in the modules): `geom::hit` degrades to
   "no hit" (`f64::INFINITY`, `false`); a degenerate zero-length segment
   measures its point distance (`distance_point_segment`'s signed rule);
   `snap_grid` keeps a non-finite value unchanged; two wildcard arms for
   the non-exhaustive `Segment` in `render/src/hit.rs` are unreachable by
   construction (they are the only uncovered lines of my code).
