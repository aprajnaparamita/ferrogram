## Goal

Walk the MS-VSDX schema and write a `docs/vsdx-inventory.md` that lists
every OPC part, every XML element, and every attribute, with an MVP
status of `supported`, `preserved-only`, or `later`.

The output is the planning document for Phase 2 (`.vsdx` read/write)
and Phase 3 (rendering). The MVP is the Phase 2 scope: parse, preserve
unknown parts, and round-trip. "Preserved-only" means we keep the XML
verbatim without modelling it. "Later" means we know about it but
Phase 2 ignores it.

## Outputs

### `docs/vsdx-inventory.md`

A single markdown file with these sections:

1. **Header.** Source URL, XSD commit, extraction timestamp.
2. **OPC parts.** A table of every OPC part path (e.g.
   `/visio/document.xml`, `/visio/pages/_rels/pages1.xml.rels`),
   with the part's content type and a short label. One row per
   part. Status is one of:
   - `supported`: Phase 2 will read and write this part.
   - `preserved-only`: Phase 2 keeps the part byte-for-byte; it is
     never parsed.
   - `later`: not in the MVP.
3. **Complex types.** A table of every `*_type-complextypevisio-xml.md`
   page: type name, parent type, child element count, status. Same
   three statuses.
4. **Elements.** A table of every element name in the XSD, with
   `parent type`, `type ref`, `cardinality`, and status. Status is
   `supported` for elements Phase 2 will read; `preserved-only` for
   elements we keep verbatim on round-trip; `later` for everything
   else.
5. **Attributes.** A table of every attribute name in the XSD, with
   `parent element`, `type`, and status.
6. **Counts.** A summary table: total parts, supported parts;
   total types, supported types; total elements, supported elements;
   total attributes, supported attributes.

The tables are sorted (parts by path, types by name, elements by
`(parent type, element name)`, attributes by `(parent element,
attribute name)`). Output is deterministic.

### Status assignment

The default for a new element is `preserved-only` (we keep the XML,
we don't model it). The P1-05 author promotes an element to
`supported` only when the Phase 2 reader is in scope. The list of
in-scope elements is in the Phase 2 task file; for P1-05, use the
following conservative rule:

- A `<Pages>`, `<Page>`, `<Shape>`, `<Cell>`, `<Section>`, `<Row>`,
  `<Connect>`, `<Masters>`, `<Master>`, or document-properties
  element is `supported`.
- Every other element is `preserved-only` in P1-05; the master agent
  may promote specific elements to `supported` in a follow-up
  before Phase 2 starts.
- Any element under a "Theme", "Comments", "Validation", "DataRecordset",
  or "User" part is `later`.

A unit test asserts the default-status logic and the promotions above.

## Implementation notes

- **XSD parsing.** The XSD is a single fenced code block inside
  `schema-mapvisio-xml.md`. Extract the block, then parse it with the
  `roxmltree` crate (MIT) — it is a fast, pure-Rust, read-only XML
  parser. We only need `<xsd:element>`, `<xsd:attribute>`,
  `<xsd:complexType>`, `<xsd:extension>`, and `<xsd:restriction>`.
- **Markdown table parsing.** The 350 complex-type pages share one
  shape: a title, a metadata block, and a small table with `Element`,
  `Type`, and `Description` columns. A hand-written parser in
  `xtask/src/extract/markdown.rs` is enough.
- **OPC part discovery.** The XSD references part paths in the
  `app.xml` and `document.xml` schemas. Hard-code the canonical part
  list (it is a closed set per [MS-VSDX]) in
  `xtask/src/extract/vsdx_schema.rs::PARTS`. The list is:
  - `/[Content_Types].xml` (always `preserved-only`).
  - `/_rels/.rels` (always `preserved-only`).
  - `/visio/document.xml` (`supported`).
  - `/visio/_rels/document.xml.rels` (`preserved-only`).
  - `/visio/pages/pages.xml` (`supported`).
  - `/visio/pages/page1.xml` ... `pageN.xml` (`supported`).
  - `/visio/pages/_rels/pages.xml.rels` (`preserved-only`).
  - `/visio/masters/masters.xml` (`supported`).
  - `/visio/masters/master{1..N}.xml` (`supported`).
  - `/visio/windows.xml` (`preserved-only`).
  - `/visio/validation.xml`, `/visio/validation_issues.xml` (`later`).
  - `/docProps/app.xml`, `/docProps/core.xml`, `/docProps/custom.xml`
    (`preserved-only`).
  - `/visio/theme1.xml` ... `themeN.xml` (`preserved-only`; Phase 3
    parses them).
  - `/customXml/*` (`preserved-only`).
  - Any other part: `preserved-only`.
- **Clean-room.** Never embed the XSD text. The inventory records
  element names, type names, and parent-child relationships; that is
  structural data, not Microsoft's prose. The `<xsd:annotation>`
  copyright notice in the source XSD is **not** written anywhere.
  Add an extractor test that reads a fixture, runs the extractor,
  and asserts the output contains no `<xsd:` strings and no `©`
  or `Copyright` substrings.
- **Determinism.** Re-running the extractor on the same input must
  produce byte-equal output. Use `BTreeMap` everywhere and a
  dedicated test.
