## Interfaces

Implement exactly the ADR 0034 signatures in
`crates/model/src/stencils/mod.rs`:

```rust
pub struct StencilDef { pub name: &'static str, pub masters: Vec<MasterDef> }
pub struct MasterDef {
    pub name_u: &'static str,
    pub name: &'static str,
    pub width: f64,
    pub height: f64,
    pub geometry: Vec<GeometryRow>,
    pub line: LineDefaults,
    pub fill: FillDefaults,
    pub shape_data: Vec<(&'static str, &'static str)>,
    pub connection_points: Vec<(f64, f64)>,
}
pub struct LineDefaults { /* weight in inches, colour index, pattern 1 */ }
pub struct FillDefaults { /* pattern 1 (solid), fore/back colour index */ }
pub fn basic_shapes() -> StencilDef;
pub fn basic_flowchart() -> StencilDef;
pub fn catalog() -> Vec<StencilDef>;
pub fn stencil_document() -> Document;
pub fn instantiate(target: &mut Document, master: &MasterDef) -> ShapeId;
```

All geometry is authored by us in inches on a unit box scaled to
`width`/`height` (the master's `Width`/`Height` cells). No shape is
traced, copied or derived from Microsoft material. Basic Shapes:
rectangle, rounded rectangle, ellipse, triangle, right triangle,
diamond, pentagon, hexagon, octagon, five-point star, arc, line (about
12). Basic Flowchart: process, alternate process, decision, terminator,
data, document, manual operation, preparation, connector (about 8).
Each master carries 2–4 Shape Data rows (e.g. `Cost`, `Process`) and
connection points at edge midpoints plus, for the connector, the ends.

`shapes_window::ShapesWindow::show` lists the catalog
(`collapsing_header` per stencil, one selectable row per master with a
small preview rendered through `render::render_raster` of a one-shape
scene). Clicking selects (`ShapesWindow::selected`); dragging onto the
page is Phase 5.

### Deviations from the task text

- **"Scaled instance"**: `instantiate` sets the instance's
  `Width`/`Height` to the master size and the pin cells per the ADR 0020
  transform (`PinX = Width*0.5`, `PinY = Height*0.5`, documented
  `LocPinX`/`LocPinY` defaults), so the local box maps to
  `(0, 0)..(width, height)` on the page; the unit test checks that
  transform. Geometry rows stay in master-local inches (ADR 0019:
  inherited rows carry master coordinates), so a differently sized
  instance needs the Phase 6 formula engine. `instantiate` also adds the
  master once (matched by `NameU`) and links the instance to it, and
  creates "Page-1" when the document has no page (the interface has no
  `Result`, so it must always land somewhere).
- **Previews until P4-05**: `render_raster` is task P4-05's stub on this
  branch, so a preview that cannot rasterize draws a placeholder box and
  the window still lists and selects. `a_preview_raster_fits_the_master_box`
  is written for both states (it asserts the raster size only when a
  raster exists), so it stays green when P4-05 merges.
- **Clicking**: the click wiring is one line into a private `select`;
  the click path through egui input is left to the P4-09 `egui_kittest`
  harness tests (ADR 0037 puts those in `crates/ui/tests/`, which this
  task does not own). Selection is tested via `select` + `selected`.
- **Row spellings** follow what the corpus files spell (checked, not
  copied): `Property` rows with `Label`/`Value` cells and the row name
  set to the label, `Connection` rows with `X`/`Y` cells and
  `T="Connection"`.
- **Line (Basic Shapes)** carries its two ends as connection points in
  addition to the edge midpoints (the task says "the ends" only for the
  connector; a line has ends too).
- `ShapesWindow` implements `Debug` and `PartialEq` by hand (egui's
  `TextureHandle` has no `Debug`; equality is the selection, not the
  preview cache).
- `geometry_row` (the `GeometryRow` to `Row` mapping) does not write the
  formula-encoded `E`/`A` data of `NurbsTo`/`PolylineTo` rows; the
  stencils never author those rows and the `X`/`Y`/`A`..`D` cells the
  reader falls back to are kept.
