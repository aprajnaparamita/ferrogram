### What was built

- **Item 1:** `package/xml.rs` resolves unprefixed *element* names against
  the in-scope default namespace (an `xmlns=""` unbinding resets it to
  none); unprefixed *attribute* names stay in no namespace. New tests:
  `<Cell xmlns="urn:x"/>` equals `<p:Cell xmlns:p="urn:x"/>` and differs
  from `<Cell/>`; unprefixed attributes; the empty binding. No hand-built
  expected tree compared against parsed output needed updating (all suites
  were green unchanged); the one test that needed the parser's new truth
  was written in item 5 (a `Relationship` child takes the relationships
  default namespace). Corpus round-trip stayed green throughout.
- **Item 2:** `remove_children` clears leftover whitespace only when it
  actually dropped elements. Tests: unit (blank text with no drop stays)
  and integration (`blank_text_only_content_survives_a_write`).
- **Item 3:** `main_part`, `is_main_content_type`, `rel_type_local`,
  `resolve_target` moved to `package/discovery.rs`; `text_content` to
  `read/node.rs`; colour parsing plus the shape classification to
  `value_parse.rs` (the shape rule is what item 7 needs, so it moved with
  the parser it belongs to). The reader and the writer import one copy
  each. No behavior change.
- **Item 4:** `interned_default` takes the lock once, recovers a poisoned
  one with `into_inner` and inserts-or-reuses in that one critical
  section. The insert-or-reuse half (`interned_in`) takes the cache as a
  parameter so the poisoned path is testable: the test poisons the cache
  with a panicking lock holder and asserts one interned value per key
  (it fails before the fix: the old `Err` arm leaked a fresh value per
  call).
- **Item 5:** `parse_relationships` keeps child *elements* of a
  `Relationship` in `Preserved` (`Preserved::children` is `Vec<XmlNode>`;
  text and comments have no slot, as everywhere in the model) and
  `relationships_xml` writes them back inside the element. Test round-trips
  a package with a child element carrying an attribute and text.
- **Item 6:** `raw.rs` docs (`diff`, `values_equal`, `parse_number_value`)
  and ADR 0012 (dated *Amended 2026-10-14, P2-14*) now say what the code
  does: a number literal with an optional suffix compares numerically,
  suffixes must match exactly, units never convert, text compares exactly.
  Docs only, no code change (so no test).
- **Item 7:** `write/value.rs` grows `unit_spelling`/`kind_code`: a value
  the model built gets the `U` the reader classifies it with — `U="BOOL"`
  for `Bool`, `U="STR"` for a `Str` whose text would read as a number or a
  colour, or whose unit would otherwise write a numeric code (kind
  fidelity wins over the unit for these two kinds; the reader gives them
  no unit back). A `U` spelling that already declares the right kind
  (`DATE` for a date string, `BOOL` for a boolean) is never rewritten, so
  unedited writes stay byte-stable and the corpus round-trip is green.
  Both writers use the rule (patcher and generator). `List` stays out of
  scope; the `write/value.rs` module docs say so. The P2-10 `from_model`
  property generator no longer excludes `Bool` and number-like/colour-like
  `Str` values, and sets the reader's preserved `U` spelling on those
  cells (a file-read `Bool` cell carries `U="BOOL"` in `Preserved`, so a
  generated model must too for full model equality).
- **Items 8–14:** tests as listed in the map. Item 13 note: the audit's
  `emit.rs` `_ => "?"` lines are test helpers that mark non-element
  children in name lists, not unit spellings; the real unit fallback is
  `write/value.rs::unit_code`'s `_ => None`. The decision is recorded at
  that arm (keep writing no `U`, never an error — an error would reject a
  model the reader accepted) and `every_unit_has_a_spelling_or_a_place`
  pins all 19 `Unit` variants (14 spell a code, 5 write none).

### Open issues

1. **Colour values with a unit** (out of item 7's scope, which named only
   `Bool` and `Str`): a hand-built `CellValue::Color` with a non-`Unitsless`
   unit still writes the numeric unit code over the `#rrggbb` literal and
   does not read back. Same shape of problem for `List`. Worth folding
   into the formula-engine task that owns `List`.
2. **The `U` of `Bool`/`Str` carries no unit**: a model `Bool` or `Str`
   cell with a real unit reads back `Unitsless` (no `U` code spells both a
   kind and a unit). Only hand-built models can be inconsistent here.
3. **Relationships part namespace spelling**: `relationships_xml` always
   writes the relationships namespace as the default one, so a preserved
   `Relationship` child that was unprefixed in a prefixed-root source
   re-parses into the relationships namespace. Latent (corpus
   `Relationship` elements have no preserved children); note for a task
   that touches relationships writing.
4. The `zip` writer's `invalid("zip writer failed")` is mapped to
   `InvalidPackage` and no input can provoke it; `write_document`'s error
   surface is therefore `MissingPart` and `InvalidPackage` only, as the
   item 10 test comment records.
