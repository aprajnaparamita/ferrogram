## Goal

Rasterize a scene to deterministic PNG bytes with the documented options
and caps.

## Interfaces

Implements (signatures fixed by P3-01):

```rust
pub fn render_png(scene: &Scene, options: &PngOptions) -> Result<Vec<u8>, Error>;
```

Consumes `scene::Scene` and the geom/text types inside it. May add private
helpers in `png.rs` (paint to `tiny_skia::Paint`, dash to `Stroke`,
glyph outline filling). Output dimensions are `ceil(width * scale)` by
`ceil(height * scale)` pixels (ADR 0025), y flipped. Input-derived sizes
are capped: return `Error::TooLarge` when either dimension exceeds
16384 pixels or the raster would exceed 256 MiB (AGENTS.md section 6,
checked arithmetic).

## Acceptance criteria

- [ ] `render_png` implemented: paths (fill and stroke), dashes, caps and
      joins, line ends, gradients, patterns, shadows (offset copy with the
      template alpha) and glyph outlines (as filled paths) all rasterize.
- [ ] Anti-aliasing on by default; `antialias: false` renders hard edges.
      Background is `Scene::background`, or transparent when `None`.
- [ ] Caps tested: an oversize scene returns `Error::TooLarge`, never
      panics, never allocates unboundedly.
- [ ] Determinism tested: rendering the same scene twice is byte-identical
      on one machine (ADR 0025).
- [ ] Unit tests render synthetic scenes (construct `Scene` values
      directly) and check PNG signature, dimensions and a few pixel
      values; no golden dependency on P3-10's harness.
- [ ] `cargo xtask gate` green (the wasm build compiles `tiny-skia`).

## Note from the master

Group A changed two things the stubs did not show. First, `ferrogram_text::layout`
bakes the text block rotation into glyph positions (ADR 0024 amendment), so
rotate each glyph outline by the block rotation when you draw it; do not
rotate the whole text block again. Second, `ferrogram_render::styles`
(P3-08) documents unit-box conventions for line ends and tile-box
conventions for fill patterns; P3-05 applies them when building the scene,
so the backend draws the scene's paths and paints as given.

## Result

_Filled in by the worker at hand-off._

Built (branch `agent/P3-06`, worktree `/Volumes/Dara/ferrogram/worktrees/P3-06`):

- `crates/render/src/png.rs`: `render_png` rasterizes the whole scene
  graph with `tiny-skia` — fills and strokes (dashes, caps, joins, miter
  limit), line ends in the `render::styles` unit box (tip at the path
  vertex, tail `length` inches along the line into the shape, `width`
  across the line centre), linear and radial gradients, repeating pattern
  tiles (background box, tile path in the foreground, `tile_size` pitch),
  shadow copies (offset fill plus stroke silhouette in the shadow colour
  and its alpha), clips on groups and shapes (intersected `tiny_skia`
  masks in device space), composed node transforms, and glyph outlines as
  filled paths. Rasters are `ceil(width * scale)` by
  `ceil(height * scale)` pixels with the y flip of ADR 0025; the
  background is `Scene::background` or transparent. Anti-aliasing is on
  by default and `antialias: false` renders hard edges.
- Caps (AGENTS.md section 6): `Error::TooLarge` above 16 384 pixels per
  side or 256 MiB of raster (checked `u64` math), and for a degenerate
  request (zero, negative or non-finite pixel size) that cannot form a
  raster. Scene nesting is followed to 128 levels (the builder's cap).
  Non-finite coordinates anywhere in the input are skipped; nothing
  panics and every allocation is bounded by the caps.
- 25 unit tests on synthetic scenes: PNG signature and IHDR dimensions
  (ceil semantics), background and transparency, the y flip, fill and
  stroke pixels, dash gaps, caps, line ends, both gradients, pattern
  tiles, the shadow copy, clip and group-transform composition, glyph
  outlines and block rotation, hard edges with anti-aliasing off, the
  caps (`TooLarge`, never a panic), dash/path-end sanitization helpers,
  and byte-identical determinism on one machine (ADR 0025).
- `crates/text/src/layout.rs` (deviation, see below) plus a test that the
  output carries the glyph sizes and the block rotation.

Deviations (the interfaces were insufficient; per the implementer role I
implemented the closest correct version):

1. **`ferrogram-text` output extended** (P3-04's crate, merged and idle):
   `GlyphPos` gains `size: f64` (points) and `Layout` gains
   `rotation: Angle` (the angle baked into the glyph positions). ADR 0024
   says backends scale outlines by `size / 72` and rotate each outline by
   the block rotation, but neither value reached the scene: `GlyphPos`
   had only positions and a run index, and no run formats are in
   `TextNode`. Without these fields a backend cannot draw text at the
   right size or orientation. Additive fields; `Layout::default()` is
   unchanged in behaviour. **P3-07 needs exactly these two fields** (its
   note from the master asks for the same outline rotation).
2. **`Error::Encode`** added in `crates/render/src/error.rs` (shared
   file): PNG encoding failure had no variant to map to. One variant,
   one `Display` arm, one test line.
3. Interpretations the stubs did not fix:
   - Text maps the y-down layout space to page space as
     `origin + (x, -y)` (the block origin is the block's top-left in the
     shape-local y-up frame); the glyph outline is rotated by
     `Layout::rotation` about the glyph origin in layout space first.
   - A `PatternPaint` tile draws as the background box with the tile path
     filled in the foreground (`PatternPaint::foreground` is documented
     as a "stroke" colour, but no stroke width is carried, so filling is
     the only self-consistent reading; `invert` must be resolved into the
     two colours by the builder). A degenerate `tile_size` falls back to
     the foreground colour.
   - A `Shape::clip` clips the fill, stroke, line ends and text, not the
     shadow (a clip would cut the offset copy away).
   - `Shadow::blur` is not applied: `tiny-skia` has no blur filter. The
     acceptance criterion ("offset copy with the template alpha") is
     met.
   - Degenerate sizes return `Error::TooLarge` (see above) because no
     better variant exists.

New dependencies: none (`tiny-skia` 0.12 was already in
`crates/render/Cargo.toml`; no feature changes).

Gate: `cargo xtask gate` green (codegen, fmt, clippy, test, doc,
coverage, deny, layers, wasm, fuzz). Coverage: `png.rs` 90.3% of

Open issues for the master:

- Amend ADR 0024 for the two output fields (`GlyphPos::size`,
  `Layout::rotation`) and record the layout-to-page mapping above; the
  same mapping must land in P3-07's `svg.rs` or the two backends will
  disagree on text placement. If P3-07's branch already added the same
  fields, keep one definition at merge.
- ADR 0025 calls `tiny-skia` MIT; its actual licence is BSD-3-Clause
  (its `Cargo.toml` and the vendored source). `cargo deny` passes, so
  the ADR wording is the only thing to fix.
- Text decoration is still missing from the scene: `Format` carries
  `underline`/`strikethrough` (the backends are meant to draw them), but
  `TextNode` has no run formats, so no backend can. Needs a scene or
  layout addition and a builder change (P3-05).
- `Shadow::blur` needs a blur step (a box blur over the shadow pass, or
  a `Pixmap` filter) if Visio-faithful shadows are wanted.
- P3-05 may construct `GlyphPos`/`Layout` literals in tests; the two
  added fields will break such literals at merge (construction from
  `text::layout` output is unaffected).
