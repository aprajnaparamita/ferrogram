### What changed

- **`functions.rs`**: `FUNCTIONS` holds the 42 rows of the ADR 0053
  evaluated set, hand-written with the names and argument bounds of the
  ShapeSheet reference's function pages (docs/sources.md rows 4 and 19)
  and our own kind tags. `lookup_function` is case-insensitive and
  returns `Ok(None)` for an unknown name (no failure path exists);
  `is_supported` is exactly "a row exists". `tests/functions.rs`
  transcribes the reference names and arities and pins them row by row,
  plus the is_supported/lookup contracts.
- **`eval.rs`**: `eval`/`eval_formula` implement the rules of the module
  docs: operators coerce through `coerce` (ADR 0052's one rule) and
  compute in the family's canonical unit (inches, radians, fraction,
  seconds), errors propagate (`IF` evaluates only the taken branch,
  `IFERROR` catches error values but not the unknown-function path), and
  the 42 functions compute with their documented shapes (`INT` rounds
  down, `CEILING`/`FLOOR` move away from/toward zero to a multiple,
  `MODULUS`/`MOD`, `SIGN` with fuzz, trig on radians, `DEG`/`RAD`, RGB,
  zero-based `INDEX`/`LOOKUP` with the list rule of the reference,
  `NA`, `STRSAME`). `GUARD(x)` is a value pass-through (the protection
  rule is P6-07's). `SETF(target, value)` writes through
  `EvalContext::set_cell` and evaluates to `value`; a refused or
  non-reference target is `#REF!` with a `SetfRefused` warning, and an
  error value is never written. An unknown (or reserved `_`-prefixed)
  function records **one** `UnknownFunction` warning per evaluation and
  stands back (the caller keeps its cached value, ADR 0053). Argument
  counts are checked against the table before anything evaluates: a
  wrong count is `#VALUE!` plus one `WrongArgumentCount` warning and no
  side effect. Division by zero is `#DIV/0!`, a non-finite result is
  `#NUM!` with a `NonFinite` warning (ADR 0052's source rule). Never
  panics: recursion is bounded (`MAX_EVAL_DEPTH` 64, deeper hand-built
  trees degrade to `#VALUE!`), `&` concatenation is capped (1 MiB,
  `#VALUE!`), and no indexing on input values.
- **`tests/eval.rs`**: one test per acceptance bullet and function
  family (mixed-unit arithmetic, comparison coercions, `IF` laziness
  incl. no `SETF` side effect on the untaken branch, `MIN`/`MAX` of
  unit values, `INT`/`ROUND`/`CEILING`/`FLOOR`/`MODULUS`/`TRUNC`/`SIGN`
  edge cases, trig, `DEG`/`RAD`, `RGB`, `INDEX`/`LOOKUP` bounds, `NA`,
  `STRSAME`, `IFERROR`, `GUARD`, `SETF` incl. refusal, the
  unknown-function and reserved-name rules, the arity rule, `#DIV/0!`
  and `#NUM!`). The trees are built by hand: `parse` is P6-02's.

### Deviations and decisions

- **Unknown-function contract**: the committed signature
  `Result<Value, Error>` has no "keep cached" channel, so the warning is
  that channel (P6-06's `recalc` keys its keep-cached rule on
  `RecalcWarningKind::UnknownFunction`, mapped from this kind) and the
  returned `Value::Err(ErrorCode::Na)` is a documented placeholder the
  caller must not write. `IFERROR` does not catch it.
- **Reserved internal names** (`_MOD`, `_ELLIPSE_THETA`, ADR 0053's
  "their own warning text"): recorded as `UnknownFunction` with the text
  `"<name> (reserved internal name)"` rather than a new kind, so the
  keep-cached rule sees them without a `recalc.rs` change (see open
  issues for the nicer vocabulary).
- **`EvalWarningKind` gained two variants** (this file owns the enum):
  `WrongArgumentCount { function, min, max, got }` and
  `SetfRefused(String)`. `recalc::map_warning`'s wildcard drops them,
  which is correct today (their values, `#VALUE!`/`#REF!`, are already
  the outcome).
- **`INDEX` bounds**: a malformed index (negative or non-integral) is
  `#VALUE!` (ADR 0060's "a bad index"); an out-of-range index follows
  the reference page's own examples instead: the `errorvalue` argument
  when given, the empty string otherwise. Flagged because ADR 0060's
  sentence can also be read as "out of range is `#VALUE!`".
- **Units**: a computed number carries the family's canonical unit
  (`1 ft` unary minus is `-24 in`); `DEG`/`RAD` deliberately return
  `Unit::Degrees`/`Unit::Radians`. A plain number joins the family it is
  used with; two operands of different families are `#VALUE!`; a result
  the one-unit value type cannot carry (`1 in * 1 in`, `5.2 cm ^ 1.5`,
  `SQRT(4 in)`) is `#DIM!` (ADR 0052's corner); a length quotient is a
  plain ratio.
- **`MODULUS`/`MOD`** take the sign of the dividend (trunc-based, the
  `CEILING`/`FLOOR` toward/away-from-zero family). The reference gives
  no sign rule: black-box check item.
- **Arity corners**: `SUM` 1..∞ (the corpus has 1-argument calls while
  the page marks the second argument required), `CEILING`/`FLOOR` 1..2
  (the page's prose documents the omitted `multiple`), `SIGN` 1..2 and
  `STRSAME` 2..3 (optional last arguments), `INDEX` 2..4 and `LOOKUP`
  2..3. `MOD` is ADR 0053's alias of the reference's `MODULUS`.
  `EXP` has **no** reference page; kept because ADR 0053 puts it in the
  math set (1 argument).
- **`RGB`** returns `Value::Color`; the reference's palette-addition
  side effect belongs to the model layer and is not done here. A colour
  coerces to a number only through `coerce` (it defaults, per P6-03).

### Open issues

- `recalc::map_warning` (P6-06) drops `WrongArgumentCount`,
  `SetfRefused`, `Coercion` and `NonFinite` (its vocabulary has no
  equivalents). The values are right; the warnings never reach
  `RecalcOutcome`. If the phase wants them visible, add mapping arms in
  `recalc.rs` and matching `RecalcWarningKind` variants.
- Nicer reserved-name vocabulary: a distinct
  `EvalWarningKind::ReservedFunction` plus one `map_warning` arm
  (`UnknownFunction` for the keep-cached rule) would satisfy ADR 0053's
  "own warning text" with types instead of a decorated payload.
- Black-box checks and P6-10: the `MODULUS`
  sign convention, `CEILING`/`FLOOR` on negative numbers, the
  number-to-string form of a unit-ed number (`1 in & ""` is `"1"` here,
  P6-03's spelling), string-to-boolean coercion (we default to `FALSE`,
  `about-operators.md` does not list the conversion), and the unit
  factors the reference names but never gives (didots/ciceros come from
  `ferrogram_geom`, the nautical mile is 1852 m, `date` counts days —
  P6-03's table is now the single source).
- `eval_formula`'s parse half is still P6-02's stub on this branch: it
  forwards `Error::NotImplemented("parse")`, and its test accepts both
  outcomes until P6-02 lands. After that, a fuzz target that feeds the
  `parse` output to `eval` (today's target stops at parsing) would cover
  the evaluator against corpus-shaped input.
- Defensive fall-throughs kept for safety (never reachable through the
  arity-checked dispatch): the `BinaryOp::Concat` arm of `arith`, the
  wildcard arm of `apply` (a table/evaluator disagreement would land
  there), the small `else` arms of `eval_if`/`eval_iferror`/
  `eval_setf`, and the `_` arm of `text_of`.
