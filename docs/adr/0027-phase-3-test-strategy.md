# 0027: Phase 3 test strategy

- Status: accepted
- Date: 2026-10-14
- Task: P3-01

## Context

The Phase 3 exit criterion is: every corpus file renders without panics,
and every geometry row type has tests. KICKOFF adds golden image snapshots
with tolerance, hand-authored fixtures per feature, and a structural
comparison against libvisio's SVG output where meaningful. ADR 0017 covers
the Phase 2 harness; this ADR extends it to rendering. ADR 0005 (corpus
fetched, not committed) and the clean-room rules apply throughout.

## Decision

### 1. Geometry row types (exit criterion part 2)

Every row type of ADR 0022 has tests at three levels:

- **Typing** (`crates/model`): each `T` value parses into its
  `GeometryRow` variant from cached cells, including the `Rel*` fraction
  rule, `NurbsTo`'s E-cell formula text and `PolylineTo`'s A-cell list, and
  their unparsable fallbacks.
- **Math** (`crates/geom`): `Curve::to_cubics` for `Arc` (bow positive,
  negative, zero), `EllipticalArc` (with and without `C`/`D`), `Nurbs`,
  `Spline`, `Polyline`, `Quad`, `Cubic`, and the degenerate cases of
  ADR 0022 (each degrades to a line and never panics).
- **Mapping** (`crates/render`): each row type maps to the right scene path
  (absolute and relative), one test per variant.

A test list in the P3-10 Result shows each variant with its test names;
P3-10 checks the list is complete.

### 2. Golden images with tolerance

- Location: `crates/render/tests/golden/<name>.png`, committed. They are
  our own output: each file gets an `ATTRIBUTION.md` row ("generated by
  `cargo test -p larrygram-render`, our own work, MIT"), added in the
  committing task (AGENTS.md section 4).
- Inputs: hand-authored fixtures (below) and, where useful, corpus files
  (the goldens are then our rendering of corpus input, regenerated with
  `LARRYGRAM_REQUIRE_CORPUS=1`).
- Regeneration: `LARRYGRAM_UPDATE_GOLDEN=1 cargo test -p larrygram-render`
  rewrites the goldens; the test prints which files changed. Review is an
  image diff of the changed files (the master reviews before merge).
- **Comparison metric** (`tests/golden.rs`, ours, small): images must have
  the same dimensions; each channel may differ by at most **2** of 255 and
  at most **0.5%** of pixels may exceed that. The metric is written once
  with unit tests on synthetic images. It absorbs libm noise across
  platforms (ADR 0025) while catching a wrong arc, missing fill or shifted
  text.

### 3. Hand-authored fixtures

`corpus/fixtures/` gains rendering fixtures built with the P2-08 fixture
builder (extended, P3-10 owns it): one minimal file per feature in
KICKOFF's Phase 3 list — every geometry row type (absolute and relative),
solid and gradient fills, line weight/pattern/ends/rounding, shadows, text
with runs, paragraphs, bullets and tabs, master inheritance, theme colors
and fonts, layer visibility, page size and background pages. Each fixture
has a `corpus/PROVENANCE.md` row ("hand-authored, our own work, MIT") in
the same commit.

### 4. Oracle comparison (libvisio, ADR 0010)

Structural comparison against `vsd2xhtml` output, behind
`LARRYGRAM_LIBVISIO_ORACLE` (skipped with a message when unset; mandatory
with `LARRYGRAM_REQUIRE_ORACLE=1`). Where it is meaningful: page count,
per-page shape and path counts, and the overall drawing bounding box with
a tolerance of **0.05 inches** (the two renderers disagree about stroke
extents). Files the oracle cannot parse record the skip and fall back to
the corpus render test; the test notes its oracle-only nature and contains
no libvisio code or copied output format knowledge beyond parsing counts
out of the XHTML.

### 5. No-panic corpus rendering (exit criterion part 1)

`crates/render/tests/corpus_render.rs`: for every `corpus/vsdx/*.vsdx`
(15 files), `read_document` -> `build_scene` for every page -> `render_png`
and `render_svg`. Assert `Ok` (warnings allowed) and no panic; skipped
without the corpus, mandatory with `LARRYGRAM_REQUIRE_CORPUS=1`. The
existing Phase 2 round-trip test must still pass (a criterion of P3-02).

### 6. Property tests and fuzz

- `proptest` over the scene builder: random bounded models (shapes with
  random cells, groups, master links) build a scene without panicking;
  random `GeometryRow` sequences map to paths without panicking.
- Fuzz target `crates/render/fuzz/fuzz_targets/render_document.rs`: raw
  bytes -> `read_document` -> `build_scene` -> `render_png`/`render_svg`,
  asserting no panic. Built by the gate's fuzz step; seed corpus committed
  (small, hand-authored).

### 7. Text and CLI

- `larrygram-text`: unit tests for wrapping, alignment, spacing, bullets,
  tabs, vertical alignment, rotation and the missing-font/glyph warnings
  (golden *text* layout numbers, not images).
- `larrygram-cli`: argument parsing and exit-code tests; `inspect --json`
  output is snapshot-tested (`insta`).

## Consequences

- Goldens pin our own visual styles (ADR 0023): changing the data file
  changes goldens deliberately, in reviewable commits.
- The oracle tests stay opt-in locally and mandatory in CI once CI exists
  (Phase 1 known issue).
- The fuzz target doubles the fuzz surface (`vsdx`, `ui-spec`, `render`).

## Alternatives considered

- **Byte-identical goldens.** Rejected (ADR 0025).
- **Compare against Visio screenshots.** Rejected: visual fidelity is out
  of scope for the alpha and screenshots are the later pass's inputs.
- **Golden SVG text snapshots too.** Adopted lightly: `insta` snapshots of
  `render_svg` output for a few fixtures (text is stable and reviewable in
  a diff); PNG goldens remain the visual check.
- **One mega-fixture instead of per-feature files.** Rejected: a failure
  would not name the feature; per-feature fixtures keep tests local.
