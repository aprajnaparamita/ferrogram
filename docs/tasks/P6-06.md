## Goal

Build the dependency graph over a document's formulas and implement the
incremental recalculation pass: dirty cells plus their transitive
dependents, evaluated in a deterministic topological order, with cycle
cutting, a deterministic evaluation budget, `SETF`-induced extra dirt, and
the write rules of ADR 0056 (values for cells that have formulas,
materialised formula + value for inherited ones).

## Acceptance criteria

- [ ] A diamond dependency evaluates the shared cell once (order test).
- [ ] Dirtying one cell recomputes exactly its transitive dependents
      (incremental test on a 20-cell document).
- [ ] A hand-built model of the `recursion-cycle.vsdx` cycle produces
      one `Cycle` warning naming the cells in the cycle, keeps their
      cached values, and terminates.
- [ ] A budget of 3 evaluations over a 10-cell chain truncates, sets
      `truncated`, records `BudgetExceeded` and leaves the rest stale.
- [ ] `SETF` in an evaluated cell writes its target and dirties it within
      the same pass (test with a two-cell chain).
- [ ] A cell with its own formula gets only its value updated; an `Inh`
      cell the pass recomputes gets the formula materialised and the value
      written (two tests, ADR 0056's rule).
- [ ] Recalc is idempotent: a second pass over the same dirty set changes
      nothing (no updates in the second outcome).
- [ ] Hand-off gate green in the worktree (AGENTS.md section 7: `--quick`
      plus **coverage**, **fuzz** if you change the shapesheet public API,
      **wasm** if you touch any `Cargo.toml`).
